## 一、翻译策略

### 1.1 契约翻译（非逐行翻PHP→Python）

老项目是Python实现，V1是Rust内核。**不是代码搬运，是按V1契约重写**：

- **读老项目的能力语义**（它做什么、入参出参、错误条件）
- **写成V1的契约声明**（JSON格式，`契约声明/能力声明/外部_<模块名>.json`）
- **命名按V1纪律修复**（禁止单字、泛名、序数代称）
- **分配号段**（每模块10,000个号，10000~999999外部模块号段）

### 1.2 依赖拓扑分层接入

**不能随机翻译**，必须按依赖层序：

```
Layer 0（无依赖） → Layer 1（只依赖Layer 0） → Layer 2 ...
```

**先扫依赖图**（任务书03），确定层序后**逐层批量接入**（任务书06）。

## 三、命名修复规则

老项目的命名**不符合V1纪律**，翻译时必须按规则修复：

### 3.1 禁止形状（4类）

| 类型 | 例子 | 修复方向 |
|---|---|---|
| 单汉字 | `件`、`止` | 改成 `文件路径`、`停止标记` |
| 泛名 | `数据`、`信息` | 改成 `用户数据`、`配置信息` |
| 序数代称 | `一条`、`第三项` | 改成 `首条记录`、`第三配置项` |
| 西文单字母 | `x`、`i` | 改成 `横坐标`、`索引` |

### 3.2 合格标准

**结构固定**：`动作 + 对象` 或 `对象 + 说明`  
**语义自解释**：不依赖上下文能看懂

### 3.3 例外机制

**外部强加的名字**（Python标准库、DOM属性）登记例外：

```bash
python3 开发工具/信息核心/信息核心.py 登记例外 <名字> <来源说明>
```

## 五、翻译器工作流

### 5.1 翻译一个模块的流程

```bash
# 1. 扫描老项目模块（Python文件）
python3 构建装配/翻译器/老项目模块翻译.py --模块 前端核心

# 2. 产出契约声明JSON
契约声明/能力声明/外部_前端核心.json

# 3. 修复命名（自动应用规则库）
# 4. 分配号段（从号段表取号）
# 5. 生成参数表（按V1数据槽格式）
```

### 5.2 验证标准

翻译完一个模块后必须：

1. **契约JSON通过验证**：`python3 开发工具/信息核心/信息核心.py 验证 --契约`
2. **命名纪律全绿**：`python3 构建装配/一键验证/闸0.py` 命名纪律不红
3. **号段无冲突**：与已分配号段不重叠
4. **能导入V1**：能被 `跨语言适配/适配器实现/` 加载调用
