## 一 用法

```sh
python3 开发工具/认领机制/认领机制.py 认领 leg-a 开发工具/并行工作树.sh 运行内核/调用调度/src/lib.rs
python3 开发工具/认领机制/认领机制.py 查活跃
python3 开发工具/认领机制/认领机制.py 收工释放 leg-a
python3 开发工具/认领机制/认领机制.py 回收 --腿 leg-a          # 显式回收（只收已过期的）
python3 开发工具/认领机制/认领机制.py 回收 --全部过期
python3 开发工具/认领机制/认领机制.py 提交闸                     # 提交闸（默认只报不拦）
python3 开发工具/认领机制/自检.py                                # 判据 × 反向/正向样本
```

`--json` 出机器可读的一版。退出码：`0` 成功 · `2` 用法/参数错 · `3` 冲突或被拒 · `4` 无此租约
（**提交闸的退出码另有一套，按模式给，见表下**）。
腿标识用 ASCII（字母/数字/短横线/下划线），与 `并行工作树.sh` 的腿名同一套。

### 1.1 提交闸（比对「将要提交的路径」与「本腿的认领集」）

```sh
python3 开发工具/认领机制/认领机制.py 提交闸 --腿 leg-a     # 只报不拦（默认）
CLAIM_GATE=硬拦 python3 开发工具/认领机制/认领机制.py 提交闸  # 真拒
```

读的是 `git diff --cached`（**将要提交的路径**，不是工作区 diff：没暂存的改动 `git commit` 不会带上）。
腿标识三级：`--腿` → 环境变量 `CLAIM_LEG` → **当前分支按 `腿/<腿名>` 推**（机制一 的分支就叫这个名）；
三级都没有 ⇒ 读数「判不了」（**不猜**：猜错腿名 = 拿别人的认领集判，那是假绿）。

| 模式 | 怎么开 | 全在集里 | 有不在集里 | 判不了 |
|---|---|---|---|---|
| **警告（默认）** | 不设 | 0 | **0**（只报） | **0**（只报） |
| **硬拦** | `--硬拦` 或 `CLAIM_GATE=硬拦`（别名 `block`/`1`/`true`/`on`/`yes`） | 0 | 3 | 2（fail-closed） |

**★ 默认必须是警告**：现在没人在用认领机制（账本实测为空）⇒ 硬拦会挡住**所有**提交，
把闸门变成「谁都不能提交」。**模式的定义只有一处**（`认领机制.py::gate_mode`）：
`pre-commit` 钩子只写 `exit $CODE`，不自行判模式（两处各判一次 = 两处定义同一件事）。
装法见 `测试验证/案例/装门禁.sh`（它是 `.git/hooks/pre-commit` 的**源头**）。

**读数的口径**：`判不了` **不是通过**（`判据的可信性.md` §二 的读数三元）——
没腿标识、本腿无租约、本次没有要提交的路径、账本读不出、两个仓根对不上，全归「判不了」。

### 1.2 装到哪里（**实测**：钩子在 `git worktree` 下是**共享**的）

装法：`sh 测试验证/案例/装门禁.sh`（**它才是 `.git/hooks/pre-commit` 的源头** ——
`.git/hooks/` 不进版本库，别人 clone 下来拿不到钩子）。

**实测两条**（撞到，不是推测）：

1. **工作树里的 `.git` 是个文件**（内容 `gitdir: …/工作树名`），不是目录 ⇒
   写死 `$ROOT/.git/hooks` 会报「本仓不是一个 git 工作区？」（**假红**）。
   故改为 `git rev-parse --git-path hooks` 让 git 自身算。
2. **那份钩子是所有工作树共享的**：`git rev-parse --git-path hooks` 在工作树里给出的是
   **公共** git 目录（`主仓/.git/hooks`）⇒ 在那里装 = 给**全仓每一棵树**（含主树）装。
   这不是一条腿该悄悄做的事 ⇒ 脚本要求显式同意：`GATE_INSTALL_SHARED=yes`。

**⇒ 一条腿在自身的工作树里跑本脚本，默认会被拒**（并说明为什么）——
要装全仓才加那个变量。**本件没有在共享钩子上装过**（那会改动所有腿的环境）。

## 二 账本形状（`git diff` 直接可读）

```json
{
  "格式版本": 1,
  "租约": [
    { "腿标识": "leg-a", "路径集": ["开发工具/并行工作树.sh"],
      "认领时间": "2026-09-25 12:00:00+0800", "到期时间": "2026-09-25 12:30:00+0800" }
  ]
}
```

写账走「临时文件 + `os.replace`」，认领/释放/回收走「`flock` 互斥 + 读改写」——
**原子性由内核锁保证，不由「没人同时跑」保证**。锁文件落 `/tmp`（按账本绝对路径哈希），
**不进仓、不进版本库**（故不需要动 `.gitignore`）。账本按 `腿标识` 排序 ⇒ diff 只显示真变化。

## 三 五条语义落在哪

| # | 语义 | 落点 |
|---|---|---|
| 1 | **原子**：任一条被占 ⇒ 整体失败，不半占 | `认领机制.py` `op_claim`：冲突时**直接 return，一次都不碰账本**（`led.save()` 在冲突分支之后） |
| 2 | **所有者 = 腿标识，不是路径** | `op_claim` 的判据是 `held["腿标识"] != leg`；同一腿重复认领走「合并路径集」分支 ⇒ 幂等成功（`新增 == []`） |
| 3 | **租约带到期；到期只是「可回收」，回收必须显式** | `lease_status` 只判读、不改账本；`op_claim` 对已过期租约**照样报冲突**；`op_reclaim` 是唯一的回收路径，且**必须显式指定目标**（`--腿 X` 或 `--全部过期`，没有默认值），未过期只能 `--腿 X --强制` |
| 4 | **释放后立刻可再认领** | `op_release` 真删该腿的租约并落盘 ⇒ 下一次 `op_claim` 看不到它 |
| 5 | **查活跃报 腿标识 · 路径集 · 认领时间 · 到期时间** | `op_query` 每条租约返回这四个字段 + `状态` + `剩余秒`，并报**账本读到总条数** |
| 6 | **提交闸**：改动路径 ⊆ 本腿认领集 | `op_gate`（核心）· `git_staged_paths`（读 `git diff --cached`）· `gate_mode`（模式只此一处）。**默认只报不拦**，硬拦是显式开关 |

路径归一化：相对路径按仓根解析、统一 `/`、去重排序 ⇒ `./a//b.rs` 与 `a/b.rs` 是同一条（`norm_paths`）。
仓外路径**拒绝**（不静默接受）。

提交闸的两条实测口径（都是**变异测试逼出来的**，不是随手写的）：

- `--no-renames`：改名必须**两边都报**。默认的改名探测只报新路径 ⇒
  「旧租约挂在 `a` 上、`b` 没人认领」这条（§五 第 5 条）就漏过去了。
- 基准一致性：`git diff --cached` 的路径是**仓根相对**的，账本里的路径也是 ⇒
  **两边必须同一个仓根**。脚本所在仓与提交所在仓不是同一个时，报「判不了」——
  硬比两套基准会**全绿而什么都没判**（假绿）。故必须 `git -C <仓根>` 跑。

## 四 判据与样本（每条都有反向 + 正向；缺任一方 ⇒ 未验证，不计入通过数）

| 判据 | 反向样本（造违规，断言抓住） | 正向样本（干净输入，断言通过） |
|---|---|---|
| **J1 同一路径集两次认领，第二次必冲突** | 两条腿认领同一路径集 ⇒ 第二次报冲突 + 报出被谁占 + 不留半占；换拼法再认领 ⇒ 仍冲突 | 两条腿认领不相交路径集 ⇒ 都成功，交集为空 |
| **J2 跨所有者写同一路径必被拒** | leg-a 占 P1 后 leg-b 认领 [P1(被占), P3(空闲)] ⇒ 冲突，且 **P3 也没被占**（原子） | 同一腿重复认领自身的路径 ⇒ 成功、`新增=[]`、账本仍 1 条（幂等） |
| **J3 到期可回收，但回收是显式的** | 过期后 leg-b 仍认领不到（没有自动静默回收）；未到期不得回收；**回收目标必须精确**（不许连带收走别人的过期租约） | 显式回收过期租约 ⇒ 成功，之后 leg-b 可再认领 |
| **J4 释放后立即可再认领** | 造「释放没生效」的陈旧租约 ⇒ 再认领必被拒 | 真释放 ⇒ 账本里已无该腿 + 立刻可再认领 |
| **M1 元判据不空转** | 注入只有正向样本的判据 ⇒ 元判据报「未验证」 | 成对样本的判据 ⇒ 元判据报「已验证」 |
| **M2 解析器自检** | 账本形状坏 ⇒ 必须报错（`ValueError`），不许静默当空账本 | 读入已知答案（2 条）⇒ 报出读到 2 条 |
| **M3 空集不算通过** | 空账本 ⇒ 读数「未判」 | 非空账本 ⇒ 读数「判得了」 |
| **M4 命令行层（判据要覆盖输出层）** | 用法错（缺路径/缺回收目标/仓外路径）不许静默成功：退出码必须 2 且账本一字未动 | 跑真命令行：认领冲突必须报出「被 leg-a 占」且退出码 3 |
| **J5 提交闸：改动路径 ⊆ 认领集** | 改了没认领的路径 ⇒ 必须报出来；**默认只报不拦**（不设开关必退 0，`--硬拦`/`CLAIM_GATE=硬拦` 才退 3）；开关**拼错**不许静默变硬拦；空集/坏账本/无此租约 ⇒ 判不了（不算通过）；改名**两边都报**；脚本仓 ≠ 提交仓 ⇒ 判不了 | 改动全在认领集里 ⇒ 报「全在集里」且退 0；在**子目录**里跑路径基准仍是仓根；腿标识按分支 `腿/<腿名>` 推 |

**J5 的样本真起 git 仓**（不是喂假数据）：闸读的是 `git diff --cached`，
只有真仓才验得到「路径基准是仓根」「改名两边都报」这两条 —— 而它们正是绕过口。

**变异实测**（把核心改坏，看样本是否报红；改坏的是 `/tmp` 里的副本，仓内代码未动）：
**14 个变异全部被样本抓住**。其中三条值得记下来当证据：

1. **「只问有人占不问是谁占」这条旧版实测缺陷原样复现 ⇒ 8 条样本报红**（A）。判据确实有牙。
2. **「回收目标不精确」（收 leg-b 时连带收走 leg-a 的过期租约）没被抓住** —— 补了一条反向样本才抓住。**样本也会漏，要靠变异测试才发现。**
3. **命令行渲染函数被写坏（`emit` 打印了函数对象本身，输出 `<function main.<locals>.<lambda>>`）也没被抓住**：19 条样本里有 17 条走核心函数，核心全绿而命令行是坏的。补了 M4（真跑子进程的命令行层样本）才抓住。**这条正是 `判据的可信性.md` §三 #2「判据在 ≠ 判据覆盖」的原样复现——扫描面不覆盖输出层。**

**变异实测（J5，2026-09-27）**：三个变异逐一植入 `/tmp` 副本（仓内代码未动），看样本报不报红：
默认模式改成硬拦 ⇒ **抓住**（2 条红）· 去掉 `--no-renames` ⇒ **抓住**（补强样本之后）·
去掉基准一致性检查 ⇒ **抓住**（1 条红）。
其中**第二个变异没被抓住**：原样本只断言「新路径报没人认领」，
而默认改名探测恰好只报新路径、且它也不在集里 ⇒ 断言照样绿。
**样本也会漏，是变异测试发现的**（与本节第 2、3 条同一类）。改法：改断言「改动路径数 = 2」。

**并发实测**（原子性不是靠「没人同时跑」）：6 条腿各起一个进程同一瞬间抢同一条路径，
连跑 5 轮，**每轮恰好 1 条成功、账本恰好 1 条租约**（`flock` + `os.replace` 起的作用）。

## 五 ★ 诚实边界：它挡不住什么（本件的重点）

**本机制是协作式的：它只挡得住愿意来认领的腿。** 下面每一条都是**实测或显然**能绕过去的：

| # | 挡不住的写者 | 为什么挡不住 |
|---|---|---|
| 1 | **`cargo clippy --fix` / `cargo fmt --all`** | 它们按 `--workspace` 遍历整棵树**重写文件**，不看账本、不认路径集。**真正造成破坏的正是它们，不是另一条腿** —— 这是 `并行开发与工作区.md` §一 与 `判据的可信性.md` §七 记的实测（**本件没有复量**，是引用）。格式化工具只认「这个文件在不在我的遍历结果里」 |
| 2 | **批量 `sed -i` / `perl -pi -e` / 全仓替换脚本** | 路径是**算出来的**（`grep -rl` 的结果），不是认领来的。它改 30 个文件时不会有 30 次认领 |
| 3 | **人手改** | 编辑器里直接改，与账本无关 |
| 4 | **任何绕过本脚本的写**：`git commit` / `git checkout` / `git merge` / `git stash` / `cp` / `mv` / 生成器写文件 / IDE 重构 / 格式化钩子 | 账本只在**经本脚本**的动作里被检查。绕过 = 不检查 |
| 5 | **改文件名/删文件** | 认领的是**路径字符串**。`git mv a b` 之后旧租约还挂在 `a` 上，`b` 没人认领 ⇒ 两条腿可以各占 `a` 与 `b` 而实际写同一个文件 |
| 6 | **本脚本自身** | 谁都能改 `认领机制.py`、删 `账本.json`、把冲突分支改成 `return 成功`。机制不保护自身 |
| 7 | **读的一方** | 本机制不管读，也不管构建。`cargo build` 不认领任何路径（它只写 target） |
| 8 | **不在工作树里跑的腿** | 没有腿标识就没有认领主体。机制一（`并行工作树.sh`）是它的前置，不是可选项 |
| 9 | **时钟** | 到期判据读系统时钟。时钟回拨/多机不一致 ⇒ 到期判据失真（本机单仓才成立） |
| 10 | **大小写与符号链接** | macOS 文件系统大小写不敏感 ⇒ `A.rs` 与 `a.rs` 被判成**两条**路径（真漏洞，见 §六）；`normpath` 不解析 symlink，两条指向同一文件的链接算两条 |
| 11 | **多机 / 多仓根** | 账本是**单文件 + 本机 `flock`**。两台机器各跑一份账本，互相看不见 |

**⇒ 真正的强制点在提交。** 两条腿唯一的**公共汇聚点**是提交（`git`）——那里才是唯一能对
「账本说谁占了什么」与「diff 里实际改了哪些路径」的地方。本脚本的作用是
**「让守规矩的腿不撞」，不是「让不守规矩的腿撞不上」**。把本脚本当强制点用，就是假绿。

## 六 已知局限 / 定不下来缺什么

1. **能力号集没做**：`并行开发与工作区.md` §六 第 5 行倾向「路径集 + 能力号集双轨」。本件**只落了路径集**——因为现在没有可对的**能力号注册表**（`能力声明/` 是空目录），做了也无源可判。**如实记为缺口**，不假装覆盖。
2. **提交闸：做了，但默认「只报不拦」** —— 原先这里是「本件最大的缺口」。
   现在 `认领机制.py 提交闸` 比对「将要提交的路径」与「本腿认领集」，
   经 `测试验证/案例/装门禁.sh` 装进 `.git/hooks/pre-commit`（钩子的**源头**是那个脚本，
   不是 `.git/hooks/` 里那份 —— 后者不进版本库）。
   **★ 默认是警告模式（只报不拦）**：账本实测为空、没人在用认领机制 ⇒ 硬拦会挡住**所有**提交。
   硬拦要显式开（`--硬拦` / `CLAIM_GATE=硬拦`），见 §一.1。
   装法见 §一.2（**钩子在 `git worktree` 下是所有工作树共享的** —— 实测，别以为装自身那棵就完事）。
   **仍缺的**（如实记，不假装覆盖）：
   （a）它**不判「谁改的」** —— `git diff` 里没有腿标识，账本里也没有提交；
      闸只回答「这些路径是不是全都在**你报的那个腿**的认领集里」，腿标识靠显式给或按 `腿/` 分支推；
   （b）它**默认没有牙** —— 不开开关就只是打印，所以「强制」这件事现在是**可选的**；
   （c）**没有登记谁开了硬拦** —— 也没测过「全仓开着硬拦跑一次」会拦下什么：
      实测到的一条副作用是 `git add -A` 会把 `账本.json` 与 `测试验证/案例/运行回执.jsonl`
      一起暂存，而它们通常不在任何腿的认领集里 ⇒ 硬拦下会**连带报出来**
      （闸如实报是对的，但「谁该认领这两份」没有定论）。**这条留给收口方裁**（§八 待裁 1）。
3. **到期后谁该回收没有机制**：现在靠人或收口方显式回收。**刻意不做自动续租**（自动续租 = 永不释放，比过期更坏）；也没有「心跳」。

## 八 待裁（本件不自行发明，列选项 + 建议 + 理由）

1. **`账本.json` 与 `测试验证/案例/运行回执.jsonl` 该由谁认领？**
   实测：`git add -A` 会把这两份一起暂存，而它们通常不在任何腿的认领集里 ⇒
   硬拦模式下会被报出来（`说明.md` §六 第 2 条 c）。
   选项：① 每条腿认领自身那份账本 —— 但账本是**共享单文件**，两条腿认领它会当场冲突；
   ② 把这两份登记成「例外的公共件」（闸里加一张白名单）；
   ③ 认领集里由收口方统一持有，腿不认领。
   **建议 ②**：理由是它们与「谁改哪条路径」不是同一类 —— 账本是机制的**状态**、
   回执是**证据**，两者都该跟着提交走而不是被某条腿独占；白名单要显式列在闸里（不许靠前缀猜）。
   **但这是口径裁决，不是本件能定的** ⇒ 留给收口方。

2. **硬拦该在什么时候真正打开？**
   选项：① 现在不打开（本件默认）；② 等账本有真实使用后由收口方在收口流程里开；
   ③ 每条腿自身决定开不开。
   **建议 ①→②**：③ 不成立 —— 闸在提交者的环境里跑，各自开关等于没有闸。
   本件按裁决只做「**默认警告** + 显式开关」，何时开留给人。

3. **腿数上限与认领粒度**（`并行开发与工作区.md` §六 第 4、5 行）仍是待定，本件不涉及。
