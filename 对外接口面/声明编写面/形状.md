# 声明编写面 · 形状

上级：系统工程平台 V1 ／ 落点：`对外接口面/声明编写面/`
相关：`契约声明/格式说明.md`（唯一事实源）· `项目文档/设计文档/接口面形状.md` §四（冻结的请求/返回形状）·
`项目文档/开发规范/开发规范.md` A2（声明只走面写）· `契约声明/号段图.json`（全平台编号布局）

**本面补的是一个空节点。** 在这之前 `对外接口面/声明编写面/` 是空目录，于是
`开发规范.md` A2 定的「`契约声明/` 的写入只有声明编写面一条路」**没有落点** ——
`POST /接口/声明` 端点已就位但缺「面校验与落盘」。本面就是那个落点。

---

## 一 面怎么用（逐条命令）

在仓库根执行（`构建环境/进入.sh` 只为把 python 钉在仓内；面只用标准库）：

```sh
# ① 写一份声明（编号留空 ⇒ 面自动分配）
python 对外接口面/声明编写面/声明编写面.py --请求 \
  '{"类别":"通知号","编号":null,"正文":{"名称":"示例","说明":"…","方向":"下行","参数":["无"]}}'

# ② 请求体也可以从 stdin 读（`-` = 读标准输入）——给 HTTP 网关留的调用姿势
python 对外接口面/声明编写面/声明编写面.py --请求 - < 请求.json

# ③ 只算号、不落盘（先看面打算给哪个号）
python 对外接口面/声明编写面/声明编写面.py --分配 通知号

# ④ 换声明根（默认 契约声明；与 生成声明.py 的 --声明根 同一口径，只认仓内相对路径）
python 对外接口面/声明编写面/声明编写面.py --请求 - --声明根 契约声明 < 请求.json
```

- 返回**一律是 JSON**，形状照 `接口面形状.md` §四（成功 `{成功,编号,落盘,指纹}`；
  失败 `{成功:false,校验:[{项,缺什么,为什么不能自愈}]}`）。
- 退出码：`成功=true` ⇒ `0`；否则 `1`（供 shell 判）。
- 除冻结键外**只加旁路字段**（`确认` · `判据器` · `面外既有红` · `留痕` · `回滚` · `分配` · `面故障`）——
  §四 冻的是「请求体形状」，旁路字段是允许的演进方式（README 第八节）。

## 二 请求体

```json
{ "类别": "能力" | "类型" | "错误码" | "通知号", "编号": 1001, "正文": { … }, "确认": false }
```

| 键 | 规则 |
|---|---|
| `类别` | 四取一，**逐字**照 `接口面形状.md` §四。它决定落哪个目录、编号字段叫什么 |
| `编号` | 整数或 `null`。`null` ⇒ 面自动分配（见 §四）。非空 ⇒ 面的落盘文件名就是它 |
| `正文` | JSON 对象，**形状 = `契约声明/格式说明.md` 里那一类 JSON，逐字一致**。面不改名、不重排、不加壳 |
| `确认` | **旁路字段**。仅当目标号**已存在**（改）时用；`true` 才允许覆盖（见 §五） |

`类别 → 目录 · 编号字段`（唯一的映射表，落在 `声明编写面/请求形状.py`）：

| 类别 | 落点目录 | 编号字段 | 号段制 |
|---|---|---|---|
| 能力 | `契约声明/能力声明/` | `编号` | 有（`平台声明.json.能力号段`） |
| 类型 | `契约声明/类型声明/` | `类型标签` | **无**（§十 待裁第 3 条） |
| 错误码 | `契约声明/错误码表/` | `码` | 有（`平台声明.json.错误段位表`） |
| 通知号 | `契约声明/通知号段/` | `通知号` | 有（`平台声明.json.通知号段`） |

面只做**请求形状**判断（等价 HTTP 400：请求本身合不合法：类别在四类里 · 正文是对象 ·
编号是整数或 null）。**内容契约一律不判**——那是判据器的事（§六）。

## 三 落盘到哪 · 文件名

```text
<声明根>/<类别对应的目录>/<编号>.json      # 编号 4 位补零，如 0001.json · 2004.json
```

- **文件名 = 编号**，`格式说明.md` §一 的原话：「一个号一个文件」是刻意的——
  编号冲突变成**文件名冲突，在文件系统层面就撞车**。面用 `O_CREAT|O_EXCL` 独占创建，
  撞号不靠面判断，靠文件系统报 `EEXIST`。
- 面负责「文件名 = 编号」这条不变量：`正文` 缺编号字段就填上；**已填且与请求编号不一致 ⇒ 拒收**
  （不静默改写：文件名与字段都已被外部引用，改哪个都是改契约）。
- 落盘字节 = `json.dumps(正文, ensure_ascii=False, indent=2) + "\n"`（UTF-8），与既有声明同形。
- 返回里的 `指纹` = `sha256(落盘字节).hexdigest()[:16]`（与 `生成声明.py` 的 `源指纹()` 同一口径）。

## 四 编号怎么分配（只从该层号段的空洞里取）

**该层 = 该声明根自身声明的「占用」**：`格式说明.md` §二 ★ 定死
「`平台声明.json` 的 `能力号段` / `通知号段` 是**本声明占哪几段**」（扩展那份叫 `包声明.json`，同形状）。
`号段图.json` 是**全平台布局**，面只用它给出「这个号落在哪一层」的标签，并交叉校验
占用 ⊆ 布局（判据 ④ 也查这条）。

```text
该层号段 = 平台声明.json.能力号段 / 通知号段 / 错误段位表 → 码区间
空洞     = 号段内的号 − 已用（该目录下的文件名与字段） − 作废号表.json 里**同空间**的号
分配     = 号段起点起，第一个空洞
```

四条硬规则：

1. **不许从 0 顺排**：不是 `0,1,2,3…` 计数器，是「在该层号段内找空洞」——已用号与作废号一律跳过。
2. **不许复用已作废的号**：`作废号表.json` 里**同空间**的号排除（判据 ③ 也是同空间口径：作废行带
   `号空间`，只排除**同一空间**里的号）。号空间互不相通（`契约声明/号段图.json`
   「四个号空间互不相通」＋ `项目文档/设计文档/字段名册与引用方式.md` §五 的「类型标签 …
   与上面四个不通」），数字相同不算同号（能力号 16 与错误码 16 是两回事）——
   全局排除会让错误码 16 去封能力号 16，是**假冲突**（实测：底座 `能力号段 0–999` 含 16 ⇒
   底座自身载不进来 · 31 条红）。
3. **不越层**：分配只在**该层号段**内找；号段占满 ⇒ 报「该层号段已满」而不是去借别层的号。
4. **错误码的号区间**：段位 `d` ⇒ 码 `d*1000+1 … d*1000+999`（§五：码 = `<段位 1 位><序 3 位>`，
   码 `0` 不是合法码）。底座 `错误段位表 = [0]` ⇒ 码区间 `1–999`。

**类型没有号段**（`格式说明.md` §十 待裁第 3 条：「类型标签的起始值与分配」未裁）⇒
`--分配 类型` **fail-closed**：报「§十 待裁，无号段可依，请显式给编号」，面**不猜**一个起始值
（猜出来的起始值就是第二个事实源）。**但类型有号空间**——它是第五个号空间（`类型`，
`字段名册与引用方式.md` §五「与上面四个不通」），只是不属号段制；`作废号表.json` 里
`号空间: "类型"` 的行照「类型」空间排除（`号段分配.作废号` 已认这一空间）。

## 五 改：只增不改 + 显式确认 + 留痕

目标号**已存在**时，面按 `格式说明.md` §七 / `开发规范.md` A5·A6 的「**只增不改**」判：

| 情形 | 面的动作 |
|---|---|
| 未带 `确认:true` | 拒收：`{成功:false,校验:[{项:"只增不改：号已存在"…}]}`，**不静默覆盖** |
| 带 `确认:true` 且**只增**（旧键全在、值全等，只多出新键） | 允许覆盖 |
| 带 `确认:true` 但**改旧 / 删旧**（任一旧键的值变了或被删） | 仍拒收：已公布字段的含义永不改写（A5 · 冻结规则）。只许新增旁路字段 |

**每次改（不论落盘还是回滚）都写一行留痕**，落在
`对外接口面/声明编写面/改动留痕/改动留痕.jsonl`（JSON Lines，只追加）：
`{时刻, 类别, 编号, 落盘, 判定, 结果, 改前指纹, 改后指纹, 改前正文, 改后正文}`。
「改动前后都要留痕」就是这两份正文 + 两个指纹。

## 六 校验：转调判据器，不在面里另写一套

**面里没有第二套校验。** 面把候选声明落盘，然后**转调既有的判据器**
`构建装配/一键验证/一键验证.py`（`格式说明.md` §九 的十项 + 四项新裁定，唯一事实源），
把它报的失败**逐条回给调用方**。

```text
写前跑一次判据器（基线）→ 落盘 → 写后再跑一次 → 分三类
```

| 类 | 判法 | 面的动作 |
|---|---|---|
| **阻断** | 失败条点到了本次落盘的文件（`位置`/`缺什么` 里有该相对路径）；**或**判据 ⑩ 报生成器 `--检查` **退出码 2**（fail-closed：本次声明不合契约形状，生成器拒了它） | **回滚**（新建的删掉、改过的恢复原文）+ `成功:false`，逐条回 `校验` |
| **生成物待重跑** | 判据 ⑩ 报生成器 `--检查` **退出码 1**（`生成物不新鲜`） | **不阻断**，列进 `生成物待重跑` + `后续` |
| **面外** | 其余（基线里就有 / 与本次写入无关） | **不阻断**，另列 `面外既有红` · `面外新增红` |

- 判据器**跑不动**（文件不在 / 加载失败 / 入口形状变了）⇒ `成功:false` + `面故障`
  写明「暂时转调不了」与**缺什么**（哪一步、什么异常）。面**不抄一份判据进来**兜底。
- **为什么 ⑩ 要单独分**：`契约声明/src/声明数据.rs` 是**生成物**，写**任何**一份声明都会让它
  不再新鲜（退出码 1）——修法是**重跑生成器**（`开发规范.md` §四：生成物过期 → 重跑生成器），
  不是回滚，所以不能当阻断理由。但生成器对本次声明 **fail-closed**（退出码 2）意味着那份声明
  确实写坏了（实测撞到过：`通知号段/2004.json` 的 `参数` 只给 1 项，而 `通知函数` 恰好两个
  usize 入参 ⇒ 必须 2 项），这时**必须**回滚。两者的区分用生成器自身的退出码契约
  （`生成声明.py`：`0` 一致 · `1` 不新鲜 · `2` 生成失败，产物未动），面不重跑生成器、不另写比对。
- **面外新增红带并发噪声**：判据器是**快照**；另一条腿同时在改仓库时，写前/写后两次读数之间的
  差异会把**它们的改动**算进来（实测撞到过：`夹具导出` 在两次读数之间出现）。故 `面外新增红`
  只能读作「与本次写入无关的变化」，面不用它阻断。

## 七 明确不做（面的职责边界）

1. **不判内容对不对**：不判「这个能力该不该存在」「参数表合不合理」——那是业务判断，属人/装配节点。
2. **不另写校验**：不自行查类型表 / 错误码表 / 号段 / 方向。判据器报什么就是什么。
3. **不重跑生成器、不碰 `契约声明/src/`**：生成物是装配节点的落点。
4. **不做删除**：删一个号要把号登记进 `作废号表.json`（§七：编号永不回收），
   那要改**已存在**的声明文件 + 有历史语义 ⇒ 面不提供删（避免绕开作废登记）。
   面的回滚只针对**自身这一次**落盘（新建的删、改过的恢复），不对外暴露成删除能力。
5. **不做鉴权 / 不做分页 / 不做版本协商**：同 `接口面形状.md` §一 的判据（面就是本机维护入口）。
6. **不写 HTTP**：面是**实现**，不是监听点。监听点只有 `对外接口面/调用接口面/` 一处（判据 ⑪ 子判据 1）。
   HTTP 那一层按 §四 的请求体/返回体形状转调本面（`--请求 -` 就是给它留的姿势）。

## 八 实测：与既有件矛盾的地方（照实记）

1. **`接口面形状.md` §四 的例子与 `格式说明.md` §一 ★ 冲突**：§四 的成功例子是
   `{"编号": 1105, "落盘": "契约声明/能力声明/1105.json"}`，失败例子说「1105 落在支持库段 1000–6999」；
   而 `格式说明.md` §一 ★ 定死「`契约声明/` 只装**底座自身的**声明……`能力声明/` 里装的是
   底座自身的 **9xxx** 能力，不是扩展的 1101–1107」，`号段图.json` 也把 `1000–1999` 划给
   「核心支持库」（扩展）。**两份冻结件对「`契约声明/能力声明/` 里能不能有 1105」说法相反。**
   本面按 `格式说明.md`（任务指定的唯一事实源）实现：层的号段取**该声明根自身的占用**，
   不取 §四 例子里的 1105。
2. **`格式说明.md` 自身也有一处不一致**：§一 ★ 说 `能力声明/` 装底座的 `9xxx` 能力，
   而 `平台声明.json` 的 `能力号段 = [(0,999)]`、`错误段位表 = [0]` 只说底座占 `0xxx`。
   两者不能同时为真。本面按 §二 ★ 的口径（`平台声明.json` 的占用 = 本声明占哪几段）取层，
   于是 `--分配 能力` 在**当前**仓库里会给出 `1`（`0–999` 里的第一个空洞 ——
   `契约声明/能力声明/0000.json` 已占 `0`）。
   哪一份该改，属裁决 ⇒ **只能人来裁**（面不替谁选）。
3. **`接口面形状.md` §四 的 `类别` 值只有四类，与判据器的四个编号目录一致** ✓（无矛盾）。
