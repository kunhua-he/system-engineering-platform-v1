## 一、核心定位

**内核 = 编译器**（不是应用服务器，不是业务系统）。一个可编程的底座：上层扩展经号段制隔离，底座不认识任何扩展。

```text
内容链   契约声明/ ← 运行内核/ ←〔 扩展根：支持库 · 模块 · 技能 〕
边界链   契约声明/ ← 运行内核/ ← 跨语言适配/ ← 对外接口面/ ← 前端呈现/
接缝     扩展装载/    （只规定扩展长什么样，不含扩展本体）
横切     构建装配/    （只读契约、只收扩展，不参与运行）
```

依赖单向、自下而上：**不许反向 · 不许跳层**；`运行内核/` 内部各 crate 之间按**同一层**读（同层互依不算违规，见库 `条款` 表 `文档路径` = `项目文档/决策记录/2026-09-27_判据口径十一条.md` §一）。

## 三、命名纪律

**合格标准**（结构检查，不是词源检查）：

```text
结构固定      动作 + 对象（读配置 · 写日志）
              对象 + 说明（配置文件 · 日志路径）
语义自解释     不依赖上下文能看懂
```

**禁止形状**（4 类）：单汉字名 · 泛名 · 序数代称 · 西文单字母。
**例外机制**：外部强加的名字（标准库 · 协议字段 · DOM 属性）登记进库 `命名例外` 表，不受纪律约束但要说明来源。

**推翻的假设（实测证据，不是元评论）**：老项目 5190 条待处理名字，**0 条能靠核心词纯组合表达** ⇒ 推翻「15 核心词 + 组合复用」思路，改「结构检查 + 禁止形状」。

**读数口径**：命名登记条数**不写死** —— 按库 `命名登记` 表现量。

## 八、开发工具 MCP 面（唯一 HTTP 传输）

`开发工具/MCP服务/` 是**开发工具**，不进底座、不参与运行（底座不调它、判据面不依赖它）。
它对外只有一个工具面、**一条传输**：Streamable HTTP（`开发工具/MCP服务_http.py`，只绑本机环回；
真实生效路 = 用户配置 `~/.zcode/cli/config.json` 与 `~/.hermes/config.yaml` 的 HTTP 43140，
仓内 `.mcp.json` 亦配 HTTP 供 Claude Code 用）。请求一律走 `协议.派发` → 同一份 `工具表` →
同一份统一信封 ⇒ **换入口不换闸**（开工 / 认领 / 指纹 / 门禁一条不少）。

**为什么只留 HTTP**：stdio 下客户端管进程生命周期，客户端一关工具面就没了；HTTP 面可常驻，
且「MCP 是薄壳、本质是网关」—— 同一份工具经 HTTP 也能被别的调用方复用。传输适配只做 HTTP 与
MCP 的握手 / 无状态响应形状 + 本机安全，**不复制**任何业务。HTTP 更新复用指纹与有界启动预检，
由唯一监听循环在所有连接排空后 exec，继承原监听器并核验；预检或 exec 失败保留旧服务。
持续繁忙时等待安全点，不在请求中途切换。`开发工具/MCP服务.py` 只保留 `--自检` / `--长样本` /
`--长样本全套` / `--启动预检` 四个具名档，**不再提供 stdio 协议主循环**。依据：库 `条款` 表
`文档路径` = `项目文档/决策记录/2026-09-27_MCP适配层.md`。
