## 零 一句话结论

项目**不是架构选错**，而是**元层（治理工具）与对象层（底座本体）挤在同一个仓、同一套门禁、同一个台账里**，
导致「维护底座」这件事被「维护维护系统」压住了。

修的方向不是重写，也不是继续加能力，而是**先把元层独立出来并给它自身的纪律**，
再让对象层去补核心接缝。

## 三 根因（六条，从底层）

### 根因一 元层与对象层没有分家（最底层的一条）

一个仓里同时住着两件性质完全不同的东西：

```text
对象层（底座本体）  契约声明 · 运行内核 · 跨语言适配 · 对外接口面 · 扩展
元层（治理工具）    MCP服务 · 门禁 · 信息核心 · 开工账本 · 合并工具 · 反馈系统 · 清理
```

它们**共用**同一套行数判据、同一套命名判据、同一个未完成台账、同一条闸0。

后果：**元层要修自身，得先过对象层的门禁；而门禁又住在元层里**。

实测已发作（性能改造腿自报）：

```text
循环导入 ⇒ 一键验证包 import 失败
       ⇒ 写前校验不可用
       ⇒ 只能直写文件
       ⇒ 又致指纹漂移
```

这不是一个 bug，是**结构性的循环依赖**：验证者与被验证者是同一团代码。

### 根因二 写入口不止一个，保护层可被绕过

设计上，改源码只有一条路：

```text
v1_edit ─ 四道闸：开工进行中 · 路径已认领 · 指纹对得上 · 旧内容唯一定位
```

★ **本轮复核：这两处旁路已经修掉了**（实测现码，不再是缺口）：

```text
① 无开工ID 的 v1_shell 写主干
   已修 —— 新件 开发工具/MCP服务/主干写盘兜底.py：
   无开工ID 时跑前/跑后各取一次主干快照，已跟踪件被改/删 ⇒ 当场还原并点明；
   新增未跟踪件如实报出（不擅自删）；带开工ID 不介入

② 自检 / 样本遥测写生产账本
   已修 —— 工具流水.py 加「记账域」：域内落进程私有临时库，
   同一份实现只换落点；出域一律 reset ⇒ 不泄漏到并发生产请求
```

⇒ 根因二**本轮收窄为**：写入口旁路已封；但「生成器 / 建库直接写盘」这一路
的记账与指纹链完整性，仍属**待核**（未实测）。

### 根因三 「当前态」有五种表达，读者无法一眼判断在途/已实现

```text
规则 · 条款 · 裁决    →  信息核心.db
未完成                →  未完成.json
当前架构              →  开发文档/实际架构.md
未来方案              →  已退役（1283 行方案已按「蒸馏后删」口径下线）
实现状态              →  代码
```

本轮复核：那份 1283 行方案**已下线**，内容已拆成台账条目（逐条现核）。
⇒ 这一处**风险已消解**；根因三**收窄为**下面这条仍然成立的现象：

```text
「能力是否已实现」没有单一机器可读读数口
   ⇒ 新会话只能读码或读台账去判
   ⇒ 台账条目写「未达成 / 部分达成」，但那是「方案项」的状态，
     不是「能力可用性」的机器可读状态
```

### 根因四 门禁测形状，不测行为；「全绿」与「核心稳固」脱钩

```text
闸0    = 闸1（声明侧）+ 闸2（实现侧）  —— 两条都是静态
行为   = 案例（9 个）+ 发布验收（T01–T09）  —— 不在每次提交门禁里
```

后果：

```text
门禁全绿  ≠  子进程隔离成立
          ≠  模块程序文本能变真实行为
          ≠  技能能按号取文
          ≠  发布/回退/恢复成立
```

项目已把这条写进《判据的可信性》，但**放行口径尚未强制绑定行为考题**。

### 根因五 台账把「任务包」当一条维护

```text
一条大台账 = 登记回滚 + 反馈蒸馏 + 源库重放 + 保全副本 + 合主干清理
              + 同步门禁 + 工具耗时统计 + 性能基线 + 历史事故证据 + 验证关闭可信性
```

而方案拆分段的 79 条虽然粒度均匀（一条一个方案项），但**没有表达依赖顺序**：

```text
79 条平铺  ⇒  看不出谁先谁后
           ⇒  无法判断「现在该做哪一条」
           ⇒  永远感觉做不完
```

### 根因六 历史现场不回收，账本与磁盘脱节

```text
初次快照：已释放但树仍在 27 条
本轮实测：worktree 只剩主干 · 工作树根为空 ⇒ 那批已清零
```

⇒ 本条**本轮收窄**：现场不回收已缓解；
但「账本状态与磁盘现场需交叉核对才能确信」这个**机制性成本仍在**
（本轮就是靠 git 实测才发现初次快照已过时）。
