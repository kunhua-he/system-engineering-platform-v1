# 易语言命名规则提炼与重建

## 发现的问题

**当前状态**：命名库有 7208 个名，大量是一次性自创名。

**核心问题**：
- "判据结果"、"判据记录"、"判据项" → 都在说判据，没有复用统一模式
- "文件项"、"明细项"、"条目项"、"台账项" → 都是"某某项"，应该有统一规则
- 没有形成统一的命名字典，随意发明名字

## 易语言命名规则提炼

### 一、从编译器支持库观察到的规律

**能力名称（7个）**：
- 词法分析、语法分析、语义分析
- 编译、诊断
- 反解容器、生成容器

**参数名称（8个，高频复用）**：
- 程序文本（出现5次）
- 命令表、常量表、类型表（各出现2次）
- 能力码字节、接口说明段、容器结构、容器字节

**模块命名**：
- 语言面、语法、词法、容器、记录流、诊断、语义
- 能力包件、编号与码面、边界编码、声明数据
- 执行函数面、命令声明面、静态声明、顺序读器

### 二、提炼出的核心规律

#### 规律1：动作+对象 / 对象+说明

```
动作+对象：
- 词法分析（动作：分析，对象：词法）
- 语法分析（动作：分析，对象：语法）
- 反解容器（动作：反解，对象：容器）
- 生成容器（动作：生成，对象：容器）

对象+说明：
- 程序文本（对象：程序，说明：文本）
- 能力码字节（对象：能力码，说明：字节）
- 接口说明段（对象：接口说明，说明：段）
- 容器结构（对象：容器，说明：结构）
```

#### 规律2：高频名大量复用

```
程序文本 → 5次
命令表、常量表、类型表 → 各2次

不是：
程序文本1、程序文本2、程序文本3...
而是：
同一个概念就用同一个名字，在不同能力里反复出现
```

#### 规律3：同类事物用统一模式

```
三个表：
- 命令表（不是：命令列表、命令集合、命令数据）
- 常量表（不是：常量清单、常量集、常量数据）
- 类型表（不是：类型列表、类型集合、类型数据）

统一用"XXX表"这个模式
```

#### 规律4：名字语义自足

```
✅ 词法分析 → 不看上下文也知道是"对词法进行分析"
✅ 程序文本 → 不看上下文也知道是"程序的文本形式"
✅ 能力码字节 → 不看上下文也知道是"能力码的字节表示"

❌ 结果 → 什么的结果？
❌ 项 → 什么的项？
❌ 表 → 什么的表？
```

### 三、新的命名体系设计（极简版）

#### 3.1 核心原则（只有2条）

**原则1：一词一义，全局复用**
- 同一个概念全局只有一个名字
- 不同模块说同一个事情，用同一个名字
- 例：程序文本出现5次，但只有1个定义

**原则2：语义自足，完整短语**
- 名字必须是完整的"动作+对象"或"对象+说明"
- 不能出现裸的"结果"、"项"、"表"
- 例：词法分析、能力码字节、命令表项

#### 3.2 命名模式（只有2类，不叫"族"）

**模式A：动作+对象**
```
实例：词法分析、语法分析、反解容器、生成容器
规则：动作（动词）+ 对象（名词）
```

**模式B：对象+说明**
```
实例：程序文本、能力码字节、命令表项、接口说明段
规则：对象（名词）+ 说明（名词/形容词）
```

就这两类，没有更多了。

#### 3.3 核心字典（只有15个，强制复用）

**易语言实际只用了8个参数名**，我们学习这个精神：

**第一组：程序相关（3个）**
- 程序文本
- 命令表
- 常量表
- 类型表

**第二组：边界编码（3个）**
- 字节集
- 容器字节
- 容器结构

**第三组：分析相关（3个）**
- 词法分析
- 语法分析
- 语义分析

**第四组：错误相关（3个）**
- 错误码
- 错误码表
- 错误信息

**第五组：其他（3个）**
- 编号
- 名称
- 说明

**就这15个，不再扩充。**

新增名字时：
1. 先看这15个能不能组合出来（如：错误码 + 表 = 错误码表）
2. 组合不出来，才新增
3. 新增必须符合"动作+对象"或"对象+说明"

#### 3.2 命名族定义（核心8族）

**族1：动作类（动作+对象）**
```
模式：<动作>+<对象>
实例：
- 词法分析、语法分析、语义分析
- 反解容器、生成容器
- 载入声明、验证契约

规则：
- 动作必须是动词：分析、反解、生成、载入、验证
- 对象必须是名词：词法、容器、声明、契约
```

**族2：表类（对象+表）**
```
模式：<对象>表
实例：
- 命令表、常量表、类型表
- 错误码表、通知号表
- 参数表、能力表

规则：
- 表示"XXX的集合"
- 不许变体：列表、清单、集合、数据、集
```

**族3：结果类（对象+结果）**
```
模式：<对象>结果
实例：
- 判据结果、验证结果、编译结果
- 解析结果、匹配结果

规则：
- 表示"XXX动作的结果"
- 不许裸"结果"
```

**族4：项类（对象+项）**
```
模式：<对象>项
实例：
- 命令表项、错误码表项、参数表项
- 台账项、明细项、条目项

规则：
- 表示"XXX的一个元素"
- 必须明确是哪个表/集合的项
```

**族5：字节类（对象+字节）**
```
模式：<对象>字节
实例：
- 能力码字节、容器字节
- 接口段字节、声明字节

规则：
- 表示"XXX的字节表示"
- 用于边界编码场景
```

**族6：面类（对象+面）**
```
模式：<对象>面
实例：
- 语言面、命令声明面、执行函数面
- 定义面、形参面、局部面

规则：
- 表示"XXX这个层面"
- 用于分层架构
```

**族7：段类（对象+段）**
```
模式：<对象>段
实例：
- 接口说明段、能力码段、指纹段
- 数据段、代码段

规则：
- 表示"XXX这个段落"
- 用于容器/文件结构
```

**族8：器类（动作+器）**
```
模式：<动作>器
实例：
- 顺序读器、解析器、验证器
- 编译器、分析器

规则：
- 表示"做XXX的工具"
- 不许变体：工具、处理器、handler
```

#### 3.3 高频名字典（强制复用）

**程序相关**：
- 程序文本（不许：代码文本、源码文本、程序源码）

**三张表**：
- 命令表、常量表、类型表
- 错误码表、通知号表

**边界编码**：
- 字节集、容器字节、能力码字节

**结构相关**：
- 容器结构、语法树、记号流

**分析相关**：
- 词法分析、语法分析、语义分析

#### 3.4 禁止模式（只有2条，能机械判定）

**禁止1：裸名**
```
❌ 结果、项、表、数据、信息、内容
✅ 判据结果、命令表项、错误码表
```

**禁止2：同义变体**
```
❌ 命令列表、命令清单、命令集合 → 统一用"命令表"
❌ 判据结果、判据记录、判据数据 → 统一用"判据结果"
```

机械判定规则：
1. 裸名 = 单字或双字，且在禁用词表里（结果/项/表/数据/信息/内容）
2. 同义变体 = 去掉后缀词后，前缀相同（命令表 vs 命令列表 → 前缀都是"命令"）

### 四、重建计划（极简版）

#### 阶段1：建新库（不动旧库）

```sql

  编号 INTEGER PRIMARY KEY,
  名字 TEXT UNIQUE NOT NULL,
  分组 TEXT NOT NULL,  -- 程序相关/边界编码/分析相关/错误相关/其他
  说明 TEXT NOT NULL

-- 新建表：命名登记（所有代码里的名）
```

### 五、维护性分析

#### 优势1：核心稳定（15个不变）

```
✅ 易语言只用8个参数名，我们用15个
✅ 15个能记住，能手工验证
✅ 新增不进核心字典，只用15个组合
```

#### 优势2：规则简单（只有2个模式）

```
✅ 只有2个模式：动作+对象、对象+说明
✅ 不需要判断"这是族3还是族5"
✅ 新来一个名字，按2个模式套就行
```

#### 优势3：验收自动（4条标准能跑）

```
✅ 所有标准都能写成assert
✅ 门禁里能自动判定
✅ 改一个名字，立即知道过不过
```

#### 优势4：扩展简单（15个组合）

```
新增场景：需要"通知号表"
判断：
1. 核心字典有"通知"吗？ 没有
2. 核心字典有"表"吗？ 有（命令表、常量表、类型表）
3. 能组合吗？ 能 → 通知号表（对象+说明）
4. 登记"通知号表"，来源=新定义，模式=对象+说明
5. 核心字典还是15个，不动
```

### 六、预期结果

**从7208个名 → 降到75~120个左右**：
- 15个核心字典
- 60~105个新定义名（都符合2个模式之一）
- 所有名字都能组合、复用

**为什么是75~120个？**
- 易语言编译器支持库（单一领域）：8个参数名，1.875倍复用
- 我们系统工程平台（多领域）：15个核心，5~8倍复用
- 15 × 5 = 75 / 15 × 8 = 120

**不是200个，也不是500个**：
- 易语言的复用率是1.875倍（单一领域）
- 我们5~8倍复用是合理预期（多领域）
- 如果达到200个 = 13.3倍复用，那说明核心字典选得太好了
