# 契约声明 · 数据格式

上级：系统工程平台 V1 ／ 落点：`契约声明/格式说明.md`
相关：`README.md` 第五节（唯一事实源）· `代码形态分工.md`（声明用 JSON）· `内核落点.md`（Rust 常量由它生成）· `验证流程图.md`（验证面读什么）

**唯一事实源**：本目录下的 JSON 是声明的唯一来源。编译进扩展的 Rust 常量是**生成物**，禁手改。

---

## 一 目录布局

```text
契约声明/
├─ 格式说明.md            本文件
├─ 平台声明.json           格式号 · 标识串 · 版本 · 要求宿主/内核版本 · 名称 · 说明 · 号段占用
├─ 类型声明/               一个类型一份 JSON（文件名 = 类型标签，如 0001.json）
├─ 能力声明/               一条能力一份 JSON（文件名 = 能力编号，如 1001.json）
├─ 错误码表/               一个段位一份 JSON（文件名 = 段位，如 2043.json）
├─ 通知号段/               一个号段一份 JSON（文件名 = 段位，如 2000.json）
├─ 作废号表.json           已作废的编号（只增不改；编号永不回收）
└─ 冻结登记.json           冻结项清单 + 旁路登记
```

**一个号一个文件**是刻意的：编号冲突变成文件名冲突，**在文件系统层面就撞车**，不需要等验证面跑。

## 二 平台声明（`平台声明.json`）

```json
{
  "声明格式号": 20000101,
  "标识串": "d09f2340818511d396f6aaf844c7e325",
  "实现版本":  { "主": 0, "次": 1, "修订": 0, "构建": 1 },
  "要求宿主版本": { "主": 0, "次": 1, "修订": 0, "构建": 0 },
  "要求内核版本": { "主": 0, "次": 1, "修订": 0, "构建": 0 },
  "名称": "系统工程平台 V1 底座",
  "说明": "底座自带的内核能力；其余能力由扩展提供，按契约热载入",
  "目标字宽": 64,
  "能力号段占用": [
    { "起": 0,    "止": 999,   "归属": "内核自有（不对外）" },
    { "起": 1000, "止": 6999,  "归属": "支持库（扩展）" },
    { "起": 7000, "止": 7999,  "归属": "模块（扩展）" },
    { "起": 8000, "止": 8999,  "归属": "技能（扩展）" },
    { "起": 9000, "止": 9999,  "归属": "接口面与构建验证（工具类）" }
  ],
  "通知号段占用": [
    { "起": 1,    "止": 999,   "归属": "下行：宿主 → 扩展" },
    { "起": 1000, "止": 1999,  "归属": "上行：扩展 → 宿主取系统值" },
    { "起": 2000, "止": 2999,  "归属": "生命周期：装载 · 卸载 · 退出 · 延迟释放" }
  ]
}
```

**`声明格式号` 是格式的身份证，不是版本号**：格式不变，它永远不变。

**★ 两张号段表必须分开**（`能力号段占用` / `通知号段占用`）：能力编号与通知号是**两个独立命名空间**，各有自己的 0–9999 与 1–2999 区间。合成一张表会把通知号 2000 判成「落在支持库 1000–6999 里」——这个错我自己的预检当场抓到过。

## 三 能力声明（`能力声明/<编号>.json`）

```json
{
  "编号": 1001,
  "名称": "取系统时间",
  "说明": "返回当前系统时间，单位为毫秒",
  "类别": 1,
  "状态位": 0,
  "返回类型": 1,
  "用户级别": 0,
  "参数表": [
    { "名称": "时区偏移分钟", "说明": "0 表示本机时区", "类型标签": 1, "状态位": 0, "默认值": { "类型标签": 1, "值": 0 } }
  ],
  "错误段位": [1001, 1002]
}
```

规则：

| 字段 | 规则 |
|---|---|
| `编号` | 必须与文件名一致；必须在 `号段占用` 里属于自己那一层；**不许出现在 `作废号表.json` 里** |
| `参数表` | **行序即契约**。一旦公布不许重排、不许插入（要加只能新增旁路字段） |
| `参数表[].类型标签` | 必须能在 `类型声明/` 里查到 |
| `返回类型` | 同上；`0` 表示无返回值 |
| `错误段位` | 每一项都必须能在 `错误码表/` 里查到，**未登记的不许声明** |

## 四 类型声明（`类型声明/<标签>.json`）

```json
{
  "类型标签": 1,
  "名称": "整数",
  "说明": "64 位有符号整数",
  "状态位": 0,
  "元素表": [],
  "属性表": [],
  "事件表": [],
  "命令号表": []
}
```

**类型标签是槽内携带的那个数**——它是多语言兼容的锚点，所以标签一旦公布，含义永不改写。

## 五 错误码表（`错误码表/<段位>.json`）

```json
{
  "段位": 2043,
  "名称": "文件不存在",
  "说明": "目标路径不存在或不可访问",
  "归属": 2000,
  "可重试": false,
  "可自愈": false,
  "需人工": true
}
```

四项登记（`归属 · 可重试 · 可自愈 · 需人工`）是「失败可编程处理」的全部依据。**未登记的错误码不许抛出。**

段位编法：`<能力段位 1 位><序 3 位>`，例 `2043` = 文件域第 43 号错误；`0xxx` = 内核错误。

## 六 通知号段（`通知号段/<段位>.json`）

```json
{
  "通知号": 2015,
  "名称": "延迟释放应答",
  "说明": "扩展返回它表示自己需要被延迟释放",
  "方向": "上行",
  "参数": ["无", "无"]
}
```

方向取 `下行`（1–999）· `上行`（1000–1999）· `生命周期`（2000–2999）。

## 八 生成关系（JSON → Rust 常量）

```text
契约声明/*.json  ──生成器（Python，仅标准库）──→  运行内核/装载入口/src/生成声明.rs
                                                      ↑ 生成物，禁手改
```

生成器落点：`开发工具/声明生成/`。产物头必须标 `// 生成物 · 由 契约声明/*.json 生成 · 禁手改`。

**判据**：任何一处出现手写的 `static 平台信息`，即为违规——声明只有 JSON 一个来源。

## 九 验证面查什么（闸 2 的声明侧）

| # | 检查 | 依据 |
|---|---|---|
| 1 | 编号与文件名一致 | 文件名即编号 |
| 2 | 编号不重复 | 文件名天然唯一，另查 JSON 内字段与文件名一致 |
| 3 | 编号不在作废号表里 | `作废号表.json` |
| 4 | 编号落在自己那一层号段内 | `平台声明.json` 的 `号段占用` |
| 5 | 参数类型都在类型表里 | `类型声明/` |
| 6 | 返回类型在类型表里（或为 0） | 同上 |
| 7 | 错误段位都已在错误码表登记，且四项齐全 | `错误码表/` |
| 8 | 通知号落在对应方向的号段内 | `通知号段/` |
| 9 | 冻结项未被改动（对照 `冻结登记.json`） | 冻结登记 |
| 10 | 生成物与 JSON 一致（指纹比对） | 生成关系 |

这十项全部是**纯数据比对**，不编译、不启动、不跑用例——所以秒级。

## 十 待裁

1. **编号分配方式**：面上自动分配还是手工填。倾向**自动**（手填必然撞号；而"一个号一个文件"已经把撞号变成文件名冲突，自动分配可再省一步）。
2. **`能力声明` 里要不要写"实现落点"字段**：写了便于验证面扫实现，不写则实现侧自报。倾向写（声明是唯一事实源，落点也属声明）。
3. **类型标签的起始值与分配**：内核自有类型用 `1–99`，扩展类型从 `100` 起？未裁。
