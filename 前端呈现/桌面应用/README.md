# 桌面应用（薄壳）

上级：系统工程平台 V1 ／ 落点：`前端呈现/桌面应用/`

## 这是什么

**同一个网页应用 + 一个壳**。这里一行 UI 都没有：`壳.swift` 只做「开一个窗口，把同一个网址
装进系统 WebView（macOS 的 WKWebView）」。UI 仍然只有一份，在 `前端呈现/网页应用/`。

判据：`项目文档/设计文档/代码形态分工.md` 第 7 节 ——「**同一个网页应用 + 一个壳（不重写 UI）**；
两套 UI 就是两条腿」。所以这里**不许**出现 HTML / CSS / 任何界面代码。

## 它在主线上的位置

`README.md` 第五节原先把 `前端呈现/` 写成「人工界面 —— 可整体替换；人类用的概率不大，**非主线**」，
**那句话作废**：网页应用就是**网页版编译器（IDE）**那个位置，桌面壳就是「换个窗口装同一个 IDE」。
裁定见 `项目文档/决策记录/2026-09-26_前端是网页版编译器.md` §一。
所以这里仍然是**形状 + 一份能跑的最小壳 + 说明**，不重活；但它是**主线的一件**，不是可随手替换的旁枝。

**引的是哪一份**：壳载入的是**接口面根地址**（`http://127.0.0.1:<接口端口>/`），
由同源托管把 `前端呈现/网页应用/index.html` 挂到那个根上 —— 所以**入口文件名没变**，
2026-09-26 那次改版（六个部分 + IDE 布局）之后，壳照旧引得到。

## 怎么起

```sh
sh 前端呈现/桌面应用/启动.sh                # 按契约端口拼 http://127.0.0.1:<接口端口>/
sh 前端呈现/桌面应用/启动.sh http://主机:端口/   # 直接给 URL
```

`启动.sh` 从 `契约声明/常量表.json` 的「接口端口」现读端口 —— **不在壳里再写一份**
（`接口面形状.md` §一：端口只有一个来源）。`壳.swift` 用 `swift 壳.swift <URL>` 解释执行：
**没有构建产物、没有包管理、没有第三方依赖**，所以它不破坏「本仓只有两个环境」。

## 前置条件（现在还不满足，如实登记）

网页应用必须**由接口面同源托管**（`接口面形状.md` §五：「静态文件由接口面进程托管，同源，
所以不需要 CORS、不需要第二个端口」）。**但现在的 `对外接口面/调用接口面/` 只实现了四个
端点，不托管静态文件** —— 拿 `/` 去请求它会得到 `404`。所以：

- 现在起壳，窗口会开、页面**加载不到**（或加载到 404），六个部分里凡要调接口的都调不通；
  编辑器与「载入示例」不受影响（它们读的是静态件），页头「连接状态」会照实写「网关连不上」；
- 要真跑，二选一：
  1. 接口面加静态文件托管（同源，推荐，正是设计里写的形态）；
  2. 临时用同源反代把 `/接口` 转给接口面、其余走静态文件（验证用，不进仓）。

缺口记在 `契约声明/冻结登记.json` 的「待办旁路」里了吗？**没有** —— 那一条是
「前端呈现恒为未判（空目录）」，前端落地后它自动转绿。而「接口面托管静态文件」这一条
**目前没有落点**，是本次实测新撞到的缺口，见 `前端呈现/说明.md` 末节。

## 怎么改

- **改界面**：改 `前端呈现/网页应用/`，**不要**碰这里。这里改了就等于开了第二条 UI 腿。
- **换 WebView 载体**（Windows / Linux）：`壳.swift` 是 macOS 那一份的最小形态。换平台时
  **换壳、不换 UI**，并且同样守住「不写端口」：URL 一律由 `启动.sh` 从契约端口拼出来。
