## 一 定位（这一节纠正过，别按旧口径改）

## 二 六个部分各自接什么（这是本页的正文）

| 部分 | 接什么 | 传参 | 现在真实回什么 |
|---|---|---|---|
| ① **编辑器** | 无端点。纯文本区 + 从语料只读载入 | 无 | 载入 `弱-lib_e2ee-7277815.txt` 得 107 字符（进编辑区 97 字符，见 §五 第 3 条） |
| ② **编译** | 逐级 `POST /接口/调用` | 编号 `1101` → `1102` → `1103` → `1106`；每个都传 `值: [{"类型标签":4,"值":"<程序文本>"}]` | 四步**全失败**：`码 1 提供者未载入`（保留项） |
| ③ **运行/结果** | **不接** | 无按钮 | 照实写「编译还没实现，所以运行也没有」，**没有假按钮** |
| ④ **案例库** | **没有端点可接** | 无 | 如实显示缺口（见 §四 第 1 条）+ 一个通用只读口 |
| ⑤ **支持库/能力** | `GET /接口` · `GET /接口/能力/<编号>` | 编号走输入框 | `200`；能力清单 1201 条；契约带参数表行序 · 类型标签 · 可抛错误码（每项三项业务判定） |
| ⑥ **调试** | `POST /接口/调用` · `POST /接口/声明` | 体由输入框原样拼出 | 调用 `200`；声明 `200` + `成功:false` + `校验[…]`（面自己说未落盘） |

**②为什么逐级不一步到底**：一步到底就看不见死在哪一层。四步都吃同一份 `程序文本`（契约里四者的参数表都是它），
所以**不提前中断**：哪一步失败就在那一步标红，其余照跑照摆 —— 现在四步都红，一眼看见「语言还没实现」。
`1107` 诊断单独一块，摆它的结果与结构化错误码。

## 三 怎么起

### 网页应用

**形态一：由接口面同源托管（设计里的形态）**

`接口面形状.md` §五：「静态文件（前端构建产物）由接口面进程托管，**同源**，所以不需要 CORS、不需要第二个端口」。
**实测还没实现**：`对外接口面/调用接口面/` 只实现四个端点，请求 `/` 回 `404`（今天复测仍是 404）。
把 `前端呈现/网页应用/` 的静态件挂在接口面进程的根上即可。

**形态二：起一个静态服务（只验页面本身）**

```sh
cd 前端呈现/网页应用 && python3 -m http.server 8080 --bind 127.0.0.1
# 浏览器开 http://127.0.0.1:8080/
```

这样页面能加载、控制台无错，但 `fetch("/接口")` 会打到静态服务上、被当成文件找、回 404
（POST 会被回 501）。页面把这段原文原样摆出来并说明原因，页头「连接状态」写「网关连不上（HTTP 404）」
—— **不是崩，是如实报**。这就是「同源托管没接上」的可见形态。

**形态三：仓外同源反代（本次取证用的，不进仓）**

在 `/tmp` 起一个 20 行的 Python 反代：路径以 `/接口` 开头就转给真网关 `127.0.0.1:43110`，
其余从仓根做静态托管。这样一个源上既有页面又有接口，也顺带让仓内语料可读。

### 桌面应用

```sh
sh 前端呈现/桌面应用/启动.sh                # 按契约端口拼 http://127.0.0.1:<接口端口>/
sh 前端呈现/桌面应用/启动.sh http://主机:端口/   # 直接给 URL
```

`启动.sh` 从 `契约声明/常量表.json` 的「接口端口」现读端口，`壳.swift` 用 `swift 壳.swift <URL>` 解释执行
—— **没有构建产物、没有包管理、没有第三方依赖**，所以它不引入第三个环境（`代码形态分工.md` 第四节）。
它引的是 `网页应用/index.html` 那份，本次改版**路径没变**，壳照旧能引到。

## 四 三条硬约束（违反了就是返工）

### 1 零业务逻辑 —— 前端不许解析契约、不许生成代码、不许做校验

`接口面形状.md` §五 第 1 条：「**前端不许有解析/生成/校验逻辑，前端是纯 UI。任何判断都在后端。**」

本实现落成四条做法：

1. **不看键名**：`呈现.js` 只按值的类型摆（空/布尔/数/文/表/对象）。后端加字段，本页不改一行。
2. **成功/失败也按值的类型扫**：顶层出现 `false` 就是失败、只出现 `true` 就是成功 —— 源码里没有一处写着
   「某个字段叫这个名字所以它表示那个意思」。
3. **判定在后端**：`调试.js` 里没有一条分支在问「这个值对不对」。敲了不合法的东西，体就带着不合法原文发出去，
   由后端回 400，页面把 400 摆出来。
4. **唯一的「编码」是 `JSON.stringify`**：程序文本要作为 JSON 字符串送，所以要把引号/换行按 JSON 规则转义。
   它只把文本编码成 JSON 字面量，**不改文本一个字节、不看文本内容、不认任何关键字** —— 不是「处理程序」。

**自检**：`sh 前端呈现/网页应用/自检.sh`。**这份脚本上一版留下的，本次一字未改**，
读数全绿（见 §五）。它按 `判据的可信性.md` 第五节成对做：违规词命中必须为 0，
另做**反向样本**（注入带违规词的文件必须报红，证明判据不空转）与**正向样本**（干净输入必须通过，证明不误报）。

> **一个必须知道的副作用**：这份脚本的违规词里有 `验证` 两个字。所以本目录的源码里**不许出现
> `测试验证`**，因此**案例区的仓内相对路径不写在前端源码里**，只写在本文档与报告里（见 §六 第 2 条）。

### 2 同源相对路径 —— 端口不许写死

四个端点的路径逐字照 `接口面形状.md` §二，**只写路径、不写主机与端口**。浏览器会把非 ASCII 路径
按 URL 规范编码成 `/%E6%8E%A5%E5%8F%A3`，接口面已做百分号解码（`对外接口面/调用接口面/src/路由.rs`）。
前端不用管这件事、也不许因为「看起来不对」改成写死端口。自检第五节数这件事（读数 0）。

**实测撞到的一个真问题（值得记住）**：模块文件名**不许**与端点前缀同前缀。最初这个 fetch 封装叫 `接口.js`，
浏览器请求的是 `/接口.js` —— 与冻结的端点前缀 `/接口` 同前缀。接口面自己的路由是按**整段路径相等**判的，
不受影响；但**按前缀分流的同源反代**会把 `/接口.js` 当成接口请求转给接口面、回 404，页面模块全挂。
已把文件名改成 `取接口.js`（不以「接口」开头）。

### 3 无构建步骤 + 视觉落在 CSS 上

`<script type="module">` 直接引 `.js`。**不许** `package.json`、不许 `node_modules`、不许 CDN 外链（离线要能跑）。
每个源文件 ≤ 400 行（读数见 §五）。**不许引 UI 组件库 / 框架**（Element Plus · Ant Design · Bootstrap 的 JS 等），
**不许用 JS 生成整套 DOM 骨架来堆视觉**。

视觉走**手写 CSS**（`样式.css`，368 行，进仓、字节可指纹），**没有进 classless CSS**：
判据是「视觉质量由 CSS 决定，不由用不用框架决定」，而自写那份已经够用，多引一份文件就多一份要同步的字节。
布局按 IDE 分：页头（现状说明）· 工具条 · 主区（编辑器 + 侧栏）· 坞（诊断 | 运行结果）· 调试 · 页脚。
深浅色随系统（`prefers-color-scheme`），不做手写切换器。

## 六 缺口与定不下来的（如实登记，不假装覆盖了）

1. **接口面不托管静态文件** —— 设计里写「静态文件由接口面进程托管，同源」，实测请求 `/` 回 `404`（今天复测仍 404）。
   于是网页应用**没有同源的家**：要么接口面加静态托管（推荐），要么临时用同源反代（取证就是这样做的，反代住 `/tmp`）。
   这一条在 `契约声明/冻结登记.json` 的「待办旁路」里没有落点。**补法在 `对外接口面/调用接口面/`，不在前端。**

2. **案例库面板接不上（这是实测缺口，不是没做）** —— 冻结的端点只有四个，**没有读案例目录的路、也没有写回执的路**；
   同源静态托管那一侧现在只托管前端自己的件。所以本面板**不列案例、不跑案例，也不造第五个端点**（造了就是第二个对外门）。
   缺什么：一个读案例的端点 + 一个写回执的端点，且两者的形状要先冻结。
   能给的是一个**通用同源只读口**：把仓内相对路径敲进来就取回原文。实测把
   `测试验证/案例/运行回执.jsonl` 敲进去 → `HTTP 200`、首行是绑了提交哈希 `819d50a3…` 的回执行。
   **这个路径不写在前端源码里**（原因见 §四 第 1 条那个副作用），只写在本文档与报告里。

3. **`<textarea>` 会把 CRLF 归一成 LF** —— 实测：语料文件 107 字符，进编辑区后 97 字符（差 10，正好是 10 个 CRLF）。
   这是浏览器的行为，不是本页写的代码。与 `程序文本格式.md`「写出恒 `\n`（LF）；读入同时认 CRLF 与 LF」
   **方向一致**，所以不算缺陷；但要知道：**编辑器不保证逐字节搬运 CRLF**。真要逐字节搬运，得走文件而非文本区。

4. **案例库正在被另一条腿写（取证期间在动）** —— 同一份 `运行回执.jsonl` 在几次取证之间从
   6066 字节（3347 字符）长到 6323 字节，再长到 3968 字符，中途还短暂 `404` 过一次（重写窗口）。
   所以案例库面板的读数是**那一刻的**，不是稳定读数。（字节数按 `ls`、字符数按 `件.文.length`，
   两者不等是正常的：一份回执里全是中文。）

5. **`GET /接口` 的「端口来源」指向一个不存在的位置** —— 那句话写「`契约声明/平台声明.json` 的 接口端口」，
   实测 `平台声明.json` **没有**该字段，端口唯一来源是 `契约声明/常量表.json`。接口面逐字照抄了那句话（冻结件不许改字面），
   所以页面摆出来的 `端口来源` 指向一个不存在的位置。**这与既有件矛盾，原样报出**。

6. **`1105` 用文本槽调用回了个非零槽标志** —— 体 `{"编号":1105,"值":[{"类型标签":4,"值":…}]}` 得
   `成功:true` + `值:[{类型标签:4294967295,值:1135}]`。`4294967295` 是 `u32` 全 1，看着像某个「空槽/错误」标志，
   而 `成功` 却是 `true`。**这是调用侧与实现侧的槽语义对不上的疑点**，不在前端能判的范围（前端只摆读数），
   **登记待裁**：`1105` 的入参契约说「字节集（类型标签 5）」，送文本槽时到底该回什么。

7. **`GET /接口` 的能力清单里有重号** —— 1201 条里 `编号 0` 出现两次（底座 `取平台信息` 与扩展的 `保留位`），
   `1100` / `1108` 等也都在表里以 `保留位` 出现。根因是「编号 = 命令表下标（0 起）」这个冻结约定，
   使扩展的占位项落在 `0xxx` 段。**前端只摆不判**，登记待裁（扩展侧已知，见其 `lib.rs` 文件头）。

8. **前端形态只此一份，尚未接进 `构建装配/一键验证/`** —— 前端没有构建步骤，所以不需要生成物；
   但「前端 0 处解析/生成/校验」这条判据目前只在 `自检.sh` 里跑，还没进 `一键验证` 的判据集。
   缺什么：把这条判据并进 `构建装配/一键验证/`（它的扫描面要覆盖 `前端呈现/网页应用/`）。

9. **「载入示例」的清单是本页写死的** —— 语料有 53 份，而浏览器没法列目录（列目录要么靠端点、
   要么靠读服务端目录页，两条都不在冻结的四个端点里）。所以下拉里只列了 6 份有代表性的 + 1 份内置模板。
   缺什么：一个「列语料」的端点；在那之前，清单改了要记得同步 `编辑器.js` 里那张表。

10. **「载入示例」在设计里的部署形态下取不到语料** —— 设计里接口面托管的是**前端自己的静态件**
    （`/` → `index.html`），**不含仓根**；而语料住在仓内 `扩展根目录/原子支持库/编译器支持库/语料/真文本/`。
    实测：把静态根指到 `前端呈现/网页应用/`（也就是设计里那种「应用挂在根上」的形态）时，
    点「载入到编辑器」得 `取不到（HTTP 404）：同源静态托管没把仓内路径交出来`，**控制台仍 0 条**。
    **这不是本页能补的**：要么托管侧把仓根也挂上（那等于把整个仓暴露给浏览器，得先裁），
    要么给一个「取语料」的端点（新增端点属 `冻结登记.json` 的旁路登记范围）。
    取证时用的是「静态根 = 仓根」的同源反代，所以语料读得到。
