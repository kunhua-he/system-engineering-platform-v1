# JSON数据支持库

## 职责和引擎

JSON文本规范化、RFC6901指针取值、取文本与固定字段摘要；输入65536字节、深度64、指针4096字节。

独立扩展，锁文件钉住第三方引擎，不给底座增加第三方依赖；部署运行只装载正式制品，不依赖老项目源码。

## 调用

- 5201 `规范化JSON`：参数按顺序为JSON文本（均为文本标签4），返回标签4。
- 5202 `按指针取值`：参数按顺序为JSON文本、选择指针（均为文本标签4），返回标签4。
- 5203 `按指针取文本`：参数按顺序为JSON文本、选择指针（均为文本标签4），返回标签4。
- 5204 `提取摘要`：参数按顺序为JSON文本（均为文本标签4），返回标签103。

## 响应塑形三条

三条能力都只做纯内存的 JSON 文本变换，不访问外部系统；输入上界按能力分派——5218/5219/5220 为 4194304 字节，本库其余能力仍为 65536 字节。

### 5218 `裁剪响应`

参数按顺序：载荷JSON、选择路径、最大条目数、最大字节数、信封键JSON、元数据键、数据键（均为文本标签4），返回标签4。

- `选择路径` 用点分路径（如 `data.items`），空文本表示不选中；命中后按 `数据键` 重建载荷，并把 `信封键JSON` 里列出的顶层键原样复制过去；信封内若有 `success`/`错误`，另给出 `upstream_success`/`upstream_error`。
- 路径未命中不报错：在元数据 `warnings` 里给一条中文说明，其余照常塑形。
- `最大条目数` 对每层列表生效，省略条数写进 `omitted_counts`（键为点分路径，根层为 `$`）。
- `最大字节数` 按两空格缩进序列化后的字节数判断；超限时先把 `数据键` 换成摘要，仍超限再换成 `{_truncated,类型,bytes_before}` 兜底，还超限则在 `warnings` 追加一条。
- `元数据键` 给空文本表示不写元数据；载荷本身不是对象时跳过元数据与字节裁剪。

### 5219 `压缩描述字段`

参数按顺序：数据JSON、字段名（均为文本标签4），返回标签4。递归遍历对象与列表，只把命中字段的字符串值折叠为单空格（`\s+` 归一），其余字段与结构原样。

### 5220 `提取带前缀JSON`

参数按顺序：文本、前缀（均为文本标签4），返回标签4，内容是 `{"找到":逻辑,"数据":对象}`。

- 从文本末尾往前逐行查找，行与前缀两侧空白先去掉；取前缀之后的 JSON。
- 解析失败或结果不是对象 ⇒ 立即返回 `找到=假`，不再继续往前找（与历史行为一致）。
- 前缀给空文本时匹配最后一行。

错误条件与编号以本包能力声明、错误码表为准。缺参、错型、负上限不得忽略（回 5201）；载荷不是 JSON 回 5201；信封键不是字符串数组回 5203。

错误条件与编号以本包能力声明、错误码表为准。缺参、错型不得忽略。

通过引擎RawValue逐层装配对象与列表，保留与引擎私有数字标记同名的普通对象键，不允许对象被静默转成数字。

JSON Pointer按RFC6901处理，空指针取根，~0为~、~1为/；路径不存在与值为null区分。取值返回JSON文本，取文本只接受原值为字符串；大整数保留数字文本。重复键按引擎取最后值，不保证保留原空白或对象键序；输入限65536字节、深度64、指针4096字节。
