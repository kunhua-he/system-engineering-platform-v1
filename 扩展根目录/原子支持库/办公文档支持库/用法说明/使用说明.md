# 办公文档支持库

6110/6111为纯计算；DOCX与XLSX能力读写明确传入的本机绝对路径。DOCX使用quick-xml，XLSX使用锁定的calamine与rust_xlsxwriter，不联网、不计算工作簿公式。

## 6110 求值公式

- 参数：`公式文本`（四则运算 `+ - * /`、括号、数字、变量名）、`变量文本`（JSON 对象，值只接受数值）。
- 返回：数值文本；整数不带小数点（`47`），小数按最短表示（`47.5`）。
- 失败：`6101 参数不合法`（参数个数/JSON 结构不对）、`6102 计算失败`（公式非法、变量缺失、除零）、`6103 内容不合法`（公式超 4096 字元、变量超 256 个）。
- 不做单元格引用、不做函数调用；需要引用请调用方先把单元格取值放进变量表。

示例：`公式文本 = "(单价*数量)-折扣"`，`变量文本 = {"单价":12.5,"数量":4,"折扣":3}` → `47`。

## 6111 解析标记块

- 参数：`Markdown源文本`（上限 256 KiB）。
- 返回：JSON 文本 `{"块":[{"类型":...,"层级":...,"文本":...,"语言":...}]}`。
- 类型集合：`标题`（带 `层级` 1–6）、`段落`、`列表项`、`代码块`（带 `语言`，围栏未闭合时按到末尾收口）、`引用`、`分隔线`。
- 空行忽略；缩进不保留；不认识的行归 `段落`。

示例输入：

```text
## 标题
- 第一条
```

输出：

```json
{"块":[{"类型":"标题","层级":2,"文本":"标题"},{"类型":"列表项","文本":"第一条"}]}
```

## 6112 解析DOCX

- 参数：`DOCX文件路径`，本机可读的DOCX绝对路径。
- 返回文本只有一套正文：`{"块列表":[...],"资源列表":[],"段数":N,"表数":M}`，块按正文顺序排列，标题/段落带文本，表格带二维字符串`表格数据`。
- 标题`来源位置.附加.level`取Heading1至Heading9样式；段落保留空文本，表格单元格内的多段以换行连接。图片资源尚未实现，空资源列表不表示提取过图片。
- 由quick-xml按WordprocessingML命名空间解析，支持前缀改名、转义实体与数值实体、制表与换行；不靠字符串前缀切XML。
- 文件与解压正文各限32MiB；坏包、缺正文、坏XML、错误命名空间、DTD、嵌套表格明确回6103。合并格/图片/页眉页脚等富文档能力未完整实现，不宣称版式保真。

## 6113 生成DOCX

- 参数：`内容文本`为JSON `{"块列表":[{"类型":"段落","文本":"正文"},{"类型":"表格","表格数据":[["单元格"]]},{"类型":"标题","文本":"标题","层级":2}]}`，以及DOCX绝对`输出路径`。
- 返回JSON文本`{"输出路径":"...","字节数":N}`；按列表顺序生成，标题层级只接受1至6，省略为1；文本做XML转义，空段保留，表格只接受非空行及字符串单元格。
- 产出类型、包关系、文档、样式关系及样式五件；Normal与Heading1至Heading6均有真实样式定义。表格带网格，独立Word引擎可读取单元格。
- 旧`段落/表格`分组JSON已移除，不回退或默默生成空文档；未知块、错误类型与非法层级回6101，写盘失败回6104。所有输入在打开输出文件之前校验；尚未实现写出失败时的原子替换。
- 所有文本槽统一上限262144字节；这不是4MiB接口。生成内容超过此上限由执行边界拒绝。

本次有序JSON正文属于实现版本0.2.0；6112/6113编号、参数顺序与外层返回文本槽不变。调用方须与同批消费者同步切换，不提供双协议运行。


## 6114 解析XLSX

- 参数：`XLSX文件路径`，可读XLSX绝对路径；返回JSON文本`{块列表,资源列表:[],工作表数}`，工作表按源顺序。
- 工作表块为`{类型:"工作表",文本:"",表格数据:[[...]],来源位置:{工作表:"表名"}}`。自A1补空到实际末格，空格为null，空工作表为[]。
- 保留文本、有限数值与逻辑；公式优先返回以等号开头的文本，日期转时间文本，错误格返回错误文字。不宣称图片、样式、宏与合并单元格保真。
- 文件32MiB；ZIP至512成员、单成员32MiB、总解压64MiB；工作表至32，每表10000行/256列，累计矩形格至200000；JSON返回至262144字节。资源坐标先预检，超限明确失败、不截断。
- 相对路径回6101；坏包、缺件、损坏、不可读或内容/容量超限回6103。

## 6115 生成XLSX

- 参数顺序：`内容文本`、绝对`输出路径`。内容为JSON`{工作表列表:[{表名:"明细数据",列:["文本","数值"],行:[["中文",3.5]]}]}`；列为可选表头，行必须为二维数组，工作表列表不能为空。
- 单元格接受文本、有限数值、逻辑、null；普通字符串`=1+1`仍为文本，公式必须显式对象`{公式:"=B2*2"}`。不计算公式；超过15位整数明确拒写，避免静默损失精度。
- 返回JSON文本`{输出路径,字节数}`。非法输入在写盘前拒绝，保留已有输出；成熟引擎先生成内存字节再写盘，不宣称崩溃原子替换。
- 非法表名/重复表名/类型/公式/容量回6101，生成字节超文件上限回6103，无法写出回6104。统一文本槽至262144字节，矩形及工作表预算同6114。
- 本轮仅追加6116至6118，不改变6110至6115外层参数和返回类型；实现版本沿用0.3.0，不因追加能力升号。

## 外部格式转换（6116-6118）

- 6116 检查转换提供者：提供者名 `textutil` / `libreoffice` / 空（全部）→ JSON 文本，如 `{"textutil":"可用","libreoffice":"LibreOffice 25.8…"}`；未找到记「不可用」。只探测，不安装。
- 6117 转换办公文件：LibreOffice 无头模式。输入路径与输出目录须绝对路径（输出目录不存在会创建），目标格式不带点，超时秒 5-600（空取 180）。
  - 同一时刻只允许一个 LibreOffice 转换，其余排队；每个任务用独立的 `-env:UserInstallation` 临时配置目录，互不污染。
  - 到点直接杀进程并等回收，回 6105；产物按 `输出主名.目标格式` 落盘，空文件或超 64MiB 分别回 6105 / 6103。
  - 返回 `{"输出路径":"…","字节数":123,"格式":"pdf"}`。
- 6118 转换文本文件：系统 textutil，参数与返回同 6117，目标格式取 textutil 认的写法（txt / html / rtf / docx 等）。
- 找不到转换器回 6106 —— 先调 6116 看状态；`LIBREOFFICE_BIN` 可指定 soffice 路径。

## 6119 检查页面结构

**做什么**：只读地读一个 pptx 的页清单（`ppt/presentation.xml` 的 `sldIdLst`）与关系文件
（`ppt/_rels/presentation.xml.rels`），回报页数、页序、缺关系、重号与孤儿页。

**参数**：`PPTX文件路径`（必填，绝对路径）。

**返回**（JSON 文本）：

```
{"页数":3,"部件数":3,
 "页序":[{"页序号":1,"关系标识":"rId2","关系文件":"ppt/slides/slide1.xml","标题":"开场","缺文件":false}],
 "缺关系":[],"重号":[],"孤儿页":[]}
```

- `缺关系`：页清单引用了某个关系标识，但关系文件里查不到它 ⇒ 该页不进 `页序`。
- `重号`：多个关系标识指向同一个页面部件。
- `孤儿页`：`ppt/slides/slideN.xml` 存在却没被页清单引用。
- `标题` / `标题来源`：先取该页标题占位符（`ph type=title` / `ctrTitle`）的文字，来源记 `标题占位符`；
  页里根本没有占位符时，退化成**该页第一个非空形状文字的首行**，来源记 `首段文字`；都没有就给空串。
  （实测：商业 PPT 大量用自由文本框，页里 `ph` 一个都没有，只认占位符等于恒返回空标题。）

**边界**：坏 zip、坏 XML、DTD、没有页清单、单个 XML 条目 > 32 MiB ⇒ `6103 内容不合法`；**整包大小不限**（zip 按名读条目，125 MiB 的真实 PPT 也照跑）；
路径不存在或不是文件 ⇒ `6101 参数不合法`。**不打开 Office、不修改文件、不写盘。**

## 图片提取、合并格与样式（0.4.0 增补）

- **6112 解析DOCX**：`资源列表` 内嵌 `word/media/` 图片（`名称`/`条目路径`/`媒体类型`/`字节数`/`内容BASE64`），单图 ≤256KiB、总量 ≤1MiB，超出进 `未内嵌` 并写原因，不静默截断；表格块新增 `合并列表`（`起始行`/`起始列`/`行跨度`/`列跨度`，行列 0 起），段落块新增 `段落样式`（`加粗`/`字号`/`颜色`/`字体`/`对齐`）。旧字段 `块列表`/`表格数据`/`段数`/`表数` 原样保留，被合并覆盖的格给空串。
- **6113 生成DOCX**：`表格数据` 的格可写对象 `{"文本","横跨","纵跨","加粗","字号","颜色","字体","底色","对齐","垂直对齐"}`，字符串格沿用旧行为；`纵跨` 由随后的行在同列自动补 `vMerge` 延续格；输出先写同目录 `.<名>.<pid>.tmp` 再 rename。
- **6114 解析XLSX**：每表新增 `合并列表`（含 `区域`）与 `样式网格`（只列有可见样式的格），顶层 `资源列表` 内嵌 `xl/media/` 图片；样式只还原字体/加粗/字号/字体色/纯色填充/对齐/换行/数字格式，主题色、渐变、边框不还原。
- **6115 生成XLSX**：单元格可写 `{"值":标量或{"公式"},"样式":{…}}`，表级支持 `合并列表`、`列宽`、`行高`；合并区域以首格值与样式为准，越界/重叠/单格合并回 6101。
