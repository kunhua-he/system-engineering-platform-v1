# 文件支持库 —— 用法说明

文件与目录域的最小原子能力：**给一个绝对路径，拿回三个可被外部工具复算的值**。

## 一行调用

```text
结果 = 取文件摘要("/Users/hekunhua/Documents/交付/报价单.txt")
     → {字节数: 1284, 行数: 37, 摘要文本: "9f86d081884c7d65…"}
```

对应网关调用（现有端点，不是新造协议）：

```text
POST /接口/调用
{"编号": 3101, "值": [{"类型标签": 4, "值": "/Users/hekunhua/Documents/交付/报价单.txt"}]}
```

`/接口/调用` 的每个值都是**带类型标签的定长槽**：裸字符串是 CLI 的输入糖（`命令行界面.py` 替它补 `{类型标签: 4, 值: …}`），curl 直发不经过那层包装，接口面不猜类型 ⇒ 裸值在解析层就 400。

## 三个值怎么用

| 字段 | 类型 | 含义 | 外部复算 |
|---|---|---|---|
| `字节数` | 整数 | 文件的字节数 | `wc -c <路径>` |
| `行数` | 整数 | 按 `\n` 计数，末字节不是 `\n` 且件非空则 +1 | `wc -l <路径>`（末行无换行时 +1） |
| `摘要文本` | 文本 | SHA-256，小写十六进制 64 字 | `shasum -a 256 <路径>` |

**空文件是成功**：`字节数 0` · `行数 0` · `摘要文本 e3b0c442…`（SHA-256 空串）。
`0` 不是失败哨兵 —— 失败一律走错误码。

## 三个失败码怎么处置

| 码 | 名称 | 可重试 | 可自愈 | 需人工 | 处置 |
|---|---|---|---|---|---|
| 3001 | 文件不存在 | 否 | 否 | 否 | 改路径 / 确认件还在 |
| 3002 | 不是普通文件 | 否 | 否 | 否 | 传普通文件的路径（不是目录 / 设备 / 套接字） |
| 3003 | 读取被拒 | 否 | 否 | 是 | 找人给读权限 |
| 3004 | 路径不是绝对路径 | 否 | 否 | 否 | 传绝对路径（相对路径不按服务进程 cwd 解析） |

只收**绝对路径**：相对路径一律 3004，不按服务进程 cwd 解析（cwd 不能成为第二语义源）。

## 不给开关

摘要算法固定 SHA-256、行数口径固定、分块 64 KiB 固定、不跟随符号链接这类选项一律不设 ——
要别的算法是**另一个编号**，不是同一个编号的参数。

## 号段

能力号段 3101–3199（三方封装 · 文件与目录）· 错误码段位 3。

## 有界文件输入输出

有界文件输入输出：绝对路径，文本UTF-8，二进制真实字节集；单文件65536字节，单层目录最多1000项；新建及复制拒覆盖，不递归删除、不删除链接；目录操作不递归，非权限隔离沙盒。
- 3102 读取文本：文件路径 → 类型标签4。
- 3103 读取字节：文件路径 → 类型标签5。
- 3104 新建文本：文件路径、文本内容 → 类型标签4。
- 3105 新建字节：文件路径、字节内容 → 类型标签4。
- 3106 创建目录：目录路径 → 类型标签4。
- 3107 列出目录：目录路径 → 类型标签100。
- 3108 复制文件：文件路径、目标路径 → 类型标签4。
- 3109 删除文件：文件路径 → 类型标签4。
- 3110 删除空目录：目录路径 → 类型标签4。

## 受控头部读取

- 3111：受控根目录（文本）、相对路径（文本）、字节数（整数）→ 原生字节集。
- 字节数允许0至1048576；只读请求的头部，不因完整文件大于64KiB拒绝。空结果成功。既有3102/3103仍保持原上界。
- 根目录必须绝对且本身不能是符号链接；子路径拒绝绝对路径、上跳、任何层文件或目录链接。Unix实现持目录描述符逐层打开，最终描述符必须为普通文件，避免先校验再按路径重开的竞态。当前实证为macOS；其他Unix标志按目标实现，非Unix明确拒绝。
- 受控根是调用方显式授权范围，不替代业务用户、文件归属或共享权限。已打开文件若被其他进程同时改写，不承诺一致性快照。
- 丢件3001、非普通文件3002、拒读或链接3003、非绝对根3004、路径/错参3010、读取数越界3012。
- 真实HTTP定向验收入口：`测试验证/业务接入/HTTP验收.py`，传仓外全新缓存目录。覆盖受控头部、空值、大文件、链接、错型、限流与并发；不等于整站验收。



## 受控整文件读取

- 3112：受控根目录（文本）、相对路径（文本）、最大字节数（整数）→ 原生字节集。
- 最大字节数显式允许0至52428800（50MiB），0只允许空文件，不表示无限。超限3012，不返回截断内容冒充整件成功。
- 与3111复用同一目录描述符打开路径：根绝对、拒子路径上跳/绝对路径/各层链接/非普通文件；先从已打开文件元信息判断大小，再最多读取上限加1字节，避免增长文件突破内存上界。读取并非文件一致性快照，并发写入不保证同一版本。
- 3111仍是至1MiB的头部截取，3102/3103仍是65536字节的既有整读。不同语义不互相扩大、不改变已有参数或返回类型。
- HTTP真实验收包含0、65537、5MiB+1、50MiB整件读回与超限/错型/路径/链接反证；50MiB字节经base64会超过原V3 8MiB响应预算，消费者须明确支持相应有界传输。验收回执仅记类型/编码长度，不保存大字节正文，结束清理独占样本。


## 受控原子文本写入

- 3113：受控根目录/相对路径/文本内容（三项文本）→ 实际写入UTF-8字节数（整数，0为成功写空文件）。上界131072字节，极端JSON转义也在当前1MiB请求体预算内；超限3012，先判再创建目录或暂存件。
- 与读取共用父目录描述符边界：根绝对且本身非链接，子路径只收正常分量，拒绝绝对路径、上跳及目录/目标符号链接。根内缺失的父目录可逐层以私有权限创建；这不是业务用户授权的替代。
- 同一父目录以独占创建方式建立私有暂存件，完整写入、保留已有目标权限、同步文件后renameat原子替换。不存在的目标创建为私有权限。不先删旧件，不截断旧件；普通失败路径回收暂存件，并发读取只见完整旧版或新版。
- 原子可见性不等于跨请求写入幂等、文件版本比较交换或断电事务。此能力未同步父目录，不承诺rename后断电持久性；进程被强杀可能遗留同目录暂存件，该资源治理未完成前不得宣称任意故障都零残留。现有目标权限通过打开的原件取得；并发替换采用最后完成者生效，不提供版本冲突检测。
- HTTP验收覆盖中文新建/覆盖/空文本/含空字符128KiB、权限保留、超限不改原文、错型/上跳/链接、四路32次覆盖与24次读取不见半截；回执只记写入长度，不留正文副本。

## 查找祖先目录

- 3116：起点路径 / 标记名（两段文本）→ 祖先目录绝对路径（文本）。起点须为绝对路径且存在；起点是文件时先取父目录再上溯。
- 每级先看当前目录末段名是否等于标记（是则返回其父），再看当前目录下是否存在同名子目录（是则返回当前目录）；两者都不成立就上移一级，到根仍没有回 3015。
- 只读目录结构，不读文件内容、不判断权限；标记必须是单段名，不含路径分隔符，至 255 字节（否则 3010）。不跟随符号链接做额外解析。
- 起点不存在回 3001，相对路径回 3004。典型用途：从一个模块文件所在目录反查出仓根（该仓根下有同名子目录）。

## 取路径元信息与清理暂存残留

- 3117：路径（绝对）→ 单段 JSON 文本，字段固定 `类型`（文件/目录/符号链接/其他）、`字节数`、`修改时间毫秒`（取不到时 -1）、`权限`（八进制三位）、`是否符号链接`（"真"/"假"）。用符号链接自身属性，不跟随解链；路径不存在回 3001。
- 3118：受控根目录 / 相对目录 / 过期秒数（整数文本，空或 0 取 300，小于 60 回 3010）→ 删除件数（整数）。
  - 只处理名字匹配 `.原子写入-<进程号>-<序号>` 的暂存件，且修改时间早于过期秒数；刚写入的暂存件不会被误删。
  - 相对目录空表示受控根本身；含 `..` 段回 3010。
  - 典型用法：进程被强杀后，下次启动先对写入目录跑一次 3118 回收残留。

## 原子写上界（本次放宽）

- 3113 文本、3115 字节的单件上界由 131072 放宽到 **4194304**（4 MiB）；其余行为不变（同目录暂存、同步后原子替换、保留原权限、失败清理暂存）。

## 扫描类属性

- 3119：目录 / 属性名 / 排除关键字（三段文本）→ JSON 数组文本。递归扫目录内 `.py`，收集「类属性 = 字符串常量」的值，去重并按字典序排序。
- 属性名只允许 ASCII 字母数字下划线（中文名回 3010），且其后必须紧跟空白、冒号或等号 —— `__tablename__片段` 这类近似名不会被误收。
- 支持两种写法：`__tablename__ = "业务表"` 与 `__tablename__: str = '业务表'`；值不是引号常量（如数字、变量）一律跳过。
- 排除关键字逗号分隔，路径含任一关键字即跳过（文件与目录都跳过）。
- 上界：目录深度 8 层、py 文件 2000 件、单件 4MiB；超件数回 3012，超单件大小则跳过该件。
- 只读源码文本做行级匹配，不做语法树解析 —— 结果用于契约编译等「取名字清单」场景，不用于语义分析。


## D4 受控自修复原子（待V3接线）

- **3120 受控工作区**：参数为操作、Git仓库绝对路径、工作区标识、仓外临时根；操作只允许「创建」或「关闭」。创建以 detached HEAD 建立 Git worktree，并落仓库归属标记；关闭校验标记归属与干净状态，调用 `git worktree remove` 后清理状态标记。临时根不得位于仓库内，仓库也不得位于临时根内。
- **3121 唯一文本替换**：工作区、相对路径、旧文本、新文本。只允许根内普通文件，拒绝绝对路径、上跳、目录或目标链接；旧文本必须非空且恰好出现一次。替换先写同目录独占暂存件、同步并原子替换；失败清理暂存件且保留旧文件。
- **3122 受控验证**：工作区、JSON 字符串参数数组、超时毫秒（1–5000）。数组首项是可执行程序，不经 shell 拼接；stdin 关闭，stdout/stderr 与状态回传；非零退出、启动失败或超时为 3018。
- **3123 受控回滚**：工作区、操作（「回滚」或「挑拣合入」）、提交标识。执行前要求工作区干净；失败执行 revert/cherry-pick abort 并读取 `git status --short`，以 3019 拒绝成功。
- 3016 受控边界不合法；3017 旧文本不唯一；3018 验证失败；3019 回滚冲突或状态不干净。
- 上述能力只在文件支持库 Rust 实现中调用进程；V3 消费者须经唯一V1网关调用，不可直接访问 Git、进程或文件系统。

## 受控创建提交（3124）

- **3124 受控创建提交**：受控工作区 / 提交说明 / 文件清单（三段文本）→ 单段 JSON 文本
  `{"状态":"已提交","提交":"<hash>","提交说明":"<说明>","文件数":<整数>,"分支":"<分支名>","工作区状态":""}`。
- **参数边界**
  - `受控工作区`：绝对路径，必须**原样**通过 3120 的 `验证工作区()` 全套校验 —— `v1-d4-` 目录名前缀、
    父目录 `.v1-d4-state/<标识>.owner` 归属标记、`git rev-parse --show-toplevel` 等于自身、
    `--git-common-dir` 等于标记里那份仓库的 `.git`。任何一项不符即 3020，不接受「像工作区的目录」。
  - `提交说明`：非空、至 200 字符、不含换行 / 回车 / NUL 等控制字符（按 `char::is_control` 判）。
  - `文件清单`：JSON 字符串数组，1 至 100 项；每项必须是工作区内相对路径 ——
    拒绝绝对路径、含 `..` 的上跳、空串、含 NUL、重复项。每一项都要解析成工作区内**真实存在的普通文件**
    （父目录 canonicalize 后仍须在工作区内，符号链接一律拒绝）。
- **严格顺序**（全程 fail-closed，任何一步不合规都不提交）：校验工作区 → 校验提交说明 → 解析文件清单 →
  逐项解析真实文件 → `git add -- <清单>` → 读 `git diff --cached --name-only` →
  再 `git commit -q -m <提交说明>`（参数数组直启，不经 shell，说明不会被二次解释）→
  回读 `git rev-parse HEAD` 与 `git status --porcelain`。
- **暂存区必须等于清单**：`git diff --cached --name-only` 的集合与清单**逐项完全相等**才 commit；
  多一个、少一个、或某件在 add 前没有任何改动，都回 3020 **且不产生提交**。
- **提交后必须干净**：commit 落地后 `git status --porcelain` 非空 ⇒ 回 3020。
  注意这条的边界：commit 已经落地、返回却是拒绝 —— 调用方看到 3020 时应把它读成
  「这一版可能已经进去了，但工作区里还有别的东西没处理」，重试前先回读 HEAD 与状态，
  不要当「什么都没发生」。
- 回读的中文文件名靠 `-c core.quotePath=false` 关掉 git 的八进制转义，否则中文路径在暂存区回读时
  形态与清单不同会假红。
- **失败语义**：3020 提交范围不合法（边界 / 路径 / 清单为空 / 文件不存在 / 暂存区与清单不一致 /
  提交后工作区不干净）；3021 提交执行失败（`git commit` 本身失败：身份未配置、钩子拒绝等）。
  3014 写入失败出现在 `git add` 写不动索引时（索引锁竞争一类），属于可重试的环境问题。
  两者都**不是**「已提交」：只有返回 `{"状态":"已提交", …}` 且 hash 能被 `git cat-file -e` 校验才算成功。
- 真实 HTTP 定向验收：`POST /接口/调用`，`{"编号":3124,"值":[{"类型标签":4,"值":"<工作区绝对路径>"},
  {"类型标签":4,"值":"<提交说明>"},{"类型标签":4,"值":"[\"相对路径\"]"}]}`；成功一次、清单不一致一次、
  重复提交一次，三条状态码与业务字段都要按上面的语义断言。
