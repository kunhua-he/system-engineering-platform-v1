## 一 怎么复跑（一条命令，带退出码）

```sh
python3 扩展根目录/原子支持库/编译器支持库/工具/跑声明记录区取证.py
```

它做两件事，**不重写一行解析逻辑**（解析器只有一处，见第三节）：

1. 跑 `开发工具/取证/声明记录区反解.py --自测 --样本 扩展根目录/原子支持库/编译器支持库/语料/样本/第一个程序.e`
   —— **样本随本扩展进仓**（2163 B，只读）⇒ 这一步**不依赖仓外路径**；
2. 跑 `… --全部 --目录 /tmp/易语言源码` —— 全语料读数（**该命令只归并逐件缓存，不自己算**）；
   语料不在就报「**未判**」（**不算通过**）；逐件缓存不齐也报「**未判**」，并把补齐的三步命令印出来。

**全量的计算不在任何一条命令里**（五秒硬顶）：全量的总 CPU 时间远超单条命令的 5 秒预算，
故「一条命令算全量」这条形态已删掉，全量由**跑齐 n 条 `--分片 i/n`** 算出，`--全部` 只归并。
补齐的三步（缓存不齐时 `--全部` 自己会印）：

```bash
# ① 先跑一片，量出「每 MB 多少毫秒」（n 取大：片小只会更慢、更安全）
python3 开发工具/取证/声明记录区反解.py --分片 0/120 --目录 /tmp/易语言源码
# ② 问片数（由刚量到的系数推，不写死）并跑齐
N=$(python3 开发工具/取证/声明记录区反解.py --建议分片数 --目录 /tmp/易语言源码)
for i in $(seq 0 $((N-1))); do python3 开发工具/取证/声明记录区反解.py --分片 $i/$N --目录 /tmp/易语言源码 || break; done
# ③ 归并出全量读数
python3 开发工具/取证/声明记录区反解.py --全部 --目录 /tmp/易语言源码
```

本扩展侧的 `工具/跑声明记录区取证.py --分片 i/n` 是「跑一条」的转发口（一条命令，5 秒内）。

**承重读数逐条断言**（任一条不符即退出码 1）：自测结论「通过」· 假绿 0 ·
全语料「解析失败 0」·「头 4 字节恒 0 = **全数**」（自洽，**不写死件数** —— 写死必随语料增长而漂）·
四种可证记录形态各 > 0。

## 三 根因与取证方法（**为什么只能这样做**）

**根因一条**：**盘面无自描述，且参照实现是黑盒、不许运行**（本项目硬约束）。
⇒ 没有「读一份规格」或「跑一次参照实现看输出」这两条路，只能靠**对照样本**：

> **同一程序改一处、看哪段动** —— 改一个可读的名字 / 常量值，观察哪些字节随它变；
> 变的那一段就属于那张表（分区边界）；不动的那一段不属于它。
> 这是**可证伪**的：若两次改动动到同一段，假设当场被推翻。

**要取到上面三处缺口，具体缺什么**：

1. **对照样本的来源**：需要**同一程序的两个版本**（只改一处），且两个版本都要是**真 `.e`**。
   仓外语料里同源多版本的文件极少（`语料/` 与 `/tmp/易语言源码` 已扫过；参照实现的
   `backup/` 目录里有同名多版本，但那是**插件备份**、不是「改一处」的对照）。
   ⇒ 缺：**一份能定位「改前 / 改后」的成对语料**，或允许运行参照实现（硬约束禁止）。
2. **表起点字段**：若盘面上真有一个「表计数 / 表偏移」字段（`声明记录区实测.md` §七 第 2 条
   点名缺它），则分区边界不必靠对照样本 —— 但**全语料 1456 条实测没找到**这样的字段。
   ⇒ 缺：**一个独立盘面字段**，或**承认它不存在**（那就只剩对照样本一条路）。
3. **操作码表**：需要**操作数宽度表**（每个操作码后面跟几个字节、什么类型）。
   实测只知 `37 xx` 带 u32 长度 + 文本。⇒ 缺：**更多操作码的出现样本 + 宽度证据**
   （可从更大语料归纳，但无法证「完整」；「完整」只有参照实现的定义能给）。

**⇒ 结论**：三处缺口**当前都取不到**（缺对照样本、缺盘面字段、参照实现不可运行）。
1103 的「带号结构」形状**只能立一半**（`声明记录区实测.md` §九：能立的部分有实测地基；
立不出来的部分是分区边界与令牌语义）。
