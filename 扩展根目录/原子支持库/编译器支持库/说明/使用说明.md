# 编译器支持库 · 使用说明

上级：`扩展根目录/原子支持库/` ／ 能力号段：**1100–1199**（申报 `[1100,1199]`，表跨度就是它）
身份：`包声明.json` 的 `标识串` = `b6ac1f87165619c4b72571bba5c4010b`
底座读的入口：导出符号 `GetPlatformInfo`（返回本扩展的 `平台信息` 静态声明）

## 两条路

| 路 | 是什么 | 判据 | 能力 |
|---|---|---|---|
| **原生路** | 我们的**程序文本** ⇄ 结构 | 文本 → 结构 → 文本，逐字节相同（基准是我们自己） | 1101 词法分析 · 1102 语法分析 · 1103 语义分析（**已实现**） |
| **互操作路** | `.e` 容器 ⇄ 结构 | `生成(反解(x)) == x` 逐字节相同（语料 1444/1444） | 1105 反解容器 · 1104 生成容器（**已实现**） |

原生格式的规格见 `项目文档/设计文档/程序文本格式.md` 第二节：UTF-8 · 换行写出 LF（读入认 CRLF）·
缩进 4 个半角空格 · 关键字以 `.` 开头 · 注释 `'` 至行尾 · 文本字面量写出全角引号（读入认半角）·
常量 `#名字` · 运算符全角 · 界符半角 · 逗号间的空实参是有意义的位次。
**文本里写名字；结构里存号**——文本里不许出现号。

## 调哪个号

| 想做什么 | 调哪个号 | 现在能不能调 |
|---|---|---|
| 程序文本 → 记号流 | 1101 词法分析 | **能** |
| 程序文本 → 语法树 | 1102 语法分析 | **能**（内部先 `切记号` 再 `建树`：契约的参数表是**程序文本**） |
| 程序文本 → 带号结构 | 1103 语义分析 | **能**（入参是程序文本 + 三张注册表，**4 行参数表**） |
| 结构 → `.e` 容器字节 | 1104 生成容器 | **能** |
| `.e` 容器字节 → 结构 | 1105 反解容器 | **能** |
| 一步到底 | 1106 编译 | **不能**（保留项；三障碍见 `项目文档/未完成事项.md` #168） |
| 整理诊断 | 1107 诊断 | **能**（`诊断/`；已接线进命令表/函数表） |

**入参的类型标签逐号不同（行序即契约），出参一律字节集（类型标签 5）**：

- 1101 / 1102 / 1106 / 1107 **只有一个参数**（程序文本）；
- **1103 有四个**：`程序文本` + `命令表` + `常量表` + `类型表` —— 三张注册表**追加在参数表末尾**、
  行序不动（裁决见 `项目文档/决策记录/2026-09-27_1103输出形状与注册表来源.md` 裁决二）。
  三张表的载荷 = **本库的注册表边界编码**（见下「原生路边界编码」）；空字节集 = 空表。

| 号 | 参数（行序即契约） | 返回 |
|---|---|---|
| 1101 词法分析 | `程序文本`（**文本**，类型标签 4） | 记号流边界编码（字节集，**所有权交出**） |
| 1102 语法分析 | `程序文本`（**文本**，类型标签 4） | 语法树边界编码（字节集，**所有权交出**） |
| 1103 语义分析 | `程序文本`（4）· `命令表`（**字节集**，5）· `常量表`（5）· `类型表`（5） | 带号结构边界编码（字节集，**所有权交出**） |
| 1104 生成容器 | `容器结构`（字节集：本库的容器结构边界编码） | `.e` 容器字节（字节集，**所有权交出**） |
| 1105 反解容器 | `容器字节`（字节集：完整 `.e` 容器字节，含 8 字节魔数） | 容器结构边界编码（字节集，**所有权交出**） |

**容器结构边界编码**（`src/lib.rs` 的 `结构编码` 模块；小端）：
`u32 段数`，每段 `u32 校验和 · u8 段类型 · 27 字节名称区 · u32 段名长 + 段名字节 · u64 数据长 + 数据字节`。
它只搬字段、不含 `.e` 格式知识（段头偏移与名称区异或在 `容器.rs`）。

**原生路边界编码**（`src/lib.rs` 的 `原生路编码` 模块；小端）：

```text
记号流：u32 原文长 · 原文 · u32 记号数 · 每枚 (u8 种类号 · u32 起 · u32 止)
语法树：记号流编码 · u32 节点数 · 每节点 (u16 种类号 · u32 起 · u32 止 · u32 子起 · u32 子止) · u32 根
```

它同样只搬字段（切分在 `词法.rs`、建树在 `语法.rs`），不含任何词法/语法知识。

**已冻结（2026-09-27）—— 落点就是本件，与上面 `容器结构边界编码` 同处并列**（既有先例：
本库的两种边界编码都写在本文档里；`能力声明/1104.json` / `1105.json` 的说明点名的
「容器结构边界编码」也指这里）。

为什么必须冻：1101 的返回类型是 5（字节集）而产物是 `记号流`、1102 的产物是 `语法树` ——
两份结构都过不了边界，除非先编成字节。故**接线必须有字节格式（不许无形状就接）**，
而**不许每次接线各编一份**（同一件事两套实现即缺陷）。本形状照 `结构编码` 的先例落
（同一条规矩：跨边界只有定长数据槽，结构过边界先编字节集；只搬字段、不含业务知识）。

范围：`能力声明/1101.json` / `1102.json` 的说明只写到产物是什么（「记号流」/「语法树」），
**字节排布由本件规定**。改本形状须走旁路登记
（`契约声明/冻结登记.json` 的 `旁路` 条目「1101 / 1102 返回的字节格式（原生路边界编码）」；
`README.md` 第八节：主结构冻结，演进只走旁路）。

**带号结构边界编码**（1103 的产物；`src/lib.rs` 的 `语义编码` 模块；小端）：

```text
号表：  u32 项数 · 每项 (u8 类 · u8 作用域 · u16 号 · u32 名长 + 名字节)
引用表：u32 项数 · 每项 (u32 节点下标 · u8 类 · u8 号来源 · u16 号 · u8 作用域)
```

`类` ∈ 变量 1 · 常量 2 · 资源 3（**当前不可达**）· 能力 4 · 子程序 5 · 类型 6；
`作用域` ∈ 平台 0 · 全局 1 · 程序集 2 · 局部 3 · 数据成员 4；
`号来源` ∈ 程序 1（1103 自建的名 → 号表）· 命令表 2 · 常量表 3 · 类型表 4。
名字是**原始字节**（按原字节比，不按解码后的字符串比）。

**注册表边界编码**（1103 的三张入参表；`src/语义/注册表定义.rs`；小端）：

```text
注册表：u32 项数 · 每项 (u32 名长 + 名字节 · u16 号)
```

空字节集 = **空表**（不是非法）；非空字节集必须正好解完（截断 / 尾部多余字节 / 项数越界 = `1134`）。

**带号结构是什么、不是什么**（这一条必须读，否则会把它读成 `.e` 记录区形状）：

- **是**：1103 **自建**的「名字 → 号」表 + 每个引用解出的号与来源。取证地基两条 ——
  名与号在盘面**不邻接**（相距 4 MB 量级）⇒ 必须自建表；号是**程序内全局 16 位序号**。
- **不是**：`.e` 声明记录区的**五类分区边界** · 令牌 `<u16 号><u8 甲><u8 乙>` 的**字段语义** ·
  语句**字节码操作码表**。这三处是 `说明/声明记录区取证.md` §二 单列的**不判项**，
  本编码**一个字节都不替它们编**（`号类::资源` 当前不可达也是同一条：语言面没有资源声明节点、
  入参也没有资源表）。不判项清单与理由逐条写在 `src/语义/建表.rs` 文件头的「不判清单」。

## 错误怎么读

所有错误都是**结构化错误码**（不是字符串、不是 panic）：返回槽的 `类型标签` = `4294967295`（错误），
`值` = 错误码。编法见 `契约声明/格式说明.md` 第五节（4 位：段位 1 位 + 序 3 位）。
本扩展的码在**本扩展自己的** `错误码表/` 里（段位 1 = 编译器域，码 1101–1137），
每条都登记了「段位 · 可重试 · 可自愈 · 需人工」四项。

| 码段 | 管什么 |
|---|---|
| 1101–1107 | 容器（反解错误 5 条 + 生成错误 2 条） |
| 1108–1117 | 记号层形状错误（`语言面.rs`，1101 词法分析的诊断面） |
| 1118–1133 | 语法树层形状错误（1102 语法分析的诊断面） |
| 1134–1135 | 本扩展自己的边界错误（结构编码非法 · 参数槽不符）。1134 也管 1103 的三张注册表载荷解不出、或号装不下 16 位 |
| 1136 | 语义层（1103 语义分析的诊断面）：名字未声明（1103 落地后**可达**） |
| 1137 | 词法层输入非法（1101 的输入面，与 1108–1117「记号流结构不合法」分族） |
