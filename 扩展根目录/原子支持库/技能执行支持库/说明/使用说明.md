# 技能执行支持库

技能包受控执行的**校验面**：只校验、只出计划，不起进程。真正跑进程交给 `进程执行支持库` 2601/2602，沙箱/超时/输出上限/取消都在那边，底座只有一条执行腿。

## 能力（8301）

- **8301 准备技能执行**（执行参数 JSON）→ 执行计划 JSON

入参字段：`技能根目录`（绝对路径）、`能力标识`（`分类.技能名`）、`参数`（字典）、`项目根目录`、`禁止导入前缀`（数组）、`解释器`（可空）、`超时秒数`（可空，默认 120）。

返回字段：`脚本路径`、`解释器`、`参数文件`、`技能目录`、`工作目录`、`超时秒`、`命令`、`提交参数`（可直接喂给 2601）、`能力标识`、`技能包文件`。

## 校验项（全部 fail-closed）

1. 能力标识必须是 `分类.技能名` 两段，拒绝 `..`、绝对路径、空段、反斜杠、冒号。
2. 六件套齐全：SKILL.md / 契约.json / 工作流.json / scripts / 验证声明.json / 依赖.json。
3. 工作流.json 的 `入口脚本` 必须落在 `scripts/` 且是 `.py`。
4. 入口脚本 `canonicalize` 后仍须在该技能 `scripts/` 内（防符号链接逃逸）。
5. 脚本源码静态审计，禁项：`subprocess`、`os.system`、`os.popen`、`os.spawn`、`os.exec`、`os.fork`、`pty.spawn`、`shell=True`、`eval(`、`exec(`、`__import__`、`importlib`、`ctypes`、`sys.modules`、`runpy`、`pickle.loads`。
6. 按调用方给的 `禁止导入前缀` 查 `import` / `from` 语句。
7. 参数 JSON 至 1MiB、脚本源码至 2MiB。

## 参数走文件不走 stdin

2601 的子进程 stdin 是 null，所以本能力把参数写成 `/private/tmp/v1技能参数-<pid>-<纳秒>.json`，技能脚本按 `sys.argv[1]` 读该文件。技能脚本要兼容两种入口：

```python
参数 = json.loads(Path(sys.argv[1]).read_text(encoding="utf-8")) if len(sys.argv) > 1 else json.loads(sys.stdin.read())
```

## 调用方编排（三步）

1. 调 8301 拿计划；
2. 用计划的 `提交参数` 调 2601 拿任务句柄，再轮询 2602 取 `标准输出`；
3. 把 `标准输出` 当 JSON 解析成 `{成功, 结果}` 或 `{成功:false, 错误码, 错误信息}`。

## 错误码（8301-8310）

8301 参数不合法 / 8302 技能目录不存在 / 8303 技能包不完整 / 8304 能力标识不合法 / 8305 工作流不合法 / 8306 脚本越界 / 8307 脚本审计不通过 / 8308 依赖越界 / 8309 资源超限 / 8310 处理失败。
