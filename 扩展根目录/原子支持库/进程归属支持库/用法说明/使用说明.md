# 进程归属支持库

## 边界

只做「进程 → 归属」的判定：入参是别人给的进程快照与归属登记，出参是三张分类表。**不读系统进程表、不杀进程、不读 launchctl**——读与杀属编排，留在技能（状态机登记归属后按登记杀）。

## 调用契约

- 6401 `判定进程归属`：顺序参数为 进程表JSON、归属登记JSON、保护参数JSON，输入均为文本标签4，返回 UTF-8 文本标签4。
  返回形如 `{"进程总数":37,"归属命中":1,"可清理":[{"pid":40118,"命令":"…","命中":"端口:40118"}],"受保护":[{"pid":4321,"原因":"保护程序:launchd"}],"未核实":[{"pid":999,"原因":"命令行缺失"}]}`。
  命中判据两种，任一成立即命中：`--port` / `--端口` / `-p` / `--port=40118` 的端口在登记的 `端口` 里；或任一参数包含登记的 `路径`。
  三层分类**互斥且受保护优先**：受保护 > 未核实 > 可清理。
- `归属登记JSON` 的 `端口` 与 `路径` 两组都空 ⇒ `6414 归属登记为空`。这是 fail-closed 的安全判据：证明不了归属就一个都不许清理。

零值说明：进程表为空数组合法（返回三张空表，进程总数 0）；空不是失败哨兵，失败一律走错误码。

## 资源与成本

纯CPU同步能力；20000 个进程项按每项约 200 字节估计约 4 MiB，判定为毫秒级。任一侧超 4 MiB 或进程数超 20000 ⇒ `6413`。预估不是实测，实测在整批统一HTTP验收后记录。

长期进程生命周期由统一执行器管理，能力不自行建立第二调度器。

## 6402 读取进程表

只读系统进程表，把「谁在跑、父进程是谁、命令行长什么样」一次拿全。它**不做归属判定**——
判定归 6401；它只负责取事实。

```
筛选参数JSON: {"可执行名":"llama-server","命令行含":"--port"}   // 空串 = 不筛选，返回全表
```

返回：

```
{"进程总数":812,"筛选命中":2,"进程":[{"pid":1561,"父pid":1,"命令行":"/…/llama-server --port 40118 …"}]}
```

两条使用铁律：

1. **进程总数不受筛选影响**——它是读到的全表行数，用来判断「这台机器到底跑了多少东西」；
   `筛选命中` 才是进程数组长度。两者不要混用。
2. **命令行可能为空**（内核线程、僵尸进程）。这类记录照样返回，别把空命令行当成「读失败」。

典型串联：`6402 读表` → 调用方按业务挑候选（例如「父子都在、父进程不在守护登记里」）→
`6401 判归属`（带归属登记与保护参数）→ 只清理 `可清理` 那一档。
