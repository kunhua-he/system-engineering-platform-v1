# 求和列表模块（7951）

**做什么**：把传入的数值列表交给 `数值计算支持库_求和`（能力 1330），把它交回的**结果结构（类型标签 103）原样返回**。模块不做算术、不分配、不释放、不解码。

## 怎么调

- 能力号 `7951`，参数 1 个：`待求和列表`（类型标签 `100` 列表，元素为整数或双精度）。
- 返回：类型标签 `103` 结果结构，字段与 1330 一致（`结果`，双精度）。
- 错误：`1001` 参数不合法（**空列表就是这一条** —— 1330 空表直接报它）、`1100` 计算失败。两个码都是依赖能力抛的，模块只透传。

## 构建

在 `扩展根目录/原子支持库/编译器支持库` 下：

```sh
V1_MODULE_SCRATCH_DIR="$HOME/Library/Application Support/系统工程平台V1/临时件/模块编译" \
  cargo run --locked --example 出模块制品 -- "$PWD/../../组合模块库/求和列表模块"
```

## 为什么是独立包

入口包装里能力号只被丢弃（入口不分派能力号）⇒ **一个制品只承载一个能力**。与 `求和模块`（7950，两整数入参）语义不同，故必须独立包、独立号段 `7951–7951`；7950 的号段已收窄为 `7950–7950`，两者不重叠。
