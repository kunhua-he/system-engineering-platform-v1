## 一、模块级映射

### 1.1 一对一：一个包声明 → 一份契约

```
老项目：系统工程平台/<路径>/包声明.json      （148 份）
V1目标：契约声明/能力声明/外部_<名称>.json    （148 份）
```

### 1.2 文件名规则（机械可判）

1. 取 `包声明.json` 的 `名称` 字段作后缀。
2. **撞名回退**：实测有 **14 组重名**（见 §七.1），同一批翻译里若两个包的 `名称` 相同，则两者都改用 **`包id` 把 `.` 换成 `_`** 作后缀：
   - `支持库.适配层.FFmpeg提供者` → `外部_支持库_适配层_FFmpeg提供者.json`
   - `支持库.后端.媒体处理支持库.FFmpeg媒体` → `外部_支持库_后端_媒体处理支持库_FFmpeg媒体.json`
3. **内部层**：`内部层` 为真（实测 **16 份**）的包用 `内部_` 前缀而不是 `外部_`：
   - `支持库.后端.OCR识别支持库.OCR识别` → `内部_OCR识别.json`

### 1.3 字段级映射

| 老项目 `包声明.json` | V1 契约 | 规则 |
|----------------------|---------|------|
| `包id` | `模块头.来源包id` | 原样（用于溯源，V1 不认识它） |
| `名称` | `模块头.名称` | 原样 |
| `类型` | （不进契约） | 只用来定号段（§五） |
| `版本` | `模块头.声明版本` | 原样；须合 `\d+.\d+.\d+` |

| `入口` | `模块头.入口件` | 原样（如 `__init__.py`） |
| `内部层` | `模块头.内部层` | 缺省为假 |
| `句柄超时秒` | `模块头.句柄超时秒` | 缺省为 0 |


### 2.2 逐字段规则

| V1 字段 | 取值规则 |
|---------|----------|
| `能力编号` | 由 §五 号段分配表给，段内按包内顺序取 |
| `名称` | `<包名称>_<能力短名>`；能力短名 = `能力id` 的**末段**（§七.2） |
| `说明` | 老项目 `说明` 原样；为空时填 `<包名称>_<能力短名>` |
| `类别` | 恒 `0`（未裁前命令类别表为空，见 `契约声明/命令类别/`） |
| `状态位` | 恒 `0` |
| `返回类型` | 按 §三.2 返回映射 |
| `用户级别` | 恒 `0` |
| `参数表` | 逐个参数映射，见下 |
| `可抛错误码` | 空表；失败走 V1 保留标签 `4294967295` + 值 = 错误段位（§五.4） |

**参数表逐字段**：

| V1 字段 | 老项目源 | 缺省规则 |
|---------|----------|----------|
| `名称` | `参数[].名称` | 必填 |
| `说明` | `参数[].说明` | 缺 ⇒ 空串（实测 2218 条只有 `名称`+`类型`，无说明） |
| `类型标签` | §三.1 类型映射表 | 未知类型 ⇒ 拒译并记账 |
| `状态位` | — | 恒 `0` |
| `默认值` | `参数[].默认值` | 缺 ⇒ 按类型零值（文本`""`/整数`0`/双精度`0.0`/逻辑`0`/空`0`） |

> **`必填` 字段的处置**：老项目 647 条参数带 `必填`，V1 参数表无此位。**不许丢** —— 写进 `说明` 前缀 `（必填）` 或 `（选填）`，否则可调性信息静默消失。

## 三、类型映射表

### 3.1 参数类型 → V1 类型标签

V1 类型标签分两段：`0~99` 内核自有（见 `契约声明/类型声明/`，现有 0~7）· `100+` 扩展自有（`契约声明/号段图.json` §类型号段）。

| 老项目类型 | 实测处数 | V1 标签 | V1 类型名 | 规则 |
|------------|------:|--------:|----------|------|
| `文本型` | 1639 | 4 | 文本 | 直映 |
| `整数型` | 398 | 1 | 整数 | 直映 |
| `双精度数型` | 246 | 2 | 双精度 | 直映 |
| `逻辑型` | 163 | 3 | 逻辑型 | 直映 |
| `字节集型` | 26 | 5 | 字节集 | 直映 |
| `空值型` | 2 | 0 | 空 | 直映 |
| `句柄型` | 1 | 6 | 句柄 | 直映 |
| `长整数型` | 2 | 1 | 整数 | **归并**：老项目长整数就是 64 位，与 V1 整数同宽 |
| `资源引用型` | 1 | 6 | 句柄 | **归并**：老项目资源引用是不透明引用 |
| `列表型` | 184 | 100 | 列表 | 扩展自有，需登记 `契约声明/类型声明/0100.json` |
| `字典型` | 175 | 101 | 字典 | 扩展自有，同上 `0101` |
| `JSON值型` | 28 | 102 | JSON值 | 扩展自有，同上 `0102` |

> **归并要记账**：`长整数型`/`资源引用型` 两处归并会丢信息（V1 侧分不出原类型）。翻译器必须把这 3 处写进翻译日志，不许静默。

### 3.2 返回 → V1 返回类型

老项目返回实测三种形态：

| 老项目返回形态 | 实测处数 | V1 `返回类型` | 规则 |
|----------------|------:|-------------:|------|
| `{"类型":"结果型","值结构":{…}}` | **756** | **103 起的结构类型** | 每个不同的 `值结构` 登记一个类型声明，`元素表` 取 `值结构` 的键；键→键同名，值→说明 |
| `{"类型":"结果型"}`（无值结构） | **84** | `0`（空） | 无结构可映，返回空 |
| `"结果型"`（字符串写法） | 116 | `0`（空） | 同上；若 `说明` 里点名了单一返回物，按该物类型定 |
| `{"类型":"逻辑型","值结构":{"存在":…}}` | 2 | `3` | 直映为逻辑型；但**它还带一个值结构**（老项目两处声明写得不一致），该结构 V1 装不下 ⇒ 丢弃并记账 |
| `{"类型":"整数型"}` | 1 | `1` | 直映 |
| **合计** | **959** | | 与能力总数对得上 |

> ★ **本表必须合计等于 959**。本件初稿曾把 `逻辑型 2` / `整数型 1` 另立两行而与前面两行重复计数（合 962），经独立复核发现后已改正 —— 这类「分类表合计对不上总数」是最容易静默遗留的错，翻译器侧的统计也要做这道合计校验。

**结构类型登记表**：翻译器维护 `值结构指纹 → 标签` 的映射（指纹 = 键表排序后压空白取散列）。指纹相同即复用同一标签 —— 实测 756 条结构化返回里大量重复（同为 `{成功, 数据, 错误}` 形态），复用能把类型表压到几十条。

> **失败不进返回类型**：老项目的 `结果型` 把失败也包在返回里（`{成功:false, 错误:…}`）；V1 的失败是**保留标签 `4294967295`** + 值 = 错误段位。所以 `结果型` 里的 `成功`/`错误` 两个键**不登记进元素表**，只留数据键。

## 四、命名修复规则

V1 命名纪律（`开发文档/设计哲学.md` §四）：合格 = 结构检查 + 不落**四类禁止形状**（单汉字名 · 泛名 · 序数代称 · 西文单字母）。

### 4.1 实测扫描结果

对 148 份包声明的 `名称` / `能力.名称` / `能力.参数.名称` 逐个匹配禁止形状：

| 扫描面 | 数量 | 违规 |
|--------|-----:|------|
| 包 `名称` | 148 | **0** |
| 能力 `名称` | 959 | **0** |
| 参数 `名称` | 2865（769 个唯一） | **11 个唯一违规名** |

### 4.2 需修复的参数名（全表）

| 违规名 | 形状 | 实测处数 | 涉及包数 | 修复为 |
|--------|------|------:|------:|--------|
| `参数` | 泛名 | 24 | 17 | `入参`（如 `入参表`） |
| `内容` | 泛名 | 15 | 10 | `文本内容` |
| `数据` | 泛名 | 13 | 6 | `载荷数据` |
| `对象` | 泛名 | 4 | 2 | `目标对象` |
| `结果` | 泛名 | 1 | 1 | `执行结果` |
| `值` | 单汉字 | 8 | 6 | `标量值` |
| `键` | 单汉字 | 4 | 2 | `键名` |
| `列` | 单汉字 | 4 | 2 | `列名` |
| `表` | 单汉字 | 3 | 1 | `数据表` |
| `域` | 单汉字 | 2 | 1 | `字段域` |
| `行` | 单汉字 | 2 | 2 | `数据行` |

**这 11 条是确定性映射**（不依赖上下文）—— 翻译器直接替换，替换后重新核一遍禁止形状。

> **为什么这 11 条能一刀切**：它们都是**单字或泛词**，而 V1 的四类禁止形状本身就是「不依赖上下文就能判」的形状。真正需要上下文的（如 `结果` 到底该叫 `编目结果` 还是 `查询结果`）在本项目里**不存在** —— 实测 `结果` 只出现 1 处，在 `平台控制面.平台状态` 里，语义单一。

### 4.3 「说明」散文也要过禁译名

实测发现：老项目 `返回.值结构` 的**说明散文**里会把逻辑类型写成外来译名（判据 ㊹ 列的禁译名码位 `U+5E03 U+5C14`）；V1 已把该类型名裁为 `逻辑型`。

**规则**：翻译器对每个 `说明` 字段（包说明 · 能力说明 · 参数说明 · 值结构说明）都要跑一遍**禁译名检测**（检测表 = `开发工具/代码地图/查名.py::禁译名码位`），命中即改写为 V1 裁定的类型名。

**不许机械全局替换** —— 要按它在该处的**实际角色**命名（判据 ㊹ 的修法要求）。实测本包只有 1 处，在 `OCR.可用性检查` 的值结构里。

### 4.4 不许改的面

- **包 `名称` 与能力 `名称` 一律不改** —— 实测零违规，且它们是跨包引用（`依赖.能力` 用 `能力id`）的锚点，改名会断链。
- **参数名的改名要同步改老项目调用处** —— 但本任务**不动老项目代码**（只读）。所以参数改名只落在**翻译后的契约**里，老项目侧原样保留；这一层不一致是**有意为之**，翻译器要在翻译日志里逐条记下（原名 → 新名 + 所在包），供小队7 核对。

## 五、号段分配规则

### 5.1 权威源

`契约声明/号段图.json` 是唯一权威（任务书 01 写的「1000~9999」与任务书 02 写的「10000~999999」都与它相抵，以它为准）。能力号段全宽 **0~9999**：

| 段 | 归属 |
|----|------|
| 0~999 | 底座自有（内核 · 跨语言适配） |
| 1000~1999 | 核心支持库（语言自身） |
| 2000~6999 | 三方封装（按域：系统 2xxx · 文件 3xxx · 文本 4xxx · 数据 5xxx · 界面 6xxx） |
| 7000~7999 | **模块**（扩展，可热载入） |
| 8000~8999 | **技能**（扩展，可热载入） |
| 9000~9999 | 接口面与构建验证（工具类） |

### 5.2 老项目 → 段的映射规则

| `包id` 首段 | `类型` | V1 段 | 实测包数 |
|-------------|--------|-------|------:|
| `支持库` | 支持库 | 2000~6999（按域） | 111 |
| `模块库` | 基础模块 / 功能模块 | **7000~7999** | 19 |
| `技能库` | — | **8000~8999** | 1 |
| `平台控制面` / `运行核心` / `启动监督器` | 支持库 | **待裁决**（§0.3 冲突二） | 17 |

段内取号：按「`包id` 字典序 → `能力id` 字典序」顺序取，**号只增不复用**；作废的号进 `契约声明/作废号表.json`。具体每包起止号以**小队2 的 `号段分配表.json`** 为准 —— 本件只定规则，不代替小队2 定表。

### 5.3 错误码段位（派生，不另分配）

错误码是 4 位 = **段位 × 1000 + 序号**，段位 = 能力号的首位。所以：

| 能力号段 | 错误码段位 |
|----------|-----------|
| 0~999 | 0（已全表定义，见 `契约声明/错误码表/`） |
| 2000~6999 | 2 / 3 / 4 / 5 / 6 |
| 7000~7999 | **7** |
| 8000~8999 | **8** |

翻译器**不新增错误码定义**；只把段位算出来，供 `可抛错误码` 引用。

### 5.4 失败怎么表达

V1 不用返回结构表达失败：返回槽类型标签置 **`4294967295`（保留标签「错误」）**，槽值 = 错误段位。所以老项目 `结果型` 里的 `成功`/`错误` 两个键在翻译后消失，调用方改看返回槽标签。

## 六、依赖关系处理

### 6.1 老项目依赖形态

```json
"依赖": [{"能力": "OCR识别支持库.OCR识别.识别图片", "版本": ">=1.0.0"}]
```

共 **113 条**，逐条指向一个**能力id**（不是包）。

### 6.2 映射规则

| 老项目 | V1 | 规则 |
|--------|-----|------|
| `依赖[].能力` | `模块头.依赖能力编号[]` | 查「能力id → 能力编号」映射表（翻译器先译被依赖包，再回填） |
| `依赖[].版本` | （V1 无对应字段） | **丢掉但记账**：V1 的依赖判据只有「依赖缺失」（错误码 12），没有版本区间。逐条写进翻译日志 |

### 6.3 翻译顺序

依赖是**能力级**的，所以翻译顺序取**包级拓扑序**（小队3 的 `老项目依赖图.json` 已给出层向；以老项目自身的 `运行核心/依赖防火墙.py::允许依赖表` 为权威口径）。**同一层内可并行**。

### 6.4 已知的三类依赖盲区（引小队3）

1. 动态 `import` / `importlib.import_module` 的变量参数不追；
2. 字符串里登记的模块名不追；
3. 老项目有 **1 条越权边**（`运行核心 → 启动监督器`），翻译时保持原样还是就地修正，需人裁决。

## 七、翻译器实现提示（边界情况与异常处理）

### 7.1 撞名（必须处理，否则会静默覆盖）

实测 **14 组包名重名**，每组的两个包分居不同目录：

| 重名 | 两个包 |
|------|--------|
| `能力目录` | `平台控制面.能力目录` · `模块库.能力目录` |
| `文档生成` | `支持库.后端.办公文档支持库.文档生成` · `模块库.文档生成` |
| 其余 12 组 | 均为 `支持库.适配层.<X>提供者` 与 `支持库.后端.<Y>支持库.<X>` 成对 |

**处置**：整批翻译**先算一遍全量名称**，撞名的整组回退到 `包id` 下划线写法（§1.2 规则 2）。**不许先写后覆盖**。

### 7.2 能力id 段数不统一

实测：2 段 254 个（`系统探针.检查提供者`）· 3 段 693 个（`平台控制面.需求登记.登记需求`）· 4 段 12 个（`平台控制面.提供者.动态库提供者.调用动态库`）。

**处置**：能力短名一律取**末段**；能力id 全串进 `来源能力id` 供溯源。

### 7.3 参数条目两种字段组合

实测：`{名称,类型}` 2218 条 · `{名称,类型,必填,说明,默认值}` 647 条。翻译器按**缺省表**处理（§2.2），两种组合走同一条路径。

### 7.4 信息损失必须记账

以下三类丢信息，翻译器**必须**写翻译日志，不许静默：

1. `长整数型` / `资源引用型` 归并（3 处）；
2. `依赖[].版本` 丢掉（113 条）；
3. 参数改名（11 个唯一名，见 §4.2）；
4. `说明` 散文里的禁译名改写（见 §4.3）；
5. `返回.类型` 写 `逻辑型` 却带 `值结构` 的 2 处（`文件系统支持库.文件操作.判断存在`）：值结构装不进 V1 的逻辑型返回，丢弃并记账。

### 7.5 未登记类型的处理

遇到 §三 表里没有的参数类型：**拒译该能力**（不猜、不默认为文本），写进翻译日志并计数。同理，`返回` 形态不在 §3.2 五类内的，拒译。

### 7.6 口径冲突（待裁决，先按默认值跑）

1. **外部契约的落点**（§0.3 冲突一）：默认落 `契约声明/能力声明/`；若裁决为「落扩展自身目录」，翻译器只需换输出前缀，不影响其余规则。
2. **平台三个面的段**（§0.3 冲突二）：默认按 `类型` 字段归段。

## 八、验收自检（翻译器跑完必查）

```sh
# 1. JSON 都能解析
python3 -c "import json,glob;[json.load(open(f,encoding='utf-8')) for f in glob.glob('契约声明/能力声明/外部_*.json')]"

# 2. 能力编号全仓无重复、无越段
python3 - <<'EOF'
import json, glob
号 = []
for f in glob.glob('契约声明/能力声明/外部_*.json'):
    d = json.load(open(f, encoding='utf-8'))
    for c in d['能力列表']: 号.append(c['能力编号'])
assert len(号) == len(set(号)), f"编号重复：{len(号)-len(set(号))} 个"
assert all(0 <= n <= 9999 for n in 号), "有编号超出能力号全宽 0~9999"
print(f"能力 {len(号)} 个，编号唯一，未越界")
EOF

# 3. 命名纪律：翻译后的契约里不许再有四类禁止形状
python3 -c "import json,glob,re;[print(f) for f in glob.glob('契约声明/能力声明/*.json') if re.search(r'[\"：]\s*\"?[\u4e00-\u9fff]\"?\s*[,}]', open(f,encoding='utf-8').read())]"

# 4. 翻译日志里三类信息损失都有记账
wc -l 构建装配/翻译器/翻译日志.txt
```

**对照实例**：`示例_OCR模块翻译对照.json` 是一份完整的前后对照，翻译器写完后拿它比一比形状对不对。
