## 三、工作内容

### 步骤1：扫描老项目所有变量名

使用代码地图或grep提取：
```bash
# 扫描Python变量名
cd ~/Documents/Agent/PHP/系统工程平台/
grep -roh '\b[a-zA-Z_\x80-\xff][a-zA-Z0-9_\x80-\xff]*\b' --include="*.py" . | \
    sort -u > /tmp/老项目变量名.txt
```

预期输出样本：
```
一条
一项
某个
结果
数据
信息
文件路径
元数据
编目结果
```

### 步骤2：违规名分类

按V1命名纪律，分类违规名：

**类别1：序数代称**（必须修复）
```
一条 → 某条记录
一个 → 某个配置
一项 → 某项任务
```

**类别2：泛名**（必须修复）
```
结果 → 编目结果 / 查询结果 / 验证结果（根据上下文）
数据 → 元数据 / 配置数据 / 文件数据
信息 → 错误信息 / 用户信息
项 → 配置项 / 菜单项 / 列表项
```

**类别3：单汉字**（必须修复）
```
件 → 文件 / 工件
止 → 停止标志 / 结束符
主 → 主键 / 主配置
```

**类别4：西文单字母**（必须修复）
```
i → 索引
x → 横坐标
f → 文件句柄
```

**类别5：已经合格**（保留）
```
文件路径 → 文件路径（动词+对象，合格）
编目结果 → 编目结果（对象+说明，合格）
元数据 → 元数据（合格）
```

### 步骤3：生成修复映射表

#### 3.1 确定性映射（机械替换）

对于明确的违规名，直接生成映射：
```json
{
  "确定性映射": {
    "一条": "某条记录",
    "一个": "某个配置",
    "一项": "某项任务",
    "i": "索引",
    "x": "横坐标",
    "f": "文件句柄"
  }
}
```

#### 3.2 上下文映射（需要上下文判断）

对于泛名，生成多个候选：
```json
{
  "上下文映射": {
    "结果": {
      "候选": ["编目结果", "查询结果", "验证结果", "执行结果"],
      "规则": "根据函数名前缀选择（编目xxx→编目结果）"
    },
    "数据": {
      "候选": ["元数据", "配置数据", "文件数据", "用户数据"],
      "规则": "根据变量用途选择"
    }
  }
}
```

#### 3.3 高频合规名（参考V1）

从V1信息核心提取高频合规名，作为翻译器的参考词典：
```json
{
  "高频合规名": [
    "文件路径",
    "配置文件",
    "编目结果",
    "元数据",
    "错误码",
    "能力编号",
    "参数表",
    "返回类型号"
  ]
}
```

### 步骤4：生成统计报告

```markdown
# 老项目命名修复统计

## 扫描范围
- 老项目路径：~/系统工程平台/
- 扫描文件数：XX 个Python文件
- 提取变量名：YY 个唯一名

## 违规名统计

| 类别 | 数量 | 占比 | 示例 |
|------|------|------|------|
| 序数代称 | 50 | 15% | 一条、一个、一项 |
| 泛名 | 80 | 24% | 结果、数据、信息 |
| 单汉字 | 20 | 6% | 件、止、主 |
| 西文单字母 | 10 | 3% | i、x、f |
| 已合格 | 170 | 52% | 文件路径、编目结果 |

## 修复策略

### 确定性修复（85个名字）
这些名字可以机械替换，无需上下文：
- 一条 → 某条记录
- 一个 → 某个配置
- ...

### 上下文修复（75个名字）
这些名字需要根据上下文选择候选：
- 结果 → {编目结果, 查询结果, 验证结果, ...}
- 数据 → {元数据, 配置数据, 文件数据, ...}
- ...

### 已合格（170个名字）
保持不变：
- 文件路径
- 编目结果
- ...

## 翻译器实现建议

1. **先跑确定性映射**（机械替换）
2. **再跑上下文映射**（根据函数名/变量用途选择）
3. **最后人工复核**（上下文映射可能有误，需要验证）
```
