## 三、工作内容

### 步骤1：读取老项目模块列表

扫描老项目目录，提取所有模块/子系统：
```bash
ls -d ~/Documents/Agent/PHP/系统工程平台/*/ | xargs -n1 basename
```

**先不假设目录结构**，扫描后再决定号段分配方案

### 步骤2：分配号段

按模块顺序分配号段（**每个10000号**，长期扩展充足）：
```
模块1   → 10000~19999
模块2   → 20000~29999
模块3   → 30000~39999
...
模块99  → 990000~999999
```

**为什么10000号一段**：
- 长期项目，模块内能力会持续增长
- 避免将来号段不够用需要重新分配
- 如果用生命周期控制（载入时分配，不用时回收），也支持

### 步骤3：更新号段图

在 `契约声明/号段图.json` 中增加外部模块区段：
```json
{
  "内置模块": {
    "范围": "0~9999",
    "分配": {
      "运行内核": "0~999",
      "扩展装载": "1000~1999",
      ...
    }
  },
  "外部模块": {
    "范围": "10000~999999",
    "每模块容量": 10000,
    "分配": {
      "模块1": "10000~19999",
      "模块2": "20000~29999",
      "模块3": "30000~39999"
    },
    "说明": "每模块10000号，支持长期扩展；如采用生命周期控制，载入时分配、不用时回收"
  }
}
```

### 步骤4：生成号段分配表

创建 `构建装配/翻译器/号段分配表.json`：
```json
{
  "说明": "老项目模块 → V1号段分配表（翻译器使用）",
  "生成时间": "2026-10-06",
  "分配规则": "每模块10000号，顺序分配（模块1→10000, 模块2→20000, ...）",
  "老项目根": "/Users/hekunhua/Documents/Agent/PHP/系统工程平台",
  "模块映射": [
    {
      "老项目路径": "系统工程平台/模块1",
      "模块名": "模块1",
      "号段起": 10000,
      "号段止": 19999,
      "容量": 10000
    }
  ],
  "生命周期控制": {
    "启用": false,
    "说明": "如启用，模块载入时分配号段，卸载时回收；可支持更多模块并存"
  }
}
```

**注意**：具体模块列表需要先扫描老项目目录结构确定

## 四、验收标准

### 标准1：号段不冲突
- ✅ 外部模块号段（1000~9999）不与内置模块（0~999）冲突
- ✅ 各外部模块号段之间不重叠

### 标准2：容量足够
- ✅ 每个模块100个号（当前老项目最大模块约16个接口，100个号足够）
- ✅ 预留8000个号给未来扩展

### 标准3：文件格式正确
- ✅ JSON格式合法（能被Python json.load解析）
- ✅ 字段完整（号段起、号段止、模块名都有）
