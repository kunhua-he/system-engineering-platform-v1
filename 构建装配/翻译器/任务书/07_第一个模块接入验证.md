## 三、工作内容

### 步骤1：选择验证模块

从依赖图的**0层**（无依赖或只依赖系统核心）选最简单的模块：

**选择标准**：
- 功能数量少（≤10个接口/函数）
- 无复杂依赖
- 命名相对规范

**建议候选**：
- 如果有"支持库"模块，优先选它（通常是底层工具函数）
- 否则选0层中功能数最少的

### 步骤2：执行翻译

```bash
cd /Users/hekunhua/Documents/Agent/PHP/系统工程平台V1

# 翻译模块
python3 构建装配/翻译器/老项目模块翻译.py --模块 <选定模块>

# 输出示例：
# 契约声明/能力声明/外部_登录.json
```

### 步骤3：验证翻译结果

#### 3.1 格式验证
```bash
# 验证JSON格式
python3 -c "import json; json.load(open('契约声明/能力声明/外部_<模块名>.json'))"

# 验证契约一致性
python3 测试验证/契约一致性/扫实现.py
```

#### 3.2 内容验证

检查翻译后的契约：
- ✅ 能力编号在分配的号段内
- ✅ 能力名符合命名纪律（<模块名>_<动作/对象>）
- ✅ 参数表完整（参数名、类型号、行序）
- ✅ 返回类型号正确

#### 3.3 命名验证

对比翻译前后的命名：
```bash
# 提取翻译前的变量名
grep -roh '\$[a-zA-Z_\x80-\xff][a-zA-Z0-9_\x80-\xff]*' \
  ~/Documents/Agent/PHP/系统工程平台/<模块名>/ | \
  sed 's/\$//' | sort -u > /tmp/翻译前.txt

# 提取翻译后的参数名
jq -r '.能力列表[].参数表[].参数名' \
  契约声明/能力声明/外部_<模块名>.json | \
  sort -u > /tmp/翻译后.txt

# 对比
diff /tmp/翻译前.txt /tmp/翻译后.txt
```

检查：
- ✅ 违规名已修复（一条→某条记录、结果→具体结果）
- ✅ 合规名保持不变

### 步骤4：集成验证

#### 4.1 门禁验证
```bash
python3 构建装配/一键验证/闸0.py
```

预期：
- ✅ 闸0通过（新增的契约文件不破坏门禁）
- ✅ 没有新增命名债务

#### 4.2 信息核心验证
```bash
# 检查新增的能力名是否已登记
python3 开发工具/信息核心/信息核心.py 验证 --债名落点
```

如果有未登记的名字：
```bash
# 登记新名字
python3 开发工具/信息核心/信息核心.py 登记 <新名字>
```

#### 4.3 号段验证
```bash
# 检查号段分配是否与预期一致
jq '.能力列表[].能力编号' 契约声明/能力声明/外部_<模块名>.json | sort -n
```

预期：
- ✅ 所有能力编号连续递增
- ✅ 在分配的号段内（如：10000~19999）
- ✅ 未超出号段上限

### 步骤5：问题记录与修正

如果验证失败，记录问题：

**问题分类**：
1. **翻译器bug**：修复 `老项目模块翻译.py`
2. **翻译规范不完整**：补充 `翻译规范.md`
3. **命名修复规则不准确**：更新 `命名修复映射.json`
4. **号段分配错误**：修正 `号段分配表.json`

修正后重新翻译，直到验证通过。
