## 三、工作内容

### 步骤1：读取老项目模块格式

先扫描 `/Users/hekunhua/Documents/Agent/PHP/系统工程平台/` 的目录结构，识别模块组织方式。

然后提取模块声明格式（可能是JSON、Python配置文件或其他格式）：
- 模块声明结构（模块名、版本、接口列表）
- 接口声明结构（能力名、参数、返回值）
- 依赖声明（import/require的目标）

### 步骤2：对照V1契约格式

读取 `契约声明/能力声明/运行内核_契约.json`，提取：
- 能力声明结构（能力编号、能力名、参数表、返回类型号）
- 类型声明结构（类型号、类型名）
- 错误码声明（可抛错误码）

### 步骤3：制定映射规则

**3.1 模块级映射**
```
老项目：系统工程平台/<某个模块>
V1目标：契约声明/能力声明/外部_<模块名>.json
```

**3.2 能力级映射**
```
老项目接口：
{
  "能力名": "编目",
  "参数": ["文件路径", "元数据"],
  "返回": "编目结果"
}

V1契约：
{
  "能力编号": 1001,
  "能力名": "知识库_编目",
  "参数表": [
    {"参数名": "文件路径", "类型号": 1, "行序": 0},
    {"参数名": "元数据", "类型号": 10, "行序": 1}
  ],
  "返回类型号": 20
}
```

**3.3 命名修复规则**
```
老项目常见违规名 → V1合规名：
一条 → 某条记录
某项 → 某项配置
结果 → 编目结果
数据 → 元数据
```

**3.4 类型映射**
```
老项目类型（PHP类型提示） → V1类型号：
string → 1
int → 2
array → 10
object → 20
```

**3.5 号段分配规则**
```
外部模块号段：1000~9999
每个模块：100个号一段
知识库：1000~1099
Agent：1100~1199
桌面：1200~1299
...
```

### 步骤4：写翻译规范文档

文档结构：
```markdown
# 老项目 → V1 翻译规范

## 一、模块级映射
（老项目目录 → V1契约文件）

## 二、能力级映射
（接口声明 → 能力声明）

## 三、类型映射表
（PHP类型 → V1类型号）

## 四、命名修复规则
（违规名 → 合规名的映射表）

## 五、号段分配规则
（每个模块的号段范围）

## 六、依赖关系处理
（老项目require → V1契约调用）

## 七、翻译器实现提示
（边界情况、异常处理）
```

### 步骤5：写示例对照

选知识库模块，写一个完整的翻译前后对照：
```json
{
  "翻译前": {
    "文件": "系统工程平台/<模块名>/配置或声明文件",
    "内容": { ... }
  },
  "翻译后": {
    "文件": "契约声明/能力声明/外部_知识库.json",
    "内容": { ... }
  },
  "映射说明": {
    "能力数量": 16,
    "号段": "1000~1015",
    "命名修复": ["一条→某条编目", "结果→编目结果"]
  }
}
```

## 四、验收标准

### 标准1：规范完整性
- ✅ 模块级、能力级、类型级、命名级、号段级映射规则都有
- ✅ 每条规则都有实例说明
- ✅ 边界情况（如：类型未知、命名冲突）有处理方案

### 标准2：可机械执行
- ✅ 规则足够明确，翻译器能照着写（不需要人判断）
- ✅ 命名修复规则能机械匹配（不需要语义理解）

### 标准3：实例验证
- ✅ 示例对照文件能跑通（手工验证翻译后的JSON符合V1格式）
