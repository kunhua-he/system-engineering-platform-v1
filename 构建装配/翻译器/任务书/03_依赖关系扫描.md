## 三、工作内容

### 步骤1：扫描依赖关系

对每个模块/子系统，扫描其Python文件：
```bash
# 示例：扫描某个模块
grep -r "^import\|^from" ~/Documents/Agent/PHP/系统工程平台/<模块名>/ | \
  grep -v "^Binary" | \
  awk '{print $2}' | \
  cut -d. -f1 | \
  sort -u
```

提取规则：
- `from 后端核心 import xxx` → 依赖 `后端核心`
- `import 支持库.xxx` → 依赖 `支持库`
- 内部相对导入 → 内部依赖（忽略）

### 步骤3：计算接入顺序

**原则**：无依赖的先接，有依赖的后接

**算法**：拓扑排序
1. 找出0层（无依赖或只依赖系统核心）
2. 依次去掉已处理模块，找下一层
3. 如果有循环依赖，标记为红

**输出顺序**：
```
第1批（0层）：支持库
第2批（1层）：前端核心, 后端核心
第3批（2层）：平台控制面, 客户端
第4批（3层）：...
```

**注意**：具体模块名和层级需要扫描后确定

## 四、验收标准

### 标准1：依赖关系完整
- ✅ 每个模块的 `require_once` 都被扫描到
- ✅ 依赖模块名正确（能与模块列表对应）

### 标准2：层级计算正确

- ✅ 按顺序接入时，被依赖的模块一定先于依赖它的模块
- ✅ 同一批次内的模块可以并行接入（互不依赖）

## 七、注意事项

1. **底层库特殊处理**：`支持库/` 等基础库标记为底层依赖即可
2. **内部导入特殊处理**：相对导入（`from . import xxx`）是模块内部依赖，不算跨模块
3. **循环依赖处理**：如果发现循环依赖，记录到 `循环依赖` 字段，需要人工打破
4. **第三方库过滤**：标准库和第三方包（如requests、flask）不算模块依赖

## 八、工具提示

### 快速扫描依赖的命令
```bash
# 扫描单个模块的依赖
scan_module() {
    local module_path=$1
    grep -rh "^import\|^from" "$module_path" 2>/dev/null | \
        awk '{print $2}' | \
        cut -d. -f1 | \
        sort -u
}

# 扫描所有模块
for dir in ~/Documents/Agent/PHP/系统工程平台/*/; do
    module=$(basename "$dir")
    echo "=== $module ==="
    scan_module "$dir"
done
```
