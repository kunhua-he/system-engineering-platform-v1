## 一 制品是什么

**一次构建产出的、可装载的整包。** 落在 `构建装配/制品产物/<制品标识>/`。

```text
制品标识 = <提交哈希 12 位>-<构建指纹 16 位>
构建指纹 = sha256(规范文本)[:16]

规范文本（逐行，行序固定）：
  profile=release
  变体=<装配变体名>
  工具链=<rustc --version>
  扩展根声明=<sha256(扩展装载/扩展根声明.json)>
  装配器=<sha256(构建装配/上线切换/构建制品.py)>
  文件 <相对路径> <sha256(内容)>        ← 按路径排序，逐行
```

**规范文本里没有时间、没有绝对路径、没有机器名** ⇒ 同一份源在两台机器上产出同一个标识。

### 制品内容（三样，一个不少）

| 件 | 是什么 |
|---|---|
| `网关` | 底座网关的可执行件（`cargo build --release --example 启动网关` 的产物） |
| `扩展/` | 本次装配装入的**可装载库**，按 `扩展/<种类目录>/<扩展目录>/<扩展目录>.dylib` 摆 |
| `扩展根声明.json` | 制品内副本：`目录` 已改指制品内的 `扩展/`，**形状与源件逐字段一致**（只改值） |
| `制品清单.json` | 身份（标识 · 提交 · 变体 · 指纹）+ 内容（文件清单）+ 读数约定。**生成物，禁手改** |

### 判据（可机器数）

| # | 判据 | 怎么数 |
|---|---|---|
| 1 | **标识不含时间戳** | 标识匹配 `^[0-9a-f]{12}-[0-9a-f]{16}$`；`构建指纹算法` 文本里 0 处时间输入；制品目录里 0 个「产出时间」字段 |
| 2 | **标识不含绝对路径** | 同上正则里 0 个 `/`；清单里 0 个以 `/` 开头的路径 |
| 3 | **同一份源同一标识** | 重跑构建 ⇒ 目录已存在 ⇒ **拒绝重建**（读数：覆盖 0 次）；改任一输入文件 ⇒ 标识必变 |
| 4 | **制品不可变** | `构建制品.py --检查 <标识>` 读数：指纹不符 **0** · 清单外文件 **0** · 缺件 **0**（三项都是 0 才算过） |
| 5 | **制品可装载** | 启动入口在制品目录内起得来，且 `GET /接口` = **200** |
| 6 | **零第三方依赖** | 制品内文件清单里 0 个来自仓库外的包（构建期 `--offline`） |

`--检查` 就是判据 4 的实现（不是第二个判据）：它只重算指纹、只数三项，不做别的判断。

## 二 上线切换 = 三件事，各有命令

**流量入口是唯一的**：`127.0.0.1:<流量端口>`，`流量端口` 的唯一来源是
`契约声明/常量表.json` 的 `常量[名=接口端口]`（实现读它，**不写死数**；可用环境变量
`ZCODE_TRAFFIC_PORT` 覆盖，仅为测试）。**同一时刻只有一个实例能持有它** —— 这是「对外监听恰好 1 处」
在运行期的样子。

| 命令 | 做什么 | 流量 |
|---|---|---|
| `装载.sh <制品标识>` | 校验制品不可变 → 起实例（**临时端口**）→ `GET /接口` 健康检查 → 记进已装载 | **不动** |
| `切换.sh <制品标识>` | 停掉所有活着的实例 → 在**流量端口**上起目标 → 健康检查 → 原子改「当前」 | 指过去 |
| `回退.sh [<制品标识>] [--步=N]` | 同切换；不给参数就取「上一份」（＝回退账账首），给参数可指**任意一份已产出制品**，`--步=N` 取账里第 N 条 | 指回去 |

**命令表仍是三条**。另有两处**不是第四条命令**：

- **「停」是 `切换` 的「模式」**（`切换.sh --模式=停`）：停掉所有活着的实例、**让流量口空着**（不起目标）。
  它与 切换/回退 是**同一个底子**（停实例 + 处置流量口），只差「停完起不起目标」这一个模式
  ⇒ 由模式变量表达，不新增命令（老仓《设计哲学》第 8 条②「底子不同但格式一样 ⇒ 加模式变量」；
  依据 `决策记录/2026-09-27_待裁九项按老仓设计哲学裁决.md` 裁决 7）。`--模式=切换` 是默认值，可显式写。
- **「上一份」是一本有界账**（`回退账.json`），不是栈深 1（#81）。见下。

运行态（**不在源码树内**，`README.md` 第十节）：落在**运行数据根**（唯一解析器
`运行内核/运行数据根/`，Python 侧经 `开发工具/运行数据根.py`）的「临时件」类下
`<运行数据根>/临时件/上线切换/`；覆盖走唯一解析器的 `V1_RUN_DATA_ROOT`。里面只有指针与日志：

```text
当前.json           {制品标识, pid, 端口, 日志, 来源}     ← 流量指向（原子写）；模式=停 后**不存在**（流量口空着）
回退账.json         {账: [{制品标识, 来源}, …], 上限}    ← 有界账，账首 = 「上一份」（原子写）
已装载/<标识>.json  {制品标识, pid, 端口, 日志}
日志/<标识>-<端口>.log
```

**回退是一条命令**：`回退.sh` 不带参数 = 指回「上一份」（＝回退账**账首**）；带参数 = 指到那一份（不必先装载，
`回退.sh` 会自身起它）；`--步=N` = 指到账里第 N 条（`--步=2` 就是再往前一份）。

**「上一份」不是栈深 1，是一本有界账**（#81）。口径三条（账多长 · 谁清 · 清到什么程度）：

| 项 | 定死 |
|---|---|
| **账多长** | 封顶 `回退账上限` = **8**（`上线切换/常量.py`）。账要能回答「上一份是谁」，也要够「回退 N 步」的常用 N；**不许无限长** |
| **谁清** | 只由本命令在 **切换 / 回退 / 停 的成功路径**上改写（`指针.py::记账`）；**装载不动账**；超上限**自动丢最旧**；运行根被删 = 账清空（运行数据不入源码树） |
| **清到什么程度** | 只留最近 8 条**去重**的「曾在流量口服务过的制品标识」（+ 来源）；**不留已死 pid、不留日志** |

`记账` 的三条动作：**去重**（同一制品先摘掉再压入，不占两格）· **压首**（最新在前）· **封顶**（超 8 丢最旧）。
账首即「上一份」；`模式=停` 也记账（把刚停下的那个记进账首）⇒ 停完 `回退`（不给参数）就是把它叫回来。

### 判据（可机器数）

| # | 判据 | 怎么数 |
|---|---|---|
| 1 | **三条命令各一条** | `装载.sh` · `切换.sh` · `回退.sh` 三个文件；`上线切换.py` 里 4 个子命令（含只读的 `现状`） |
| 2 | **回退是一条命令** | 一条命令即改回流量（无第二、第三条命令要跑） |
| 3 | **回退到任意一份** | `回退.sh <任意已产出标识>` 成功；不在 `制品产物/` 里 ⇒ 非零退出并列出可回退的（可数） |
| 4 | **切换是原子的** | 「当前」指针走同目录临时件 + `os.replace`（一步换掉）；读到半个指针 = 0 次 |
| 5 | **健康检查不是看进程** | 判据是 `GET /接口` = 200；进程活着但答不了 ⇒ 不算起得来 |
| 6 | **切换后实例数恰好 1** | `现状` 读数：活着的实例 **1** 个 · 且它持有流量端口 |
| 7 | **流量端口唯一来源** | 实现里 0 处硬编码端口字面量（端口一律从 `常量表.json` 现读） |
| 8 | **装载不动流量** | 装载后 `当前` 指针逐字不变（读数：改 0 次） |
| 9 | **停是模式不是第四条命令** | 子命令仍是 **4** 个（装载 · 切换 · 回退 · 现状）；`停` 只作 `切换` 的 `--模式` **值**出现，命令表条目 **0 增** |
| 10 | **停 = 停下 + 流量口空着** | `切换 --模式=停` 后：活着的实例 **0** 个 · `当前.json` **不存在** · 对流量端口的连接**被拒**（`实例.py::端口空着` 为真） |
| 11 | **回退账有界且答得出「上一份」** | 账长 ≤ `回退账上限`（8）· 账首 = `现状` 打的「上一份」· `回退 --步=N` 取第 N 条；连写 12 条后账长仍 **8**（自证读数） |

## 三 `扩展装载/扩展根声明.json` 的形状

**扩展从哪里载入。** 只许有**根目录**与**怎么扫**两件事 —— 这是 README 第五节三条硬边界的第一条
（底座不认识任何扩展的名字、路径或特例分支）在数据上的样子。

```json
{
  "路径基准": "工作目录",
  "扫描": { "找什么": "GetPlatformInfo", "怎么扫": "…三步…" },
  "种类": [ { "种类": "支持库", "号段": "1xxx-6xxx", "目录": "扩展根目录/原子支持库",
              "可装载件": true, "产物形态": "…", "必备件": "…" }, … ],
  "判据": "…"
}
```

**只有 `可装载件 = true` 的种类进候选**（`可装载件` 必填、必须是布尔；缺键或非布尔一律 fail-closed
并指路，**不给默认值** —— 默认 true 把旁路放回来，默认 false 把支持库静默漏掉）。
模块（组装件）与技能（声明／工作流）都不编 cdylib、不 dlopen，故不进候选：底座按声明组装走唯一调用口。

**怎么扫**（三步，缺一步即「不是扩展」并报原因）：

1. 对每个 **`可装载件 = true`** 的 `种类[].目录` 的**每一个直接子目录**（按名字排序 —— 装载顺序即依赖序，不许随文件系统飘）；
2. 该子目录内**恰好一个**可装载库文件（按后缀找 `.dylib` / `.so` / `.dll`，**不按名字找**）；
3. 对它取符号 `GetPlatformInfo` 并调用，拿到静态常量指针 ⇒ 这就是该扩展的声明。

### 判据（可机器数）

| # | 判据 | 怎么数 |
|---|---|---|
| 1 | **0 个扩展名** | 扫 `种类[].目录/*/` 的目录名，逐个在本文件里搜 ⇒ 命中 **0** 处 |
| 2 | **怎么扫写明** | `扫描.找什么` 存在且 = `GetPlatformInfo` |
| 3 | **路径基准写明** | `路径基准` 存在（否则「目录」是相对谁不可判） |
| 4 | **目录可解析** | 每个 `种类[].目录` 相对工作目录可解析；不存在 ⇒ 跳过并打一行（不崩） |
| 5 | **缺了照跑** | 扫到 0 个扩展时启动入口仍起得来（判据见 §四） |
| 6 | **只有可装载件进候选** | 每个 `种类[]` 都有 `可装载件`（布尔）；装配侧 `扫扩展` 只遍历 `可装载件 = true` 的种类 ⇒ 模块／技能的目录**一个都不进**候选（读方 = `构建装配/上线切换/构建制品/扩展.py::可装载种类`） |
| 7 | **两侧同一条规则（无第二套实现）** | 装配侧与运行期**两侧都读 `可装载件`**，且都 fail-closed —— 见下「两侧分界」表。判据：把 `模块`／`技能` 的 `可装载件` 改成 `true` ⇒ 两侧**同时**去 dlopen 它们（技能无 `src` 当场编不动）⇒ 红；把 `可装载件` 整个删掉 ⇒ 两侧**同时**指路拒启 ⇒ 红 |

### 两侧分界（台账 #241 裁决 · 2026-09-27）

**同一条扫描规则**（「只对 `可装载件 = true` 的种类找可装载库」）在**两处实现**，这是台账 #241 点的缺口：
装配侧早已收窄，而运行期启动入口曾按 `种类[].目录` **全扫**。现在**两侧一致**，但「同一件事两处实现」
本身仍是缺陷面 —— 故把**分界写死在此**（本件是形状的唯一定义处），任一侧再改须同时改另一侧。

| | 装配侧（构建期） | 运行期（启动入口） |
|---|---|---|
| 落点 | `构建装配/上线切换/构建制品/扩展.py::可装载种类` | `对外接口面/调用接口面/examples/启动网关/装配.rs::跑` 第二步 |
| 读什么 | `种类[].可装载件`（布尔） | **同左**，逐字同一条规则 |
| 缺键 / 非布尔 | fail-closed 指路（`raise SystemExit`） | **同左**，fail-closed 指路（回 `Err`，不起监听） |
| 默认值 | **不给**（默认 true 把旁路放回来 · 默认 false 把支持库静默漏掉） | **同左** |
| 何时跑 | 出制品时（编 cdylib / 装 `扩展/`） | 起服务时（`dlopen` + 取接缝） |

**为什么两侧都要收窄、而不是只改一侧或只写文档**（二选一里选「① 把启动入口也收窄」）：

- **只写文档不改代码**被否决：台账 #241 记的实测是「现在**无观测差异**（模块／技能目录是空的）⇒ 潜伏：真放进去就错」。
  文档改不动那个潜伏 —— 一旦有人在 `技能封装库/` 放一个目录，运行期就会拿它去 `dlopen`，
  报出一个**只有运行期才看得见**的错（构建期不报），正是「同一份声明两处口径」。
- **只改装配侧**被否决：现状就是只改了装配侧，缺口正是这么来的。
- **两处实现合并成一处**不成立：一在 Python（构建期）、一在 Rust（运行期），**没有共同的可调用面**
  （共享就是加一条跨语言调用腿，违反 §五 唯一腿）。故采用「**两侧各一份实现 + 本表把分界钉死**」——
  这是本平台对「两侧同规则」的既有处置（同 `扫实现.py` §四.14：不能合并的复制，用**成对读数**兜底）。

**读数（台账 #241 的验证命令）**：`grep -n "可装载件" 对外接口面/调用接口面/examples/启动网关/装配.rs`
⇒ **8 处命中**（含 `let Some(可装载) = 类.取("可装载件")…` 那一处判据本体）· 退出码 **0**。
`grep -n "可装载件" 对外接口面/调用接口面/examples/启动网关/JSON读取.rs` ⇒ **1 处**（`值::布尔` 的口径注释）。

## 四 生产启动入口（那个缺件）

`对外接口面/调用接口面/examples/启动网关.rs`。一条链，四步，一步不少：

```text
读 扩展装载/扩展根声明.json
  → 扫扩展根 + 调接缝 GetPlatformInfo（dlopen + dlsym，零第三方依赖）
  → 递给 服务::绑定（声明根 = [底座, …装上的扩展]，顺序即依赖序）
  → 起监听（把实际端口打在 `监听 127.0.0.1:<端口>` 这一行上，上线切换靠它拿端口）
```

**三条硬边界在这里怎么成立**（README 第五节）：

1. **底座不认识任何扩展**：文件里 0 个扩展名、0 条特例分支 —— 扫到谁就是谁。
2. **改一个扩展不用动底座**：加一个扩展 = 往扩展根里放一个目录，本文件一行不改。
3. **扩展缺了底座照跑**：逐个**试装**（用同一个 `适配器::装载声明根`，不另写一套），
   装不进的剔除并报原因，最终用剩下的声明根起服务 —— **载入失败不是启动失败**。

### 部署事实注入（三处，各有其根）

启动入口有三个**部署事实**参数（`--声明根` · `--静态根` · `--工具根`），网关不替它们猜位置。
上线切换起实例时**三者不同根**，这是实测逼出来的口径，不是设计选择：

| 参数 | 上线切换给什么 | 为什么 |
|---|---|---|
| `--声明根` | `扩展根声明.json`（相对 **cwd**） | 制品内副本；`扩展/` 就在制品目录里 |
| `--静态根` | `<仓根>/前端呈现/网页应用` | §五 静态托管的根；静态件住在**仓根** |
| `--工具根` | `<仓根>` | §七 工具族的根（案例库 `测试验证/案例` · 扩展根声明 · 外部 CLI） |

**cwd 必须是制品目录**（不是仓根）：制品内 `扩展根声明.json` 的 `路径基准` 就是「工作目录」、

## 六 实测缺口与既有件矛盾（如实登记）

| # | 实测事实 | 后果 / 修法 |
|---|---|---|
| 1 | **`扩展装载/扩展根声明.json` 不是空的** —— 它已有内容（扩展根 · 热载入 · 种类 · 判据），缺的是「怎么扫」 | 本节点只**补**「扫描」与「路径基准」，不动原有键。任务书「三个节点是空的」与实测不符（只有 `上线切换/` 与 `制品产物/` 是空的） |
| 2 | **扩展根里没有可 `dlopen` 的件**：`扩展根目录/原子支持库/编译器支持库/Cargo.toml` 的 `[lib]` 没写 `crate-type` ⇒ 只出 rlib（`GetPlatformInfo` 在符号表里，但没有可装载的库文件） | 扫描读数：可装载库文件 **0** 个 ⇒ 该扩展被剔除，底座照跑。修法二选一：扩展仓加 `crate-type = ["cdylib"]`（不在本腿可动范围），或由**装配侧**再编一遍（本节点走的是这条：`cargo rustc -- --crate-type cdylib`） |

| 4 | **启动入口拿底座声明走的是 dev-dependency 边**：`v1_loader::底座声明()` 不在 `v1-gateway` 的 `[dependencies]` 里 | `对外接口面/调用接口面/Cargo.toml` 已如实登记这条破口（适配器没有再导出 `底座声明`）。修法在适配器，不在网关、不在本节点 |
| 5 | **中文端点必须百分号编码**：Python 标准库 `http.client` 按 ASCII 编请求行，`GET /接口` 当场 `UnicodeEncodeError` | 上线切换的健康检查用 `urllib.parse.quote("/接口")`；网关侧认百分号编码（`路由.rs`），两边口径一致 |

| 10 | **环境变量名必须 ASCII**：`export ZCODE_流量端口=…` 在 sh / zsh 下**不生效**（标识符只认 ASCII） | 故实现里的环境变量是 `ZCODE_TRAFFIC_PORT`（端口）与 `V1_RUN_DATA_ROOT`（运行数据根的覆盖口，唯一解析器的口）。这是「中文标识符」在本节点唯一让步的地方，理由与 通用纪律 同一条 |
