# 系统工程平台 V1

**一句话**：一份声明说清全部能力，一个内核兜住全部跨边界，一个适配器适配所有语言，能力只负责实现。

本仓是重写，不是搬家。上一版作为参照物保留，不参与本仓构建，本仓也不引用它的任何代码与数据。

本文件即目录树的唯一事实源。**「现在是什么」不写在这里** —— 它由判据与库 `未完成` 表回答；
本文件只写「为什么这样设计」。写死状态必漂。

**命名规则**：目录名一律 4 字及以上，语义自足，不用简称。

---

## 一 定位

**这个平台首先是给 agent 用的，人类用的概率不大。** 由此推出两个角色，且这两个角色是本仓一切设计的出发点：

| 角色 | 是谁 | 要什么 | 判据 |
|---|---|---|---|
| **使用角色** | 调用能力的 agent / 程序 / 界面 | **极简**：一个入口、一次调用、一次返回 | 第一次用不需要读文档就能调对 |
| **维护角色** | 写声明与实现的 agent | **轻量**：改完一条命令、秒级知道对错 | 全量验证的墙钟时间是秒级 |

平台自身不做业务判断。它只保证三件事：**找得到**（编号唯一寻址）、**传得对**（跨边界不串味）、**坏了看得见**（失败可编程判定 + 有痕迹）。

## 二 两个角色

### 使用角色

一次调用的完整形状，只有三件事：**报编号 · 按契约行序填值 · 拿结构化结果**。

- **不握手、不注册、不连接管理**。入口只有一个，无状态，不存在"先连上再调"。
- **不需要 SDK**。绑定由契约生成；哪怕不生成绑定，任何语言直接按边界说话也能调。
- **读与调同一条路**。想知道有什么、怎么调、返回什么，走的是同一个入口，不是另一套文档或另一套接口。
- **失败是结构化码**，不是异常、不是一段文字。一次返回里必须同时回答三件事：成功没成功、拿到什么、失败为什么。

判据：**第一次用不需要读文档就能调对**。做不到就是使用面设计错误。

### 维护角色

改完代码或新增一个能力，只需要**一条命令**：

```text
验证 → 通过数 / 失败数 / 逐条明细（哪一条 · 缺什么 · 为什么不能自愈）
```

- **秒级是默认事实，不是目标**。默认档只做**声明层比对**（读声明 + 扫实现的公开符号 + 比对结构），不编译、不启动、不跑用例。
- **两档**：`静态验证` 秒级无实测；`实测验证` 在静态之上加超小型实测，慢一档，按需才跑。
- **一次全量**。不是"选几个模块跑跑"，是全仓一次过。**没有"选模块跑"这一档**。
- **分钟级即缺陷**。全量验证跑到分钟级，那是纯粹的代码 bug，按 bug 修：修法是**并发**——多线程读、多进程解析、按能力/按文件/按类型分片后归并。不是放宽判据，也不是"再等等"。

判据：**默认档墙钟秒级。出现分钟级，先当 bug 查并发，不许改判据。**

### 两个角色的接缝

维护角色改完声明，使用角色**不需要任何改动**就能看到新能力——因为使用角色读的就是同一份契约。

判据：**新增一个能力，使用角色零改动即可调到它。** 如果需要改客户端、发版本、重新注册，说明契约不是唯一事实源。

## 三 设计前提（硬约束，改架构前先读这一节）

这九条是本仓的宪法。任何设计与此冲突，改设计不改宪法。

1. **一个唯一入口**。装载、调用、卸载都只有一条路。不存在"另一条也能跑"的旁路。
2. **一份静态契约清单**。宿主读一次就掌握全部可装载性，不需要试调、不需要扫描、不需要运行时发现。
3. **跨边界只走一个定长数据槽，类型标签在槽内**。位置错位、类型不符，当场可判，不允许静默通过。
4. **所有权单向**。入参归调用方，返回值所有权交出；谁分配谁释放，跨边界只认一个分配器。
5. **双向通知通道**。下行有通知号派发，上行有能力主动取系统值，两个方向都是号段制。
6. **接口按号取用，未命中返回空**。新版本调旧内核、旧调用方调新内核，都不得崩，只许降级。
7. **号段分层且只增不复用**。删除的能力编号作废不回收；已被占用的号，含义永不改写。
8. **同一套源码可裁剪出多种形态**。形态差异由装配决定，不由源码分叉决定。
9. **语言不是边界**。全平台只有一个边界，边界之上不区分语言（见第四节）。

由此推出三条**必须做对、上一版没做对**的事：

- **失败可编程处理**：错误是带段位的结构化码，不是"成/败 + 一段文字"。调用方能据此判断可重试、可自愈、需人工。
- **多实例安全**：状态显式持有并传递，不落进程级全局；两个实例互不污染。
- **跨边界可追溯**：每次调用留痕（谁 · 调什么 · 入参指纹 · 结果 · 耗时），且留痕本身不阻塞调用。

## 四 语言与实现（已裁决 2026-09-26）

**语言无所谓。一个适配器适配所有语言，就完事了。**

- **语言不构成架构决策**。架构只认边界，不认语言。前端可以是 Vue 或 PHP，宿主可以是 Python 或 Java，底层可以是 C 或 C++，都不改变架构。
- **只有一个适配器**。它读 `契约声明/`，对外给出一个稳定边界；任何语言接上这个边界即可调用。不做第二个适配器。
- **绑定由契约生成，禁手写**。手写绑定必然与契约漂移，漂移即缺陷。
- **实现语言按效率就地选，允许混用**。同一个平台里，不同能力可以分别用不同语言写，只要它们都只经边界说话。选型判据是效率，不是统一。

判据：**任一处出现「因为用了某种语言所以架构要这样」，即为违规。**

**表达规范**：库 `条款` 表 `文档路径` = `项目文档/哲学.md` 那一节（精炼第一 · 注释一句+索引 · md 权威分级 · 临时文档另类）。

### 底座与扩展：本仓只放底座

**本仓是底座，不含任何扩展实现。** 支持库、模块、技能这三样都是**额外开发的扩展**，平时维护底座**不需要维护它们**；契约定下来之后，按契约载入就行。

| 谁是 | 在哪 | 平时维护要不要碰 |
|---|---|---|
| **底座**（契约 · 内核 · 适配 · 接口面 · 构建验证 · 工具 · 文档） | **本仓** | 是 |
| **支持库**（原子能力，1xxx–6xxx） | 扩展根，各自成仓 | 否 |
| **模块**（组合流程，7xxx） | 扩展根，各自成仓 | 否 |
| **技能**（agent 用法包，8xxx） | 扩展根，各自成仓 | 否 |

底座与扩展的接缝只有一处：**`扩展装载/`**。它不含任何扩展代码，只规定「一个扩展要能被载入必须长成什么样」。扩展本体落在 `扩展根声明.json` 的 `种类[].扩展落点`（相对 `路径基准`）给出的落点里，**不在本树内**。

三条硬边界：

1. **底座不认识任何扩展**——底座里不许出现任何扩展的名字、路径或特例分支。
2. **改一个扩展不用动底座**——不需要改底座一行代码，也不需要重发底座。
3. **扩展缺了底座照跑**——载入失败只是该能力不可用（未命中返回空），不是启动失败。

**新增一个能力的最小动作**：在扩展仓里按 `扩展装载/开发标准/` 写声明与实现 → 本地自检（秒级）→ 放进扩展根 → 底座按契约载入。**底座侧零改动。**

## 六 分层与依赖方向

单向，自下而上，**不许跳层、不许反向**；`运行内核/` 内部各 crate 之间按**同一层**读（同层互依不算违规，见库 `条款` 表 `文档路径` = `项目文档/决策记录/2026-09-27_判据口径十一条.md` §一）。两条链共用底部：

```text
内容链：  契约声明/  ← 运行内核/  ←〔 扩展根：支持库 · 模块 · 技能 〕   ← 底座边界到此为止
边界链：  契约声明/  ← 运行内核/  ← 跨语言适配/  ← 对外接口面/  ← 前端呈现/
接缝：    扩展装载/  （只规定扩展长什么样，不含扩展本体）
横切：    构建装配/  （只读契约、只收扩展，不参与运行）
```

| 层 | 可以依赖 | 明确禁止 |
|---|---|---|
| `契约声明/` | 无 | 依赖任何实现。**例外**：容器格式的实现（`契约声明/src/契约声明/容器封装/容器.rs`）住这里 —— 底座与扩展都要用它，而扩展只许依赖 `契约声明/`（见该件文件头）；JSON 源仍禁含可执行代码 |
| `运行内核/` | `契约声明/` | 依赖任何扩展；知道任何具体能力名 |
| `扩展装载/` | `契约声明/` `运行内核/` | 含扩展本体；为某个扩展开特例分支 |
| `跨语言适配/` | `契约声明/` `运行内核/` | 依赖 `对外接口面/`；手写绑定；为某种语言开专用通道 |
| `对外接口面/` | `契约声明/` `跨语言适配/` | 绕过适配器直连扩展实现；在面里写业务判断 |
| `前端呈现/` | `契约声明/` `对外接口面/` | 直接依赖某个扩展实现 |
| `构建装配/` | `契约声明/` `扩展装载/` | 参与运行；**只许写生成物**（`契约声明/src/*数据.rs`，由 `形态装配/生成声明.py` 出），不许写 JSON 源 |
| 〔扩展根：支持库 · 模块 · 技能〕 | `契约声明/`（只读） | 依赖底座内部任何节点；反向要求底座为它改代码。**已登记豁免**（唯一出口，不另开口子）：`扩展根目录/原子支持库/编译器支持库/{工具,语料}/` 下的**开发期工具件**可 `import 构建装配/门禁`（共用叶 · 非运行期依赖）—— 豁免面住 `构建装配/一键验证/一键验证/基础定义/常量.py::层序文件豁免`、判据读它（`判据_拓扑.py`），裁决全文住库 `规则` 表 `层序-9`。除这一条边外的反向 / 跳层仍判红 |

**扩展只读契约、只经边界说话**：模块只保存能力编号与契约版本、经唯一调用器调用，不 import 实现也不 import 提供者。这是「组合不产生分叉」的唯一保证。

判据：**任一层出现向上 import，即为架构违规**，不是风格问题。

## 七 编号与号段

编号即对外契约。**只增不复用**：能力删了，号作废，永不回收；号一旦公布，含义永不改写。

### 能力编号

```text
0xxx   底座自有（内核内部，不对外）              ← 底座
1xxx   核心支持库 · 语言自身的能力               ← 扩展，可热载入（编号保留，三方不许进）
       （编译器 · 语言运行核心 · 数组/文本/流程/数学/日期）
2xxx   三方封装 · 系统与环境                     ← 扩展，可热载入（按域分段，以下同）
3xxx   三方封装 · 文件与目录
4xxx   三方封装 · 文本与编码
5xxx   三方封装 · 数据与存储
6xxx   三方封装 · 界面与呈现
7xxx   模块 · 组合流程                           ← 扩展，可热载入
8xxx   技能 · agent 用法包                       ← 扩展，可热载入
9xxx   接口面 · 构建与验证（工具类）              ← 底座
```

### 核心支持库 与 三方封装：两个轴，各管一段

| | 核心支持库（`1xxx`） | 三方封装（`2xxx–6xxx`） |
|---|---|---|
| 是什么 | **语言自身的能力**——它定义「这个语言能做什么」 | **对外部东西的封装**——外部世界的适配器 |
| 分段轴 | 按**来源**（就它一类） | 按**域**（系统/文件/文本/数据/界面） |
| 编号 | **保留**，三方永远不许进 | 开放分配 |
| **缺了会怎样** | **语言不完整**（必须随底座一起发布） | **那个能力不可用**（底座照跑，未命中返回空） |
| 怎么判归属 | 只依赖语言自身（类型 · 槽 · 编号） | 依赖**外部**（某个 DLL / 某个服务 / 某种文件格式） |

**两者都算「扩展」**：物理上都可热载入、都住扩展根，底座**不认识**其中任何一个的名字——这保住了「底座不认识任何扩展」。分界只落在**号段保留 + 发布纪律**上，不落进底座代码（否则底座就要认识核心支持库的名字）。

**号段即层级，也即归属**：拿到号就知道它是底座还是扩展、是三类扩展里的哪一类、该放哪个仓、能不能组合别人。

**1xxx–8xxx 全部是可热载入的扩展**：装载与卸载都不需要重启底座，也不影响已在跑的其他扩展。底座只有 0xxx 与 9xxx。

### 错误码

```text
<段位 1 位><序 3 位>         例：2043 = 段位 2 的第 43 号错误
段位                          = 码的首位十进制数字（0–9）
0 = 内核自有 · 1–6 = 支持库 · 7 = 模块 · 8 = 技能 · 9 = 接口面与构建验证
```

**`段位` 与 `码` 是两个东西，不要混**：`码` 是完整的 4 位号（`错误码表/<码>.json` 的文件名），`段位` 只是它的首位（也即能力号段的首位——号段即归属）。
每个错误码在 `契约声明/错误码表/` 登记**三项业务判断**：`可重试` · `可自愈` · `需人工`（这三项验证面猜不出来，必须人给）。另有**一项冗余登记**：`段位`（可从 `码` 导出，故意写出来让验证面交叉比对抓错）。

**这三项必须到得了运行期**：`平台信息` 里有 `错误码表`，调用方拿到 `码` 之后能查到它们——只写进注释就等于没写。**未登记的错误码不许抛出**。

### 通知号

```text
**唯一事实源 = `契约声明/号段图.json` 的 `通知号段`**（本节不复述号与区间）：三个方向 ——
下行（宿主 → 扩展）· 上行（扩展 → 宿主取系统值）· 生命周期（装载 · 卸载 · 退出 · 延迟释放）。
```

## 八 冻结项与旁路

**主结构冻结，演进只走旁路。** 冻结的不是实现，是别人已经依赖的形状。

**冻结项清单只有一处**：`契约声明/冻结登记.json`。本文件**不复述它**——复述必漂移。要查有什么冻结了，去读那份。

**`落点` 的形状**（定死，别靠猜）：**单个**落点，两种写法之一——
- `相对路径`（指向整份文件）
- `相对路径::符号名`（指向文件里的某个类型 / 函数 / 常量）

**不许复合**（不许写成 `首件.md · 次目录`）：复合落点让「这个冻结项在哪」变得不可判定，判据只能靠拆分隔符，而文件名里一旦出现同一个分隔符就误判。

允许的演进方式，**只有这三种**：

1. 新增号段（不动旧号）
2. 新增段类型号（不动旧段）
3. 新增旁路字段（不动旧字段含义）

每次冻结或旁路，在 `契约声明/冻结登记.json` 记一行：**冻的是什么 · 为什么冻 · 旁路走哪 · 日期**。没有登记的形状变化，视为违规。

## 十 本树明确不含什么
