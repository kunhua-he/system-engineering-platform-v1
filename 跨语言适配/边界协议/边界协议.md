# 边界协议（冻结）

上级：系统工程平台 V1 ／ 落点：`跨语言适配/边界协议/边界协议.md`
相关：`README.md` 第八节（冻结项）· `全局连接器与网关.md`（拓扑）· `多语言兼容实现.md`（槽与类型标签）· `能力包件.md`（编译产物）
· `项目文档/决策记录/2026-09-27_接缝结构不复刻.md`（**接缝不复刻参照实现**的裁决；§二 ★ 那一节的理由与实测全在里面）· `项目文档/设计文档/接缝实测.md`（字节级实测）

**本文是冻结件。** 冻结的是**跨边界的对外形状**：符号名 · 参数形状 · 所有权 · 错误通道。一旦公布，只许新增旁路字段与新增符号，**不许改旧符号语义**。

**★ 先读这一句**：本协议定的是**我方自有**的接缝与对外边界。接缝符号名 `GetPlatformInfo` 与它返回的结构**都是我方的**，
与参照实现（易语言 `.fne` 的 `GetNewInf`）**无兼容承诺** —— **不复刻**它的结构（理由与实测见 §二 ★）。
「兼容易语言支持库」这个说法在接缝这一层**不成立**。

---

## 一 先分清两个方向（这一条不定清，「唯一 C ABI 边界」永远说不清）

| 方向 | 谁导出 | 数 | 是什么 |
|---|---|---|---|
| **扩展 → 宿主**（向内） | 每个扩展各导出 `GetPlatformInfo` | **我方纪律：每个扩展恰好 1 个**（见 §二 ★） | **接缝**。底座读扩展的声明靠它 |
| **宿主 → 外面**（向外） | **全局连接器**（`跨语言适配/适配器实现/`） | **全平台恰好 1 组** | **对外边界**。任何语言、任何上层都只经它 |

两者形状完全不同，**不许混成一套**：接缝只有「读声明」一件事；对外面有「读接口 / 调用 / 释放」三件事。

---

## 二 接缝形状（扩展 → 宿主）

```c
const 平台信息* GetPlatformInfo(void);   // 符号名 ASCII：外部协议边界，别的语言要按名字绑
```

- **返回静态常量指针**，终生有效；调用方**不得释放、不得修改**。
- **我方纪律：每个扩展恰好一个导出**。多个就是两条接缝。**这不是「参照实现如此」**（见下面 ★）。
- 这是**唯一**允许扩展导出的符号；扩展要提供别的能力，一律走命令表（`平台信息.命令表` + `函数表`），**不许再导出第二个符号**。

### ★ 不复刻参照实现（必读，别把它误读成「兼容易语言支持库」）

**我方接缝不复刻参照实现（`GetNewInf`）的结构。符号名 `GetPlatformInfo` 是我方自有名，与参照实现无兼容承诺。**

依据：`项目文档/决策记录/2026-09-27_接缝结构不复刻.md`（裁决）· `项目文档/设计文档/接缝实测.md`（字节级实测）。三条事实：

1. **符号名**：参照实现的导出名是 `GetNewInf`（实测全树 **93** 个 `.fne`，**93/93** 命中）；我方 `GetPlatformInfo` **语料 0 命中，是编的**。
2. **返回结构不是 1:1**：字段**顺序**不同（它的 `m_nCategoryCount` / `m_szzCategory` 插在类型表与命令表之间）· 字段**集合**不同
   （它有语言 / 作者八串 / 类别表 / AddIn / SuperTemplate；我方有四个号段与错误码表）· 连版本字段**宽度**都不同（它 3×`i32`，我方 4×`u16`）。
3. **「每个扩展恰好 1 个导出」是我方纪律，不是对参照实现的描述**：实测参照实现 **15/93** 个 `.fne` 导出多于 1 个
   （`e2ee` **993** 个 · `krnln` **307** 个 · `iDraw` **227** 个）。**纪律保留**（我方确实只出一个口），但**不许再写成「参照实现如此」**。

**为什么不复刻**（按「稳固 · 简单 · 不漂移 · 可读 · 不两条腿」）：
① 1:1 复刻会把本项目的**号段体系**（能力号段 / 通知号段 / 错误段位表 / 资源号段）挤掉 ——「号段即层级」是宪法之一；
② 1:1 复刻会引入一批**没有消费者的字段**（作者八串 / AddIn / SuperTemplate）—— 那正是准入判据要禁的**死键**；
③「能装真 `.fne`」**不是本项目目标**（我方扩展是 Rust `cdylib`，不是 `.fne`）。

**这个符号名从此冻结**：谁要改，必须先答「改了之后**已发布的 N 份外部库**怎么办」。

## 三 对外边界形状（宿主 → 外面）

```c
// 读：有哪些能力、某条能力怎么调（agent 只看这三样，见 能力包件.md）
const char* 平台_取接口描述(uint32_t* 长度);      // UTF-8 JSON；长度由出参带回
// 调：按号 + 按契约行序填值
int32_t     平台_调用(uint32_t 号, uint32_t 参数个数, const 数据槽* 参数表, 数据槽* 返回槽);
// 还：把调用方拿到的值的所有权交回
void        平台_释放值(数据槽* 值);
```

| 项 | 规定 | 为什么 |
|---|---|---|
| **符号名** | **ASCII**，前缀 `平台_` | 它是外部协议边界，别的语言按名字绑（`代码形态分工.md` 第三节例外之一） |
| **参数形状** | 只走**定长数据槽**（类型标签在槽内） | 宪法第 3 条。槽自描述 ⇒ 换载体（进程内 / IPC / 网络 / WASM）不用改形状 |
| **不许 by value 传结构体** | 一律指针 + 个数 | 结构体布局随编译器变；这是跨语言最经典的坑 |
| **字符串 / 字节集** | **必须带长度**（出参带回），不许只给 `char*` | 冻结项：参照内核的文本不带长度，是跨语言兼容最经典的缺陷来源，**不复刻** |
| **返回值** | `int32_t` 只表达**协议层**结果（成功 / 参数不合法）；**业务失败走返回槽里的结构化错误码** | 失败是可编程处理的数据，不许塞进返回码 |
| **错误通道** | **结构化错误码**（4 位：段位 × 1000 + 序号），随包带回三项业务判断 | 宪法「失败可编程处理」。**不许跨边界抛异常**、**不许用 errno 一类隐式通道**（隐式通道在多线程下必然串味） |
| **所有权** | **谁分配谁释放**；返回值的所有权单向交给调用方，调用方用 `平台_释放值` 还 | 宪法第 4 条。跨边界分配器 = `运行内核/内存分配器`，**全平台只有一个** |
| **状态** | 边界**无状态**。要状态就用句柄（`运行内核/实例状态`），句柄是值不是指针 | 宪法「多实例安全」。边界带状态就无法重启、无法多实例 |
| **线程** | 边界函数**可重入**；同一句柄的并发调用由内核的账本与配额管，不靠边界加锁 | 边界加锁会把整个平台串成一条线 |

## 四 判据（可机器数）

| # | 判据 | 怎么数 |
|---|---|---|
| 1 | **宿主侧导出符号恰好 1 组**（三个：`平台_取接口描述` · `平台_调用` · `平台_释放值`） | 搜导出属性，**排除 `GetPlatformInfo`**（那是接缝） |
| 2 | **我方纪律：每个扩展恰好 1 个导出**（`GetPlatformInfo`）—— 纪律是我方自定，**不是参照实现的实测**（它 15/93 多于 1 个，见 §二 ★） | 每个扩展目录数一遍 |
| 3 | **边界里 0 处业务判断** | 搜 `if 号 ==` 一类特例分支 |
| 4 | **边界里 0 处状态** | 搜模块级可变全局 |
| 5 | **不许出现第二个 `extern "C"` 导出面** | 搜导出属性，按方向归类后各恰好一组 |

## 五 明确不做

| 不做 | 为什么 |
|---|---|
| 不做按语言分口（Python 专用口 / JS 专用口） | 一个适配器适配所有语言（宪法第 9 条）；专用口就是第二套实现 |
| 不做按版本分口（`平台_调用_v2`） | 版本靠契约与错误码表达，不靠符号名分裂 |
| 不做 C++ 名字修饰的导出 | 修饰名随编译器变，绑不上 |
| 不跨边界抛异常 | 异常要两侧运行时一致，而「一个适配器适配所有语言」的前提正是**不假设对端运行时** |
| 不传结构体 by value | 布局随编译器变 |
| 不用隐式错误通道（errno / 全局 last_error） | 多线程下必然串味；且违反「失败可编程处理」 |
| 不让边界带状态 | 带状态就无法重启、无法多实例 |
| 不给扩展开第二个导出符号 | 接缝只有一个符号；能力一律走命令表 |
