# 开发规范

上级：系统工程平台 V1 ／ 落点：`项目文档/开发规范/开发规范.md`

**一句话**：一个循环，一条命令，一次全量。改完就跑，秒级知道对错。

---

## 一 开发循环

```text
① 登记占用（路径级互斥，谁改谁占）
        ↓
② 声明先行：先在 声明编写面 上写/改能力声明
        ↓
③ 写实现（只经边界说话，不直连别的能力）
        ↓
④ 跑 一键验证 · 静态档（秒级）
        ↓
   ┌── 红 ──→ 看明细（哪一条 · 缺什么 · 为什么不能自愈）
   │              ↓
   │          改那一处，回到 ④
   │
   └── 绿 ──→ ⑤ 跑 一键验证 · 实测档（按需；改动涉及行为时）
                  ↓
              ⑥ 提交（只用精确路径）
                  ↓
              ⑦ 释放占用
```

**循环的终点是绿，不是"改完了"。** 没跑验证就提交，等于没开发完。

## 二 规范条款（每条都可判定）

### A 声明与实现的关系

| # | 条款 | 判据 | 违反的表现 |
|---|---|---|---|
| A1 | **声明先行** | 实现里出现的每个能力编号，必须先在声明里存在 | 先写实现再补声明；实现里有声明查不到的编号 |
| A2 | **声明只走面写** | `契约声明/` 的写入只有声明编写面一条路 | 直接改声明文件 |
| A3 | **类型必须来自类型声明表** | 参数表每一行的类型都能在 `契约声明/类型声明/` 里查到 | 实现里冒出一个自造类型 |
| A4 | **错误段位必须先登记** | 抛出的每个段位都在 `契约声明/错误码表/` 里，且登记了可重试/可自愈/需人工 | 运行期冒出未登记段位 |
| A5 | **编号只增不复用** | 删除的号进作废表，永不回收 | 复用了旧号，或改了已公布号的含义 |
| A6 | **参数行序是冻结项** | 已公布的参数行序不许重排、不许插入 | 为了新参数把旧参数往后挪 |

### B 代码与依赖

| # | 条款 | 判据 | 违反的表现 |
|---|---|---|---|
| B1 | **一次改动只动一个节点** | 一次提交的改动面落在一个节点内 | 一次提交横跨三层 |
| B2 | **只许向下依赖** | 任一层出现向上 import 即违规 | 能力实现 import 接口面 |
| B3 | **同层不许互依** | `能力实现/` 内部各能力之间不互相调用 | 一个能力直接调另一个能力的函数 |
| B4 | **绑定禁手写** | `跨语言适配/语言绑定/` 全部是生成物 | 手改绑定文件 |
| B5 | **不为某种语言开专用通道** | 任何语言都只经同一个边界 | 给某语言加一条捷径入口 |
| B6 | **状态显式持有** | 状态是句柄，不落进程级全局 | 模块级可变全局变量 |
| B7 | **留痕不进关键路径** | 留痕缺席时调用照样成功，留痕存在时调用不变慢 | 写日志失败导致调用失败 |

### C 验证与提交

| # | 条款 | 判据 | 违反的表现 |
|---|---|---|---|
| C1 | **改完必跑默认档** | 每次改动后跑一次静态验证 | 凭"看着对"提交 |
| C2 | **秒级是默认事实** | 默认档墙钟秒级 | 分钟级 —— 按 bug 修并发，不许改判据 |
| C3 | **一次全量** | 全仓一次过，没有"选模块跑"这一档 | 只跑改动的模块 |
| C4 | **失败必须说清原因** | 每条失败给出：哪一条 · 缺什么 · 为什么不能自愈 | 只报红不给原因 |
| C5 | **提交只用精确路径** | 显式列路径 | 通配提交、整目录提交 |
| C6 | **冻结项改动要登记旁路** | `契约声明/冻结登记.json` 有对应行 | 悄悄改冻结形状 |

## 三 冻结与旁路：改动怎么演进

**主结构冻结，演进只走旁路。** 允许的演进方式只有三种：新增号段、新增段类型号、新增旁路字段。**不许改旧字段含义、不许复用旧号。**

改动前先问一句：**我动的是形状还是实现？**

- 动实现 → 随便改，验证会兜住。
- 动形状 → 必须先登记旁路，再改。没登记的形状变化一律视为违规，哪怕它"只是加了一个字段"。

### ★ 什么时候必须先冻结形状，什么时候必须先写实现

「接口先冻结，再派活」不是无条件成立的。**判据是有几个实现者**：

| 情况 | 顺序 | 为什么 |
|---|---|---|
| **只有一个实现者** | **先写实现，让实现撞出形状，再回头把形状冻上** | 冻结时没实现过，几乎必然漏——本项目九处冻结缺口全是这么漏的（详见 `内核落点.md` 第五节） |
| **有多个实现者，或跨进程/跨语言** | **先冻结形状，再派活** | 两个实现者各写一套再对齐，代价是两套都要改 |

**但「先写实现」不等于不冻结**：实现写完那一轮，必须**同一轮内**把形状冻上并登记（`契约声明/冻结登记.json`）。否则「先实现」就退化成「没有形状」。

**冻结形状前先问四句**（这四句是从九处缺口里提炼的）：

1. 谁调它？
2. 调的时候手里有什么？
3. 它在生命周期的哪个时点被调？
4. **它的参数里有没有「其实是两个东西共用同一个名字」？** —— 本项目在 `能力号段`（布局 vs 占用）· `号段`（能力 vs 通知）· `段位`（域 vs 整个码）· `错误`（占位 vs 已废止）四处都栽在这一句上。**同名不同义是冻结面最常见的缺陷形态。**

## 四 验证红了的处置顺序

```text
红
├─ 是不是"实现与声明不一致"？ → 改实现（或回声明面改声明），不要改判据
├─ 是不是"生成物过期"？       → 重跑生成器，不要手改生成物
├─ 是不是"旁路没登记"？       → 去登记，不要删检查
└─ 是不是"验证本身慢/错"？    → 先确认是 bug，再修验证面；不许为了绿而放宽判据
```

**唯一禁止的动作是"改判据让它变绿"。** 判据是资产，红了是判据在干活。

|---|---|

| 装配与验证 | `构建装配/` |
| 测试 | `测试验证/` |

**放不进去就说明树缺节点**——先补树并说明理由，不许随便塞一个目录。

## 六 文件怎么拆（主文件是路由）

**判据一句话**：**改一处的时候，不需要把整个文件读进来。**

### 硬数（可机器数，不是感觉）

| 规则 | 数 | 为什么是这个数 |
|---|---|---|
| **单个源文件** | **≤ 400 行**（含注释与空行；Rust 与 Python 同一条） | 400 行 ≈ 一万二千 token，是「改一处时能被整体读进来」的上限。超过它，agent 就得**先定位再读**，而定位错了就是改错文件 |
| **入口文件**（`lib.rs` / `__init__.py` / 具名模块） | **≤ 120 行**，且**只做三件事**：声明子模块 · 再导出公开面 · **零实现** | 入口是「路由」，不是「实现」。路由里有实现，就等于每个读入口的人都被迫读一遍实现 |
| **拆出来的文件** | 一个关注点一个文件，放**同名字文件夹**里（入口 `X.py` ⇒ `X/`；Rust 侧 `X.rs` ⇒ `X/`）；**新起**的文件夹名 4 字以上 | 与 `README.md` 第五节「目录名 4 字以上」同一条规矩 |

**两条要求冲突时以「同名」为先**（2026-09-27 裁，实测撞车）：入口名本身不足 4 字时（`扫实现.py` · `语言面.rs`），
**按同名走**，不许为了凑字数改成 `扫实现模块/` 之类。理由：「同名」是**结构规则**——拆分的形就靠它
（入口 `X.py` + 包 `X/`，`from X import …` 逐字不变）；「≥4 字」是**给新起的名字**的要求，不是用来破坏同名的。
仓内先例已有 8 个不足 4 字的同名字文件夹：`语言面/` · `容器/` · `记录流/` · `词法/` · `语法/` · `语义/` · `诊断/` · `扫实现/`。

### 主文件是路由（这一条是哲学，不是风格）

```text
运行内核/装载入口/
├─ src/
│   ├─ lib.rs          ← 路由：mod 声明 + pub use 再导出。零实现。
│   ├─ 判定.rs         ← 一类：可装载性判定六步
│   ├─ 载入.rs         ← 一类：载入与台账
│   ├─ 声明校验.rs     ← 一类：号段 / 标签 / 段位校验
│   └─ 底座声明.rs     ← 一类：底座自己的静态声明
```

**为什么「主文件是路由」值得当成哲学固定下来**：

1. **公开面与实现分开**：别人只需要知道「从哪拿」，不需要知道「里面怎么摆」。入口只有路由时，「从哪拿」一眼看完。
2. **拆的时候公开面不动**：`pub use` 再导出让 `调用地址` 逐字不变 ⇒ 拆分**不需要改任何调用方**。本平台历史上做过一次同形的拆分（`平台适配.py` → 同名包 + `__init__` 纯再导出，1613 行，约 90 处导入地址一字未改），先例成立。
3. **改一处只读一个文件**：这是判据本身。

### 拆的时候的硬要求

1. **先冻行为基线**：`__all__` 顺序 · 函数签名 · 常量取值 · 若干行为探针。拆分**不许**改行为。
2. **公开面逐字不变**：导入地址、符号名、参数顺序一律不动。
3. **不许在拆分时顺手改逻辑**：拆分是纯搬家。要改逻辑另开一次改动——两件事混在一起，红了分不清是谁的。
4. **不许为拆而拆**：本来就小的文件不动。拆分的理由是「读起来太大」，不是「看起来不够细」。
5. **不许拆出循环依赖**：拆完要过 `开发规范.md` B2（只许向下依赖）与 B3（同层不许互依）。
6. **拆之前先跑一遍判据**：有的判据是**按文件**解析的 —— 把同一条判据要的两样东西拆到两件里，判据会**当场红**。
   实测（2026-09-27）：`测试验证/契约一致性/扫实现.py` 的 ③f 在**同一份文件**里解析「错误码号」与「错误码登记表」；
   把两者拆开 ⇒ 逐条报「错误码信息 表里没有它」。**先拆、再跑判据、按判据把该同处的合回去**，
   比拆完再看红去猜快得多。
7. **同名脚本与同名包可以并存**：`X.py` + `X/`（Rust 侧 `X.rs` + `X/`）—— **脚本是路由、包是实现**。这是上面「入口只做三件事」在同名情形下的落地形态。先例：`声明编写面.py` + `声明编写面/` · `语言面.rs` + `语言面/` · `容器.rs` + `容器/`。**不许**为了「不重名」把入口改叫别的名字——那会改动导入地址，违反第 2 条。

## 七 提交纪律

1. 提交前先跑默认档验证，绿了才提交。
2. 提交只用精确路径，禁用通配。
3. 一次提交一件事，提交信息说清"改了什么节点、为什么"。
4. 架构级改动必须同时更新 `项目文档/决策记录/` 与 `契约声明/冻结登记.json`，否则视为未完成。
5. 生成物与源码分两次提交，生成物在后（源码先落地，生成物跟着刷新）。

## 八 测量与引用纪律（协调方与各腿同守）

来源：前三条曾是 `未完成事项.md` 里的条目，但**教训不是「未完成的活」**（那本台账只记未完成）
⇒ 规则搬到这里，条目销掉。每条都带一次真实撞车。

1. **读数一律带退出码。** 只 grep `test result: ok` 的行数会把一次崩溃读成全绿 —— SIGSEGV
   既不匹配 `ok` 也不匹配 `error`（实测撞车）。判据只给红绿 + 末行时，每个红都要人复现定性。
2. **「现状」与「机理」都要自己先量再写。** 派活信与报告里的现状不许凭印象：实测撞过两次 ——
   写「判据面已经在读某常量」而全仓无任何读方；写「刚派了某条腿」而当时并没有派。量不出就不写。
3. **选工具前先判编码 / 格式，别拿一个顺手的方法代替测量。** 实测撞车：拿 GBK 扫 UTF-16LE
   文本 ⇒ 读出 7,423 个「噪声」，其实 74% 字节就是文字；只数 `TPF0` 出现 0 次就断言「拿不到
   界面」，而界面就在资源 4 菜单 / 5 对话框 / 6 字符串表里。
4. **源码注释里不出现台账号，也不出现「哪条腿 / 哪一轮」。** 注释要回答的是「**为什么这么写**」
   —— 把原因直接写清楚就完事。台账号只说明「这活是从哪条账上派下来的」，它**回答不了读者的
   问题**；而台账的规则是「做完即删」⇒ 号按设计会消失（实测 2026-09-27：全仓 158 处「台账 #N」
   里 **123 处的号已经不在册**，等于在指一个不存在的东西）。要指落点就引 `决策记录/… §节名`
   或源码符号（`路径::符号名`）。**注释的读者不该被要求去 git 历史里翻一条已销的台账。**
5. **带反引号 / `$` 的文本一律走文件，不走 `-m` 或 `echo`。** 实测撞车：`git commit -m "…\`路径\`…"` 里
   的反引号被 zsh 当**命令替换**执行 ⇒ 提交信息里那一处路径**整个消失**，而 `git commit` 照样成功
   （只在 stderr 留一行 `no such file or directory`）⇒ **不细看读不出错**。凡提交信息 · 派活信 ·
   含反引号或 `$` 的正文，先写进文件再 `git commit -F <文件>`；heredoc 定界符必须带引号（`<<'EOF'`）。
6. **★ 收口方每解完一处冲突、每合完一条腿，立刻跑一次门禁。** 理由：**收口方自己是回退的主要来源**——
   实测 2026-09-27：解 `行数基线.json` 的合并冲突时留下两个空对象 `{}`，`一键验证.py` 当场崩
   `KeyError: '路径'`。腿的红是「已知的、被记下来的」，而收口方手抖引入的红**没有任何人记**。
   ⇒ 「短期红可接受」说的是**腿的**红（有报告、有归因）；**收口动作本身必须当场验**。
   共享文件（基线 · 登记表）被两条腿各删一条时，正确解法是**两边的删除都要**（原基线 减去 现已不超限的件），
   不许挑一边——挑一边会把另一条腿的成果静默回退。

## 九 md 治理（一份事实一个落点）

来源：md 曾经是「哪儿都写一点」—— 实测 72 个文件 · 13213 行，同一件事在 N 处各写一份，改一处别处就漂。
漂过的实例（都是实测）：`README.md` 第十一节手抄 `决策记录/` 的裁决表，而表里列的两条早已在台账销掉 ·
`说明/语言面形状.md` 写「错误码表 26 条」而实测 35 件 · `并行工作树.sh` 文件头写「构建锁是十几路在抢的真因」
而设计文档实测把它推翻了（锁真在，代价 0.04 秒）。**单看一处都没问题，摆成一个项目就扛不住** ——
上下文装不下，冲突装不下。

1. **三类职责，不许越界。**
   - **规范 / 形状**（可判定的规则与形状）：`README.md` 的设计前提节与结构节 · 本件 · `契约声明/格式说明.md` · 各 `形状.md` · `设计哲学.md` · `判据的可信性.md` · `边界协议.md`。
   - **裁决**：`项目文档/决策记录/`（一次一条，含理由与实测）。
   - **取证 / 实测**：`*实测.md` · `*覆盖.md` · `*证据缺口.md` —— 它们是**读数**，不是规则。
2. **一份事实一个落点。** 同一件事不许在两处各写一份；要指过去就按符号（`路径 §节名` 或 `路径::符号名`）。
   尤其：**裁决与未定项不许在 `README.md` 复述**（`ls 项目文档/决策记录/` 就是索引）·
   **交付纪律不许在 `README.md` 复述**（落点是本件）。
3. **不许有「关于文档自身历史」的元评论。** 「本项此前写…是过期说法」「已更正为」「上一版作废」这类句子
   **只许出现在 `决策记录/`**（记录一次裁决的变更，那是它的职责）。别处**直接写现状**；要追溯去 `git log`。
   理由：留痕把每份 md 变成变更日志 —— 读者要读两遍才知道现状，而两句话还都躺在文件里，那就是数据污染。

   **★ 例外（实测撞出来的）：不许把「实测证据」与「反向样本」当成更正痕删掉。** 两者的分界是
   **指向谁** —— 说「**本文件 / 本项**此前写 X」= 文档自己的变更日志 ⇒ 删；说「**我们 / 系统**试过 X，
   实测不成立 / 量错了」= 证据与反向样本 ⇒ **留**（`判据的可信性.md` 第五节要求判据成对，设计文档同理：
   一条结论旁边那句「不这么量会得出反结论」正是它可信的理由）。实测：第一轮清理把
