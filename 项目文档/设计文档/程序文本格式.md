# 程序文本格式（原生格式裁定）

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/程序文本格式.md`
相关：`语言面证据缺口.md`（原先的死结）· `字段名册与引用方式.md`（名字与号）· `资源网关口.md`（`.e` 那一侧）· `容器格式实测.md`

**本文是一条裁定**：**编译器的原生格式是「程序文本」，不是 `.e`。**

---

## 一 裁定

| | 是什么 | 判据 |
|---|---|---|
| **原生格式**（`.程序文本`） | **通用可读文本**：UTF-8 · 行式 · 人手可写可改 · agent 可写可改 · 任何系统都能读 | **我们自身的往返**：文本 → 结构 → 文本，逐字节相同 |
| **导入导出格式**（`.e` / `.ec`） | 参照实现的容器。**互操作用**：把现成程序导进来，把我们的程序导出去 | **逐字节相同**（容器层已过 1444/1444） |

**为什么原生格式不选 `.e`**：

1. **它的本质是给人看的。** 参照实现的容器**不是没有承载源文本的能力**，但**没有一份源码文本是参照 IDE 直接渲染输出的**（见 `语言面证据缺口.md` 第一节；逐条复核在 `说明/真文本覆盖.md §六.1`）—— 源码文本平时只在参照 IDE 的内存里、由结构渲染出来。我们要的东西正好相反：**把那份文本存下来当一等格式**。
2. **agent 编辑的时候用户要能看到。** 二进制容器做不到——用户看到的是乱码，只能靠工具。
3. **用户要能手动编辑。** 同上，二进制做不到。
4. **跨系统兼容。** UTF-8 行式文本是所有系统的最大公约数；容器格式每加一种，就要多一个解析器。
5. **它把死结解开了。** 原生格式由我们自身定义 ⇒ 「文本 → 结构 → 文本」的基准是我们自身 ⇒ **不需要拿参照实现当黑盒 oracle**。原先「语言面链不可验」那条证据缺口，随这一裁定消失。

**`.e` 不是被否掉，是被放回它该在的位置**：它是一条**互操作通道**（导入已有程序 / 导出给别人），不是我们的存储格式。

---

## 二 格式规格

规格里的每一条**都有语料实测出处**（`语言面证据缺口.md` 第六节；个别由裁决纳入，见下）：

| 项 | 规定 |
|---|---|
| 编码 | **UTF-8**（参照实现用 GBK，我们不用；导入 `.e` 时边界处转一次）。关键字身份按**区间文本**比对 ⇒ GBK 原文认不出关键字、整行落兜底（读数见 `扩展根目录/原子支持库/编译器支持库/src/语法/测试/真形状其余.rs::GBK原文_关键字认不出_落到兜底但仍建出合法树`） |
| 换行 | 写出恒 `\n`（LF）；读入**同时认** `\r\n` 与 `\n` |
| 缩进 | **4 个半角空格**，缩进层级 = 块嵌套深度 |
| 关键字 | 以 `.` 开头（`.版本` `.子程序` `.参数` `.局部变量` `.如果真` `.判断` `.计次循环首` …），少数不带点（`返回` `置入代码`） |
| 注释 | `'` 至行尾，**不含行尾换行**（CRLF 的 `\r` 归行尾，随注释之后由 `换行` 记号认领） |
| 文本字面量 | 写出用全角 `“…”`；读入**同时认**半角 `"…"` |
| 常量引用 | `#名字` |
| 数值字面量 | **十进制整数**（可带负号）、可选小数；**十六进制 `0x`/`0X` 前缀**（后跟至少一位十六进制数字）。小数语料 4 例（全在备注位）；十六进制语料 0 例 ⇒ 由裁决纳入（`决策记录/2026-09-28_华哥的尺子与七条裁决.md` §二） |
| 备注文本 | **不是**关键字/标识符/字面量，而是规格没点名的那些字节（`记号种类::备注文本`，第 12 种）。判据 = 一段「标识符字符 ∪ 未点名字节」的极大连续段里**含至少一个未点名字节**（裁决 `决策记录/2026-09-28_华哥的尺子与七条裁决.md` §二） |
| 运算符 | **全角**：`＝` `＋` `÷`（语料代码位实测）；另有 `－` `＞` |
| 界符 | **半角**：`( ) [ ] , . & { }` |
| 空实参 | 逗号之间可以什么都没有（`(首参, , 次参)`）。**空位是有意义的位次** |
| 运算符（文档级、语料代码位未见） | `×` `％` `＼` `＜` `＞` `≤` `≥` `≠` `≈` 与逻辑 `且` `或` —— **证据等级 = 文档**；**已接入词法**：9 个符号进 `src/词法/字符集.rs::是否运算符`，逻辑 `且`/`或` 另列 `是否逻辑运算符` 且**只在独立成词时**成运算符。出处 `help/esdn.chm → zlsc/lang.htm`，见 `真文本覆盖.md` §九.2 |

### 名字与号的分离（本格式的核心机制）

> **文本里写名字；结构里存号。**

- 文本是给人（与 agent）看的 ⇒ 写名字（`计数`、`信息框`、`#版本号`）。
- 结构是给机器与跨边界用的 ⇒ 存号（变量序号、能力号、常量号）。
- 编译器负责在两者之间解析。**解析规则必须写死**，否则同一个名字会歧义：

| 类 | 解析成 | 遮蔽顺序 |
|---|---|---|
| 变量 | `(作用域, 序号)` | **局部 > 程序集 > 全局**（取最近的，且诊断里要报出取了哪一个） |
| 常量 | 常量号 | 程序内唯一 |
| 资源 | 资源号 | 程序内唯一 |
| 能力（命令） | 能力号 | 平台侧号段，与程序侧无关 |
| 子程序 | `(程序集, 序)` | 程序集内唯一 |

**不许靠名字消歧。** 同名不同物一律按号区分——这条已在 `字段名册与引用方式.md` 立过。

## 三 扩展名（我定的）

**`.程序文本`**（UTF-8 文本文件）。

理由，按判据排：

1. **自描述**：扩展名本身就说明「这是什么」——用户看到文件名就知道能用文本编辑器打开，不需要查文档。这直接服务于「用户要能手动编辑」。
2. **与全仓一致**：本项目目录名与标识符一律中文（`代码形态分工.md` 第一节），扩展名跟着同一条规则走，不另立一套英文缩写。
3. **不会撞车**：`.txt` 太泛（一堆工具会抢着关联它），`.json` 会诱导人把它当数据去写括号，英文缩写（`.sx` `.sep`）又回到「要查文档才知道」。
4. **它是文本**，所以 `git diff` 看得见、`grep` 搜得到、任何语言一行读得进来——这就是「所有系统的兼容格式」。

**工具链例外**：若某个环节（某语言的工具链、某个打包器）不接受非 ASCII 扩展名，按本项目既有规矩——**登记成一条工具链强制的例外**（`代码形态分工.md` 第三节已有四条同类），不许为此改回英文扩展名。

### ★ 只有一个后缀、一个存储格式

**不许再搞第二个存储格式**（例如「可读版 + 紧凑二进制版」）——**两种存储格式就是第二条腿**（同一件事两种形态，`代码形态分工.md` 第五节硬判据 1）。一旦有两个格式，就得回答「谁是源、谁是派生」「两者怎么同步」「同步漏了谁报红」，这三问的答案就是两条腿。

**所以：可读文本既是原生格式，也是交换格式。** 它同时满足「用户能看到能手动编辑」与「所有系统都读得进来」两条诉求——不需要为后者另造一个紧凑格式。将来若真出现「文本太大、读得太慢」的实测问题，那是**同一个格式的编码优化**（例如加一层可选压缩），**不是第二个格式**。

## 四 对已有工作的影响

**没有白做，只是两条路各归各位**：`容器.rs` 往返 1444/1444 与「段数据 ⇄ 记录流」归**互操作路**（`.e` ⇄ 结构）；`语言面.rs` 与编译器能力 `1101–1107` 归**原生文本路**（文本 ⇄ 结构），只有声明的输入类型文字要从「参照实现的源文本」改成「我们的程序文本」。

## 五 明确不做

| 不做 | 为什么 |
|---|---|
| 不用 `.e` 当原生存储 | 它是二进制、要专用工具才能看（源码文本只装在个别段里，且不是参照 IDE 的直接输出）⇒ 与「用户要能看到、要能手动编辑」直接冲突 |
| 不用 GBK | 跨系统兼容的最大公约数是 UTF-8；编码转换只在导入边界做一次 |
| 不用 JSON 当程序文本 | JSON 是**数据**的好形态（`代码形态分工.md` 已定），但程序文本要人手写，满屏括号与引号会把可读性毁掉 |
| 不把缩进做成「有意义但不可见」 | 缩进在**文本层**表达块嵌套（人看得见）；在**结构层**块嵌套由节点表达。两层都要能独立还原，不许只靠一层 |
| 不做「导出时逐字节还原参照实现的文本」 | 那是拿黑盒当基准（已由本裁定否掉）。导出 `.e` 的判据是**容器逐字节一致**，不是文本逐字节一致 |
| 不许文本里出现号 | 号是结构层的事。文本里写号 = 人看不懂、agent 改不动 ⇒ 违背本格式的存在理由 |
