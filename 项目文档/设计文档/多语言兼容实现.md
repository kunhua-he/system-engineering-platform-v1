# 多语言兼容实现

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/多语言兼容实现.md`
相关：`README.md` 第四节（语言与实现）· `语言选型对照.md`（语言层落点）· `现代架构落点.md`（边界四种载体）

**核心一句话**：**语言之间不互相理解，只共同理解一个定长数据槽。**

不给每种语言写一套接口——那会变成 N 份契约互相漂移。做法是：契约是数据，槽是唯一的交换形状，绑定由契约生成。

---

## 一 三个机制

### 机制 1：槽（唯一的交换形状）

跨边界只走一个**定长数据槽**，**类型标签在槽内**（宪法第 3 条）。

```text
槽 = { 类型标签 · 长度 · 值或值的引用 · 所有权标记 }
```

**每种语言只需要会两件事**：把值放进槽、把槽读出来。语言不需要理解对方的类型系统，因为类型标签是槽自身带的，不是靠位置约定的。

这是"多语言兼容"能成立的唯一原因。若参数靠位置传、类型只写在契约文档里，那么任何一方读错位都会静默通过——语言越多，错位组合越多。

### 机制 2：契约 → 绑定的生成

**一个生成器**读契约，**每语言一个模板**（只管语法形态）⇒ 产物落 `跨语言适配/语言绑定/<语言>/`，**是生成物、禁手写**（开发规范 B4）；指纹写回、验证时比对（`验证流程图.md` ③d/④）。

### 机制 3：类型映射表（数据，不是代码）

契约里的类型 → 每种语言的具体类型，是一张**表**，不是散落在各处的 `if 语言 == ...`。

| 契约类型标签 | Rust | C / C++ | Go | Python | Java / C# | TypeScript |
|---|---|---|---|---|---|---|
| 空 | `()` | `void` | — | `None` | `void` | `void` |
| 逻辑 | `bool` | `int32` | `bool` | `bool` | `bool` | `boolean` |
| 整数 | `i64` | `int64_t` | `int64` | `int` | `long` | `bigint`（或 `number`） |
| 双精度 | `f64` | `double` | `float64` | `float` | `double` | `number` |
| 文本 | `&str` / `String` | `char*` + 长度 | `string` | `str` | `String` | `string` |
| 字节集 | `&[u8]` | `uint8_t*` + 长度 | `[]byte` | `bytes` | `byte[]` | `Uint8Array` |
| 列表 | `Vec<T>` | 元素数组 + 个数 | `[]T` | `list` | `List<T>` | `T[]` |
| 句柄 | 不透明句柄类型 | 不透明指针 | 不透明结构 | 不透明对象 | 不透明类 | 不透明包装 |
| 错误段位 | `u32` | `uint32_t` | `uint32` | `int` | `int` | `number` |

**文本与字节集必须带长度**：不带长度的 `char*` 是历史上跨语言兼容最经典的缺陷来源。

## 二 四件事必须逐字一致（跨语言验收判据）

同一份契约、同一个能力，用 N 种语言调用，下面四件事必须**逐字一致**：

| 项 | 一致的含义 |
|---|---|
| **错误段位** | 同一个失败，所有语言拿到同一个数字 |
| **参数行序** | 所有语言的绑定按同一顺序对位 |
| **返回形状** | 成功时槽的形状相同（含类型标签） |
| **所有权归属** | 入参归调用方、返回值所有权交出，所有语言的绑定落实同一条规则 |

**判据**：把 N 种语言的调用结果并排打印，去掉语言特有的包装后必须完全相同。不一致即缺陷——它意味着某一种语言的绑定在替调用方做额外翻译，而翻译就是漂移。

---

## 三 载体无关

边界四种载体（进程内 ABI · 本机 IPC · 网络 · WASM 组件，见 `现代架构落点.md` §三）**读同一份契约，产出同一套号段与错误码**：调用方在任一载体拿到的错误段位必须一模一样 —— 否则"错误可编程"就只在一个载体里成立，等于没做。

---

## 四 新增一种语言的成本

| 要做 | 不用做 |
|---|---|
| 写一个模板（语法形态） | 不动内核 |
| 加一张类型映射表 | 不动任何能力实现 |
| 跑一次绑定生成 | 不动其他语言的绑定 |
| 跑一次验证，确认四件事逐字一致 | 不改契约 |

**判据**：新增一种语言，改动面必须全部落在 `跨语言适配/语言绑定/` 之内。改动溢出到别处，说明边界没落干净。

---

## 五 明确不做

| 不做 | 为什么 |
|---|---|
| 每语言一套语义 | 语义只有一套，语言只是语法外壳 |
| 语言特化捷径入口 | 违反宪法第 9 条；捷径必然与主路漂移 |
| 手写绑定 | 手写必然与契约漂移（开发规范 B4） |
| 靠位置传参 | 位置错位静默通过，是"底层不适配"的根因 |
| 不带长度的文本/字节集 | 跨语言兼容最经典的缺陷来源 |
| 让调用方自身管理跨边界内存 | 所有权规则必须由边界统一，不能让每种语言各定一套 |
| 为"性能"让某语言绕过槽 | 绕过一次，那个语言就永久脱离契约 |

---

## 六 待实测

1. **绑定生成链三条**：Rust ↔ Python、Rust ↔ Java、Rust ↔ TypeScript，验证生成的绑定可读、可编译、四件事逐字一致。
2. **四种载体的错误码一致性**：同一份契约在进程内与跨进程（或跨网络）下，错误段位是否逐字一致。
3. **所有权规则在托管语言里的落实**：Java/C#/Python 侧谁负责释放返回值，需定死一条并写进生成的绑定。
4. **槽的定长口径**：值多大算"定长"、超过阈值走引用时引用如何跨载体表达，需定数。
