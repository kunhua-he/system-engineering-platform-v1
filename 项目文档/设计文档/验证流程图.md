# 验证流程图

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/验证流程图.md`
相关：`两个角色与接口面.md`（角色与命令形状）· `开发规范.md`（改完必跑）

**节点即组件**：下面每个节点都对应一个将来真实存在的路径；节点之间标了父子归属与数据流向。**没有"选模块跑"这一档，没有"分钟级"这一档。**

## 一 流程图

```text
入口：构建装配/一键验证/一键验证.py :: 验证(档位 = 静态 | 实测)
│
├─ ① 读声明                                并行：多线程（IO 密集）
│   ├─ 契约声明/平台声明.json              格式号 · 版本三元组 · 标识串 · 四张总表指针
│   ├─ 契约声明/能力声明/**                逐能力：编号 · 参数表 · 返回表 · 错误段位
│   ├─ 契约声明/类型声明/**                类型标签表
│   ├─ 契约声明/错误码表/**                码 → 段位 · 可重试 · 可自愈 · 需人工
│   ├─ 契约声明/通知号段/**                下行通知号 · 上行取值号
│   └─ 契约声明/冻结登记.json              冻结项清单 + 旁路登记 + 作废号表
│
├─ ② 扫实现                                并行：多进程（CPU 密集，纯静态解析，不编译）
│   ├─ 能力实现/**                        公开符号 + 声明块（编号 · 参数行序 · 类型标签 · 错误段位）
│   ├─ 跨语言适配/适配器实现/**            边界入口形状
│   └─ 跨语言适配/语言绑定/**              生成物指纹
│
├─ ③ 比对                                  并行：按分片；纯集合运算
│   ├─ ③a 声明 ↔ 实现                      一个能力一行，双向都要有
│   │   ├─ 编号：声明有实现有 · 实现有的声明也有
│   │   ├─ 参数行序：逐位一致
│   │   ├─ 类型标签：逐位一致，且都来自类型声明表
│   │   └─ 错误段位：都在错误码表里且已登记四项
│   ├─ ③b 声明 ↔ 声明
│   │   ├─ 编号不重复
│   │   ├─ 编号不在作废号表里（宪法第 7 条）
│   │   └─ 编号落在声明所属号段内
│   ├─ ③c 声明 ↔ 冻结登记
│   │   ├─ 已冻结形状未被改动（调用形状 · 契约主结构 · 声明面写入形状 · 边界形状 · 容器主结构）
│   │   └─ 形状变化都有旁路登记行
│   ├─ ③d 生成物 ↔ 契约指纹
│   │   └─ 语言绑定是否过期（过期即重生成，见 ④）
│   └─ ③e 分层依赖
│       └─ 有无向上 import · 同层互依 · 绕过适配器直连实现
│
├─ ④ 自愈                                  串行，极短
│   ├─ 可自愈：绑定过期 → 重生成；索引/摘要过期 → 重算；指纹缺失 → 补算
│   └─ 不可自愈：逐条产出「哪一条 · 缺什么 · 为什么不能自动补上」
│
├─ ⑤ 输出
│   ├─ 通过数 / 失败数
│   └─ 逐条明细（不可自愈项必须带"缺什么"）
│
└─ ⑥ 实测（仅档位=实测时执行）              并行：多进程，按用例清单全量跑，每个都超小
    ├─ 按 契约声明/能力声明 的清单逐个跑超小型实测
    ├─ 逐条比对：错误段位 · 返回形状 · 所有权归属
    └─ 并入 ⑤ 的输出
```

**失败回路**：任一分片红了只重跑该分片，**不许触发全量重跑**。全量重跑是最常见的"分钟级"来源。

## 二 并发要求（这是秒级的实现手段）

| 阶段 | 性质 | 手段 | 分片键 |
|---|---|---|---|
| ① 读声明 | IO 密集 | 多线程 | 按文件 |
| ② 扫实现 | CPU 密集 | 多进程 | 按文件/按能力 |
| ③ 比对 | 纯计算 | 多进程 | 按能力（③a）、按规则（③b–③e） |
| ④ 自愈 | IO | 串行（极短，量小） | — |
| ⑤ 输出 | 汇总 | 串行 | — |
| ⑥ 实测 | 混合 | 多进程 | 按用例 |

**硬约束**

1. **分片之间不许有共享状态**（对应宪法"多实例安全"）。
2. **不许串行复跑**：一处失败只重跑该分片。
3. **不许在阶段之间做全量物化再投影**：先构造全量再裁剪，等于把并行收益吃回去。
4. **读文件必须给上限**：静默截断会让解析腿拿到半个文件，是"红了但看不出为什么"的常见真因。

## 三 秒级判据

```text
默认档墙钟 ≤ 秒级     → 正常
默认档墙钟 到分钟级   → 缺陷（bug），不是档位
```

**处置顺序**：先查并发度 → 再查串行点 → 再查有没有全量重跑 → 最后才查单点算法。**不许改判据、不许"再等等"。**

历史教训（可复用）：上一版慢的真因不是磁盘慢，是**全仓串行扫描 + 并发下缓存失效**——所有分片在排队等同一段代码。把串行点去掉，吞吐提升一个数量级。所以"慢"通常不是机器的问题。

## 四 自愈边界（哪些能自己补、哪些必须人/agent 补）

| 现象 | 能自愈吗 | 谁补 |
|---|---|---|
| 语言绑定过期 | ✅ 重生成 | 验证面 |
| 索引 / 摘要 / 指纹过期 | ✅ 重算 | 验证面 |
| 实现缺某个声明的编号 | ❌ | 写实现 |
| 声明缺某个实现的编号 | ❌ | 走声明编写面补声明 |
| 参数行序不一致 | ❌ | 改实现（或走旁路登记后改声明） |
| 类型不在类型声明表里 | ❌ | 走声明编写面补类型 |
| 错误段位未登记 | ❌ | 走声明编写面补段位登记 |
| 编号重复 / 复用了作废号 | ❌ | 换号（走声明编写面） |
| 向上 import | ❌ | 改依赖方向 |
| 冻结形状被动过且无旁路登记 | ❌ | 补登记或还原 |

**判据**：能自愈的当场自愈并报告；不能自愈的必须回答"缺什么"——只报红等于把定位成本推给维护者。
