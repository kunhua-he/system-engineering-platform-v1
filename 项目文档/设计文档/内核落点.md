## 一 语言定案：Rust

语言无所谓——但「稳定到不会漂移」不是无所谓的。按这个要求筛，只剩 Rust：

| 你的要求 | Rust 为什么满足 |
|---|---|
| **0 漂移** | 无隐式数值转换；跨边界必须写 `extern "C"`；结构布局必须写 `#[repr(C)]`；整数宽度必须写死 `u32`/`u64`。**实现与契约不一致就编译不过**，漂移进不了制品 |
| **语言自身不漂** | edition 三年一次且**是可选开关**，老代码不升就不受影响 |
| **一个静态编译快速检测** | `cargo check` 只做类型检查不做代码生成，秒级；`cargo clippy` 再加一层规则 |
| **不会带伤继续** | `Result` 无法被忽略；无 GC ⇒ 无不可预测停顿，单项超时才有意义 |
| **跨边界 ABI 可控** | `#[repr(C)]` + `extern "C"` 给出确定的函数表与结构布局 |

**不选 Go**：带 GC 与运行时，边界内停顿不可预测（见 `语言选型对照.md`）。
**不选 C/C++**：隐式转换与拷贝语义是漂移温床，正是要避免的那件事。

**已实测工具链**：`rustc 1.95.0 (59807616c 2026-04-14)` · `cargo 1.95.0` · arm64 · 32 核。

### 宽度策略：以 64 位为主，32 位可做——最大兼容靠「把宽度声明出来」

不是不做 32 位。**最大兼容不是靠少做，是靠把差异声明出来。**

**三条设计规则**（让同一套源码能出 32 位与 64 位两种构建，且宿主能分辨）：

1. **跨边界结构里不出现 `usize` / `isize`**。这两个类型随目标变宽，是最隐蔽的漂移源。一律用显式 `u32` / `u64`。
2. **数据槽的形状与字宽无关**：`类型标签 u32 · 标志 u16 · 保留 u16 · 长度 u64 · 值 u64`——固定 64 位值域。32 位构建下指针放进 `值` 时高 32 位为 0，64 位构建下满宽。**槽的形状在两种构建下逐字节一致**，所以跨语言绑定只需一套。
3. **唯一随目标变宽的是「表指针」**（`表段<T>` 里的项表指针）。所以声明里必须有 **`目标字宽`** 字段，宿主据此知道对面是 32 位还是 64 位构建、表指针该按几字节读。

由此得到的兼容性：

| 维度 | 怎么做 |
|---|---|
| **跨语言** | 槽的形状与字宽无关 ⇒ 一套绑定通吃；表指针只在同进程内使用，不进槽 |
| **跨平台** | arm64 / x86-64 / 32 位都可构建；差异只在 `目标字宽` 一个字段里 |
| **跨版本** | 未命中返回空（宪法第 6 条）；新旧扩展与新旧底座互不崩 |

**并发按本机能力设计**：本机 32 核，验证与构建按「32 路并行」设计分片粒度，而不是按"保守一点"设计再回头优化。**慢就是 bug**（README 第二节）。

## 二 环境：钉死，不用机器上碰巧装的那份

Rust 没有 Python venv 那种运行时隔离。等价物是三件，比 venv 更硬：

| 件 | 落点 | 作用 |
|---|---|---|
| **钉工具链** | `rust-toolchain.toml`（仓库根） | 写死 `channel = "1.95.0"`。机器上装别的版本也没用，rustup 按这个文件选 |
| **零第三方依赖** | `Cargo.toml` 内核 crate 只依赖 `std` | 仓库外没有任何东西能改变行为——这是最强的「虚拟环境」 |
| **锁 + 离线** | `Cargo.lock` 提交 · `.cargo/config.toml` 设 `offline = true` | 构建期不联网，依赖不可能被替换 |

**判据（环境自检一次问三件事）**：

```text
① 当前 rustc 版本 == rust-toolchain.toml 里钉的版本
② Cargo.lock 里除本仓成员外无任何第三方包
③ cargo check --workspace --locked 通过（离线）
```

三条全过 = 环境稳定。任一条不过 = 不许开工。

## 三 0 漂移的四道闸

漂移在本项目有三个含义（实现与契约漂移、语言自身漂移、代码行为漂移），四道闸分别挡住它们：

| 闸 | 在哪 | 挡住什么 | 什么时候响 |
|---|---|---|---|
| **1 编译期** | `cargo check` | 类型不符 · 宽度不符 · 布局未声明 · 失败未处理 | 每次保存/构建 |
| **2 静态验证** | `构建装配/一键验证/` 默认档 | 声明 ↔ 实现不一致（编号 · 参数行序 · 类型标签 · 错误段位）· 号段冲突 · 冻结项被动 · 生成物过期 | 每次改完 |
| **3 冻结登记** | `契约声明/冻结登记.json` | 形状被悄悄改动 | 改形状时 |
| **4 生成物指纹** | `跨语言适配/语言绑定/` · `构建装配/制品产物/` | 生成物与契约脱节 | 每次验证 |

**四道闸的关系**：闸 1 管「写得对不对」，闸 2 管「跟声明对不对」，闸 3 管「改得许不许」，闸 4 管「派生物新不新」。**四道全过才算改完。**

## 四 1:1 复刻内核：映射表

复刻的是**契约形状与语义**，不是 32 位字节布局。唯一允许的差异是**宽度按目标平台定**（64 位），且这一条必须登记为旁路。

| 参照内核要素 | V1 内核节点 | 复刻口径 | 状态 |
|---|---|---|---|
| 唯一入口返回契约主结构指针 | `运行内核/装载入口/` | 一个导出函数返回 `*const 平台信息`；宿主读一次掌握全部可装载性 | 冻结 |
| 契约主结构（格式号 · 标识串 · 版本 · 要求版本 · 四张表 · 通知 · 依赖） | `契约声明/平台声明.json` → `平台信息` | 字段与含义 1:1；**格式号是常量，不是版本号** | 冻结 |
| 命令表（名称 · 类别 · 状态位 · 返回类型 · 参数个数 · 参数表指针） | `运行内核/统一注册表/` | 1:1 | 冻结 |
| 参数表（名称 · 类型标签 · 状态位 · 默认值） | `运行内核/统一注册表/` | 1:1；**参数行序即契约** | 冻结 |
| 数据类型表（名称 · 状态位 · 命令号表 · 事件表 · 属性表 · 元素表） | `运行内核/统一注册表/` | 1:1 | 冻结 |
| 常量表（名称 · 排布 · 类型 · 文本 · 数值） | `运行内核/统一注册表/` | 1:1；数值用双精度 | 冻结 |
| 调用形状：三参数、返回槽与参数槽分离、返回 void | `运行内核/定长数据槽/` | 1:1：`(返回槽, 参数个数, 参数表指针) -> ()` | 冻结 |
| 数据槽自带类型标签 | `运行内核/定长数据槽/` | 1:1：类型标签在槽内 | 冻结 |
| 下行通知（宿主 → 库） | `运行内核/通知通道/` | 号段 1–999 | 冻结 |
| 上行通知（库 → 宿主取值） | `运行内核/通知通道/` | 号段 1000–1999 | 冻结 |
| 生命周期通知（装载 · 卸载 · 退出 · 延迟释放） | `运行内核/通知通道/` | 号段 2000–2999 | 冻结 |
| 宿主提供内存分配，所有权单向 | `运行内核/内存分配器/` | 1:1：跨边界只认一个分配器 | 冻结 |
| 缺项占位（命令/常量/类型各有占位项） | `运行内核/统一注册表/` | 1:1：**载入失败用占位项保住编号不塌** | 冻结 |
| 状态位（隐含 · 错误 · 发布禁用 · 对象构造/释放） | `运行内核/统一注册表/` | 1:1 | 冻结 |
| 要求宿主版本 / 要求内核版本 | `契约声明/平台声明.json` | 1:1：不满足即拒绝载入 | 冻结 |
| 依赖文件清单 | `扩展装载/载入约定/` | 1:1：依赖缺失即拒绝载入或按声明降级 | 冻结 |
| 主结构冻结、演化走旁路 | `契约声明/冻结登记.json` | 1:1：新增号段 / 新增段类型号 / 新增旁路字段 | 冻结 |

**唯一允许的差异（须登记旁路）**：字段宽度按 64 位定；文本与字节集**必须带长度**（参照内核不带长度，是它的缺陷，不复刻）。

## 五 冻结的 Rust 接口（派活依据）

**命名**：内部标识符一律中文；**导出的 ABI 符号一律 ASCII**（外部协议边界，属规则允许的英文）。

```rust
// 契约声明层
#[repr(C)] pub struct 版本三元组 { pub 主: u16, pub 次: u16, pub 修订: u16, pub 构建: u16 }

#[repr(C)] pub struct 表段<T> { pub 项数: u32, pub 项表: *const T }

#[repr(C)] pub struct 平台信息 {
    pub 声明格式号: u32,              // 常量，非版本号
    pub 标识串: *const u8,            // 32 位十六进制 + NUL
    pub 实现版本: 版本三元组,
    pub 要求宿主版本: 版本三元组,
    pub 要求内核版本: 版本三元组,
    pub 名称: *const u8,
    pub 说明: *const u8,
    pub 状态位: u32,
    pub 类型表: 表段<数据类型信息>,
    pub 命令表: 表段<命令信息>,
    pub 函数表: *const 执行函数,
    pub 常量表: 表段<常量信息>,
    pub 通知函数: Option<通知函数>,
    pub 依赖清单: 表段<*const u8>,
}

#[repr(C)] pub struct 命令信息 {
    pub 名称: *const u8, pub 说明: *const u8,
    pub 类别: u16, pub 状态位: u16,
    pub 返回类型: u32,               // 类型标签
    pub 用户级别: u16,
    pub 参数个数: u32, pub 参数表: *const 参数信息,
}

#[repr(C)] pub struct 参数信息 {
    pub 名称: *const u8, pub 说明: *const u8,
    pub 类型标签: u32, pub 状态位: u16, pub 默认值: 数据槽,
}

#[repr(C)] pub struct 数据类型信息 {
    pub 名称: *const u8, pub 说明: *const u8, pub 状态位: u32,
    pub 命令个数: u32, pub 命令号表: *const u32,
    pub 事件个数: u32, pub 事件表: *const 事件信息,
    pub 属性个数: u32, pub 属性表: *const 属性信息,
    pub 元素个数: u32, pub 元素表: *const 元素信息,
}

#[repr(C)] pub struct 常量信息 {
    pub 名称: *const u8, pub 说明: *const u8,
    pub 排布: u16, pub 类型标签: u32,
    pub 文本: *const u8, pub 数值: f64,
}

// 跨边界唯一定长槽（类型标签在槽内）
#[repr(C)] #[derive(Clone, Copy)]
pub struct 数据槽 {
    pub 类型标签: u32,
    pub 标志: u16,                   // 所有权 · 是否引用 · 是否空
    pub 保留: u16,
    pub 长度: u64,                   // 文本/字节集必带
    pub 值: u64,                     // 内联值 或 数据指针
}

// 调用形状：1:1
pub type 执行函数 = unsafe extern "C" fn(返回槽: *mut 数据槽, 参数个数: u32, 参数表: *const 数据槽);
pub type 通知函数 = unsafe extern "C" fn(通知号: u32, 参数一: usize, 参数二: usize) -> isize;

// 唯一入口（导出符号 ASCII）
#[export_name = "GetPlatformInfo"]
pub extern "C" fn 取平台信息() -> *const 平台信息;
```

**内部分层接口**：

```rust
pub fn 载入(声明: &'static 平台信息) -> Result<注册表, 载入错误>;   // 运行内核/装载入口
impl 注册表 {                                                        // 运行内核/统一注册表
    pub fn 按号取命令(&self, 号: u32) -> 命令槽;                      // 未命中返回占位项
    pub fn 按号取类型(&self, 号: u32) -> 类型槽;
    pub fn 按号取常量(&self, 号: u32) -> 常量槽;
    pub fn 占位项(&self, 号: u32) -> 命令槽;                          // 载入失败兜底
}
pub unsafe fn 调用(注册表: &注册表, 号: u32, 参数: &[数据槽], 返回槽: *mut 数据槽) -> 调用结果;
pub fn 派发通知(&self, 通知号: u32, 参数一: usize, 参数二: usize) -> isize;   // 运行内核/通知通道
```

**判据**：以上签名一旦冻结，任何模块实现都**不许改签名**；要改必须走冻结登记（README 第八节）。

### 冻结后被实现侧撞出的四处缺口（已登记为待办旁路）

冻结接口在真写实现时暴露了四处不足。**这不是实现写错，是我冻结时漏了**，逐条登记在 `契约声明/冻结登记.json` 的 `待办旁路` 里：

| 缺口 | 后果 | 修法（走新增旁路字段） |
|---|---|---|
| `平台信息` 缺号段字段 | 扩展**没法声明自己占哪段号**，编号只能按「表内下标」约定 ⇒ 扩展的 1xxx–8xxx 表达不出来 | 新增 `号段起` / `号段止` |
| `数据类型信息` 缺类型标签字段 | 标签只能用表内下标，而下标取决于合并顺序 ⇒ **跨版本不稳定**（参照实现正是为此才要占位项保索引） | 新增显式 `类型标签`——**这是对参照实现的改进，不是复刻** |
| `平台信息` 缺错误段位字段 | 「未登记的错误段位不许抛出」判不了 | 新增 `错误段位表` |
| `判定可装载` 缺已载入台账入参 | ②标识串唯一 ③号段冲突 ⑤依赖都在，三项**跨扩展判定全做不了**；而 `开发规范` B6 禁进程级全局，不能用全局台账顶 | 给判定加台账入参，或由装载器统一收口 |

**这四条必须在下一轮开工前收口**：前三条是「新增旁路字段」，第四条要动签名。**收口前不许发布任何扩展声明**——现在任何扩展的编号都表达不出来。

## 六 内核的施工顺序（接口先冻结，再派活）

```text
① 契约声明层（平台信息 / 命令信息 / 参数信息 / 数据类型信息 / 常量信息 / 数据槽）
      ↓ 冻结
② 运行内核/定长数据槽      —— 值的放入与读出、类型标签判定
③ 运行内核/统一注册表      —— 四张表 + 占位项 + 状态位
④ 运行内核/装载入口        —— 可装载性判定六步 + 载入
⑤ 运行内核/通知通道        —— 三个号段的派发与接收
⑥ 运行内核/内存分配器      —— 所有权单向
⑦ 运行内核/实例状态 · 调用调度 · 调用留痕
      ↓ 以上是内核本体
⑧ 构建装配/一键验证        —— 闸 2：声明 ↔ 实现比对（秒级）
⑨ 对外接口面/调用接口面    —— 使用角色的门
```

**①②必须先冻结再派活**：它们是所有模块共用的脊梁，改了全体返工。

## 七 待裁与待实测

1. **`声明格式号` 取什么值**：照参照内核取常量、还是另取。倾向照取（它就是"格式号"这个概念的身份证）。
2. **导出符号的 ASCII 名**：暂定 `GetPlatformInfo`；是否要保留一个参照内核同名符号做兼容，未裁。
3. **文本与字节集的长度口径**：字节长度还是字符数，未定。**已被实现侧撞到**：`定长数据槽` 的 `放入整数` 写 `长度 = 8`、`取出整数` 要求 `长度 == 8`，下游若自己用 `数据槽::内联(标签, 值, 0)` 造整数槽就会拿到 `长度不符` —— 口径必须尽快定死并写进本节。
6. **`内存分配器` 的 `&self` 改成了 `&mut self`**（记账需要可变状态；用 `RefCell`/`Mutex` 会引入 panic 路径）。代价是并发调用必须外部加锁。本机 32 核，**这条要复核**：热载入与并行验证都会并发分配，最终可能要分片分配器或无锁结构。
7. **生命周期段内子号未登记契约**：`通知通道` 自定义了 `装载/卸载/退出/延迟释放` = 2000/2001/2002/2003，而 `契约声明/通知号段/` 目前只有范围、没有段内子号。子号一旦裁定，需回填契约并改该节点常量（已集中在 `pub mod 生命周期通知` 一处）。
8. **`调用留痕.已丢弃` 的口径**：除「满而丢」外，容量 0 与认领超时也计入。口径必须写死，否则「丢痕是静默的」这条判据会失效。
9. **`内存分配器` 的 `单次分配上限` 落在本 crate**（`u32::MAX`，依据是 32 位构建下指针高 32 位为 0）。若它要成为跨语言可见的契约常量，须走冻结登记上提到契约层。
4. **闸 1 基线（2026-09-26 实测，9 crate 空骨架）**：热编译 **0.070 s** · 摸一遍源码的冷编译 **0.164 s** · 清空缓存全量重建 **0.226 s**。依赖 9 个包＝全部是本仓成员、**零第三方**。
   **注**：首次运行会慢到分钟级——那是在建环境（备 std 元数据、建构建缓存），**不是验证慢**；稳态是亚秒级。判据仍按稳态算：**超过 3 秒即视为 bug**。
5. **`cargo clippy` 是否纳入默认档**：未裁。当前默认档只跑 `cargo check`（亚秒），clippy 单列为加强档。
