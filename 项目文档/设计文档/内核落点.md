## 一 语言定案：Rust

语言无所谓——但「稳定到不会漂移」不是无所谓的。按这个要求筛，只剩 Rust：

| 你的要求 | Rust 为什么满足 |
|---|---|
| **0 漂移** | 无隐式数值转换；跨边界必须写 `extern "C"`；结构布局必须写 `#[repr(C)]`；整数宽度必须写死 `u32`/`u64`。**实现与契约不一致就编译不过**，漂移进不了制品 |
| **语言自身不漂** | edition 三年一次且**是可选开关**，老代码不升就不受影响 |
| **一个静态编译快速检测** | `cargo check` 只做类型检查不做代码生成，秒级；`cargo clippy` 再加一层规则 |
| **不会带伤继续** | `Result` 无法被忽略；无 GC ⇒ 无不可预测停顿，单项超时才有意义 |
| **跨边界 ABI 可控** | `#[repr(C)]` + `extern "C"` 给出确定的函数表与结构布局 |

**不选 Go**：带 GC 与运行时，边界内停顿不可预测（见 `语言选型对照.md`）。
**不选 C/C++**：隐式转换与拷贝语义是漂移温床，正是要避免的那件事。

**已实测工具链**：`rustc 1.95.0 (59807616c 2026-04-14)` · `cargo 1.95.0` · arm64 · 32 核。

### 宽度策略：以 64 位为主，32 位可做——最大兼容靠「把宽度声明出来」

不是不做 32 位。**最大兼容不是靠少做，是靠把差异声明出来。**

**三条设计规则**（让同一套源码能出 32 位与 64 位两种构建，且宿主能分辨）：

1. **跨边界结构里不出现 `usize` / `isize`**。这两个类型随目标变宽，是最隐蔽的漂移源。一律用显式 `u32` / `u64`。
2. **数据槽的形状与字宽无关**：`类型标签 u32 · 标志 u16 · 保留 u16 · 长度 u64 · 值 u64`——固定 64 位值域。32 位构建下指针放进 `值` 时高 32 位为 0，64 位构建下满宽。**槽的形状在两种构建下逐字节一致**，所以跨语言绑定只需一套。
3. **唯一随目标变宽的是「表指针」**（`表段<T>` 里的项表指针）。所以声明里必须有 **`目标字宽`** 字段，宿主据此知道对面是 32 位还是 64 位构建、表指针该按几字节读。

由此得到的兼容性：

| 维度 | 怎么做 |
|---|---|
| **跨语言** | 槽的形状与字宽无关 ⇒ 一套绑定通吃；表指针只在同进程内使用，不进槽 |
| **跨平台** | arm64 / x86-64 / 32 位都可构建；差异只在 `目标字宽` 一个字段里 |
| **跨版本** | 未命中返回空（宪法第 6 条）；新旧扩展与新旧底座互不崩 |

**并发按本机能力设计**：本机 32 核，验证与构建按「32 路并行」设计分片粒度，而不是按"保守一点"设计再回头优化。**慢就是 bug**（README 第二节）。

## 二 环境：钉死，不用机器上碰巧装的那份

Rust 没有 Python venv 那种运行时隔离。等价物是三件，比 venv 更硬：

| 件 | 落点 | 作用 |
|---|---|---|
| **钉工具链** | `rust-toolchain.toml`（仓库根） | 写死 `channel = "1.95.0"`。机器上装别的版本也没用，rustup 按这个文件选 |
| **零第三方依赖** | `Cargo.toml` 内核 crate 只依赖 `std` | 仓库外没有任何东西能改变行为——这是最强的「虚拟环境」 |
| **锁 + 离线** | `Cargo.lock` 提交 · `.cargo/config.toml` 设 `offline = true` | 构建期不联网，依赖不可能被替换 |

**判据（环境自检一次问三件事）**：

```text
① 当前 rustc 版本 == rust-toolchain.toml 里钉的版本
② Cargo.lock 里除本仓成员外无任何第三方包
③ cargo check --workspace --locked 通过（离线）
```

三条全过 = 环境稳定。任一条不过 = 不许开工。

## 三 0 漂移的四道闸

漂移在本项目有三个含义（实现与契约漂移、语言自身漂移、代码行为漂移），四道闸分别挡住它们：

| 闸 | 在哪 | 挡住什么 | 什么时候响 |
|---|---|---|---|
| **1 编译期** | `cargo check` | 类型不符 · 宽度不符 · 布局未声明 · 失败未处理 | 每次保存/构建 |
| **2 静态验证** | `构建装配/一键验证/` 默认档 | 声明 ↔ 实现不一致（编号 · 参数行序 · 类型标签 · 错误段位）· 号段冲突 · 冻结项被动 · 生成物过期 | 每次改完 |
| **3 冻结登记** | `契约声明/冻结登记.json` | 形状被悄悄改动 | 改形状时 |
| **4 生成物指纹** | `跨语言适配/语言绑定/` · `构建装配/制品产物/` | 生成物与契约脱节 | 每次验证 |

**四道闸的关系**：闸 1 管「写得对不对」，闸 2 管「跟声明对不对」，闸 3 管「改得许不许」，闸 4 管「派生物新不新」。**四道全过才算改完。**

## 四 1:1 复刻内核：映射表

复刻的是**契约形状与语义**，不是 32 位字节布局。唯一允许的差异是**宽度按目标平台定**（64 位），且这一条必须登记为旁路。

| 参照内核要素 | V1 内核节点 | 复刻口径 | 状态 |
|---|---|---|---|
| 唯一入口返回契约主结构指针 | `运行内核/装载入口/` | 一个导出函数返回 `*const 平台信息`；宿主读一次掌握全部可装载性 | 冻结 |
| 契约主结构（格式号 · 标识串 · 版本 · 要求版本 · 四张表 · 通知 · 依赖） | `契约声明/平台声明.json` → `平台信息` | 字段与含义 1:1；**格式号是常量，不是版本号** | 冻结 |
| 命令表 / 参数表 / 数据类型表 / 常量表 | `运行内核/统一注册表/` | 1:1；**旁路新增显式 `编号` · `可抛错误码` · `常量号`**；**参数行序即契约**；数值用双精度 | 冻结 |
| 缺项占位（命令/常量/类型各有占位项）· 状态位（隐含 · 错误 · 发布禁用 · 对象构造/释放） | `运行内核/统一注册表/` | 1:1：**载入失败用占位项保住编号不塌** | 冻结 |
| 调用形状：三参数、返回槽与参数槽分离、返回 void；数据槽自带类型标签 | `运行内核/定长数据槽/` | 1:1：`(返回槽, 参数个数, 参数表指针) -> ()`；类型标签在槽内 | 冻结 |
| 通知（下行 / 上行 / 生命周期） | `运行内核/通知通道/` | 号段 1–999 / 1000–1999 / 2000–2999 | 冻结 |
| 宿主提供内存分配，所有权单向 | `运行内核/内存分配器/` | 1:1：跨边界只认一个分配器 | 冻结 |
| 要求宿主版本 / 要求内核版本 | `契约声明/平台声明.json` | 1:1：不满足即拒绝载入 | 冻结 |
| 依赖文件清单 | `扩展装载/载入约定/` | 1:1：依赖缺失即拒绝载入或按声明降级 | 冻结 |
| 主结构冻结、演化走旁路 | `契约声明/冻结登记.json` | 1:1：新增号段 / 新增段类型号 / 新增旁路字段 | 冻结 |

**唯一允许的差异（须登记旁路）**：字段宽度按 64 位定；文本与字节集**必须带长度**（参照内核不带长度，是它的缺陷，不复刻）。

## 五 冻结的 Rust 接口（派活依据）

**命名**：内部标识符一律中文；**导出的 ABI 符号一律 ASCII**（外部协议边界，属规则允许的英文）。

**形状不在本文件复述** —— 复述必漂，本节自身就是反向样本：这里曾抄一份 `平台信息` 副本，漏了后来新增的 `目标字宽` · `保留` · `错误码表` 三字段（`契约声明/src/lib.rs` 里有），而副本照旧「看着是全的」。所以本节只给**指针**，形状一律按符号名去读那一处：

| 层 | 事实源（按符号名读） |
|---|---|
| **契约结构**（`平台信息` · `命令信息` · `参数信息` · `数据类型信息` · `常量信息` · `数据槽` · `版本三元组` · `表段` · `号段` · `执行函数` · `通知函数` · 唯一入口 `取平台信息`） | `契约声明/src/lib.rs` |
| **内核内部接口**（装载 · 取号 · 调用 · 通知派发） | `运行内核/装载入口/src/装载.rs::载入` · `运行内核/统一注册表/src/取号.rs` · `运行内核/调用调度/src/调度核心.rs::调用` · `运行内核/通知通道/` |
| **上下文接口**（已载入台账 · 调用账本 · 命令状态位） | `运行内核/装载入口/` · `运行内核/调用调度/` |

**为什么形状要冻结**：它是所有模块共用的脊梁，改了全体返工；冻结的不是实现，是别人已经依赖的形状。

**判据**：上述形状一旦冻结，任何模块实现都**不许改签名**；要改必须走冻结登记（README 第八节）。
要读形状，去上表那一处，不要从本节抄。

### 冻结后被实现侧撞出的十处缺口（**已全部收口**）

冻结接口在真写实现时撞出十处不足，**不是实现写错，是冻结时漏了**：缺号段字段 · 缺类型标签字段（标签只能用表内下标 ⇒ 跨版本不稳定） · 缺错误段位字段 · 缺上下文入参（多实例不隔离） · 缺废止段位 · 超时未定数（定 `单项超时毫秒 = 1_000`） · 缺显式编号与 `可抛错误码`（编号 = 表内下标 ⇒ 重排一次表所有号静默全变） · `命令状态::错误` 一位两义 · `调用账本` 方法时点错 · `已载入台账::号段已占用` 缺命名空间入参（能力号与通知号是两个独立命名空间，并集判会产生假冲突）。

**教训（可复用）**：冻结接口时最容易漏的不是字段，是**「谁在什么时点、拿什么上下文」**。冻结前先问四句：谁调它？调时手里有什么？它在生命周期哪个时点被调？**参数里有没有「其实是两个东西共用同一个名字」？**

**另一条教训：先实现、再冻结，比先冻结、再实现更少漏**——只有一个实现者时先实现（让实现撞出形状），有多个实现者时才必须先冻结。这条已写进 `开发规范.md` 的施工顺序。

## 六 内核的施工顺序（接口先冻结，再派活）

```text
① 契约声明层（平台信息 / 命令信息 / 参数信息 / 数据类型信息 / 常量信息 / 数据槽）
      ↓ 冻结
② 运行内核/定长数据槽      —— 值的放入与读出、类型标签判定
③ 运行内核/统一注册表      —— 四张表 + 占位项 + 状态位
④ 运行内核/装载入口        —— 可装载性判定六步 + 载入
⑤ 运行内核/通知通道        —— 三个号段的派发与接收
⑥ 运行内核/内存分配器      —— 所有权单向
⑦ 运行内核/实例状态 · 调用调度 · 调用留痕
      ↓ 以上是内核本体
⑧ 构建装配/一键验证        —— 闸 2：声明 ↔ 实现比对（秒级）
⑨ 对外接口面/调用接口面    —— 使用角色的门
```

**①②必须先冻结再派活**：它们是所有模块共用的脊梁，改了全体返工。

## 七 待裁与待实测

1. **`声明格式号` 取什么值**：**已裁（2026-09-27）：另取 `1398362929`**（ASCII `SYS1`），**不**照参照实现取 `20000101` ——
   同值会让「只查格式号」的装载器分不出我方 `平台信息` 与易语言 `LIB_INFO`（详见 `接缝实测.md` §九 第 1 条）。
2. **导出符号的 ASCII 名**：暂定 `GetPlatformInfo`；是否要保留一个参照内核同名符号做兼容，未裁。
3. **文本与字节集的长度口径**：字节长度还是字符数，未定。**已被实现侧撞到**：`定长数据槽` 的 `放入整数` 写 `长度 = 8`、`取出整数` 要求 `长度 == 8`，下游若自身用 `数据槽::内联(标签, 值, 0)` 造整数槽就会拿到 `长度不符` —— 口径必须尽快定死并写进本节。
6. **`内存分配器` 用 `&mut self`**（记账需要可变状态；用 `RefCell`/`Mutex` 会引入 panic 路径）。代价是并发调用必须外部加锁。本机 32 核，**这条要复核**：热载入与并行验证都会并发分配，最终可能要分片分配器或无锁结构。
7. **生命周期段内子号未登记契约**：`通知通道` 自定义了 `装载/卸载/退出/延迟释放` = 2000/2001/2002/2003，而 `契约声明/通知号段/` 目前只有范围、没有段内子号。子号一旦裁定，需回填契约并改该节点常量（已集中在 `pub mod 生命周期通知` 一处）。
8. **`调用留痕.已丢弃` 的口径**：除「满而丢」外，容量 0 与认领超时也计入。口径必须写死，否则「丢痕是静默的」这条判据会失效。
9. **`内存分配器` 的 `单次分配上限` 落在本 crate**（`u32::MAX`，依据是 32 位构建下指针高 32 位为 0）。若它要成为跨语言可见的契约常量，须走冻结登记上提到契约层。
5. **`cargo clippy` 是否纳入默认档**：未裁。当前默认档只跑 `cargo check`（亚秒），clippy 单列为加强档。
