# 接口面形状（冻结）

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/接口面形状.md`
相关：`README.md` 第二节（两个角色）· 第八节（冻结项）· `两个角色与接口面.md`（为什么这样分面）· `多语言兼容实现.md`（槽与类型标签）· `代码形态分工.md`（各节点形态）

**本文是冻结件。** 它冻结的是 `对外接口面/` 的**对外形状**：端点 · 请求体 · 返回体 · 错误体。冻结项一旦公布，**只许新增旁路字段，不许改旧字段含义、不许改旧端点语义**（README 第八节）。

**为什么现在就要冻**：`对外接口面/调用接口面/`（Rust）与 `前端呈现/网页应用/`（纯 UI）两件都只能照着形状写。形状不冻，两件会各自长出一套，然后靠联调对齐——那就是漂移。

---

## 一 一条判据决定全部取舍

> **使用角色：第一次用不需要读文档就能调对。**

这条判据把设计逼成一个形状：**根端点自己就是说明书**。agent 的第一次调用是 `GET /接口`，它的返回里同时给出「有哪些端点」和「有哪些能力」。从此不需要第二份文档。

推论（都是判据的直接后果，不是偏好）：

| 由此得出 | 因为 |
|---|---|
| **不做鉴权、不发 token** | 「要先拿 token」就是违反判据 |
| **只监听回环地址** | 没有鉴权，就必须只对本机开放 |
| **不做分页** | 契约读一次就是全量；「翻页查能力」是第二个动作 |
| **不做握手 / 会话 / 连接管理** | 入口无状态；不存在「先连上再调」 |
| **不做版本协商** | 契约版本随根端点一起返回，客户端不需要协商 |
| **端口只有一个来源** | 端口写在 `契约声明/常量表.json` 的「接口端口」条目里；前端**不写死端口**，用同源相对路径（上一版就是前端默认端口与网关端口不一致，两头各写一份） |

## 二 端点总表（四个，就这些）

传输：本机 HTTP/1.1，请求与响应体一律 `application/json; charset=utf-8`。

| 方法 | 路径 | 角色 | 做什么 |
|---|---|---|---|
| `GET` | `/接口` | 使用 | **自描述根**：端点表 + 能力总清单 + 契约版本 + 端口来源 |
| `GET` | `/接口/能力/<编号>` | 使用 | 单条能力的完整契约：参数表（**行序即契约**）· 返回表 · 可抛错误码 |
| `POST` | `/接口/调用` | 使用 | 报编号 + 按行序填值 → 结构化结果 |
| `POST` | `/接口/声明` | 维护 | 写一份声明（面先校验，过了才落盘到 `契约声明/`） |

维护侧的**读**走 `GET /接口/能力/<编号>` 与 `GET /接口`（读与调同一个入口，不另开一套文档接口）；**待分配号**由 `POST /接口/声明` 的 `编号` 字段留空时由面分配（见 §五）。

## 三 使用侧形状

### `GET /接口` → 自描述根

```json
{
  "契约版本": { "主": 0, "次": 1, "修订": 0, "构建": 1 },
  "声明格式号": 1398362929,
  "端口来源": "契约声明/常量表.json 的 接口端口；前端一律用同源相对路径，不写死",
  "端点": [
    { "方法": "GET",  "路径": "/接口",             "说明": "本清单" },
    { "方法": "GET",  "路径": "/接口/能力/<编号>",  "说明": "单条能力的契约" },
    { "方法": "POST", "路径": "/接口/调用",         "说明": "体：{\"编号\":N,\"值\":[...]}；值按契约行序" },
    { "方法": "POST", "路径": "/接口/声明",         "说明": "写声明；面校验通过才落盘" }
  ],
  "能力": [
    { "编号": 0, "名称": "取平台信息", "参数个数": 1, "返回类型": 0 },
    { "编号": 1106, "名称": "编译",     "参数个数": 1, "返回类型": 5 }
  ]
}
```

`能力` 是**全量**，不是首页。未载入的扩展其能力不在表里（宪法第 6 条：未命中返回空，不是报错）。

### `POST /接口/调用`

请求：

```json
{
  "编号": 0,
  "值": [ { "类型标签": 5, "值": "<base64 字节集>" } ]
}
```

- `值` 按契约 `参数表` 的**行序**对位；空位写 `{"类型标签":0,"值":0}`（空槽），**不许省略位次**（省略就是改行序）。
- 每个值都是**带类型标签的定长槽**（宪法第 3 条：类型标签在槽内）。
- 文本 ⇒ `值` 是 JSON 字符串（UTF-8，长度由 JSON 自带）；字节集 ⇒ `值` 是 base64 字符串。两者靠 `类型标签` 区分，不靠形状猜。

成功返回：

```json
{
  "成功": true,
  "值": [ { "类型标签": 5, "值": "<base64 字节集>" } ],
  "耗时微秒": 812
}
```

失败返回：

```json
{
  "成功": false,
  "错误": {
    "码": 1,
    "段位": 0,
    "名称": "提供者未载入",
    "可重试": false,
    "可自愈": true,
    "需人工": false
  },
  "耗时微秒": 8
}
```

**失败不抛 HTTP 5xx。** HTTP 状态码只表达「请求本身合不合法」（400 = 请求形状不合法），业务失败一律 200 + `"成功": false`。理由：失败是**可编程处理的数据**（本项目三条补缺陷之一），把它塞进 HTTP 状态码就等于让调用方去解析协议层，而协议层不该承载业务。

### 返回必须同时回答三件事（判据）

| 问 | 答在哪 |
|---|---|
| 成功没成功 | `成功` 布尔，不靠猜、不靠异常 |
| 拿到什么 | `值` 数组，每项自带 `类型标签`，不需要二次解析 |
| 失败为什么 | `错误.码`，且四项登记（`段位 · 可重试 · 可自愈 · 需人工`）随包带回 |

**判据**：把这个返回原文直接喂给另一个 agent，它不需要额外上下文就能决定下一步做什么。

## 四 维护侧形状

### `POST /接口/声明`

请求（写入形状 = 冻结项）：

```json
{
  "类别": "能力",
  "编号": null,
  "正文": { "名称": "反解容器", "说明": "…", "参数表": [ … ], "返回类型": 5, "可抛错误码": [1101] }
}
```

- `类别` ∈ `能力` · `类型` · `错误码` · `通知号`。
- `编号` 为 `null` ⇒ **面自动分配**（手填必然撞号；「一个号一个文件」已把撞号变成文件名冲突，自动分配再省一步）。自动分配只从该层号段的空洞里取，**永不回收同空间的作废号**（作废只封**同空间**的号：错误码空间作废的号，能力空间仍可用 —— `格式说明.md` §七 · `作废号表.json` 的 `号空间`）。
- `正文` 的字段形状 = `契约声明/格式说明.md` 里那一类 JSON 的形状，**逐字一致**。面不改名、不重排、不加壳。

面校验通过：

```json
{ "成功": true, "编号": 0, "落盘": "契约声明/能力声明/0.json", "指纹": "…" }

**★ 落盘口径（2026-09-26 裁定，本表原先与 `格式说明.md` §一 ★ 相反）**：
**一份声明根装它自己的声明** —— 底座 = `契约声明/`；**每个扩展 = 它自己目录里的 `能力声明/` 等**
（编译器扩展就是落在 `扩展根目录/原子支持库/编译器支持库/能力声明/`）。
生成器的 `--声明根` 参数本来就是按这个口径做的。**底座自己的能力编号落 `0xxx`**
（`平台声明.json` 申报的占用就是 `0–999`）；`9000–9999` 是「接口面与构建验证」那一层，不是底座的命令。
```

面校验失败：

```json
{
  "成功": false,
  "校验": [
    {
      "项": "编号落在自己那一层号段内",
      "缺什么": "该编号不落在本声明根申报的号段里（例：往 契约声明/ 写一条 1105 —— 那是扩展段，扩展的声明要写进扩展自己的声明根）",
      "为什么不能自愈": "层号段由 平台声明.json 固定；面不能替调用方换层，换层等于换归属"
    },
    {
      "项": "可抛错误码都已登记",
      "缺什么": "1101 不在 错误码表/ 里",
      "为什么不能自愈": "错误码必须先登记四项（段位·可重试·可自愈·需人工）才允许被抛出；面不替它编四项"
    }
  ]
}
```

**`为什么不能自愈` 不许写「需要人工确认」这种废话。** 必须写清是哪一个事实挡住了自动补全；能自愈的当场自愈并在返回里报告（例如补上可推导的 `段位` 字段）。

### 面的两条硬规则

1. **面是 `契约声明/` 的唯一写入口。** 绕过面直接改文件 = 违规（判据见 README 第九节）。
2. **面只做结构校验，不做业务判断。** 面不判断「这个能力该不该存在」，只判断「它合不合契约形状」。

## 五 部署形状（前后端怎么分开）

```text
浏览器 / 纯 UI（前端呈现/网页应用/）
        │  同源相对路径 fetch，前端零逻辑、零端口硬编码
        ▼
对外接口面（Rust，本机 HTTP）── 唯一对外门
        │  唯一腿：转调 跨语言适配/适配器实现/
        ▼
跨语言适配/适配器实现/ ── 读契约 → 装载内核 → 转发调用（全平台只此一个）
        ▼
运行内核（装载入口 · 统一注册表 · 调用调度 …）
```

三条不许：

1. **前端不许有解析/生成/校验逻辑**——前端是纯 UI。任何判断都在后端。
2. **接口面不许绕过适配器直连扩展实现**（分层链：`契约声明/ ← 运行内核/ ← 跨语言适配/ ← 对外接口面/ ← 前端呈现/`）。
3. **不许出现第二个对外门**——`对外接口面/` 只有一个；多一个门就多一套形状要同步。

静态文件（前端构建产物）由接口面进程托管，**同源**，所以不需要 CORS、不需要第二个端口。

**实测状态（2026-09-27）：已实现** —— 请求 `/` 回 `200`、13758 字节。落点 `对外接口面/调用接口面/src/静态件.rs`，两条测试守着（根路径回 `index.html`、仓内别处一律 `404`）。

## 七 旁路端点（工具族 · 生命周期族 · 留痕，2026-09-27 新增）

§二 那张「四个端点，就这些」的表是**冻结项**（`冻结登记.json` 的「对外接口面形状」）。
本节新增的**九个**端点**不进那张表** —— 把新端点塞进 `端点` 数组就是改冻结项的含义。
它们另立一张旁路表（`常量.rs::旁路端点表`），由 `GET /接口` 的**旁路字段 `旁路端点`** 交出：
只读 `端点` 的旧读者读到的东西**逐字不变**，而第一次用的人照样一次拿全（§一 判据）。

旁路演进已登记：`契约声明/冻结登记.json` 的 `旁路`（日期 2026-09-27）。
实现落点：`对外接口面/调用接口面/src/{路由.rs · 分发.rs · 请求.rs · 工具响应.rs · 工具链.rs}`。

### 九个端点

工具族**六个**（`v1-case-runner` / 构建工具链的读数）：

| 方法 | 路径 | 请求体 | 成功时 `数据` 里有什么 |
|---|---|---|---|
| `GET` | `/接口/案例` | 无 | `案例根` · `回执件` · `回执行数` · `坏回执行数` · `案例[]`（每项 `案例标识` · `案例名` · `有回执` · `最新回执`，有说明的带 `说明`） |
| `POST` | `/接口/案例/跑` | `{"案例标识":"…"}` | `案例标识` · `案例名` · `案例结果` · `回执` · `案例跑者退出码` |
| `GET` | `/接口/扩展` | 无 | `扩展根` · `扩展根声明` · `种类[]`（每项 `种类` · `目录` · `扩展[]`：`扩展目录` · `名称` · `标识串` · `能力号段` · `声明落点`） |
| `POST` | `/接口/导出` | `{"目标":"案例\|支持库\|模块\|技能\|制品","标识":…}`（`标识` 可省） | `目标` · `程序` · `参数[]` · `退出码` · `标准输出` · `标准错误` |
| `POST` | `/接口/程序文本` | `{"动作":"读\|写"}` | **没有成功形状**：一律 `9006`，回执说清缺哪一条裁决 |
| `POST` | `/接口/菜单命令` | `{"编号":"0xe100"}` | **没有成功形状**：一律 `9001`，回执带命令名与 `在菜单表里` |

生命周期族**两个** + 留痕**一个**（2026-09-27 随 `#80` / `#99` 补；实现在 `生命周期响应.rs` · `留痕响应.rs`）：

| 方法 | 路径 | 请求体 | 成功时 `数据` 里有什么 |
|---|---|---|---|
| `GET` | `/接口/生命周期` | 无 | `已装载声明数` · `通知端点数` · `已注册标识串[]`（读数取自生命周期那本账 = 通知端点表，不另存健康表） |
| `POST` | `/接口/生命周期` | `{"动作":"卸载","标识串":"…"}` | `标识串` · `派发结果`（`成功` / `请求延迟释放` / `失败` / `未命中`）· `通知端点数` |
| `GET` | `/接口/留痕` | 无 | `已启用` · `条数` · `已丢弃` · `留痕[]`（每项 `实例` · `调用类` · `能力号` · `资源号` · `操作号` · `入参指纹` · `结果码` · `耗时微秒` · `追踪号`） |

生命周期族的**顶层一律 `成功: true`**：`派发结果` 的四种结局都放在 `数据` 里如实报出 ——
`未命中` 按宪法第 6 条不是错误，`请求延迟释放` 是**允许被拒绝**（扩展还有在飞引用），
`失败` 是 fail-closed 但段位 9 里没有对应码（**不许自造码**）⇒ 都不编错误对象。
`GET /接口/留痕` 的 `已启用` 由装配侧决定（生产装配按契约常量 `留痕容量` 开 ⇒ 通常为 `true`）；
`false` 是「没开」不是「取不到」，两者靠这个旁路字段分开。

四条 `POST` 的**请求体形状**判在 `请求.rs`（不合法 ⇒ **HTTP 400**）。
`目标` 是不是落在五种出口的闭合枚举里、`编号` 是不是已登记的命令，**都不在协议层判** ——
那是业务失败，回**真错误码**（`分发.rs` 文件头那条分工：HTTP 状态码只表达请求合不合法）。

转调的不是能力：案例族与导出族转调的是**构建 / 验证工具链**（`v1-case-runner` ·
`构建装配/上线切换/构建制品.py`，见 `工具链.rs` 文件头），唯一腿仍是
`跨语言适配/适配器实现/`（案例跑者自己就经适配器装载并调用）。

### 旁路字段 `数据` 为什么用（与 §三 的 `值` 怎么分工）

§三 的四个端点返回的是**能力调用的结果**：`值` 是「带类型标签的定长槽」数组。
本节的九个端点返回的是**工具链与内核的读数**（案例清单 · 回执 · 子进程退出码 · 扩展清单 ·
通知端点表 · 留痕）—— 它们**不是槽**。硬塞进 `值` 就等于给 `值` 编一个「有时是槽、有时是对象」
的第二含义（同一件事两套形状）。故本节一律用**旁路字段 `数据`** 承载载荷：

```json
{ "成功": true,  "数据": { … }, "耗时微秒": N }
```

§三 那三问照旧被回答：`成功` / `数据` / `错误.码`。**失败时 `数据` 是结构化回执**
（说清缺什么裁决、哪一步失败、子进程退出码是多少），不是「失败就不给信息」——
那正是 `9006` / `9001` 这两条码存在的理由。没有回执可给时 `数据` **整个键都不出现**：
不编一个空对象（空对象与「没有回执」不可区分）。

### 失败一律回真错误码

```json
{
  "成功": false,
  "错误": { "码": 9002, "段位": 9, "名称": "案例不存在",
            "可重试": false, "可自愈": false, "需人工": false, "已登记": true },
  "数据": { … },
  "耗时微秒": 42
}
```

错误对象是 §三 的**六项 + 旁路字段 `已登记`**（`错误形状.rs` 的口径，本节无例外）。
`段位` 一律 `9`（接口面与构建验证那一层）。七个码的唯一来源是
`契约声明/错误码表/9xxx.json`：**不许自造码、不许把失败写成成功。**

| 码 | 名称 | 什么时候回 |
|---|---|---|

### 本节如实登记的缺口（不假装覆盖了）

1. **子进程超时未裁**（`工具链.rs` 文件头）。本面转调的外部命令**不设执行上限**：
   案例跑者实测 50 ms 量级，而制品装配器要跑 `cargo build --release`（分钟量级）。
   给不给上限、给多少，是**部署策略**而不是契约里的数 ⇒ 未裁。**不静默给一个数**：
   猜一个上限会在慢机器上把真成功报成失败（假红），而假红会训练人忽略红灯。
2. **`支持库` 与 `制品` 共用同一个装配器**：**这不是两套实现**（一条命令、两个目标），
   差别只在 `--变体`（变体名进构建指纹）。共用这件事只在这一处成立，不另开第二条命令。
3. **`扩展根声明` 的 `种类[].目录` 口径与实现不吻合**（2026-09-27 实测）：
   声明的 `路径基准` 是「工作目录」，`种类[].目录` 写的是 `扩展根目录/原子支持库`
   （即**相对工作目录**）；而实现按 `工具根 / 扩展根 / 目录` 拼，得到
   `扩展根目录/扩展根目录/原子支持库` ⇒ `GET /接口/扩展` 恒回 `9007`。
   修法是二选一（声明改口径，或实现改拼法），**须裁**；本面不擅自改已跑通的返回语义。
