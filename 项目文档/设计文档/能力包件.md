# 能力包件（编译产物的格式）

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/能力包件.md`
相关：`程序文本格式.md`（原生源格式）· `容器格式实测.md`（容器骨架）· `接口面形状.md`（agent 从哪读）· `代码形态分工.md`（各节点形态）

**本文是一条裁定**：**编译产物叫「能力包件」**。★ 2026-09-28 更正（`项目文档/决策记录/2026-09-28_核心后缀表.md`）：**`.能力包件` 降为「容器格式名」，不再是文件后缀** —— 容器格式只有一个（本文这套），**后缀按种类给**：`.支持库制品` · `.模块制品` · `.技能制品`。

## 一 它是什么

| | 是什么 | 谁看 |
|---|---|---|
| **程序文本**（`.程序文本`） | 源：人写、agent 改、用户看 | 人 · agent（编辑时） |
| **能力包件**（`.能力包件`） | 编译产物：**可载入的机器码 + 只讲怎么调的说明** | 底座（载入）· agent（调用） |

一个 `.能力包件` 是一个文件，里面装三段：

| 段 | 段类型号 | 装什么 | agent 能不能看到 |
|---|---|---|---|
| **接口说明段** | `16` | **只讲怎么调**：编号 · 名称 · 参数表（行序）· 返回类型 · 可抛错误码 · 一句用法 | **能，而且只看这个** |
| **能力码段** | `17` | 可载入的机器码 —— **支持库 = 本机机器码**（它是本机原生实现）· **模块 = WebAssembly**（1106 编译产出） | 不能（也没必要） |
| **技能本体段** | `19` | 技能的 md 正文（技能不含实现 ⇒ 没有机器码）· **段类型号待登记** | **能**（技能本体就是给人 / agent 读的） |
| **指纹段** | `18` | 各段的 sha256 | 不能（判据自用） |

**接口说明段的字段不是这里定的**：它**就是** `接口面形状.md` 里 `GET /接口/能力/<编号>`
返回体的那六个字段，**逐条同名同序**（一份数据两个出口）。字段表只在 `接口面形状.md` 一处，
本文不复述（复述就是第二个来源）。

段类型号 `16–18` 是**我们自身新增的段类型号**——`冻结登记.json` 允许的三种演进方式之一
（「新增段类型号，不动旧段」）。骨架（44 字节段头 + 段类型号 + 名称区密钥）沿用已冻结的容器主结构，
**不另造一套外壳**。

**盘面段类型是 `u8`（1 字节），`256` 在盘面上不存在** ⇒ 号取 u8 里的空洞 **`16–254`**，本包件用前三个（`16–18`）。理由与判据见 `决策记录/2026-09-27_语言主线三缺口裁决.md` §三。

## 二 为什么码那一侧选 WebAssembly

判据是**「各个系统都兼容」**（华哥原话）。逐条对：

| 要求 | WASM 为什么满足 |
|---|---|
| 各系统都载得动 | 浏览器原生 · Node/Deno 原生 · Python 有 wasmtime · Java/.NET 有 Wasmtime/Wasmtime.NET · Go 有 wazero · Rust 有 wasmtime/wasmer。**一套字节码，所有系统都有现成载入器** |
| 类似 DLL 的形式 | 它是**可载入模块**，有导出表、有导入表、有线性内存，与 DLL 的形态一一对应 |
| 沙箱 | 默认**不能**碰文件、网络、时钟——正是「资源网关口」默认拒绝的同一条哲学 |
| 确定性 | 浮点与内存语义被规范钉死，跨平台不漂移（本项目「0 漂移」的直接诉求） |
| 与既有形态分工一致 | `代码形态分工.md` 里已经有「编译到 WebAssembly 的那份」，不新增形态 |

**不选别的**：原生共享库（`.dll`/`.so`/`.dylib`）**不跨系统**（Windows 载不了 Mach-O）；我们自身造一套字节码要自身写所有载入器（每个语言一个，那就是 N 条腿）。

---

## 三 最重要的一条：agent 只看到「怎么调」

**判据**：agent 拿到一个能力包件，**读一次就知道怎么调**，**且拿不到源码**。

这不是「权限控制」，是**格式设计**——源码根本不进包：

1. **包里没有源码**。程序文本不被打包进去；反解出来的结构也不进去。包里只有机器码与接口说明。
2. **接口说明只讲怎么调**。每条能力最多六行：`编号` · `名称` · `参数表（行序）` · `返回类型` · `可抛错误码` · 一句用法。**不写实现思路、不写内部结构、不写算法**。
3. **读侧两个口**（`接口面形状.md` 已冻结）：`GET /接口` 给**紧凑清单**（每条能力一行），`GET /接口/能力/<编号>` 给**那一条的完整契约**。要哪条读哪条 ⇒ 一个有一百个能力的包，agent 也不会被灌一屏。

**为什么「源码进包」是污染而不是便利**：agent 的上下文是它最贵的资源。把源码塞进去，等于每次调用前先读一遍实现——它**不需要**实现，只需要接口；而多出来的东西会挤掉它真正要判断的依据。

---

## 四 为什么是一个文件而不是两个

**接口说明与机器码必须在同一个文件里**，不许拆成 `.wasm` + `.说明` 两个文件。

理由是本项目最常踩的那一类：**两个文件就是两个来源**。一旦分开，就会出现「说明是旧的、码是新的」这种状态，而**没有任何东西能保证它们同步**——同步漏了不会报错，只会让调用方按旧说明传参、拿新码执行。

同封装之后，**指纹段**可以给两者各算一个哈希，任何一边被换过都判得出来。

## 五 明确不做

| 不做 | 为什么 |
|---|---|
| 不做第二个包格式 | 两种格式就是第二条腿（`代码形态分工.md` 第五节硬判据 1） |
| 不把源码或结构打进包 | agent 只需要会调用；源码进包就是上下文污染 |
| 不做「按能力分文件」的包 | 一个包 = 一个扩展；按能力拆包会让「载入」变成「载入一串」，而载入必须是原子的 |
| 不用原生共享库当包 | 不跨系统；每个系统一个二进制就是 N 条腿 |
| 不让包自带「我守时 / 我很安全」这类自述 | 自述不是判据。超时与配额由关口执行（`资源网关口.md` 同一条） |
| 不做「可执行包」（双击就跑） | 包是**被载入**的，不是**被运行**的。它没有自身的入口，只有导出表 |
| 不许包里的段用旧段类型号 | `1–15` 与 `255` 是参照实现占用的号；我们的号取 u8 里的空洞 `16–254`（盘面段类型是 **`u8`**，没有 `256`）。动 `1–15`/`255` 就是改冻结形状 |
