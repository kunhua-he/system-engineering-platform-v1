## 〇 结论摘要（先给裁决依据）

1. **界面结构在资源里，而且是明文。** 13 个顶层类型 / **195 条叶子** / 叶字节合计 **750 884**；
   菜单 **17 个 386 项**、对话框 **56 个 606 控件**、字符串表 **47 块 365 条** —— 全部解出。
   每个模板都满足**最强自洽判据**：`解析消耗字节数 == 资源声明字节数`，**56/56 对话框、17/17 菜单、
   47/47 字符串块精确到 1 字节**。这不是「大概对」，是边界闭合。
2. **协调方「大块被压缩/打包」不成立。** 菜单 + 对话框 + 字符串表共 52 058 字节里，
   实测 **19 262 个可读 UTF-16 字符**（约 74% 的字节就是文字本身）。
   协调方那 7 423 个「GBK 噪声」是**按 GBK 去扫 UTF-16LE 文本**的错配产物，不是压缩痕迹。
   全树压缩判定：**RCDATA 2 条 + 自定义 240 1 条 + HTML 1 条，一条都没被压缩**（见 §六）。
3. **`TPF0` 出现 0 次属实，但推论（「界面样式拿不到」）不成立。** Delphi 窗体签名确实没有，
   可界面不在那里 —— 它在 PE 资源类型 4/5/6 里，是 Windows 原生模板，与 Delphi 无关。
4. **与既有文档矛盾 1 处**：MSDN 说 `MENUITEMTEMPLATE` 的最后一项（`MF_END`）**没有** `mtID`；
   本文件实测 **`MF_END` 项有 `mtID`**，判据见 §二 2.2。
5. **1:1 复刻分四项裁决**（详证 §十）：

   | 项 | 能不能 1:1 复刻 | 依据 |
   |---|---|---|
   | 菜单结构 | **能** | 386 项全解：层级 · 文字 · 加速键文本 · 命令 id · 分隔线 · 灰化位 |
   | 对话框布局 | **能** | 56 个 606 控件全解：类 · x/y/cx/cy · style/exStyle · 控件 id · 标题 · 字体 |
   | 主窗体布局 | **不能** | 资源目录里没有任何主窗体定义（13 个类型已穷尽，见 §七） |
   | 配色 / 字体 | **字体能，配色不能** | 对话框字体 3 种已解；无配色表，字符串表里「颜色/字体/背景/配色」0 命中 |

## 二 菜单（类型 4）：17 个资源 · 386 项

### 2.1 格式判据

`MENUHEADER`（`WORD wVersion` + `WORD cbHeaderSize`，实测全 0）+ 串行的 `MENUITEMTEMPLATE`：

```
WORD  mtOption          ; MF_* 位
WORD  mtID              ; 只在「非 MF_POPUP」项存在（本文件实测，见 2.2）
WCHAR mtString[]        ; UTF-16LE，NUL 结尾
```

- `MF_POPUP`=0x0010 表示该项是子菜单、其子项紧随其后；`MF_END`=0x0080 表示该项是本层最后一项。
- 层深推进规则（实测）：**`MF_POPUP` 优先于 `MF_END`** —— 带 `MF_POPUP|MF_END` 的项先开子层，
  由子层最后一项的 `MF_END` 收口。反过来的优先级会让 17/17 菜单全部 `MF_END` 下溢。
- 判据：解析必须**恰好消耗**资源声明字节数，且结束时层深 == 0。17/17 通过。

**menu 127 头 32 字节**（`00 00 00 00` 是 MENUHEADER，`10 00` 是 MF_POPUP，`26 00 46 00 2e 00 0b 7a 8f 5e 00 00`
就是 `&F.程序\0`，紧随的 `00 00` 是下一项的 mtOption、`00 e1` 是它的 mtID 0xE100）：

```
00 00 00 00 10 00 26 00 46 00 2e 00 0b 7a 8f 5e 00 00 00 00 00 e1 26 00 4e 00 2e 00 b0 65 fa 5e
```

### 2.2 与既有文档矛盾：`MF_END` 项的 `mtID` 存在

MSDN 的 `MENUITEMTEMPLATE` 说「`mtID` 只在 `MF_POPUP` 未置位**且该项不是最后一项**时存在」。
本文件实测**不是这样**：`MF_END` 项仍带 `mtID`。判据是**两条独立证据**：

1. menu 127 的「退出」项：字节 `80 00 41 e1 26 00 58 00 ...`。按实测规则读作 `opt=0x0080 / id=0xE141 / "&X.退出"`；
   按 MSDN 规则则 `id` 缺席，文字会变成 `"\ue141&X.退出"` —— 开头多一个**私用区字符 U+E141**。
2. 按 MSDN 规则扫全部 **386 项，出现 1 项含私用区/控制字符；按实测规则 0 项**。
   且 0xE141 落在本文件真实存在的命令 id 段里（`0xE100..0xE104`、`0xE110`、`0xE122`、`0xE123`、`0xE12B`、`0xE12C`、`0xE800`、`0xE801`；
   加速键资源里的 `0xE300..0xE303` 同段）。

### 3.1 格式判据

两种模板并存，靠首 DWORD 分辨：

| | 头 | 控件头 |
|---|---|---|
| `DLGTEMPLATE`（53 个） | 18 字节：style(4) exStyle(4) cdit(2) x(2) y(2) cx(2) cy(2) | 18 字节：style(4) exStyle(4) x y cx cy (各 2) id(2) |

## 七 主窗体布局与配色：资源腿为什么给不出

13 个顶层类型已**穷尽**（`①` 的 195 条叶子），里面**没有**任何一条是「窗体定义」：
没有 Delphi 的 `TPF0`（全文件 0 次，与协调方一致）、没有 `MSFT`、没有第二种窗体模板。
全文件里 `<?xml` 只 3 次，全在 `.rdata`（0x25E4E0 / 0x25E79C / 0x25E970），是**三个应用程序清单（assembly manifest）字符串**，
不是窗体；`OBJECT ` 1 次在 0x221D30，是 ASN.1/crypto 的类型名字符串（`OBJECT DESCRIPTOR` 一带），也不是窗体。

⇒ **IDE 主窗口的控件树、各面板尺寸与分隔位置不在资源里**。它们是运行时由代码创建的。
资源腿能给的「主窗体」证据只有三样：菜单栏（menu 127）、工具条位图（类型 2 的 41 条）、
图标与光标。要拿主窗体布局，得走 `.text` 的反汇编（本腿不做），或让 IDE 跑起来量窗口（安全约束禁止运行）。

**配色**同理：对话框字体在资源里（3 种），但**编辑器语法高亮色、工具条底色、面板配色不在资源里**。
字符串表 365 条里「颜色/字体/背景/配色」0 命中 ⇒ 本腿**给不出配色**，且能证明「资源里没有」，

## 十 结论：能不能 1:1 复刻

| 项 | 裁决 | 证据强度 |
|---|---|---|
| **菜单结构** | **能 1:1 复刻** | 386/386 项解出，含层级、文字、加速键文本、命令 id、分隔线、`MF_GRAYED` 位；17/17 资源边界闭合 |
| **对话框布局** | **能 1:1 复刻** | 56/56 资源、606/606 控件解出：控件类（预定义序数 + 具名类）、x/y/cx/cy、style/exStyle、控件 id、标题、字体；5 个贴图静态框的序数已解析到具体位图/图标资源 |
| **主窗体布局** | **不能** | 13 个资源类型已穷尽，无窗体定义；面板尺寸/分隔位置在 `.text` 里（§七） |
| **配色 / 字体** | **字体能，配色不能** | 对话框字体 3 种（宋体 9pt / MS Shell Dlg 8pt / 宋体 9pt+字符集1）；配色表在资源里 0 命中 |

**一句话**：IDE 的**菜单树与全部对话框布局可以逐字节 1:1 复刻**；
