# 资源网关口（裁定：黑盒这样处置）

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/资源网关口.md`
相关：`README.md` 第八节（冻结与旁路）· `现代架构落点.md`（边界四种载体）· `多语言兼容实现.md`（定长数据槽）· `扩展装载与开发标准.md`（底座与扩展的接缝）

**本文是一条裁定**：不透明的外部东西（黑盒）怎么处置。裁定结果：**当「资源」，只经一个关口访问，声明里没写的一律拒绝。**

---

## 一 裁定要解决的问题

`扩展根目录/原子支持库/编译器支持库/说明/语言面证据缺口.md` 记了一个死结：

> 语言面那条链（`源码文本 → 记号 → 语法树 → …`）要验，需要「容器字节 → 源码文本」的**独立路径**（参照实现的「查看源码」），而参照实现是**黑盒、不许运行**。⇒ 当前证据下这条路走不通。

把「不许运行」当前提，这个死结无解。**所以问题出在前提上**：不许运行不是「看不见它」，而是「**没有一种受控的方式碰它**」。补上那种方式，黑盒就变成**可声明、可隔离、可拒绝**的资源。

---

## 二 Docker 那一套怎么映射过来

| Docker | 本平台 | 作用 |
|---|---|---|
| **镜像**（image） | **资源声明** | 说清这个资源是什么、能做什么、怎么调、要什么、什么时候算超时。**声明里没写的操作不存在。** |
| **容器**（container） | **资源实例** | 真跑起来的那一份。状态与别人隔离，崩了不影响底座，可重建 |
| **网关口**（gateway） | **资源网关口** | **唯一出入口**。所有访问都经它，它按声明放行或拒绝 |
| **`docker run` 的默认网络策略** | **默认拒绝（fail-closed）** | 没声明 = 不放行。**拒绝是默认值，不是异常。** |
| `docker inspect` | **资源清单** | 现在有哪些资源、各自声明了什么、健康否 |

**一句话**：**看不见的东西不需要看懂，只需要能声明它、隔离它、拒绝它。**

## 三 资源声明（形状冻结）

```json
{
  "资源号": 9001,
  "标识": "参照实现",
  "种类": "不透明外部程序",
  "入口": { "载体": "本机进程", "路径": "（由部署方填，不写进声明仓）" },
  "操作": [
    { "操作号": 1, "名": "文本转容器", "输入类型": [4], "输出类型": 5, "超时毫秒": 5000 },
    { "操作号": 2, "名": "容器转文本", "输入类型": [5], "输出类型": 4, "超时毫秒": 5000 }
  ],
  "允许": { "读文件": false, "写文件": false, "联网": false, "派生进程": false },
  "隔离": { "载体": "本机进程", "可重建": true, "崩溃影响面": "仅本资源" },
  "留痕": true
}
```

四条硬规则：

1. **`操作` 是白名单，不是能力清单。** 没列出的操作**不存在**——关口不会「尽力而为」，直接拒。
2. **`允许` 全默认 false。** 要读文件就显式写 `true`，且要说明读哪个根。**「默认能用」是最危险的默认值。**
3. **`入口` 不写进声明仓。** 声明说「怎么调」，部署说「调哪一份」——两者分开，声明才能公开而入口不公开。
4. **`输入类型` 是表，不是单值**（2026-09-27 裁，依据 `项目文档/决策记录/2026-09-27_待裁九项按老仓设计哲学裁决.md` 裁决 1）。
   它按**行序**逐位对齐 §四 的「**输入槽表**」：第 k 个入参槽的类型标签就是 `输入类型[k]`；一条操作要几个
   入参就写几项（`[4]` = 一个入参，`[4, 4]` = 两个同类型入参，`[4, 5]` = 两个不同类型入参）。
   **`输入类型` 写成单值 = 只能在「恰好一个入参槽」时自洽**，那正是要修的病。
   **明写「资源操作恒单入参」是收窄约束**——能力不足就补底座，不许收窄约束绕过（老仓第 7.7）；
   依据同裁决 1。**反向样本**：声明或文档里出现「恒单入参」这类收窄措辞 ⇒ 红。

## 四 访问形状（唯一腿）

```text
资源调用(资源号, 操作号, 输入槽表) -> 输出槽表 | 结构化错误
```

- **与能力调用同一条形状**：也是「按号 + 按契约行序填值 + 结构化结果」。资源不是第二套东西，是同一套东西的另一个被调方。
- **`输入槽表` 的行数与类型由声明的 `输入类型` 表逐位约束**（§三 规则 4）：**个数与行序都是契约**，不许尽力而为地补齐或截断。
- **数据只走定长数据槽**（宪法第 3 条），类型标签在槽内。跨进程/跨机器同理——槽是自描述的，所以载体换了不用改形状。
- **失败是结构化错误码，不是异常**（宪法「失败可编程处理」）。
- **超时与配额由关口执行**，不由资源自己保证。资源是黑盒，不能指望它守时。

## 五 拒绝发生在哪一层（这是本节的关键）

关口**四处拒绝**，每处都有明确依据：

| # | 拒绝什么 | 依据 |
|---|---|---|
| 1 | 没声明的**资源** | 资源清单里没有这个号 |
| 2 | 没声明的**操作** | 该资源的 `操作` 白名单里没有这个操作号 |
| 3 | 声明里**没允许的副作用** | `允许` 里是 `false`（默认全 false） |
| 4 | 输入**形状不合契约** | 槽的**个数或类型标签**与声明的 `输入类型` **表逐位（按行序）**不符（§三 规则 4） |

**「不许运行参照实现」这条禁令，落点就是第 1 条**：默认的资源清单**不含**参照实现 ⇒ 关口拒。要放行，得**显式加一条资源声明**——那是一个有日期、有署名、可回滚的声明动作，不是一句注释。

这就是「**这样子不就拒绝了**」的机制：**拒绝不靠自觉，靠清单里没有。**

## 六 裁定：语言面那个证据缺口怎么关

**裁定 = 用资源网关口关掉它，不放弃。**

参照实现成为一种资源，声明两个操作：`文本转容器` 与 `容器转文本`。有了它：

- 语言面链（`文本 → 记号 → 语法树 → …`）**可验**：拿真文本喂进去，把参照实现产出的容器字节当基准。
- 还能反向验：拿语料里现成的容器，经 `容器转文本` 拿到参照实现的文本，再走我们自己的 `文本 → 记号 → 文本` 判恒等。

**默认状态**：资源清单里**不含**参照实现（因为既有硬约束是「`e.exe`/`el.exe` 只读解析、不许运行」）。所以缺口现在是**「已裁定怎么关、开关未打开」**，不是「无解」。

打开它的动作只有一步：加一条资源声明。**这一步由华哥点头才做**——它是「运行那个可执行文件」这件事本身，不是我能自己决定的范围。在此之前，编译器那条线按**语料可验的两层**推进：`容器字节 ⇄ 容器结构`（已过 1444/1444）与 `段数据 ⇄ 记录流`（在飞）。

## 七 明确不做

| 不做 | 为什么 |
|---|---|
| 不做「尽力而为地猜黑盒」 | 猜出来的东西不能当判据；宁可不验，不要假验 |
| 不做资源专属的第二套调用形状 | 资源与能力是同一套形状的两个被调方；两套形状必然漂移 |
| 不把 `入口` 写进声明仓 | 声明可公开、入口不公开；混在一起两边都做不好 |
| 不让资源自己声明「我守时」 | 黑盒的自述不是判据；超时与配额由关口执行 |
| 不做「默认允许」 | 默认允许 = 每加一个资源都扩大攻击面；默认拒绝才是有界的 |
| 不把 `输入类型` 收窄成「恒单入参」 | 那是**收窄约束**：多入参操作就表达不出来。能力不足就补底座，不许收窄约束绕过（老仓第 7.7）；`输入类型` 是**表**（§三 规则 4） |
| 不用资源网关口代替扩展装载 | 扩展**提供能力**（底座认识它的编号），资源**被访问**（底座不认识它的内部）。两者是接缝的两侧，不许合并 |
