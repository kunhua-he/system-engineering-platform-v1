# 语言选型对照

上级：系统工程平台 V1 ／ 落点：`项目文档/设计文档/语言选型对照.md`

**前提**：V1 的宪法第 9 条已定——语言不构成架构决策，只有一个适配器，绑定由契约生成，实现语言按效率就地选、允许混用。本文不是「选一个语言做全平台」，而是**给每个节点挑它最合适的语言**。

---

## 一 结论先说

1. **没有任何一个语言适合所有节点。** 按节点选，不按平台选。
2. **边界与内核首选 Rust**。理由不是「快」，是**不容易漂移**：无隐式数值转换、`#[repr(C)]` 与 `extern "C"` 要显式写、所有权模型天然对上「所有权单向」，漂移在编译期就报错，进不了制品。
3. **能力实现按能力选**。同一个平台里，文本处理用脚本、数值计算用编译型、界面用前端栈，互不冲突——它们只经边界说话。
4. **前端与工具随便选**。它们不在边界内，漂移的代价由各自的测试兜。
5. **判据是效率，不是统一**。统一语言会为了迁就最弱的那个节点牺牲最强的节点。

## 二 选型的尺子：本项目只在意这九条

通用语言评比（流行度、薪资、社区大小）与本项目无关。下面九条全部来自 V1 的宪法与三条补缺陷，**任一条不达标的语言，就不能放在对应节点上**。

| # | 判据 | 为什么本项目在意 | 对应 |
|---|---|---|---|
| 1 | **跨边界 ABI 可控** | 边界只有一个，必须能稳定给出确定的函数表与结构布局 | 宪法 1 · 3 |
| 2 | **漂移抵抗** | 契约是唯一事实源；实现与契约的偏差必须编译期就报，不能靠人盯 | 宪法 2 · 7 |
| 3 | **所有权可控** | 入参归调用方、返回值交出、跨边界只认一个分配器 | 宪法 4 |
| 4 | **开销可预测** | 单项超时要有意义，启动代价要能裁剪成多种形态 | 宪法 6 · 8 |
| 5 | **并发与实例隔离** | 状态不落进程级全局，两个实例互不污染 | 补缺陷·多实例安全 |
| 6 | **错误可编程** | 错误必须是结构化码，不是异常或字符串 | 补缺陷·失败可编程 |
| 7 | **留痕不阻塞** | 每次跨边界调用留痕，且留痕不能拖慢调用 | 补缺陷·可追溯 |
| 8 | **构建可重现** | 主结构冻结、形态裁剪、制品可复现 | 宪法 8 |
| 9 | **平台与部署覆盖** | 制品要能落到目标平台，含无运行时的裸形态 | 宪法 8 |

## 三 大量语言的优势与劣势

按族分组。每条只写**本项目视角**下的优劣，以及能放在哪个节点上。

### 系统级 / 编译型

| 语言 | 优势 | 劣势 | 本项目落点 |
|---|---|---|---|
| **Rust** | 无 GC 与无运行时；`repr(C)`/`extern "C"` 显式声明边界；无隐式转换，类型错就在编译期；所有权与借用＝「所有权单向」的语言级实现；`Result` 强制处理失败＝「错误可编程」的天然形态；edition 每三年一次且**可选**，语言本身不漂；静态链接可裁剪出裸形态 | 编译慢；学习曲线陡；GUI 与快速原型生态弱；跨语言 FFI 样板多（正由「绑定由契约生成」解决）；async 生态仍在演进 | **边界协议 · 适配器实现 · 内核** 首选；要求确定性的能力实现 |
| **C** | 唯一真正的通用 ABI；几乎所有语言都能调；零运行时；编译产物最小；工具链无处不在 | 无类型安全、无边界检查、手动内存＝漂移几乎不可防；错误只能靠返回码加约定；宏与未定义行为是长期负担 | 只在必须与既有裸 ABI 对接时；不作为新写代码的默认 |
| **C++** | 能同时给裸 ABI 与高层抽象；生态最厚的系统级库；模板可做零开销抽象 | 语言复杂度极高；隐式转换与拷贝语义是漂移温床；构建系统与 ABI 兼容性历史包袱重；同一段代码不同编译器行为可不同 | 现状兼容；新写边界不选它 |
| **Zig** | 无隐式控制流、无隐藏分配；`comptime` 让泛型零成本；内置 C ABI 互操作与交叉编译；构建系统自带 | 生态与人才都少；语言仍在 1.0 前，语义会变＝**漂移风险**；包管理刚起步 | 观望。若「构建可重现」成为最痛的点可试点 |
| **Go** | 编译快、部署单文件、交叉编译省心；并发模型简单；标准库与工具链质量高；新人上手快 | **带 GC 与运行时**，边界内停顿不可预测；接口是隐式的，契约边界不显式；错误靠返回 `error` 且无段位＝要额外包装才够「可编程」；泛型刚有，抽象能力仍弱 | **能力实现**很合适（网络/IO/服务类）；**不进边界** |
| **D** | 兼具 GC 可选与系统级能力；`extern(C++)` 互操作；语法比 C++ 干净 | 社区小、工具链分裂（多套标准库）；GC 与 `@nogc` 混用易出坑 | 不考虑，无独占优势 |
| **Nim** | 语法接近 Python 但编译成 C；GC 可关；宏系统强 | 生态小；语义与工具链稳定性不足＝漂移风险 | 不考虑 |
| **Ada** | 强类型、契约式设计（前置/后置条件内建）、并发与实时支持一流；适航级验证历史 | 生态与人才稀缺；工具链贵；与主流栈互操作成本高 | 若将来有硬实时或安全认证要求再看 |
| **Object Pascal / Delphi** | 编译快、可读性好；Windows 原生与 VCL 生态成熟 | 跨平台与开源生态弱；社区萎缩；现代工具链分裂 | 不考虑（参照物里有历史包袱，不继承） |
| **Swift** | 类型安全、值语义、错误处理清晰；Apple 平台首选；`@convention(c)` 可给 C ABI | 非 Apple 平台生态弱；Linux 支持可用但周边少；工具链与 Xcode 绑定 | 只在做 Apple 客户端时用 |
| **Assembly** | 完全可控；无任何运行时 | 不可维护；不可移植；漂移无法防 | 只在极端性能热点或引导代码；不作为语言选型 |
| **Fortran** | 数值与数组运算性能一流；长期科学计算库积累 | 通用性差；字符串与 IO 弱；生态封闭 | 若出现大规模数值内核可借其库，经边界接入 |

## 四 为什么边界与内核倾向 Rust（把「不容易漂移」说清）

「漂移」在本项目里有三个具体含义，Rust 恰好三条都挡：

**其一，实现与契约的漂移。** 契约声明了参数表的行序、类型、返回与错误段位。C 或 C++ 里参数传错顺序、整数宽度悄悄变窄、结构体字段被编译器插入填充，都要靠人盯；Rust 里没有隐式数值转换，跨边界必须写 `extern "C"`，结构布局必须写 `#[repr(C)]`，宽度必须写 `i32`/`u64` 这类明确类型——**写错就编译不过**。

**其二，语言自身的漂移。** Rust 的 edition 每三年一次，且**是可选开关**：老代码不升 edition 就不受影响，新语法不会污染旧代码。对比 C++ 每个标准都在改语义细节、Python 2→3 一次断层、Zig 尚未 1.0——边界上的语言不能是「每隔几年就要重审一遍」的东西。

**其三，代码行为的漂移。** 所有权与借用把「谁持有、谁能改、什么时候释放」写进类型；`Result` 让失败无法被忽略，正对上「错误必须是结构化码、调用方能编程处理」；无 GC 意味着没有不可预测的停顿，单项超时才有意义。

代价也说清楚：编译慢、学习曲线陡、GUI 与快速原型生态弱、跨语言 FFI 样板多。最后一条正是 `跨语言适配/语言绑定/` 存在的理由——绑定由契约生成，人不写。

## 五 节点 → 语言

| 节点 | 首选 | 备选 | 说明 |
|---|---|---|---|
| `跨语言适配/边界协议/` | Rust | C（仅当必须裸 ABI） | 边界形状要冻结，语言自身也必须稳 |
| `跨语言适配/适配器实现/` | Rust | Go | 无 GC 停顿；只此一个适配器 |
| `跨语言适配/语言绑定/` | **生成物**，无手写语言 | — | 由契约生成，各语言各一份 |
| `运行内核/` 全部节点 | Rust | — | 定长数据槽、分配器、注册表都要求确定性与单一所有权 |
| `能力实现/系统环境/` | Rust | C++ / Go | 要与宿主打交道，确定性优先 |
| `能力实现/文件目录/` | Rust | Go | IO 密集，但要可预测超时 |
| `能力实现/文本编码/` | Rust | Python（原型） | 编码转换易错，静态类型收益大 |
| `能力实现/数据存储/` | Rust | Go / Java | 内部可用 SQL；引擎选型另议 |
| `能力实现/界面组件/` | Rust（绑系统 UI） | C# / Swift / Dart | 按目标平台选，经边界接入 |
| `能力实现/可选扩展/` | 任意 | — | 第三方能力，只要求经边界说话 |
| `前端呈现/网页应用/` | Vue + TypeScript | React + TypeScript | 不在边界内 |
| `前端呈现/桌面应用/` | 视平台 | — | 可与网页应用共用前端栈 |
| `前端呈现/命令行界面/` | Rust / Go | Python | 单文件分发优先 |
| `构建装配/` | Rust / Go | Python | 装配与检查要可重现 |
| `开发工具/` | Python | Rust / Bash | 开发期工具不进制品，效率优先于严格 |
| `测试验证/` | 与被测层同语言 | Python | 端到端测试可全用脚本 |

## 六 与宪法的对照：哪些语言被哪条排除

| 宪法 | 排除了什么 |
|---|---|
| 第 3 条 类型标签在槽内 | 排除一切**在边界上擦除类型**的语言与机制（TypeScript 的类型擦除、动态语言的运行时类型丢失）——它们只能待在边界之外 |
| 第 4 条 所有权单向 | 排除**共享可变状态为默认**的语言进内核（多数带 GC 且对象到处引用的语言） |
| 第 6 条 按号取用未命中返回空 | 排除把**异常当作跨边界主通道**的用法（Java/C++/Python 的异常必须在边界处转成结构化码） |
| 第 7 条 号段只增不复用 | 与语言无关，但要求**编号生成走工具**，不靠人写 |
| 第 8 条 一套源码多形态 | 排除**强依赖运行时环境**的语言做裸形态（Python/PHP/Node 必须有解释器或运行时） |
| 第 9 条 语言不是边界 | 排除「为了统一语言而让某个节点将就」的所有方案 |

## 七 待实测（未定项）

1. **边界协议形态会改变选型自由度**。若最终是线协议（进程间/网络），边界内语言自由度更大；若是进程内 C ABI，Rust 的优势更绝对。此条与 README 第十节的未定项联动。
2. **需要一次绑定生成链实测**：Rust ↔ Python、Rust ↔ Java、Rust ↔ TypeScript 三条，验证「由契约生成绑定」可行且生成物可读。
3. **需要一次形态裁剪实测**：同一套 Rust 源码能否稳定产出「静态链接裸形态」与「带运行时形态」两种制品。
4. **Go 进边界的否决是否成立**：需实测 GC 停顿对单项超时的实际影响，再决定它是「不进边界」还是「可进但设更长超时」。

## 前端选型收口（2026-09-26，本条是裁决，与 `代码形态分工.md` 第七节同源）

**本文件原先把 Vue(TypeScript) 写成 `前端呈现/网页应用/` 的默认选择，与 `代码形态分工.md` 第七节「无构建步骤的原生 ES 模块」直接矛盾 —— 两份设计件对同一件事两个说法，这本身就是漂移。以本节为准。**

**裁决：前端 = 无构建步骤的原生 ES 模块（HTML + CSS + `<script type="module">`）。**

| 候选 | 为什么不是它 |
|---|---|
| **Vue / 任何带构建器（Vite/webpack）的方案** | 要 npm ⇒ 引入 `node_modules` 依赖图 + 锁文件 + 构建产物。**最致命的一条：运行的字节 ≠ 审阅的字节** —— 产物是源码的变换，人读不了，而本项目的全部价值是「读数可信 + 制品可指纹」。**多一条构建链就多一处漂移，而且是最难判的那种。** |
| **PHP** | 它是**服务端**语言。要用它就得起**第二个 HTTP 服务** ⇒ 直接违反判据 ⑪「对外监听恰好 1 处」。而且它不省事：客户端的交互仍然得写 JS，只是多了一个运行时。 |
| **Go** | ① 它是**第二个工具链**（本仓钉死 `rust-toolchain.toml` 一个工具链、零第三方依赖）；② **它替代不了客户端** —— 浏览器里只能跑 JS 或 WASM；③ Go 编到 WASM 的正当用途是**性能热点**（见 `代码形态分工.md` 第一节与第七节），不是 UI 壳；④ 服务端已经是 Rust 网关，且已冻结。 |
| **TypeScript（要 `tsc`）** | 同 Vue 第一条。**唯一可接受的形式**是「JSDoc + `// @ts-check` + 只读检查（不产出）」—— 那不算构建步骤，但**现在不需要**：前端薄到不需要类型（见下）。 |

**客户端其实只有两个漂移最小的选择：原生 ES 模块，或 WASM。** 而 WASM 在本项目的用途是 `.能力包件`（**编译产物**，见 `能力包件.md`），不是 UI。

**「JS 没有类型、怕漂移」这条担忧的正确解法不是引 TS 构建链，是让前端薄到不需要类型。** 实测：前端现在 **438 行**（`取接口.js` 64 · `呈现.js` 112 · `应用.js` 146 · `index.html` 116），**零业务逻辑**（判据面有一条专门数「前端 0 处解析/生成/校验」）。**漂移抵抗靠的是薄，不是类型。**

**环境实测（本机已装齐，所以这不是「装不上」的问题，是「装了就会漂」的问题）**：`node v22.23.0` · `npm 10.9.8` · `php 8.5.5` · `go` · `python3 3.14.4` · `cargo 1.95.0`。
