# MCP 工具面不犯错纪律

> 本件是「MCP 工具面异常 / 失败时，代理如何不犯错」的**唯一落点**（一份，不双写）。
> 为什么单立：工具面是常驻网关（HTTP 43140）带自愈重载，长活会跨过前台窗口、会断链、会被重试；
> 没有一处写清「什么算工具坏、什么算业务失败、哪些能重放」，代理只能靠猜 —— 猜错就把
> 「工具异常」当「业务判词」，或把「超时」当「失败」。
> 一句话：**工具回执只是读数，不是判词；唯一的凭据是真实提交与可复现读数。**

## 一 分清「工具坏了」与「业务真失败」

- 工具层异常（进程崩 · 网关重载 · 连接断 · 前台窗口超时）**不是**业务失败，**不许**当业务判词。
- 已编码：`作业.py` 转后台后回 `服务常量.待取作业码`（-3）+ `错误.种类 = 待取作业` + 运行中任务ID
  ⇒ 这是「还没到终态」，不是失败；`协议.py` 明写「未到终态 ≠ 失败」；`信封样本.py` 钉三态
  （同步完成 / 窗口内未完成 / 后台真失败）。
- 判定法：先取终态（`v1_job` 操作 status / log）；只有**作业到终态且退出码非 0**才算业务失败。

## 二 重试边界（哪些可重放、哪些不可）

- **可重放（只读 / 幂等）**：`v1_context` · `v1_tree` · `v1_search` · `v1_symbol` · `v1_db` · `v1_repo` ·
  `v1_log` · `v1_job` 的 status / log · `v1_task` 的查询类操作 —— 重放只多读一次。
- **有副作用、绝不自动重试**：写盘（`v1_edit`）· 记账（`源件记账` / `生成物记账`）· 推送（`git push`）·
  合并（`合并主干`）· 释放 · 判词 / 关闭。`作业.py` 明写：`start` 每次建**新**作业，`push` / `merge` 绝不自动重试。
- 有副作用的操作若「结果未知」（超时 / 断链），先**读**（`v1_task` 取检查点 · 工具流水 · `git log`）
  确认它到底做没做，再决定是否重发 —— 不许凭「没看到回执」就再发一次。

## 三 失败留痕与唯一凭据

- 失败必须留痕：具体错误内容 + 事项（不许只报「失败」）。
- **不许拿工具回执的自我声明当证据**：完成 = 真实提交对象（`git log`）+ 可复现读数；状态字段会漂，不作凭据。
- 验证关闭类操作（`验证关闭`）须给真实存在的承接提交，工具会做 git 校验。

## 四 断链恢复口（三条读数互证）

- 断链 / 换会话 / 崩溃后，先取检查点：`v1_task` 操作 `取检查点`（开工行 + 认领 + 改动 + 恢复摘要）。
- 三条读数互证：① `取检查点`（项目记忆）② 工具流水（`~/.zcode/cli/log/*.jsonl` · `v1_log`）③ 作业日志
  （`<运行数据根>/日志/<任务ID>.log`）。三者不一致时，以**真实提交与盘上读数**为准。

## 五 假绿与假红

- 假绿：空集当通过 · 部分绿当全绿 · 把「未判」当「通过」。
- 假红：超时当失败 · 工具异常当业务失败 · 把「还没到终态」当失败。
- 识别法：看判据的**对象数**（0 ⇒ 未判，不是通过）；看退出码的**语义**（-3 待取作业 ≠ -1 失败）；
  分清「同步窗口内没跑完」与「后台真失败」。全文见库条款 `项目文档/设计文档/判据的可信性.md`。
