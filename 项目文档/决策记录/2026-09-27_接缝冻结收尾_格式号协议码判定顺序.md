## 一 声明格式号（#86）：裁决 3 的施工 —— 实测**有门**，按裁决升阻断级后**改值**

**先查门（裁决 3 要求的第一步）**：拿这个数**做了门**，而且**两道**：

- 判定①：`运行内核/装载入口/src/判定.rs::判定可装载` 第一步 `声明.声明格式号 != v1_contract::声明格式号`。
- 建表①：`运行内核/统一注册表/src/建表.rs` 建表第一步同款比对（`建表错误::声明格式号不匹配`）。

⇒ 按裁决 3 的分支，这**不是**「将来接上时爆」，而是**现存的静默错误装载入口**，优先级升到阻断级。

**裁决：改值。** 取 ASCII `SYS1` = `0x53595331` = `1398362929`。

- **为什么不能留 `20000101`**：参照实现 `LIB_INFO.m_dwLibFormatVer` 用它，`lib2.h` 对这个数的用途原话正是「防止错误装载」；我方 `平台信息` 结构与它**不同**（字段顺序 / 集合 / 版本宽度三处都不同，`项目文档/设计文档/接缝实测.md` §七）⇒ 同值让这一关**形同虚设**：一份用参照实现格式号写的声明会被放行，然后按我方布局解出垃圾。
- **为什么取 ASCII 而不是日期 / 版本形态**：`契约声明/格式说明.md` §二 明确它「不是版本号，格式不变它永远不变」，日期形态会被误读成版本。
- **值本身可换**：它只需满足「与参照实现不同 + 永不改」。若要别的值，改 `契约声明/常量表.json` 与 `契约声明/平台声明.json` 两处、重跑生成器即可。

**施工**：`契约声明/常量表.json` · `契约声明/平台声明.json` 同改 → 重跑 `构建装配/形态装配/生成声明.py`（`--检查` 退出码 0）→ `契约声明/src/声明数据.rs::底座声明格式号 = 1398362929`。已登记 `契约声明/冻结登记.json` 旁路。

**未做（不在本腿所有权，归各落点）**：`扩展根目录/原子支持库/编译器支持库/包声明.json` · `项目文档/设计文档/接口面形状.md` §三 示例 · `项目文档/设计文档/接缝实测.md` 的两处读数 · `跨语言适配/适配器实现/src/接口描述.rs` 的文件头示例。

## 二 协议层结果码（#16）：**冻数值**

- **现状**：`边界协议.md` §三 只定「`int32_t` 只表达成功 / 参数不合法」这个**口径**，**没给数**；`跨语言适配/适配器实现/src/边界面.rs::协议结果` 自定 `成功 = 0` / `参数不合法 = -1`。
- **裁决：冻 `成功 = 0` · `参数不合法 = -1`，只有这两个数**（第三个数须走 `契约声明/冻结登记.json` 旁路登记）。业务失败不占返回码（一律回 `成功`，真实结果在返回槽的错误码里）。
- **为什么必须冻**：不冻则每种语言的绑定各定一套，而「一个适配器适配所有语言」的前提正是**边界只有一套形状**。
- **施工**：`跨语言适配/边界协议/边界协议.md` 新增 §三·一（数值 + 触发 + 理由）与 §四 判据 6（取值恰好 `{0, -1}`）。已登记 `契约声明/冻结登记.json` 旁路。
- **承重证明（退回一步）**：若**不冻**（保持「只给口径不给数」）—— 每条语言绑定各自定义（Python `0/-1`、Java `1/0`…），而 `跨语言适配/适配器实现/src/边界面.rs::协议结果` 已是既成事实的 `0/-1` ⇒ 「一个适配器适配所有语言」退化成「每种绑定各一套数」。冻它 = 把既成事实变成契约；退回 = 边界形状出现 N 套。
- **防回潮**：§四 判据 6（取值集合 ⊆ `{0, -1}`）。**诚实标注：暂无 runner** —— 在 runner 接上前它只是**文本约定**，不许当成已有判据（接法已写在那一行）。
- **未做**：`边界面.rs::协议结果` 的注释仍写「本文件是这两个数的唯一定义处」，与「契约侧 §三·一 是冻结口径」构成两处源 ⇒ 归适配器侧改成引用本节的数（本腿所有权外）。

## 三 判定顺序（#148）：裁定「先撞号段」显式化 —— **施工不在本腿**

**实测现状（更正旧描述）**：`跨语言适配/适配器实现/src/适配器测试.rs::装载_扩展撞底座号段即拒` **已经**显式匹配 `载入错误::号段冲突` 并断言 `(起, 止)`；其夹具 `跨语言适配/适配器实现/src/测试夹具.rs::造扩展声明` 的 `编号 = 号段.起`、`状态位 = 0` ⇒ 以底座段 `[0,999]` 调用时 `编号 = 0` **落在申报号段内**（裁决 5），且非错误项 ⇒ 第 ⑥ 步 `判声明自洽` **不会**也报错。**⇒ 当前这条样本并没有靠「③ 先于 ⑥」的顺序巧合。**

**裁决不变**：顺序**不许是隐式的** —— 后人把夹具改成错误项、或改判定顺序，就会坏。

**裁定**：把「**号段冲突（③）先于声明自洽（⑥）判定**」写成**显式口径**，不靠实现顺序：
① `扩展装载/载入约定/载入判定.json` 的「判定顺序」明写这条优先级；
② `适配器测试.rs` 那条样本注明「本样本只撞号段（编号落申报段内、非错误项），断言的是号段冲突本身，不依赖步骤顺序」。

**未施工 —— 缺什么**：落点 `扩展装载/载入约定/` 与 `跨语言适配/适配器实现/` **都不在本腿所有权**（本腿只有 `扩展装载/开发标准/**`）。缺 = ① 一条显式顺序口径 ② 一条「夹具改成错误项后仍报号段冲突」的反向样本。

### 施工完成（2026-09-27 · 协调方）

① **显式口径已落**：`扩展装载/载入约定/载入判定.json` 新增键 `判定顺序的优先级`（**不是**塞进 `判定顺序` 数组 —— 那是数组，装不下这句话；作为兄弟键，语义等价且更可读）。写明「六步是 fail-closed 的**先于**关系 · **号段冲突（步 3）先于声明自洽（步 6）** · 数组顺序只是这条先于关系的一种排布，**改数组顺序不许改判定语义**」。**未走 `冻结登记.json`**：该件不是冻结件（`冻结登记.json` 里只在一条「缺口」的说明里提到它，不是冻结项），且全仓只有准入判据按**文本**读它（`一键验证.py` 完全不读）。

② **反向样本已落**，且**落成两条、各有其职**：
   - **行为侧（真证明）**：`跨语言适配/适配器实现/src/适配器测试.rs::装载_同时撞号段与不自洽_先报号段冲突` —— 同一份夹具**同时**成立 ③（编号 `0` 落在底座段 `[0,999]`）与 ⑥（`状态位 = 命令状态::错误` 而段位 `0` 不在夹具的 `错误段位表 = [1]`）⇒ 断言报的是**号段冲突**。**并带一句「非空转自证」**：换不撞的号段（`[3000,3999]`，段位 3 仍未登记 ⇒ ⑥ 仍成立、③ 不成立）⇒ 报的必须是 **⑥ 声明不自洽**。两句合起来才排得掉「⑥ 那一支根本不会响」。实测 `cargo test -p v1-adapter --locked 装载_` ⇒ **5 passed / 0 failed · 退出码 0**。
   - **文本侧**：`测试验证/准入判据/准入判据.py` 的 ⑪ 样本从「正=注入 · 反=**真文件现状**」改成「正=**真件** · 反=**真件去掉那条键**（合成）」。**为什么必须改**：原来的反向样本读的是实物，实物一被修好，反向样本就**当场消失**（判据的身份证没了）—— 违反 `判据的可信性.md` §五「反向样本 + 正向样本」是**固定**输入的要求。实测 `准入判据.py --自测` ⇒ **退出码 0 · 样本断言全过**；`准入判据.py` 读数由 通过 7 · 失败 2 变成 **通过 8 · 失败 1**（⑪ 由红转绿；剩 1 条是 ⑭ 指纹，归语言主线收口时刷）。
