# 组件操作协议草案（2026-11-02）

> 定位：把「组件句柄式交互」从两个操作（排序、翻页）扩成一整套协议。
> 目标：V4 不为任何组件写前端逻辑，所有操作都是「拿句柄 + 报操作名 + 传参」。

## 零、已落地（2026-11-02）

- 渲染即签发：每个渲染出来的节点都登记实例、发一个句柄（起点 `100000`），节点上带 `data-hs-h`。
- 4929 已支持八个操作：`排序` `翻页` `移动` `设置` `最小化` `最大化` `还原` `嵌套`；属性名可直接当操作名。
- 回执统一 JSON：`{"片段": "<html>", "句柄组": [数字…]}`；片段只含这一个组件。
- 父子同步：子组件的声明在父容器的「子」数组里也有一份，改子组件会同步写回父容器，
  否则会出现「子组件改了、父容器照旧画」。
- 嵌套回句柄组：`嵌套` 按插入顺序回新签发的子句柄。
- 真实 HTTP 实测（走 43110 网关）：移动 `上:"+100"` → `top:120px`；`宽:"-50"` → `width:250px`；
  排序同列再点一次换方向（`▲` ↔ `▼`）；最小化 → `height:38px`，还原 → `height:200px`；
  嵌套回 `[100010, 100011]`；释放后同一句柄操作报 `4924 组件句柄无效`。

## 一、一句话形态

```text
渲 染 树（声明）        → 得到整页 + 每个可交互组件的句柄
操 作 组 件（句柄, 操作名, 参数） → 只回这一个组件的新片段（最小渲染）
读 组 件 状 态（句柄）   → 回当前状态（排序、页码、位置、文本…）
释 放 句 柄（句柄）      → 一次性组件用完就还
```

- 一个入口：底座只认 `操作组件`，不为每个组件各开一条腿。
- 操作名就是动词或属性名：`移动`、`排序`、`最小化`、`文本`、`标题`、`嵌套`、`释放`。
  `编辑框.文本='文本'` 与 `编辑框.设置({文本:'文本'})` 等价，两种写法都不必分家。
- 参数一律是 JSON 对象；组件类型决定认哪些键，认不得的键直接拒，不静默丢弃。

## 二、容器 = 有序组件清单（骨架一次，格子各刷）

一个容器里有什么，就写成一个**有序数组**：数组里每一项是一个组件，写清「类型 + 该组件自身的初始参数」。
容器只管顺序与排布，**不转述**子组件的参数；子组件的参数归子组件自身。

```json
{
  "类型": "画布",
  "键": "桌面",
  "子": [
    { "键": "壁纸", "类型": "原样", "内容": { "类型": "图片", "资源": "/资源/…" } },
    { "键": "图标网格", "类型": "网格", "列数": 6, "行间距": 12, "列间距": 12 },
    { "键": "工作区", "类型": "行", "内边距": "0 12px" }
  ]
}
```

- `键` 可选：给了就能用「键」直接定位（人读得懂、日志里也认得）；不给就只用句柄。
- 渲染回执除 HTML 外，另给一张「键 → 句柄」对照，页面宿主存着，后续操作按需取句柄。
- 改一个组件只碰该组件自身：`操作组件(句柄, "移动", { "上": "+20" })` → 只回这个组件的新片段。
- 容器加子组件：`操作组件(容器句柄, "嵌套", { "子": [ {"类型":"表格", …} ], "位置": "末位" })` → 回新句柄组。

这样分工干净：

```text
树/容器    →  孩子是谁、什么顺序、怎么排（骨架）
子组件     →  自身长什么样、参数是多少（格子）
句柄       →  寻址：操作谁就传谁的句柄
```

好处正是你说的三条：改一处不用大改重画；组件之间只靠句柄联系；底座只有一套入口，不因组件变多而变脏。

## 三、传参语义（三条，全局统一）

数值类（左、上、宽、高、字号、层级、页码…）：

- 给数字（`100`）：**绝对设置**。
- 给带符号字符串（`"+20"` / `"-20"`）：**在当前值上增减**。
- 不给这个键 / 给 null / 给空串：**继承原值，不动**。

文本类（标题、文本、占位提示、值…）：

- 给字符串：整体替换；空串 `""` 表示清空。
- 不给这个键：继承原值。

逻辑类（是否最大化、是否可见、是否开合、是否升序…）：只收 `真` / `假`。

这条规则的价值：界面微调不用重画整棵树，也不用前端算坐标。

```text
容器.移动(左, 上, 宽, 高)
容器.移动(, 100, , )     → 只把上边设成 100，其余继承
容器.移动(+20, , , )     → 左边右移 20，其余继承
容器.最小化 = 真          → 缩到最下面
```

## 四、句柄规则

- **签发**：渲染树时，凡声明了可操作的组件都登记成一个实例并发一个组件句柄；节点上带 `data-hs-h`。
- **段位**：组件句柄用 `100000` 起（与能力号 4xxxx、窗口标识分开，看数字就知道是什么）。
- **句柄组**：`容器.嵌套(('表格','按钮'))` 回 `[表格句柄, 按钮句柄]`，顺序与传入的类型列表一致。
- **一次性**：弹层、确认框、临时子组件，用完即 `释放句柄`。
- **常驻**：页面/窗口级的组件，页面卸载或窗口关闭时统一释放；超过空闲上限按归属回收。
- **永不复用**：句柄用过即废，旧页面操作不到新实例。

## 五、组件清单（按现在底座能渲染的来，缺口单列）

容器类（能装子组件、能移动、能嵌套）：

- `行` / `列` / `网格`：布局容器，操作 = 移动、间距、对齐、嵌套。
- `侧栏`：操作 = 移动、展开/收起、宽度、嵌套。
- `分区`：操作 = 移动、标题、展开/收起、嵌套。
- `画布`：操作 = 移动、嵌套；子组件用绝对坐标。
- `窗口`：操作 = 移动、最小化、最大化、还原、关闭、置顶、标题、开合。
- `表单容器`：操作 = 移动、提交地址、嵌套。
- `悬浮层`：操作 = 显示/隐藏、移动、嵌套。

叶面类（有内容，改内容是常态）：

- `文字` / `标题`：操作 = 文本、字号、颜色、粗细、对齐。
- `图标`：操作 = 尺寸、颜色、资源。
- `按钮`：操作 = 文本、变体（默认/主要/成功/警告/危险）、禁用、点击回传地址。
- `输入`：操作 = 文本（值）、标题（标签）、占位提示、类型（文本/密码/数字/邮箱）、只读、禁用。
- `表格`：操作 = 排序、过滤、翻页、选中行、追加行、删除行、列宽、每页行数。
- `聊天流`：操作 = 追加消息、清空、滚动到底。
- `原样`：操作 = 替换 HTML（同源白名单内）。
- `分隔条`：操作 = 位置、方向。

**缺口（现在底座没有，要新造节点类型）**：

- `文件夹`：文件树 / 文件列表（现在的文件管理是拿表格凑的）。需要：展开节点、选中、进入目录、面包屑。
- `浏览器`：内嵌网页视图（同源或白名单域名），需要：载入地址、前进后退、刷新。
- `列表`：通用条目列表（选择、多选、拖排序）。
- `菜单`：右键菜单 / 下拉菜单（弹层定位、选项回传）。
- `进度条` / `状态条`：长任务的可视反馈。

## 六、每个组件最少要有的操作（先做这批）

1. `移动`：左、上、宽、高（三条传参语义都吃）。
2. `设置`（或直接写属性名）：标题、文本、颜色、可见、层级、圆角、字体大小。
3. `窗口三件`：最小化、最大化、还原。
4. `表格四件`：排序、过滤、翻页、选中行。
5. `嵌套`：往容器里加子组件，回句柄组。
6. `释放`：还句柄。

先把这六类做实，其余组件按同一张表往后长；新增组件 = 加节点类型 + 在操作表里加一行，不改入口。

## 七、最小渲染与并行

- 每次操作只回该组件那一块片段，页面只替换那一个节点；不整页刷新，用户看不到闪。
- 不同组件的操作互不相干，天然并行；底座按句柄取实例、算完就放，不长时间持锁。
- 状态挂在实例上，页面不在就回收 —— 组件不常驻，进程不必一直在。

## 八、待裁（需要华哥定的一只手数得完的点）

1. **句柄段起点**：用 `100000` 起，还是照你举例的 `10000` 起？（我倾向 100000，六位不容易和能力号混）
2. **属性直当操作名**：`编辑框.文本='文本'` 这种写法保留吗？保留就少一层 `设置` 包装；不保留就统一走 `设置`。
3. **缺口组件优先序**：`文件夹` 与 `浏览器` 先做哪个？（文件管理现在拿表格凑，`文件夹` 更像真缺）
4. **嵌套创建的类型白名单**：是「谁都能嵌」还是「容器只能嵌声明里许可的类型」？后者更安全但要多写一份许可表。
