# 组件收敛裁决（2026-11-02）

> 一句话：**组件类型冻结在 21 种，只补 2 个；重复字段合并；其余一律不做，并写清替代方案。**
> 目的不是把易语言的组件搬过来，而是让底座不再无限长类型。

## 一、冻结清单（21 种，到此为止）

现有 19 种（不动结构，只统一字段规则）：

- `窗口` · 对应易语言 窗口 · 动作：移动、最小化、最大化、还原、标题
- `分区` · 对应 分组框 / 外形框 · 动作：移动、标题、嵌套
- `行` / `列` / `网格` · 对应 布局容器 · 动作：移动、间距、嵌套
- `侧栏` · 无直接对应 · 动作：移动、展开收起、嵌套
- `画布` · 对应 画板 · 动作：移动、嵌套（子组件按左、上定位）
- `悬浮层` · 对应 弹出层 · 动作：显示隐藏、移动、嵌套
- `分隔条` · 无对应 · 动作：位置、方向
- `文字` / `标题` · 对应 标签 · 动作：文本、字号、颜色、对齐
- `图标` · 对应 图片框（静态图）· 动作：尺寸、颜色、资源
- `按钮` · 对应 按钮 / 图形按钮 / 超级按钮 · 动作：文本、变体、禁用、点击回传
- `输入` · 对应 编辑框 / 组合框 / 日期框 / 颜色选择器（靠 `种类` 区分）· 动作：文本、标题、占位、种类、只读
- `表格` · 对应 表格 / 报表 / 超级列表框 / 高级表格 · 动作：排序、翻页、过滤、选中行、追加行、列宽、每页行数
- `聊天流` · 无对应（我方独有）· 动作：追加消息、清空
- `表单` / `表单容器` · 无对应 · 动作：提交地址、嵌套
- `原样` · 对应 超文本浏览框 / 互联网浏览器（走 iframe 白名单）· 动作：替换内容

新增 2 种（这是唯一的加法）：

- `树型框` · 对应 树型框 / 目录框 / 驱动器框 / 文件框
  - 职责：分层条目，可展开收起、可选中、可带图标
  - 动作：`展开` `收起` `选中` `嵌套`（加子节点）`移动` `设置`
  - 字段：`条目`（嵌套数组，每项 `键` / `文本` / `图标` / `展开` / `选中` / `子`）、`连线`、`缩进`、`行高`
  - 为什么必须新造：展开与选中是交互状态，`原样` 塞 HTML 做不出来
- `列表` · 对应 列表框 / 选择列表框
  - 职责：一维条目，可单选 / 多选、可拖排序
  - 动作：`选中` `多选` `拖排序` `追加` `删除` `移动` `设置`
  - 字段：`条目`（数组，每项 `键` / `文本` / `图标` / `禁用`）、`多选`、`可拖排序`、`行高`
  - 为什么不复用表格：表格是二维带列头，列表是一维带图标；混用会让表格字段爆炸

冻结的含义：以后新增第 22 种类型，必须写进本文件的追加节并说明「为什么 21 种里没有一个能表达」，口头提出不算。

## 二、不做清单（33 条，每条给替代）

按易语言已确证的界面组件逐条对账，明确不做的不再讨论：

- 选择夹 / 高级选择夹 / 卷帘式菜单 → 不做类型。替代：`分区` + `切换显隐`，多页签就是多个分区按标识互斥显示
- 组合框（下拉） → 不做类型。替代：`输入` + `悬浮层`（点输入框弹悬浮层列表）
- 调节器 / 滑块条 / 横向滚动条 / 纵向滚动条 → 不做类型。替代：`输入` 的 `种类` 声明为数字并交给原生控件；滚动靠容器的 `溢出`
- 日期框 / 月历 / 农历日期框 / 农历月历 → 不做类型。替代：`输入` 种类 `日期`，交给浏览器原生日期选择器
- 颜色选择器 → 不做类型。替代：`输入` 种类 `颜色`
- 进度条 → 不做类型。替代：`分区` + `文字`，进度值走句柄 `设置`
- 状态条 → 不做类型。替代：`分区` 固定底部 + `文字`
- 工具条 → 不做类型。替代：`行` + 若干 `按钮`
- 菜单 / 超级菜单 → 不做类型。替代：节点上的 `右键菜单` 字段 + `悬浮层`
- 气球提示框 → 不做类型。替代：节点上的 `提示文案`（已有 toast）
- 超级链接框 → 不做类型。替代：`文字` + `打开地址`
- 图片框 / 影像框 → 不做类型。替代：`图标`（静态图）/ `原样` 内嵌 `video`
- 动画框 / 动画物体 → 不做类型。替代：`原样` + CSS 动画
- 矢量动画框 / 图形窗口 → 不做类型。替代：`画布` + `原样` 里的 SVG / Canvas
- 柱状图控件 / 曲线图控件 / 饼形图控件 → 不做类型。替代：数据由底座算，图形用 `原样` 里的 SVG 输出
- 超级列表框 / 高级表格 → 不做类型。替代：`表格`（需要多选时用 `列表`）
- 代码编辑框 / 超级编辑框 → 不做类型。替代：`输入` 种类 `多行`
- 通用对话框 → 不做类型。替代：V4 侧的文件上传入口
- 时钟 → 不做类型。替代：V4 侧定时任务（底座不该跑计时器）
- 每日一贴 / 鼠标手势框 → 不做类型。业务用不到
- 脚本组件 → 不做类型。脚本只允许底座那一份公共引导脚本
- 驱动器框 → 不做类型。替代：`树型框` 根节点列出盘符，或直接 `目录框` 语义由 V4 给数据
- 目录框 / 文件框 → 不做类型。替代：`树型框`（目录）+ 文件列表用 `列表`

## 三、字段收敛清单（5 条，本轮已改）

问题：外观字段有两套（通用 21 个、控件 9 个），7 个字段名重复但**取值规则不一样**，同一份声明在两个路径上一个过一个不过。

1. `字号` 与 `字体大小` 值域统一为 1 至 200（现在控件路径是 8 至 72）
2. `字重` 统一为 100 至 900 任意值（现在控件路径要求整百，150 报错）
3. `内边距` 两条路径都已接受纯数字与带单位段（复核代码确认无需改），只把这条写进参数总表，避免读者以为两边不一样
4. 两个字段名互为回退：控件路径也认 `字体大小`，通用路径也认 `字号`，写哪个都生效
5. 参数总表里把这两套标成「同一含义的两个名字，规则已统一」，不再写成两节

收敛后不改变现有界面的任何视觉，也不改 V4 已有声明（V4 里两种写法都在用，见文件管理与桌面外壳声明）。

**已落地（2026-11-02）**：`外观属性.rs` 新增统一取值 `字号取值()`，校验与拼样式都走它；
`控件样式.rs` 的字号上下限改为 1 至 200、字重去掉「必须整百」。网页界面支持库编译零错误零警告。

## 表格行列原子按易语言命名重写（2026-11-03）

- 落点：`src/组件操作/表格行列.rs` 按命名规范整件重写，覆盖插入行、删除行、插入列、删除列、清空、移动列、设置列属性、设置行高、表项提示、列提示、列标题。行级 11 个数组字段与列级 6 个数组字段在行列变更时同步插、删、移；缺位按各字段在声明里给出的默认值补齐（`列宽` 补 `自适应`、`列对齐方式` 补 `左`、图片与提示补 `null`），不留长度不符的半截数组 —— 渲染侧对「数组长度 ≠ 行数/列数」一律判内容不合法，补齐是硬要求。
- 移动列必须同时搬每行对应单元格，否则表头与数据错位；这是重写时补上的口径。
