# MCP 工具层四项修复 —— 生成物记账 · 重复登记检测 · 前置固化 · 认领失败口径

日期：2026-09-27 ｜ 起因：一晚六条腿暴露的四个缺口（`开发工具/MCP服务/`）

---

## 一 生成物记账：`v1_task` 功能 = 5「跑生成器并记账」

**缺口**：生成物由**生成器**写出、本来就不走 `v1_edit` ⇒ `释放` 的「绕过检测」把它们当越界
（`git status` 里有、`改动` 表里没有）⇒ 只要那条腿重跑过生成器，释放**恒被拒**。实测：一条腿
改了 59 件、重跑生成器，收口方只能手工把生成物补进账本 `改动` 表 —— 那是**绕过账本**，不是记账。

**裁**：`v1_task` 加功能 = 5，吃 `开工ID` + `生成器`（仓内相对 `.py`）+ 可选 `生成器参数`。
工具**自己跑那条生成器**，然后：

1. **产出集不写清单** —— 跑前 / 跑后各读一次 `git status --porcelain -uall` 的**盘上指纹**，
   取「这次跑真正写过的件」（指纹变了 / 新出现 / 没了）。生成物的**唯一来源是生成器自己**：
   不另立清单、不另立口径，「由生成器产出」是**跑出来**的事实。
2. **每一件还要自称是本生成器的产物** —— 读产物**自己的头标**（`生成物` ＋ `禁手不改` ＋
   一行 `// 生成器：<同一个生成器>`）。那是 README §九 与判据 ⑩ 已经立的那**一处**标记
   （产物头标四件事），本件只**读**它。有一件不认 ⇒ **一件都不记**（fail-closed）。
3. **记账动作复用账本里已有的两步**：`写回指纹`（认领 upsert）＋ `记改动`（功能
   「生成物（重跑生成器产出）」）—— 与 `v1_edit` 写盘之后那两步**同一套**，不新造写入口。
4. **不放松闸**：`释放` 的越界检测一字未改 —— 没跑过生成器、或生成器没写过的件**照拒**；
   工具还会把「另有这些件脏且不是这次生成器写的」单独报出来。

**为什么不给 `v1_edit` 加这个档**：`v1_edit` 的四道闸建立在「认领 + 指纹 + 旧内容唯一定位」上，
而生成器产出**不由内容定位**、也不逐条给旧内容 —— 塞进去要么给它编旧内容（假的），要么加第二个
schema。且「记账」是账本的事（`v1_task` 已在管登记/补充/释放），落点与 `开工.py::释放` 的越界
检测相邻，两处共用同一个「什么算脏」的解析（`开工.py::变更路径表`）。

**为什么不选「让越界检测认出声明的生成物就放行」**：那样生成物**不会进 `改动` 表** ⇒ 释放提交时
`git add -- <改动表路径>` 根本不带它们 ⇒ 一次「绿着交付、内容缺失」的释放。记账必须落进 `改动` 表。

## 二 重复登记检测（只报不拦）

**缺口**：一条腿登了两次（`v1-100002` 与 `v1-100007`，工作内容一模一样），留下一棵孤儿工作树。

**裁**：`开工账本.py::查重复登记` 两个面 —— ① 未释放开工的工作内容**逐字相同**；② 认领路径
**高度重叠**（重合 ≥ 2 件且占本次认领的一半以上）。**只报不拦**，口径与
`开工账本.py::查跨开工冲突` 同一条（有时确实要重开一条）；路径那一面**复用** `查跨开工冲突`
的读数聚合，不写平行的第二套判断。

## 三 派腿前置固化进工具

**缺口**：六条腿里四条把大半时间花在**重新论证已裁的结论**上 —— 根因是派活信没带共享前置；
收口方补的 `<运行数据根>/临时件/派腿前置.md` 腿**不知道它存在**。

**裁**：`v1_task` 功能 = 1 的返回里加一行指向它（**存在才提**；路径走 `运行数据根` 包取 ——
`开工账本.py::前置提示行`，**不许自身拼路径**，判据 ㉕），并附一句「工具行为异常 ⇒ 让收口方
重启 ZCode（MCP 服务是长驻进程）」。

## 四 认领失败口径：全读不出 ⇒ 返回非 0，且不登记

**缺口**：`文件认领` 里的路径读不到盘 ⇒ 只打印一行「★ 没认领上」但**仍返回码 0**，腿以为认领
成功、到写盘时才撞第 ② 道闸。

**裁**：**给了认领件、却一件都没读上盘 ⇒ 返回 2，并把刚建的工作树清掉、不登记**。
依据：「新建的件不必先认领」（`v1_edit` 功能=0 允许盘上不存在的件，建完指纹自动补进认领表）
⇒ **不存在「合法的全读不出」**，全读不出只可能是路径写错。

- **为什么不选「警告措辞硬到不会被忽略」**：腿的唯一可靠信号是**退出码**（MCP 把它映成
  `isError`）；措辞再硬也在输出末尾、会被略过 —— 今晚那条腿正是看完输出仍以为认领成功。
- **为什么部分读不出仍返回 0**：那几件已在认领集里、腿能接着干，且第 ② 道闸会在写它们时
  **具名**拦住 —— 没必要把一条已经能用的开工推倒。
- **为什么「清工作树 + 不登记」而不是「登记了再报错」**：后者留一棵没账的工作树，正是 ② 要清的
  那类孤儿。登记要么整条成功、要么什么都不留。
