## 一 面要不要提供「撤回 / 删除」

**现场**：声明编写面只有「四取一」的**写入**（能力 / 类型 / 错误码 / 通知号，`接口面形状.md` §四 冻结）⇒ 删号**走不了面**，只能按 `格式说明.md` §七 的形状直写。

**裁决：面不提供删除。** 依据：
- **①老仓 1.2「不保留旧腿」+ 2.1「分层」**：面是**写入面**（一个动作：把一条声明写进去）。删除不是「写入的补充」，是**另一个动作** —— 它改的是**已存在的文件**（`作废号表.json`），带**历史语义**（谁在什么时候因为什么作废的）。把它塞进写入面 = 让一个面承担两种语义。
- **②既有裁决（宪法 7「号段只增不复用」）**：号删了**不回收**，要作废就得**登记**。所以「删除」在本平台**本来就不存在** —— 存在的动作叫「作废登记」，它是一次**新增**（往 `作废号表.json` 追加一行五键），不是删除。
- **③易语言口径**：易语言的命令/类型号也没有「删掉这个号」这个动作，只有「这个号不再使用」。**指认成立**。

**落法**：把这条写进 `设计文档/接口面形状.md` §四 的旁路区（一句：**面只有写入，没有删除；要停用一条号 = 作废登记**），并指向`决策记录/2026-09-27_作废号收进声明编写面.md` 的第五类别「作废」。
**判据**：`rg -n '删除|撤回' 对外接口面/调用接口面/src/` 在**接口面**里 0 处新增的删除路径（现状已满足 ⇒ 这条是**把现状写成口径**，不是新增施工）。
**反向样本**：若有人给面加了 `DELETE /接口/声明` ⇒ 判红（口径里明写不做）。

## 二 「标签 → JSON 形状」表该冻在哪

**现场**：实测**已有一张事实表**（逻辑 ⇒ `0`/`1` 数字 · 句柄 ⇒ 非负整数 · 文本 ⇒ 字符串 · 字节集 ⇒ base64），但它**只存在于网关实现与 CLI 里**（两个地方各自表述）—— 这正是老仓 1.3「同一件事两套实现即缺陷」。

**裁决：冻进 `设计文档/接口面形状.md` §三**（新增一节「标签 → JSON 形状」），并按 `冻结登记.json` 的 `旁路` 数组**尾部追加**一条登记。依据：
- **①老仓 1.3「结果唯一即收口」**：这张表是**调用方看得见的事实**（他按 JSON 传值），必须住在**唯一一个**对外形状件里，不许留在实现里各自表述。
- **①老仓 7.9「派生优先」**：冻进形状件之后，实现与 CLI **读它**（或由它派生），不再各自维护一份。
- **②既有裁决（`冻结登记.json` 的冻结项两条都落 `接口面形状.md`）**：它是冻结件 ⇒ 「加一节」是**改形状**，必须走旁路登记（`格式说明.md` §八 同款口径）。
- **③易语言口径**：易语言的「逻辑型/整数型/文本型/字节集型」到外部表示的映射，是**公开且固定**的（不是实现细节）—— 指认成立。

**落法**：
1. `接口面形状.md` §三 新增该节（表体 = 标签 · JSON 形状 · 边界情形，如「逻辑只认 `0`/`1`，其他值拒」）。
2. `契约声明/冻结登记.json` 的 `旁路` 尾部追加一条（写清：新增一节、为什么必须冻、旁路走哪）。
3. 网关实现与 CLI 改成**读/派生**这张表（不再各自写死一份）；做不到派生的，**在该文件里写明为什么不能派生**（老仓 7.9 的硬要求）。

**判据**：`rg -n 'base64' 对外接口面/` 命中的处数 **≤ 1**（只剩形状件那一处；实现侧改成引用）。
**反向样本**：给实现侧再写一份 base64 映射 ⇒ 判红。

## 三 ③h 的一般式表达不了（已知洞）

**现场**：`命令信息.参数表` 是**裸指针无长度**，`const` 求值**不许比指针** ⇒ ③h（「命令声明的可抛错误码 ⊆ 能力声明的可抛错误码」这类断言）**只能逐条列名**（1101–1107 各一条）。漏加断言由末条 `已核条数 == 表.len()` 拦住，**但**「同时改 `参数个数已核条数` 又不加断言」**拦不住**。

**裁决：承认这个洞，并用「处数判据」把它关小 —— 不改 const 求值这条路。** 依据：
- **①老仓 11.1「拿不出数字不许装」+「不做的结论同样是结论」**：一般式**做不出来**（`const` 环境的限制是语言给的，不是我方设计缺陷）⇒ **写明不做 + 为什么**，而不是硬造一个假的一般式。
- **②既有裁决（判据口径：**「三元读数 · 反向样本是判据的身份证」）**：一个「拦不住某一种改法」的断言，必须**自身承认**拦不住什么；不承认就是假绿。
- **③易语言口径**：无对应物（这是 Rust `const` 求值的限制，不是平台语义）⇒ **指不出**，故不作为依据，只按 ① 处置。

**落法（两条一起做才算关小）**：
1. **写明洞**：在断言件自身的文件头写清「③h 是一般式的**逐条展开**；`参数个数已核条数` 与逐条断言**必须同批改**，只改前者不加断言**本判据拦不住**」。
2. **补一条处数判据**：把「`参数个数已核条数` 的出现处数」与「逐条断言的行数」都**钉成固定值**（照判据 ⑲/㉒ 的基线形状：**实测 > 登记即红 · 登记不许陈旧**）⇒ 改一处而不同批改另一处，**处数就对不上** ⇒ 报红。这样「同时改两处」需要**故意**做，而不是**顺手**做。

**判据**：处数判据的读数（带退出码）+ 一条反向样本（只改 `参数个数已核条数` ⇒ 必红）。
**边界（不许含糊）**：这条**不消除**「两处同时故意改」的可能 —— 它消除的是「顺手改一处而不报」；**「故意同时改两处」在任何判据下都拦不住**（那是人在骗门禁，不是门禁的洞），这一点要写进该件。
