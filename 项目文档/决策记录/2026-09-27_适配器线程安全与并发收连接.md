# 适配器线程安全与并发收连接：一条 `unsafe` 断言 + 网关共享 `&服务`

日期：2026-09-27 ｜ 华哥派活：高并发 + 资源回收稳固
触发：「高并发不成立：网关单线程 accept（根因在适配器，不在网关）」。

---

## 一 问题（派活前先量过）

`对外接口面/调用接口面/src/网关.rs` 的 accept 循环原本是**单线程**的，且它自己在文件头
登记了根因：**适配器不是 `Send` / `Sync`** ⇒ 全平台只有一个适配器实例，网关没法把它
交给多个工作线程；而网关**不许替下层 `unsafe impl Sync` 担保**（那是替别的 crate 断言
一件自己验证不了的事）。

查表侧**不是瓶颈**（装载时建表 + `按号取命令` 二分查找 O(log n)）；瓶颈就是 accept 串行。

## 二 裁决：线程安全的断言放在**适配器**，网关**零 `unsafe`**

### 2.1 适配器的 `Send` / `Sync` 断言只此一处

适配器逐字段为什么能跨线程，逐条写在 `跨语言适配/适配器实现/src/线程安全.rs` 文件头：

| 字段 | 为什么安全 |
|---|---|
| `装载单元s`（含 `&'static 平台信息`、`注册表`） | 装载后**只读**，全部方法以 `&self` 读；指向 `'static` 静态只读数据 |
| `账本` | `配额账本` 内部已用 `Mutex` |
| `通知` | `Mutex<通知账>`：通知通道（内含 `RefCell`）+ 按标识索引**同一把锁** |
| `留痕` | `留痕缓冲` 逐字段原子，`记` 取 `&self` |
| `追踪号` | `AtomicU64` |

`unsafe impl Send/Sync for 适配器` 与 `unsafe impl Send for 通知账` 各配一段 Safety 说明；
**不**把 `通知通道` 裸交出去（它自己不声明线程安全，要动它得改内核节点，越权）。

### 2.2 网关侧不新增任何 `unsafe`

网关要共享 `&服务`，而 `服务` 里原有一个 `契约来源: &'static 平台信息` 字段 ——
`平台信息` 带裸指针、**不是 `Sync`**，会把整个 `服务` 卡住。裁决：**把根端点要的契约身份
改成标量快照**（`契约身份 { 版本: 版本三元组, 声明格式号: u32 }`，构造时从注入的声明现读）。
声明是静态只读的 ⇒ 快照与现读等价，不是第二份事实；而 `服务` 因此**自动 `Sync`**。

- 新增 `服务::跑并发(工作线程数)`：`std::thread::scope` 起 N 个工作线程，各自 `accept`。
- `服务::跑()` 改为 `跑并发(默认并发线程数())`；`默认并发线程数 = available_parallelism()`，
  取不到退 1（**不写一个拍脑袋的契约常量**：并发度是部署事实，不进 `常量表.json`）。
- 新增 `服务::请求停止()`（服务级停止）：置原子标志 + 连 `并发线程数` 次
  短连接把阻塞在 `accept` 上的线程叫醒。

## 三 这条裁决关掉了什么 / 留了什么

- **该条台账可删**：根因（适配器非线程安全）已修，accept 已并发，验证在
  `对外接口面/调用接口面/src/并发测试.rs`（12 连接 > 4 工作线程，成功/失败各归各的连接）。
- **网关 `服务` 不再持有 `&'static 平台信息`**：`响应::自描述根` 与 `分发::处理` 的签名
  随之改成收标量/`&契约身份`（同一批改动）。
- **留给协调方的**：新增旁路端点要补 `契约声明/冻结登记.json` 的旁路登记，并同步
  `项目文档/设计文档/接口面形状.md` §七（那两件不在本腿所有权内）。

## 四 不许回潮

`适配器必须能跨线程发送与共享`（`适配器测试.rs`）是**编译期判据**：谁给适配器加了
`Rc` / 裸 `RefCell`（不在 `Mutex` 内）这类破坏线程安全的字段，**编不过**。
网关侧若有人把 `&'static 平台信息` 加回 `服务`，`跑并发` 的 `thread::scope` 会**编不过**。
