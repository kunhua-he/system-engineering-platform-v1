# 前端是网页版编译器（IDE），不是 API 控制台

日期：2026-09-26 ｜ 裁决人：协调方（华哥授权「这个你来裁决」）
触发：华哥问「前端应该是类似于易语言的编译器吧？」「前端用 html？不用 go？或者 vue 或者 php 这些？你看看哪一个不容易漂移用哪一个」

## 一 定位裁决：前端 = 网页版编译器

**原定位是错的。** `README.md` 第五节把 `前端呈现/` 写成「人工界面 —— 可整体替换；**人类用的概率不大，非主线**」，我据此做出来的是一个 **API 控制台**（列能力清单 + 点一下调用）。那不是编译器，是调试工具的一页。

**对应关系**（易语言 → 我们）：

| 易语言 | 我们 |
|---|---|
| `e.exe` —— **IDE**：编辑器 + 编译器 + 运行 + 诊断 + 支持库管理 | **`前端呈现/网页应用/` = 网页版编译器** |
| 支持库（`krnln.fne` 等，接缝符号 `GetNewInf`） | `扩展根目录/` |
| 例程（大量 demo） | `测试验证/案例/` |
| 编译产物（`.exe`） | `.能力包件`（见 `能力包件.md`） |

⇒ **`README.md` 那句「非主线」作废。** 前端就是那个 IDE 的位置，它是**人用的那一个面**。上一版做的能力清单/调用/声明**不删**，降级成其中的「**调试**」页。

**网页版编译器要有的部分**（六块）：编辑器（写 `.程序文本`，可从案例库与语料载入示例）· 编译（**逐级调** `1101→1102→1103→1106`，每步显示自己的结果，不许一步到底——看不见死在哪一层就白做）· 运行/结果 · 诊断（`1107` + 结构化错误码 + 三项业务判断）· 案例库面板（读 `测试验证/案例/`，**只读**）· 支持库/能力浏览。

**诚实边界（必须做进界面）**：`1101/1102/1103/1106/1107` **全是保留项**（调它得到「提供者未载入」），只有 `1104/1105` 是真实现 ⇒ **编译现在跑不通**。界面必须把这件事**如实显示成结构化诊断**，**不许做假按钮、不许假装成功**。这正好就是 `2026-09-26_验证面的边界.md` §五 要的形态：跑不通时死在哪一层、哪个码，一眼看见。

## 二 技术选型裁决：无构建步骤的原生 ES 模块

**裁决：`前端呈现/网页应用/` = HTML + CSS + `<script type="module">`。零 npm、零打包器、零第三方库、零 CDN 外链。**

判据不是「哪个先进」，是**哪个最不容易漂移**。

| 候选 | 否决理由 |
|---|---|
| **Vue / 任何带构建器（Vite/webpack）** | 要 npm ⇒ 引入 `node_modules` 依赖图 + 锁文件 + 构建产物。**最致命的一条：运行的字节 ≠ 审阅的字节** —— 产物是源码的机器变换，人读不了；而本项目的全部价值是「读数可信 + 制品可指纹」。**多一条构建链就多一处漂移，而且是最难判的那种。** |
| **PHP** | 它是**服务端**语言。用它就得起**第二个 HTTP 服务** ⇒ 直接违反判据 ⑪「对外监听恰好 1 处」。而且它不省事：客户端交互仍然得写 JS，只是多了一个运行时。 |
| **Go** | ① 第二个工具链（本仓钉死 `rust-toolchain.toml` 一个工具链、零第三方依赖）；② **它替代不了客户端** —— 浏览器里只能跑 JS 或 WASM；③ Go 编到 WASM 的正当用途是**性能热点**（`代码形态分工.md` 第一/七节），不是 UI 壳；④ 服务端已经是 Rust 网关，且已冻结。 |
| **TypeScript（要 `tsc`）** | 同 Vue 第一条。唯一可接受的形式是「JSDoc + `// @ts-check` + **只读检查**（不产出）」——那不算构建步骤，但**现在不需要**（见下）。 |

**客户端其实只有两个漂移最小的选择：原生 ES 模块，或 WASM。** WASM 在本项目的用途是 `.能力包件`（**编译产物**），不是 UI。故取前者。

**「JS 没有类型、怕漂移」的正确解法不是引 TS 构建链，是让前端薄到不需要类型。** 实测：前端 **438 行**（`取接口.js` 64 · `呈现.js` 112 · `应用.js` 146 · `index.html` 116），**零业务逻辑**（判据面有一条专门数「前端 0 处解析/生成/校验」）。**漂移抵抗靠的是薄，不是类型。** 将来若真出现「非 Vue 不可」的复杂度，那是**新落点**，按判据单独评估，不是现在替它先交学费。

**环境实测**（本机已装齐 ⇒ 这不是「装不上」的问题，是「装了就会漂」的问题）：`node v22.23.0` · `npm 10.9.8` · `php 8.5.5` · `go` · `python3 3.14.4` · `cargo 1.95.0`。

## 四 明确不做

| 不做 | 为什么 |
|---|---|
| 不做「前端里跑编译」 | 编译是扩展的能力（1101–1106），前端只送参数、显示结果。前端里做编译 = 第二套实现。 |
| 不做「前端里解析契约」 | 判据面有一条专门数「前端 0 处解析/生成/校验」。 |
| 不做假按钮 / 假成功 | 编译没实现就显示「没实现」的结构化诊断 —— 这是本项目对「假绿」的一贯态度。 |
| 不为前端开第二个监听口 | 判据 ⑪「对外监听恰好 1 处」。静态文件由接口面**同进程**托管（`接口面形状.md` §五；**实测尚未实现**，请求 `/` 回 404）。 |
| 不把「非主线」当结论 | 那句话本身就是本条要推翻的东西。 |

## 五 补裁：视觉与类型（华哥补充信息后，2026-09-26）

华哥提了两点：「HTML 的视觉是最丑的」「TS 我觉得还行」「有时候需要兼容视觉」。第一条里有一处**归类错误**要先纠正，因为它决定选型对不对。

### 5.1 视觉质量不是「用不用框架」决定的，是 **CSS** 决定的

**Vue 的产出就是 HTML + CSS。** 所有好看的网站都是 HTML+CSS —— 视觉的**天花板完全相同**，因为 Vue 最终 emit 的还是同一套 DOM 与 CSS。「裸 HTML 很丑」指的是**没有 CSS 的浏览器默认样式**，那是「没写样式」，不是「HTML 丑」。

Vue 提供的**不是视觉**，是三样：组件化 · 响应式数据绑定 · 生态（UI 组件库）。**真正的代价是没有现成的 UI 组件库**（按钮/表格/表单要手写），不是「丑」。

### 5.2 而这两层的漂移风险是**反的** —— 这条反而支持不用框架

| 层 | 漂移风险 | 依据 |
|---|---|---|
| **CSS** | **≈ 0** | W3C 标准 + 浏览器向后兼容极强。2010 年写的 CSS 今天照样跑 |
| **框架** | **≠ 0** | **Vue 2 → Vue 3 是破坏性升级**，整个生态被迫大迁移（Element UI→Element Plus、Vuetify 2→3）—— 实际发生过、代价巨大 |

**CSS 是最稳的那一层，框架是最不稳的那一层。** 华哥担心的「视觉」正好落在**最稳**的那层上，而引框架会把**最不稳**的那层引进来。

### 5.3 视觉怎么拿到（不违反「无构建」）

**默认：手写 CSS，进仓，字节钉死。** 理由：IDE 布局（三栏 + 面板）本来就不复杂；手写 CSS 同样零依赖、零构建。当前已有 `前端呈现/网页应用/样式.css`（163 行）。

**退路（若手写达不到要求）**：进仓**一份 classless CSS**（例如 Pico.css 这类**单文件、零 JS、零构建**的样式表），`<link>` 进去即得现代观感。**仍不违反无构建** —— 一个 `.css` 文件不是构建链。要求：**字节进仓、可指纹**（不许 CDN 外链，离线要能跑）。

**明令**：视觉要求的落实方式是「**把界面做成 IDE 的样子**」（编辑器为主区 · 诊断面板 · 案例/能力侧栏 · 等宽字体 · 明确的空状态与错误状态），**不是**「引一个 UI 组件库」。前者是设计活，后者是把最不稳的一层引进来。

### 5.4 TypeScript：给一条**可复算的门槛**，不拍死

**现在不用**：前端 438 行、零业务逻辑（判据面有一条专门数「前端 0 处解析/生成/校验」），类型检查的收益小于引入 `node_modules` 的代价。

**但要有一条可复算的重评门槛**（避免「当初说不必，后来长到几千行还不改」）：

> **当前端满足下列任一条，重新评估引入 `tsc --noEmit`（只读检查、不产出）**：
> ① 前端源文件合计 **> 2000 行**；
> ② 出现**第一个非平凡状态机**（例如「编译中 → 编译失败 → 编译成功 → 运行中」这类多态流转）；
> ③ 出现**需要类型才能表达的跨页数据**（同一份数据在 ≥3 个页面间流转）。

注意形式：**只许 `tsc --noEmit`（不产出）**。一旦开始产出，就变成构建链 ⇒ 违反 §二。

### 5.5 最后一条、也是最重要的一条：这个决定**可逆且代价低**

`README.md` 对 `前端呈现/` 的定义是「**人工界面 —— 可整体替换**」。所以：视觉不满意 ⇒ 换样式表，**不碰内核一行**；真到了非 Vue 不可的复杂度 ⇒ 重写前端，**仍不碰内核一行**。

**这才是选它的根本理由**：它把「可逆性」留给了以后，把「最稳」拿在了现在。反过来，现在为了视觉引 Vue，是把**不可逆**（构建链、依赖图、破坏性升级）提前买进来 —— 而那三样恰好都是本项目判据最反对的。

## 六 补裁：案例怎么跑（解一条与冻结接口的冲突）

`2026-09-26_验证面的边界.md` §五 写「前端落地后，它就是那个验证器（**载入案例 → 跑**）」，而 `接口面形状.md` §一 冻的是「**四个端点，一个不多**」（`GET /接口` · `GET /接口/能力/<编号>` · `POST /接口/调用` · `POST /接口/声明`）——**没有案例相关端点**。两条并存 ⇒ 前端要「跑案例」就得自己编排（那是逻辑），或者加第五个端点（违反「一个不多」）。**这是真冲突，必须裁。**

**裁决：跑案例的活归「案例跑器」，前端只读回执。**

| 谁 | 干什么 |
|---|---|
| **案例跑器**（`测试验证/案例/跑案例/`，独立 crate） | 载入声明 → 按案例调能力 → 比对期望 → **追加一行回执**到 `运行回执.jsonl` |
| **前端** | **只读** `运行回执.jsonl` 与案例目录，**显示**「哪个案例通过/失败、死在哪一层、哪个码」。**不跑、不编排、不写回执。** |
| **阻断门禁** | 挂在**提交**上（两条腿唯一的公共汇聚点）。跑器失败即拒提交。 |

**为什么这么分**：
1. **四个端点不许动** —— 加第五个就是给案例开专用通道，判据 ⑪「每类出入口恰好一个」要的就是这个约束。
2. **前端零逻辑** —— 编排一次案例运行（多步、要按依赖顺序、要聚合结果）是**逻辑**，放进前端就破了「前端 0 处解析/生成/校验」那条判据。
3. **跑器是独立的一环** —— 它不需要人看着跑，也不需要前端在场；门禁挂在提交上，所以「跑没跑」是**机器**的事，不是「人点了没点」的事。

**「前端就是那个验证器」这句的准确含义**：前端是**人看的那个验证界面**（一眼看出跑没跑通、死在哪），**不是执行者**。措辞按本条修正。
