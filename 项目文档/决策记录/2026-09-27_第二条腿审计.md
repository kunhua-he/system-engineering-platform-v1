## 二 查实并已修的两条

### 1. PE32 解析器两份（`开发工具/取证/`）

`接缝反解/形状.py`（97 行）与 `界面反解/形状.py`（68 行）**各养一份** `解析错误` + `PE`，
两件的文件头都写着「原 `xxx反解.py::解析错误/PE`，**纯搬家**」—— 各从自身的老脚本搬的。
实测两件**已经各自长出了对方没有的方法**（一份有 `取址`/`读串`/`导出`，另一份有 `读u16`/`节区间`），
相似度 0.61 ⇒ 典型「一处修了另一处不知道」。

**修法**：合成 `开发工具/取证/PE形状.py`（并集，行为逐条保留），19 处 import 改向，删两件旧件。
唯一的行为差异是「没有资源目录就抛」：接缝反解要扫**整个库目录**（`.fne` 未必都带资源目录）⇒
不能无条件抛；故把它从构造器挪成 `要资源目录()`，由界面反解自身调（fail-closed 一点没变，
只是**谁来决定要不要**清楚了）。两件的 `--自测` 都复跑通过（接缝 14 条命令 · 界面 20 个坏样本）。

### 2. JSON 写出器两份（`跨语言适配/` 与 `对外接口面/`）

`适配器实现/src/小写出.rs` 与 `调用接口面/src/协议写出.rs` **各养一份** `写`/`缩进`/`写值`/`写文本`。
实测 `缩进` **逐字相同**、`写文本` **逻辑相同但已经漂了**（一处 `format!` 外面多一对大括号）——
转义表是**正确性资产**（少转一个控制字符就产出非法 JSON），维护两份就是两颗定时炸弹。

**修法**：转义 + 缩进**下沉到下层**（`小写出` 提成 `pub mod`，两个函数转公开并写明为什么公开），
上层删掉自身那两份、`use v1_adapter::小写出::{写文本, 缩进}`。方向合法（README §六：
`对外接口面/ → 跨语言适配/`，网关本就只依赖适配器），**不新增依赖边**。
全仓 `u{08}` 转义表现在只剩 **1 份**（grep 实测）。`cargo test --workspace` 28 目标全过。

**值模型不合并**（有意）：适配器的 `值` 只六种、**明确不支持浮点**（文件头写了为什么）；
网关的 `协议值` 多 `无符号`/`小数`（非有限浮点写 `null`）。两份值模型范围不同是**设计**，
不是重复；重复的是机制。

## 三 查实但**不合并**的（写清为什么，免得后人再查一遍）

| 现象 | 为什么不合并 |
|---|---|
| `取证/声明记录区反解/公共.py::解析错误` 与 `PE形状.py::解析错误` 同名 | 前者是 CNWTEPRG 容器/段数据层的 fail-closed 异常，后者是 PE32 的；解析域不同，各自随本工具的字节格式走 |
| `接缝反解/接缝.rs::取平台信息` 与 `装载入口/底座静态声明.rs::取平台信息` 同名同签名 | 一个是**扩展侧接缝符号**（`#[unsafe(export_name = "GetPlatformInfo")]`），一个是**底座侧内部取用口**；README §六 明写底座不导出接缝符号 ⇒ 角色不同 |
| `声明记录区反解/运行数据根.py` 与 `开发工具/运行数据根.py` | 前者**是转发件**（只 `from 运行数据根 import …` + 加本包私有缓存落点），不是第二份实现 |
| 三个 `渲染.py`（认领机制 · 生成声明 · 资源声明） | 同名不同责：人读输出 / 拼多份产物 / 渲染资源声明 |
| 各包的 `常量.py` / `命令行.py` / `__init__.py` | 目录结构约定，不是重复实现 |

## 四 已查实、**待改**的一条（判据 ㉒ 的扫描面）

规则已收成一份（`开发工具/代码地图/查名.py`，判据 ㉒ 也 import 它）；
但**扫描面**仍是自研剥器（`命名扫描.py`），它有实测的两类假阴性：`. 后一律排除`（看不见 `self.d`）、
字符串整段抹空（看不见 f-string 里的名字）。**改成吃索引会更好，但有个硬约束**：
索引是整仓产出的 ⇒ `--自测` 的**合成仓**没有索引 ⇒ 那条判据在夹具上会永远「未判」，
而正向样本要求「干净夹具上所有判据通过」。故要改就得**先给夹具挂合成索引**
（`V1_RUN_DATA_ROOT` 可覆盖运行数据根，这条路是通的）。**已进台账**。
