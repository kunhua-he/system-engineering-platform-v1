# 段位 9 错误码表：接口面与构建验证

日期：2026-09-27 ｜ 裁决人：协调方（华哥授权「其他 d 你专业由你来判断。我不做阻断」）
触发：后端端点**一个端点都没落**，回报的唯一阻断是「接口面端点失败回不出真实错误码」——`号段图.json` 已把段位 9 划给「接口面与构建验证」，但 `契约声明/错误码表/` 里 9xxx **一条也没有**。

## 一 先分清：哪些失败**不该**要错误码

`对外接口面/调用接口面/src/分发.rs` 文件头已经定死了一条分工，动手前必须照它办，否则会造出第二套：

| 层 | 失败形态 | 回什么 |
|---|---|---|
| **协议层** | 请求体不是合法 JSON · `值` 项形状不合法 · 编号不是十进制数 | HTTP `400` |
| **协议层** | 路径不在端点表里 · 静态托管根下没有这个件 | HTTP `404` |
| **协议层** | 方法不对 | HTTP `405` |
| **业务层** | 端点**在表里**、能力也做了，但这次调用业务上失败 | **真错误码**（`响应.rs::组装` 里 `错误对象::由码`） |

⇒ 本裁决只补**业务层**那格。协议层不许再添 HTTP 码，业务层不许用 HTTP 码顶替。

## 二 裁决：段位 9 立码，一码一失败，不凑数

`号段图.json` 的 `错误码段位图` 已经写明「段位 = 码的首位，号段即归属」，段位 9 归「接口面与构建验证（工具类）」。故码为 `9NNN`，且判据 ⑦ 要求冗余登记项 `段位 == 码 // 1000`。

**只立这次真的会撞到的 7 条**（一条对应一个可区分的失败，没有一条是「凑满一段」）：

| 码 | 名称 | 它跟谁必须分得开 |
|---|---|---|
| 9001 | 端点未实现 | 与 HTTP `404` 分开：404 = 路径不在表里；本码 = 路径在表里、能力还没做 ⇒ 调用方知道是**已排期的缺口**，不是自身拼错路径 |
| 9002 | 案例不存在 | 与 9003 分开：查不到案例 vs 跑过但没回执，一个该补清单、一个该补回执 |
| 9003 | 案例回执缺失 | 判据要的是「案例 + 运行回执」两件齐，缺回执不可采信 ⇒ 防止把「跑过、没记录」当成通过 |
| 9004 | 导出目标不合法 | 五种出口是**闭合枚举**，不许按前缀或别名猜 |
| 9005 | 导出失败 | 与「导出成功但结果不合期望」分开：前者重跑可能就好，后者要改代码 |
| 9006 | 程序文本路径未定 | 契约缺口（`程序文本格式.md` 只定了格式与扩展名、没定落点）⇒ **如实回执，不许替调用方猜一个路径**（猜出来的路径会让「读写成功」变成假绿） |
| 9007 | 列扩展失败 | 失败时**不返回部分清单** —— 残缺清单比空清单更危险（调用方会以为就这些） |

三条业务登记项（`可重试` / `可自愈` / `需人工`）逐条填齐；`需人工 = true` 的只有 9001 / 9005 / 9006（分别是排期、看构建日志、等人裁落点）。

## 五 不做的事

- **不碰协议层**：不给 400/404/405 加平台码，那是 `分发.rs` 已定的分工。
- **不给段位 1–8 预先立码**：它们归各支持库/模块/技能，谁用谁立；空段位预先填满等于造一批没有读方的声明。
- **不加 9008+ 备用码**：没有调用方的码就是「一份没有任何效果的声明」，等真撞到再加。
