# 命名规范：停用天干，单字名要有实义

日期：2026-09-27 ｜ 裁决人：协调方（华哥提出：「变量就 1 个字…需要理解一下语义，丑儿吧唧的」「天干序数名已经不要了，用更现代的表达」）

## 二 裁决一：**天干一律停用**（作标识符）

**天干（十干）不许再作标识符**（变量 · 参数 · 字段 · 类型 · 函数 · 测试名）。

**改成什么**：**按它在这一处的实际角色命名**，不许机械替换成「第一个/第二个」了事 —— 那只是把「十干」换成「一/二」，语义还是没填。三条要求：

1. **说清它是什么**，不是它在第几个：`首数组/次数组/末数组` → `原数组/改后数组/期望数组`；`首句柄/次句柄` → 按用途（`首句柄` 若是「先取的那个」，就叫 `先取句柄`）。
2. **测试夹具里**用「**被测物 vs 对照物**」这类角色词（`被测关口` / `对照关口` / `期望结果`），而不是序号 —— 序号在测试里最容易读错（改一行断言就看不出谁是谁）。
3. **确实是两个同类东西**（例如两个魔术字节、两段相邻区间）时，用**位置/序关系**的词：`前段/后段` · `首字节/次字节` · `左值/右值`。

**为什么不许保留**：十干字在中文里**没有语义**（它只是序数代称），而本项目其它地方全是语义命名（`值` `码` `槽` `前止` `后起`）。一处无义，读者就得停下来反推 —— 这正是华哥说的「读的时候还需要理解一下语义」。

## 三 裁决二：单字名**不设硬门槛**，但分两档

不设「标识符 ≥ 2 字符」这种硬规则：它会连 `值` `码` `槽` `止` `前止` 一起判红 —— **那是假红工厂**（本项目判据最反对的东西）。改成分两档：

| 档 | 判据 | 例 |
|---|---|---|
| **实义单字名：允许** | 该字在**本项目词表里是有义的领域名词**（`值` `码` `槽` `号` `根` `表` `键` `止` `起` `名` `项` `条` `位` `序`） | `let 码 = 错误码();` ✓ |
| **无义单字名：不许** | 拉丁单字母（`f` `i` `n` `s` `d` `b` `t` `r`）· **指代不明的**单字（`出` `加` `做` `取` `查` `判` 这类**动词或泛指**单字，因为「出」是输出还是产出、「加」是加什么，读者反推不出） | `let 出 = list(文本)` ✗ → `结果` · `let 加 = lambda 行: …` ✗ → `追加行` |

**判断口径一句话**：**这个字单独出现时，一个不懂上下文的人能不能说出它是什么？** 能（`值`/`码`/`槽`）就留；不能（`出`/`加`/`f`/`i`）就改。

**已知要改的存量**（实测抽样，非全量）：

```
构建装配/一键验证/一键验证.py   出 = list(文本) / "".join(出)      → 结果
                              加("…") 这个局部闭包                → 追加行
                              _剥(文本, 保串) 的 出 / n            → 结果 / 长度
扩展根目录/…/src/lib.rs        f / i / n 之类的循环计数             → 序号 / 下标
```

## 四 执行纪律（**不许边改边发现**）

1. **存量改名是一次独立批次**，不是顺手做。理由：天干 354 处散在 **37 个文件**里，而此刻有 9 路腿在飞 —— 现在改就是「两条腿写同一文件」⇒ 静默丢更新（本会话实测过 4 次）。
2. **必须配防回潮判据**，否则后人又写回来（本项目已有的教训：改判必须配防回潮判据）。判据形状照本项目既有做法 —— **存量入基线、新增即红**（同「实现默认值差异升为债务冻结」那一条）：
   - 判据 A：全仓标识符里**天干字**出现 ⇒ 与基线比对，**新增即红**。
   - 判据 B：全仓标识符里**拉丁单字母** ⇒ 同上（存量入基线）。
   - 两档口径按 §三（实义单字名不判）。
3. **改完必须**：全仓 `cargo test --locked` 全绿 · `clippy -D warnings` 零告警 · 判据面读数**不变差** · 公开面清单**逐字对拍**（改名会碰公开面 —— 例如 `形状错误` 变体里的载荷名 `首父/次父`，那是**已冻结的形状**，改它要走 `契约声明/冻结登记.json` 的旁路登记）。

## 五 明确不做

| 不做 | 为什么 |
|---|---|
| 不设「标识符 ≥ 2 字符」硬门槛 | 会把 `值`/`码`/`槽` 一起判红 —— 假红工厂 |
| 不机械替换（十干→一二） | 那只是把无义换成另一种无义，读者仍要反推 |
| 不拿 12549 那个数字当依据 | 它把实义单字名算进去了，**数字本身是错的**（我第一版量法就错在这） |
| 不在腿在飞时改存量 | 37 个文件里很多正被写 ⇒ 静默丢更新 |
| 不动已冻结形状里的载荷名而不登记 | `形状错误` 的 `首父/次父` 属冻结项，改名要走旁路登记 |

## 六 裁决三：**名字要语义自明**（2026-09-27 追加 · 华哥原话）

> 「我在想，你为啥不把变量的定义全变成中文？四个字以上的，保持语义的干净，一读就懂。定义干净他。
> 当然如果两三个字能表达清楚的也行。**主要是语义问题**。不然现在这样子，变量乱飞，还时不时没定义。」

**这条是 §三 的加强，不是替代**。§三 只说「无义单字不许」，这条把标尺抬到**读者一眼看懂**：

| 档 | 判 | 例 |
|---|---|---|
| **4 字及以上：目标** | 名字自己把话说清 | `出现位置表` · `该符号出现位表` · `缺失工具表` · `原始索引路径` |
| **2–3 字：可以** | 前提是**一读就懂**、无歧义 | `退出码` · `语言键` · `定义表` · `相对路径` |
| **1 字：只在有义领域名词时留** | 同 §三 的「实义单字名」档 | `值` `码` `键` `表` `位` `根` `止` |
| **拉丁名：一律换成中文** | 除非是**语言或协议强加**的名字 | `__init__` `self` `main` `crate` ✓ ／ `cx` `cy` `res` `rows` `args` `cfg` ✗ |

**判断口径一句话**（沿用 §三，标尺抬高）：**把这一行单独摘出来给一个不懂上下文的人看，他能不能说出这个变量是什么？**
能 ⇒ 留；要反推 ⇒ 改。

**为什么不做成判据**：这条是**语义**要求（华哥原话「主要是语义问题」），不是长度规则 ——
「≥4 字」写成判据就会把 `退出码`/`语言键` 这类**已经说清了**的名字判红，正是 §五 反对的假红工厂。
故它**只进规范、不进判据**：靠写代码的人当场按它取名，靠代码评审（闸 2 的实现侧判据）兜。

**落法**：① 新写的代码当场按这条取名；② 存量按 §四 的纪律**分批**改（一腿一工作树、按文件所有权切开）。
