## 二 三类错，各归各家（这是本文的全部内容）

| 什么错 | 例 | 谁能抓 | 该用什么 |
|---|---|---|---|
| **① 写的时候就知道会死的** | 少写一个 `match` 变体 · 用了已释放的值 · 数据竞争 · 把 `能力号` 传给要 `资源号` 的地方 · 造出「标签是文本却没有文本指针」的槽 | **Rust 编译器**（编不过，运行时根本到不了） | **不用测试**。把「非法状态不可构造」**做进类型**，让这种代码**写不出来** |
| **② 数据 ↔ 代码 不一致** | 声明里说 1101 词法分析存在、实现里没有 · 声明参数 1 个、实现 3 个 · `const 目标字宽 = 64` 与常量表两份 · 错误码没登记就抛 | **编译器看不见**（`.json` 不是类型的一部分） | **判据面**（薄）—— **这一类只有它能抓** |
| **③ 端到端跑不通** | 网关 → 适配器 → 内核 → 扩展，死在哪一层 | 单元测试抓不到（它们是**分片**，每片自身过） | **demo 案例 + 运行回执**（华哥提的）：前端当验证器，载入样板案例，跑不通当场自爆，死在哪一层由错误码与留痕直接给出 |

**「编译就知道，为什么还要测试」——对①完全成立，这条是华哥说对的。**
**「直接用 demo 当验证」——对③完全成立，而且比单元测试好**（demo 是**使用面本身**，它同时验证「第一次用不读文档就能用对」这条判据；单元测试做不到）。
**但 demo 替代不了②**：demo 只证明**我选的这条路径通了**，**不证明覆盖**。声明里 7 条能力、demo 跑了 2 条 ⇒ 剩下 5 条「声明有实现无」**demo 永远不报**。本次会话反复咬人的正是这一类（命令编号=下标、常量第二来源、错误码未登记、`1101–1103/1106/1107` 声明了没实现）。**而「demo 的传参是契约固定死的」这句话本身，就以「契约正确」为前提** —— 契约错了 demo 照样跑通。

⇒ **判据面必须留，但只留②，且必须薄。**

## 三 ①类：把「写的时候就知道会死」做进类型（当下就能做，收益最大）

Rust 里已经用上的：穷尽匹配（形状错误码 26 变体）· `Option`（无 null）· 私有字段 + 唯一构造口（`注册表` 只能经 `建表` 得到）· `&'static` 生命周期（声明终生有效）· `#[repr(C)]` 定长槽。

**还没用、但本项目最该用的两条：**

### 3.1 号空间 newtype —— 让「传错号」编不过

现在 `能力号` · `资源号` · `错误码` · `类型标签` · `通知号` **全是裸 `u32`** ⇒ 把一个资源号传给要能力号的地方，**编得过**，运行期才炸。而 `号段图.json` 已经明写「四个号空间互不相通，任何跨号空间的比较都是缺陷」—— **这句话现在是靠判据维持的，应该靠类型维持**。

做法：`#[repr(transparent)] pub struct 能力号(pub u32);` 四个号各一个类型。`#[repr(transparent)]` 保证跨边界 ABI 逐字节不变（宪法第 3 条不破），而类型层上四个号**不能互相赋值**。

### 3.2 `const` 断言 —— 形状不变量在编译期死

定长槽的大小、`size_of::<数据槽>()` 不变、段位算术（`段位 × 号段类宽度 + 序号 ≤ 9999`）都可以写成 `const _: () = assert!(...);` ⇒ **改了就在编译期死**，不需要运行期测试。

### 3.3 边界处的张力（这条是理解全局的钥匙）

跨语言边界的槽**必须是定长字节**（宪法第 3 条）⇒ **边界上「非法状态」在类型层不可禁止**，只能用判据。但边界**内侧**（Rust 里）可以用类型。
⇒ **判据面只该覆盖边界那一薄层**。它一旦开始判内核内部不变量（例如「记号流无缝隙」「语法树父包住子」），就是在做类型系统该做的事 —— **那才是「又做了一条腿」**。

**具体处置**：`语言面` 的 11 条形状不变量，现在靠 17 条测试的反向样本维持。改法 = 把不变量**移进构造器**（`记号流::新建(原文, 记号表) -> Result<Self, 形状错误>`，字段私有）⇒ 非法值**构造不出来** ⇒ 那 17 条反向样本可以删，只留「构造器对坏输入报码」的 1 条。

## 五 ③类：demo 案例 + 运行回执（主门禁）

形态（与 `接口面形状.md` 一致，不另造）：

```text
案例/                      每个案例 = 一份输入 + 一份期望
  <案例名>/
    输入.程序文本           送进编译器的真实源码（我们的原生格式）
    期望.json               期望的容器/结构/错误码
运行回执.jsonl              每次运行的读数：提交哈希 · 案例 · 通过/失败 · 死在哪一层 · 耗时
```

三条硬要求：
1. **回执必须绑提交哈希** —— 否则「回执是旧的」和「代码坏了」不可区分（`判据的可信性.md` 假绿来源 4）。
2. **挂阻断门禁** —— 案例跑不通 = 提交被拒。不是「报告一下」。
3. **失败即自爆，且必须报出死在哪一层** —— 靠既有设施：结构化错误码（可重试/可自愈/需人工）+ 调用留痕。**不另造一套「测试断言」**。

**前端落地后，它就是那个验证器**（`接口面形状.md` 的四个端点 → 载入案例 → 跑）。前端现在是空目录，所以这条**先落案例与回执的形状，前端接上时直接跑**。

## 七 补裁两条（2026-09-26，判据面回执后）

### 7.1 判据面**不许用一套词法去读另一种语言**

**实测现场**：`构建装配/一键验证/一键验证.py` 的 ⑪/⑫ 用 **Rust 词法**扫全仓代码（要数导出符号名，所以**必须保留字符串**），而它的扫描后缀里含 `.py`。后果：在 `测试验证/契约一致性/扫实现.py` 里写一句 Rust 形状的示例（比如把 `#[unsafe(export_name = "…")]` 写成样本），**会被读成那个文件里的一个真导出** ⇒ ⑪ 判据 2a 与 ⑫ 同时报红。判据面实测撞到两次（改注释时在注释里引了一条完整形状，又红一次）。**现在只靠「`构建装配/` 被排除」与「引号恰好被转义」两条偶然条件维持。**

**裁决**：判据**按语言分**，不许跨语言借词法。

| 判据 | 扫描面 |
|---|---|
| Rust 类（⑪/⑫/⑬ 与 `扫实现.py` 全部） | **只收 `.rs` + `.json` + `.toml`**。**`.py` / `.js` / `.ts` / `.html` / `.css` 一律不进。** |
| 前端类（⑪-6「前端 0 处解析/生成/校验」） | **只收 `前端呈现/**` 下的 `.js/.html/.css`**，用文本/正则读，**不借 Rust 词法** |
| Python 源码（`构建装配/` · `测试验证/` · `开发工具/` · `对外接口面/声明编写面/`） | **不进任何 Rust 词法判据的扫描面**（判据器自身的源码更不许被判据读） |

**理由**：一套词法读另一种语言**必然误判**（本次实测），而误判的方向是**假红**——假红会让人去改没坏的东西，比假绿更费时间。

### 7.4 派活信里的「现状」必须标取证时间（本条是我自身的翻车）

我给判据面的任务书写「`扫实现.py` 按单文件解析、13 个整份夹具被当生产代码 ⇒ 假红」，**实测它早就修好了**（读到 15 个，正确；任务书说的 13 是更早的仓态）。我把一条**过期读数**当成了现状派下去。

**这已经是第二次**（上一次是「任务书里两条指向不存在的代码」）。**教训**：派活信里凡是「现状 / 改前读数」，要么**标取证时间**，要么**不写，让腿自身去量**。写一个过期读数比不写更坏——腿会照着它去改没坏的东西。
