## 二 借用结论（一张表，决定性结论）

| 借 | 依据（源码） | 落点 |
|---|---|---|
| 终态唯一 + 迟到结果丢弃 | Temporal 状态机 `Canceled --(Completed)--> Canceled` | 图驱动：内核拒收就不写槽表与失败表 |
| 失败判定固定顺序 + 两阶段终态 | K8s `job_controller.go` else-if 链、`FailureTarget → Failed` | 图驱动 + 调度实例 |
| 取消拆「已请求」与「已取消」两个时间位 | Temporal 两条独立事件 | 任务表取消请求时刻 |
| 车道报序：不可变序号升序 + **老化** | K8s `PrioritySort.Less`、Nomad `ReadyEvaluations.Less` 三家同形；K8s 重投递掉队尾是反面教材 | 资源接线 |
| 收尾回收三条硬约束 | K8s `ttlafterfinished_controller.go` | 调度实例独立 tick |
| 持久化只抄两张表 + 双守卫 + 尝试号 + 启动分流 | DBOS `workflow_status` / `operation_outputs` | 批七 |
| 序号只在真落盘后推进 | Restate `APPLIED_LSN` | 同上 |
| 拓扑与环检测 | `petgraph::algo::toposort` O(V+E) | 已有实现，不引依赖 |
| 落盘参数 `WAL + FULL`、写者唯一、不关检查点 | SQLite 官方矩阵 | 同上 |

**不借（连同理由，防反复）：** `depends` 表达式引擎（用不上、契约膨胀）·
`Omitted`/`Skipped` 都算成功（会把「全跳过」判成绿灯）· mutex/semaphore（我们的原子试取更强）·
事件重放与 WAL 引擎（无多副本、无长时工作流）· K8s 四档失败策略（无 index 概念）·
Nomad 随机平手与 K8s 观察期循环（不可复现 / 单机不需要）· `daggy`（删节点移位索引）。

## 三 语义定盘（已定，不再二选一）

### 3.1 取消：先做两档，第三档挂起

| 取值 | 对在跑节点 | 对调用方 |
|---|---|---|
| `只挡未开始`（缺省 = 现行为，正式命名为「放弃」） | 照实跑完，结果保留 | 立刻回执 |
| `等在跑收口` | 照实跑完 | 阶段停在「收尾中」直到收口 |
| ~~`请求中止`~~ | 需协作通道（能力侧接取消令牌） | **挂起**：通道未定前不做，不做假承诺 |

### 3.2 等待截止：只管等待，不管任务

提交字段 `请求等待截止`（整数毫秒时间戳）：到点只让这次请求早点交回任务标识，
**不终止任务、不进失败或已取消**。缺省不设。同 `同步等待毫秒` 取较小者，再受五秒硬顶。

旧名 `截止时刻` 收到即 400 并点名新名——不许让调用方按旧协议误以为「到点图会停」。
真截止（到点终止整图）不做，理由见 §五。

### 3.3 失败判定顺序与两阶段终态

顺序写死（多条件同时命中只能报一个理由）：**失败策略 → 重试预算 → 截止**。
「决定失败」与「写终态」分两步：先标「即将失败」→ 停本地子进程 / 等回执 flush → 再写「失败」。
否则会出现「回执说失败了，子进程还在跑」。

### 3.4 收尾与回收

只对终态任务回收 · 删前再取一次状态校验 · 回收是独立 tick 可单独关 ·
**保留最后一试的回执与错误摘要**（K8s 删 Job 会连日志一起带走，这是它的问题不是优点）。

### 3.5 任务表六列：随所属批次进入，不一次加齐

| 列 | 进入批次 |
|---|---|
| `状态` | 已有 |
| `请求等待截止` | 已落地（只是请求等待窗口，任务表不必存） |
| `取消请求时刻` | 批四 |
| `尝试号` · `下次尝试` · `最近进度` | 批七（重试） |

### 3.6 资源车道：只借「序号升序 + 老化」，不借优先级

同额度车道内按提交序先进先出，回执写队位（`等资源` + 第几位）；
排序键只有「提交序号升序」，**不做优先级、不做抢占**（本机私有，抢占会打断在跑的能力调用）；
同车道排队超阈值时回执标「在等」，由调用方决定是否放弃，调度器不自作主张。

### 3.7 数据传递：先立体积上限，再谈命名槽

**顺序不能反：** 没有上限时，按名取复合值会让人以为拿到的是小值，实际整个槽都在内存里。

1. 量真实分布：取十个已知大返回的能力（整段转写、大文件摘要、公式求值、随机数、文本处理…），
   记录返回槽字节数，取 `最大实测值 × 4` 作初值，落进协议说明。
2. 超限明确报错，不静默占用、不截断（截断的结果看起来像「能力返回的就这么多」）。
3. 命名槽：能力声明的返回是复合类型时才允许按名取，不支持就明确报「该能力不支持按名取」。

### 3.8 输入引用只支持整槽

`输入引用` 只有 `目标参数` 与 `来源节点` 两个字段：上游只交一个返回槽，按名取复合值里的某一项做不到。
协议里的 `来源参数` 已删除；收到即 400 并说明「要传上游结果就整槽引用」。

不静默忽略：带着它提交的调用方会以为按名取生效了，实际拿到整槽——那是更坏的结果。

### 3.9 持久化：只抄最小集

只落「任务与节点的当前状态 + 尝试记录 + 幂等表」，不落事件历史、不做重放。
重启对账：库里「执行中」而进程不在 ⇒ 判「失败·已中断」（不猜成功），未开始节点报「已取消」，任务进终态；
`请求标识` 加唯一索引，发号改 `AUTOINCREMENT`（内存计数重启从 1 重来会与历史号相撞）。
新开一张运行态库，**不进治理库**——否则「清运行数据」和「清台账」变成同一件事。

### 3.10 重试：默认关闭，且排在最后

**底线：默认不重试，必须调用方显式开启。** 我们的「失败」包含「结果未知」，能力可能已做了一半副作用；
自动重放等于替能力承诺幂等，而它只自报了「可重试」这一位。

实现时的硬口径（写在此处防止将来重新推演）：
新增节点阶段 `待重试` 属于**未终态集合**但写结束时刻与本次时长，下游不许在其上就绪 ·
只存内部值 `总次数上限`（含首次），对外 `重试次数` = 总次数 − 1 并写死「不含首次」·
退避 `底数 × 乘数^(已失败次数−1)` 双重封顶，**抖动确定性**（节点标识与批号哈希，不用随机数）·
到期时间**落列**只比较不重算 · 连续失败在出现一次成功时清零 · 失败策略只两档（`忽略` / `立即失败`），
匹配用「错误类别 + 连续同错次数」· 重试不改节点标识只递增批号，尝试记录只增不改。

**落点澄清（审计修正）：** 加 `待重试` **不动内核**。节点阶段枚举与跃迁表都是
`契约声明/调用任务协议.json` 派生的，内核 `运行内核/调用调度` 只是再导出 + 包错误类型
（文件头写明「本件不写第二份规则」）。改的是协议 JSON → 重生派生件 → 适配器侧判定。

## 四 标准进化流程

### 4.1 每批固定七步（顺序不许调）

| 步 | 动作 | 判据 |
|---|---|---|
| 1 冻结 | 写清本批**改哪几件、哪些件不许碰**，落进台账 | 落点件路径逐个存在，禁碰清单点名 |
| 2 判据先写 | 先写能红的测试/断言，再写实现 | 未改实现时跑一遍，确认**真红** |
| 3 实现 | 只改冻结范围内 | 超范围即停，回步 1 |
| 4 定向验证 | 只跑受影响的 crate 与测试件，不跑全量 | 适配器 / 接口面 / 内核 三个数各自报，**不合并成一个"全绿"** |
| 5 闸0 | `V1_GATE_QUIET=1 python3 构建装配/一键验证/闸0.py` | 63 项 + 12 项 0 失败 |
| 6 真机 | 构建制品 → 候选端口装载 → 真实 HTTP / 验收页 | 候选制品 SHA + 端口 + 回执原文，缺一不算 |
| 7 提交与销账 | 提交 + 台账销账或转记新债 | 提交含实测读数；债务条目的验证命令是仓内真能跑的 |

**任何一步不绿：不提交，工作树回退到该批开工前。** 不许带着红色读数进下一批，也不许用「其余都过了」当理由。

### 4.2 批次（按代价从低到高，不按主题分组）

| 批 | 内容 | 落点 | 退出条件 |
|---|---|---|---|

## 五 明确不做（连理由，防反复）

| 不做 | 理由 |
|---|---|
| 协作取消通道 / 第三档「请求中止」 | 要改能力声明面；在跑节点怎么收手没定，先不做假承诺 |
| 真截止（到点终止整图） | 同上，与取消第三档绑定 |
| 事件历史重放 | 纯内部调度器，无多副本无长时工作流，重放换来的「跨天续跑」用不上 |
| 优先级与抢占 | 本机私有；有队位与「在等」标识即可，由调用方决定 |
| 跨机分布式 | 单机就是边界，分布式要引入选主与分区语义 |
| 引入第三方工作流框架 | 装配层已能跑，换框架等于推翻冻结的协议与门禁 |
| 子图 / 嵌套 DAG | 没有真实调用方；等真有需求再立项 |
| 用 petgraph/daggy 做调度 | 只做图算法，不管状态与资源；环检测已有 |
