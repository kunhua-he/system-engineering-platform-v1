## 一 现状（先量再写）

`运行内核/调用留痕/src/lib.rs::留痕` 原六字段：`{实例, 能力号, 入参指纹, 结果码, 耗时微秒, 追踪号}`。
**只有一个号字段**，而资源访问要两个号（`字段名册与引用方式.md` §三：资源按 **资源号 + 操作号** 引用）。
实测两处写侧各自塞法（`grep -rn "留痕 {"` 全仓）：

| 写侧 | 落点 | 塞法 |
|---|---|---|
| 资源访问 | `跨语言适配/资源网关口/src/关口/关口主体.rs::资源网关口::资源调用` | 资源号 → `能力号` 格 · 操作号 → `追踪号` 格 |
| 能力调用 | `跨语言适配/适配器实现/src/留痕口.rs::适配器::记一条留痕` | 名副其实 |

两处毛病，**都不只是「名字不好看」**：
1. **`能力号` 格装资源号** ⇒ 同一个数字在两个号空间里是两样东西（`号段图.json`：「四个号空间互不相通」），
   而记录里**没有任何判别** ⇒ 读的人只能猜（`契约声明/格式说明.md` §四 禁的正是这种「不可区分」）。
2. **`追踪号` 被征用装操作号** ⇒ 资源访问**丢掉了关联号**。`追踪号` 的语义是「一次调用一个，
   跨进程/跨网络透传」（`现代架构落点.md` §六）——那是「坏了看得见」的骨架，比字段名错更重。

`留痕` 是否冻结形状：**实测不是**。`契约声明/冻结登记.json` 的 `冻结项` 七条里搜「留痕」**0 命中**
（`grep -c 留痕 契约声明/冻结登记.json` = `0`，退出码 0）⇒ 字面上不必走旁路；
但「别人已经依赖的形状」有四处（见 §六），故本裁决**按架构级改动**处置（`README.md` §十二 第 5 条）。

## 二 五判据对比

判据 = `README.md` §三：**稳固 · 简单 · 不漂移 · 可读 · 不产生第二条腿**（同 `决策记录/2026-09-27_三条裁决_按稳定性判.md` 的用法）。

| 判据 | **(a) 给 `留痕` 加显式字段**（本裁决） | (b) 裁「资源调用走另一条留痕」（资源访问用自身的记录形状 + 自身的缓冲实例） |
|---|---|---|
| **稳固** | 旧六字段**逐字不动**，只在尾部追加 ⇒ 正是 `冻结登记.json` 写明的演进方式「新增旁路字段（不动旧字段含义）」，也是它写明的理由「追加在尾部则旧读者仍能读前缀」。**记录形状仍是一份** | 能力侧一字不动（零回归），但**形状变成两份**，且随调用类数目**线性增长**（来第三种调用就第三份形状）⇒ 每加一种都要再定一次「谁记哪一条」 |
| **简单** | 一条记录 · 一个缓冲实现 · 零泛型。写侧多填三个字段，读侧多读三个字段 | 缓冲机制要么**泛型化**（`留痕缓冲<T>` ⇒ 公开面改动 + 每加一种记录多一次实现）要么**复制一份**（`同一件事两套实现即缺陷`）⇒ 两条都不简单 |
| **不漂移** | 每个号只有一个义：资源号只在 `资源号` 格、操作号只在 `操作号` 格、`追踪号` 回归本义。判别显式 ⇒ 不必靠「哪个号非零」反推 | 每条记录内部不漂；但**「谁记哪一条」这条事实落在两处**（两个缓冲 · 两个容量 · 两个丢弃计数）⇒ 读侧要拼两处才看到全貌 |
| **可读** | 平铺字段、平铺 JSON；读侧第一步看 `调用类`，再按它取号 | 读者要 match 两种记录；JSON 要嵌套 |
| **不两条腿** | 一条记录类型 · 一个缓冲实现 ⇒ **一条腿**，无需论证 | 需论证（拓扑判据数的是调用路径与出入口，留痕不是出入口；且「多实例不等于第二条腿」有先例）—— 但机制泛型化/复制那份代价是真的，**论证成立也要付** |

**裁决：走 (a)。** (b) 唯一的赢面是「能力侧零回归」，而这一项 (a) 也拿到了（旧六字段逐字不动）。
(b) 的三项代价（形状随调用类增长 · 机制泛型或复制 · 谁记哪一条落两处）都不是「更好」，是**多一条要维护的腿**。

### 为什么不走「判别靠 `资源号 != 0` 反推」（即只加两个号字段、不加判别）

看着更省一个字段，实则**把判据换成约定**：`0` 在能力号空间里**是合法号**
（底座自有段 `0xxx`，`契约声明/能力声明/0000.json` 在）⇒「这个号位不适用」既不能用 `0` 表达，
也不能从 `0` 读出来。本项目对同一类问题已有定论：`契约声明/src/lib.rs::号段空间` 的注释写
「参数不能靠约定补，**要进类型**」（早先靠并集判，产生假冲突）。故判别**进记录**，
读侧「当场可判、不允许静默通过」——与宪法第 3 条「类型标签在槽内」同一条口径。

### 被否掉的第三个形态（把「调什么」收成一个带载荷的枚举字段）

`留痕 { 实例, 对象: 能力{能力号} | 资源{资源号, 操作号}, 入参指纹, 结果码, 耗时微秒, 追踪号 }`
—— 类型最干净（判别与载荷同体、不可能不一致），但它**把已有的顶层字段 `能力号` 搬进变体**，
破「只增不改」，且四处依赖方全都要改（读侧加 match、JSON 变嵌套）。
它换来的「不可能不一致」，本裁决用**两个构造口 + 编译期判据**同样拿到（见 §三），
而代价只需追加字段 ⇒ 按「稳固」优先，取追加形态。

## 三 形状（定死）

落点：`运行内核/调用留痕/src/形状.rs::留痕`（形状）· `src/缓冲.rs::留痕缓冲`（机制）。

```text
留痕 {
    // ── 冻结区（原六字段，逐字不动）──
    实例: u64 · 能力号: u32 · 入参指纹: u64 · 结果码: i32 · 耗时微秒: u64 · 追踪号: u64
    // ── 旁路区（2026-09-27 追加，只增不改）──
    调用类: 调用类        // 能力 = 0 · 资源 = 1（#[repr(u8)]）
    资源号: u32           // 调用类::资源 时有义；能力调用恒 0
    操作号: u32           // 调用类::资源 时有义；能力调用恒 0
}
```

- **写侧只有两个口**：`留痕::能力调用(实例, 能力号, 入参指纹, 结果码, 耗时微秒, 追踪号)` ·
  `留痕::资源访问(实例, 资源号, 操作号, 入参指纹, 结果码, 耗时微秒, 追踪号)`。
  两个口一次把判别与号位写对，调用方不维护「哪个号有义」。
- **结构体字面量在 crate 外写不出来**：`留痕` 带 `#[non_exhaustive]` ⇒ 别的 crate 写
  `留痕 { … }` 是 **E0639 编译错**（实测，见 §四），不是纪律。
- **`追踪号` 恢复本义**：一次调用一个，不再是操作号的寄存处。
- **零 `usize`/`isize`**（同原形状）；`留痕` 仍 `Copy`，跨边界形状不含指针。

### 防回潮判据（改形状必配）

| # | 判据 | 怎么判 |
|---|---|---|
| 1 | **判别与号位必须一致** | `留痕::自洽()`：`调用类::能力 ⇒ 资源号 == 0 && 操作号 == 0`；`调用类::资源 ⇒ 能力号 == 0 && 资源号 != 0`（后者据 `号段图.json` 资源号段从 `1` 起） |
| 2 | **坏痕不许静默** | `留痕缓冲::不自洽数()`：`记` 到号位不自洽的记录时加一（痕照记——事件不许抹掉，但缺陷必须能读到）。与「丢痕不许静默」（`已丢弃`）同一条纪律 |
| 3 | **写侧不许绕过两个口** | 编译期：crate 外结构体字面量 E0639（`#[non_exhaustive]`）⇒ 判据由类型承担，不靠人眼 |
| 4 | **留痕缓冲/留痕/调用类 必须 `Send + Sync`** | 编译期 `const _: fn() = …` 断言（`缓冲.rs`）。留痕侧的并发前提 |

### 「退回一步」承重证明（判据不是空的）

退一步 = 把修法倒回原样，判据必红。四条都已**真跑**（命令与退出码见 §七）：

1. **退回旧塞法**（资源号 → `能力号`，操作号 → `追踪号`，资源号位空着）：`const _` 断言
   `assert!(!退回一步.自洽())` 在 `cargo check` 即红（实测把「资源」支判据放宽成恒真
   ⇒ `error[E0080]: evaluation panicked: assertion failed: !退回一步.自洽()`）。
   运行期同一处方：`号位串味_照样记下但不静默` 断言旧塞法记录进缓冲后 `不自洽数 == 1`。
2. **退回「字面量随便写」**（去掉 `#[non_exhaustive]` 的等价物 = 外部 crate 直接构造）：
   实测外部 crate 写字面量报 **E0639** `cannot create non-exhaustive struct using struct expression`。
3. **退回「缓冲可以带线程亲和状态」**：往 `留痕缓冲` 里注入一个 `Cell<u32>` 字段 ⇒
   `const _` 断言当场红（`error[E0277]: Cell<u32> cannot be shared between threads safely`）。
4. **行为基线**：原八条测试（`容量内不丢` · `丢最旧_超容量` · `丢最新_超容量` · `取最近_边界` ·
   `取最近_丢最新_边界` · `容量零` · `反复覆盖不崩` · `多实例互不污染`）**逐条同名同断言**保留，全绿。

## 五 `留痕容量` 建议数与依据（只报，该常量归声明侧）

**建议值 `10000`**。依据（三条都可复算）：

1. **它能兑现一句能检验的话**：`10000` = `常量表.json::配额上限`（单号每 `配额窗口毫秒`（1000）内最多被调
   `10000` 次）⇒ **一个号若独占打满配额，它这一整窗的调用一条不丢、全部读得到**。
   **不承诺跨号**：多号并发时缓冲按总调用数滚动，单号可读窗口 ≈ 容量 ÷ 并发号数（这句话必须连同数一起写进依据，
   否则后人会把它读成「最近一秒全都在」）。
2. **内存不构成约束**：槽实测 **72 字节**（本机 1.95.0）⇒ 每实例 `10000 × 72 B = 720,000 B ≈ 703 KiB`；
   本机内存 **103,079,215,104 B（96 GiB）** ⇒ 占比 **7×10⁻⁶**。容量为 0 合法、留痕默认关（装配侧给容量才开）。
3. **同一条判据管两个数**：值与 `配额上限` 同源 ⇒ 那个数改了，容量按同一句判据跟着改，不必再裁一次。

**另报一处待裁**（同一个 `留痕` 族、也在声明侧）：`丢弃策略` 至今无契约常量
（`现代架构落点.md` §十 第 4 条「未裁」）。留痕的用途是「坏了看得见」⇒ 建议取 **`丢最旧`**
（保最近，诊断看的就是最近；`丢最新` 保历史，与用途相反）。当前是构造参数，装配侧给。

### 留痕侧的并发前提（本腿已落成编译期判据）

留痕**不阻塞调用**（`README.md` §三）⇒ 它对并发的要求是「谁都能记、谁都能读、谁都不等谁」：

- `留痕缓冲` 的全部状态是**实例字段 + 原子量**，模块里**没有** `static mut` · 没有单例 · 没有进程级计数
  ⇒ 多实例天然互不可见（`B6`：状态显式持有）。
- `记` 与 `取最近` 都取 `&self`：写者一次 `fetch_add` 领号（唯一共享写点，常数时间），落格用逐字段原子
  + `就绪` 顺序锁发布；同格写者用一次 CAS 认领串行化；**认领与读取都有界重试，宁可丢一条绝不转圈等待**。
- 调用方**不需要外部加锁**：`留痕缓冲` / `留痕` / `调用类` 的 `Send + Sync` 是 `缓冲.rs` 末尾的
  **编译期**断言（不是声称）；给缓冲加线程亲和字段（`Cell`/`Rc`/`RefCell`）当场红（实测，§四）。
  这一条正是那条「适配器 `unsafe impl Sync`」的留痕侧依据（`适配器实现/src/线程安全.rs`
  那张表里「`留痕`: 已经是 `Sync`」那句，现在**有编译期判据撑着**）。
