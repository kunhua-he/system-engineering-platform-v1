# 台账号与「腿 / 轮」的引用口径

**背景**：`开发规范.md` §八.4 早就写了「源码注释里不出现台账号，也不出现『哪条腿 / 哪一轮』」，
但那条纪律**一直只有纸面**。清存量时（三条腿按顶层目录切，共清 141 处）撞出四个口径问题，
都是「不裁就没法判」的。逐条裁如下。

## 一 台账号的**形态**不止一种 —— 我原来只认一种，量错了

第一版派活信给的正则是 `台账 ?# ?[0-9]+`，只认「`台账 #N`」。实测**漏掉两种**：

| 形态 | 例 | 实测 |
|---|---|---|
| `台账 #N` | `（台账 #数字）` | 189 处 |
| `未完成事项.md #N`（**路径夹在中间**） | ``（`未完成事项.md` #数字）`` | 41 处 |
| `台账 \`路径\` #N` | ``台账 `项目文档/未完成事项.md` #数字`` | 2 处 |
| **第四形态：裸 `#N`**（无任何前缀） | `（#<编号> 段相交口径）` · 标题 `## 一 #<编号> · …` · `（#<编号>/#<编号>）` | `项目文档/**/*.md` 实测 89 行 |

**第四形态的辨认口径（2026-09-27 补）**：**只在散文文档（`.md`）里认**「`#` 紧跟数字」，
正则原文 `(?<!\w)#[1-9][0-9]{0,3}(?![0-9A-Za-z（])`（`\w` **Unicode 感知**，故 `预定义#<类原子>`
这类**程序文本里的标识符**天然不匹配）。三条排除：① `#` 后不是数字（`#常量名`）⇒ 不匹配；
② 程序文本里的类原子 / 资源序数（`预定义#<类原子>` · 标题 `'#<序号>（资源序数）'`）⇒ `(?<!\w)` 与
`(?![（])` 排掉；③ 十六进制颜色码（`#ffffff` / `#888888` / `#000`）⇒ `[1-9]`（不许前导 0）
与「右邻不许是字母数字」排掉。**清法同前**：清出处、留事实（`#<编号> 段相交口径` → `段相交口径`；
纯指针括号 `（#<编号>/#<编号>）` 整括删除）。

**裁**：四种**都算**，一律按下面的口径清。**判据（清完之后立）**：源码树里 0 处
「`台账`/`未完成事项` 后 24 字符内出现 `#<数字>`」—— 正则写成
`(台账|未完成事项)[^\n]{0,24}# ?[0-9]+`（**这一条是本次的教训**：口径写窄了，
腿按窄口径清完、我按窄口径复量，两边都说「0 命中」，而全仓还剩 37 处）。

## 二 **gitignored 的生成物快照不清**（自检命令必须排除它）

`构建装配/制品产物/<标识>/扩展根声明.json` 里有 4 处（它是对源 `扩展装载/扩展根声明.json` 的快照）。
**裁：不清，也不许手改。** 三条理由：① 同目录 `说明.md` 与 `制品清单.json` 明写「生成物，禁手改：要改就改源再重出」；
② `制品清单.json` 的「不可变判据①」会重算该文件的 sha256，手改即当场变红（那是**没人记的红**）；
③ 它是 gitignored 的**快照**，不是源码 —— 源已清，重出即干净。
⇒ **口径**：`--exclude-dir=制品产物`（与 `构建缓存/`、`.git/` 同级）。

## 三 「腿 / 轮」：清**点名**的，留**自指**与**架构义**

§八.4 的理由是「**注释的读者不该被要求去 git 历史里翻一条已销的台账**」。按这条理由划：

| 类 | 例 | 裁 |
|---|---|---|
| **点名某条派活腿** | `接缝冻结腿⑮` · `本腿（语言主线）` · `演示腿` · `解析腿 / 编译腿`（组件绰号，指某次派活的实现） | **清**（去腿名，留事实） |
| **工作轮次** | `本轮撞到` · `上一轮的内容`（= 工作轮次义） | **清** |
| **自指** | `本腿不许跑 cargo` · `本文件补上这条腿` | **留** —— 自指不指向任何可查的编号或名字，读者**不需要去翻任何东西**；且清它必须改写措辞，与「纯搬家口径」冲突 |
| **架构 / 层义** | `装配那条腿` · `v1-adapter 那条腿` · `通知腿 / 留痕腿`（本义） | **留** —— 这里的「腿」是「通道 / 层」，不是派活腿 |
| **普通词** | `值的上一轮` · `本轮只冻形状` | **留** —— 与工作轮次无关 |

## 四 JSON **数据字段**里的出处：清出处、留事实

`契约声明/冻结登记.json` 的 `来源` / `现象` 字段里有 14 处「…腿回执…」。
**裁：与注释同口径** —— 它们的作用是「记这条为什么被冻」，不是「记它从哪条腿来」。
⇒ 去掉腿名/轮次，**事实句逐字留**。（这一条推翻了「JSON 数据一律不动」那句泛化纪律：
该纪律的**真意**是「不许动**语义**」，不是「不许动散文」——`为什么冻` 这类字段就是散文。）

## 五 **文档侧也算**（含 `决策记录/`）—— 这是我先前挂着「待裁」的那一条

`项目文档/**` 里有 46 处（`决策记录/` 18 处最多）。先前我把「`决策记录/` 里的台账号算不算」挂着等人裁。
**裁：算违规，同一口径清。** 理由：`决策记录/` 是**裁决的落点**，它自身就是 durable 的 ——
它去引一条**做完即删**的台账，等于让唯一持久的记录依赖一个会消失的东西。修法 = 把「为什么」写清，
或改指 `决策记录/… §节名` 这种真正的 durable 落点。**留证据、去出处**这一条同样适用
（说「我们试过 X，实测不成立」的句子留着，只去掉号）。

## 六 清的时候**不许**顺手做的事

- 不许把一个号换成另一个号（换号只是把悬空换个地方）。
- 不许引入行号引用（判据⑮ 禁按行号 —— 只能 `路径::符号名` 或 `路径 §节名`）。
- 不许改**行为**：注释之外的字符串若会被**运行期返回给调用方**（例：
  `响应.rs` 里返回给客户端的消息文本），**不动** —— 它是用户可见输出，不是注释。
  例外只允许一处：**测试失败时才显示的消息串**（`.expect("…")`）可以随注释一起清
  （它不进生产路径；三条腿里出现过一处，已如实登记）。
- 不许改**排版**：删括号后留下的双空格/多余空格**不补**（顺手改排版会让 diff 读不出真改动）。
