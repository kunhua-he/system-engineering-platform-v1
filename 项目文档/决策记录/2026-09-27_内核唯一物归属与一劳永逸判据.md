# 内核唯一物的归属 · 两门确认 · 一劳永逸的判据

日期：2026-09-27 ｜ 裁决人：华哥
原话一：「**有两个网关。一个是调用，一个是开发。这个没错。**」
原话二：「我希望是**内核是一劳永逸的**，我不希望后面天天修内核。」
相关：`2026-09-27_核心只放唯一物.md`（入核五问 · 核心预算 · 12 个唯一物）· `README.md` §二（两个角色）· §五（两条链）

---

## 一 对外两个门（已确认，不是缺陷）

| 门 | 对谁 | 干什么 | 实现 |
|---|---|---|---|
| **调用网关** | 使用角色 | 报编号 + 按契约行序填值 → 结构化结果（读与调同一条路） | `对外接口面/调用接口面/` |
| **开发网关** | 维护角色 | 写 · 改 · 校验能力声明，落盘到 `契约声明/` | `对外接口面/声明编写面/` |

**两门的分工是「调能力」与「写声明」，不是两条运行路径。** 判据（可数）：

1. **运行期对外只有一个门**：任何「调用能力」只走调用网关；开发网关 0 处调用能力。
2. **两门都不许直连内核**：各自只经自身的相邻下层（调用网关经适配器；开发网关只写声明区）。
3. **开发网关不参与运行**：关掉它，调用网关照跑。

## 二 唯一物的主人（补主人，**不增节点**）

按 `2026-09-27_核心只放唯一物.md` §五 盘出的「无主 / 半有主」机制，**一律并进现有唯一物**，
唯一物个数**仍是 12 个**——只是每个都补上明确的主人：

| 机制 | 主人 | 要补什么 |
|---|---|---|
| 实例身份（签发 · 回收 · 不复用） | **实例状态** | 身份由谁签发、单调、**永不复用**（宪法 7 该覆盖的第七个号空间） |
| 并发模型（谁可以并发 · 线程安全边界 · 顺序保证） | **调用调度** | 「同一适配器多线程共享」还是「每实例一个」；线程安全边界在哪；通知与调用之间有没有序 —— **并发语义要写进契约**，不许隐式 |
| 时间口径（单调时钟 · 单位 · 超时基准） | **调用调度**（超时）· **调用留痕**（耗时） | 那两个数出自哪个时钟、什么单位、单调还是墙钟 —— 定一处 |
| 权限判定（谁能碰什么） | **资源网关口** | 「默认拒绝」有了；缺「扩展**要求**什么权限」进契约（否则无可比对） |
| 故障处置（谁有权剔除 / 降级 / 上报） | **装载入口**（剔除）· **调用调度**（单次故障不扩散） | 谁有权摘掉一个扩展、谁有权降级 |
| 版本协商（格式号 / 要求版本不符怎么办） | **装载入口的判定** · **契约声明的版本字段** | 门有了；缺「不符怎么办」的规则（未知字段容忍 vs 未知格式拒绝） |
| 降级兜底（未命中返回空） | **统一注册表的占位项** | ✅ 已完整 |

**唯一新增的第 13 个唯一物**：**运行数据根**（现在**完全无主**，README §十一 未定项）。
它不属于任何现有节点 ⇒ 单独立项：**全平台运行数据（数据库 · 缓存 · 日志 · 临时件）的唯一落点**，
判据 = 源码树内 0 处运行数据 + 唯一解析器。

## 三 引导点（特权调用方，不是核心节点，也不是第二条路）

「读扩展根 → 装 → 起监听」这件事现在落在 `对外接口面/调用接口面/examples/启动网关.rs`。
**它是调用方，不是核心节点**（它调 `适配器::装载` + `服务::绑定`，不摸内核 crate）。
判据（可数）：源文件 0 处扩展名 · 0 处 `TcpListener` / `.bind(`（监听只有一条路）· 只用 `v1-gateway` + `v1-adapter`。

## 四 一劳永逸的判据：内核不再天天修，靠什么

**「一劳永逸」不是承诺，是六个条件全绿的状态。** 只要有一条不绿，内核就会被反复打开：

| # | 条件 | 不绿会怎样 |
|---|---|---|
| 1 | **核心只放唯一物**（入核五问） | 核心承载业务 / 策略 ⇒ 每来一个业务就改一次内核 |
| 2 | **每个唯一物有唯一主人**（§二） | 机制无主 ⇒ 每次用到都撞「没定义」⇒ 临时凑合 |
| 3 | **边界表达力足够** | 外面表达不出来 ⇒ 新需求被塞回核心 |
| 4 | **规则有判据（纸面 = 0）** | 规则漂了没人拦 ⇒ 靠人记 ⇒ 修不完 |
| 5 | **号不复用 + 已发布标识符不可变** | 改名 / 复用号 ⇒ 波及所有调用方 |
| 6 | **冻结边界、内部自由** | 边界不稳 ⇒ 每个外部依赖都要跟改；内部不敢动 ⇒ 全成石头 |

**1 / 2 / 4 / 5 / 6 都是「自身可控」**——靠纪律与判据就能关住。
**只有 3 是外部风险**：边界够不够宽，不由纪律决定，由「外面的需求能不能被现有原语表达」决定。

V1 的边界现在押了三个赌注：**定长槽 · 同步单返回 · 无状态**（症状已登记）。
这三条一旦不够宽，被赶出去的东西**会被迫塞回核心**，第 1 条就守不住。

⇒ **核心要「一劳永逸」，前提是先证明边界够宽。** 这两件事是一体两面：
**入核五问管「不许进」，边界表达力管「出得去」。**

## 五 本件不解决的（如实登记）

1. **边界表达力尚未验证**（定长槽 / 同步单返回 / 无状态够不够宽）—— 这是第 3 条条件的唯一缺口。
2. **「核心准入」判据族还没写**（认扩展名 · 含策略分支 · 能被替换而不动调用方 ⇒ 红）。
3. **核心预算的具体数字还没定**（唯一物个数 / 总行数 / 判据条数各设多少）。
4. **第 13 个唯一物（运行数据根）的落点与命名**还没定。
