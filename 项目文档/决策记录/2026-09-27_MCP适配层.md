# MCP 适配层 —— 把仓内入口变成**工具表里的工具**

日期：2026-09-27 ｜ 裁决人：华哥（原话：「封装工具是没用的，agent 天然的弱点。只有 mcp 这种强制协议才不会漂移。如果不用强制协议，本质上就算放了一大堆工具给你都没用。很少会用上的」）

---

## 一 裁决

本仓提供一套 MCP 服务（`开发工具/MCP服务.py` ＋ `开发工具/MCP服务/`），**三个工具**：

| 工具 | 干什么 | 转发到 |
|---|---|---|
| `v1_gate` | 跑本仓的一键门禁（闸 0：闸 1 声明侧 ＋ 闸 2 实现侧）并返回退出码与读数；`自测: true` 改跑反向样本自检 | `构建装配/一键验证/闸0.py` · `一键验证.py --自测` |
| `v1_symbol` | 查**预建符号索引**（不是文本匹配）：给 `关键词` 查符号；给 `限定名` 查它的全部出现位置（定义 ＋ 引用，带 `路径:行:列`） | `开发工具/代码地图.py 查` / `… 引用`（吃 SCIP 索引） |
| `v1_replace` | **符号级**批量替换：只动索引认得的那几处。默认 dry-run；`应用: true` 才写盘，写盘前过认领机制的所有权闸 | `开发工具/代码地图.py 引用` ＋ `开发工具/认领机制/账本.json` |

**★工具名必须 ASCII（2026-09-27 装上后实测更正）**：原名是 `v1_门禁` / `v1_符号` / `v1_替换`，
结果**三个只剩一个能用**。客户端把工具名归一化成 `mcp__<服务名>__<工具名>` 时**截掉非 ASCII**
⇒ 三个中文名全截成同一个 `v1_`，撞名去重只活下来一个。证据：日志 `mcp.server.connected` 报
`toolCount: 3`（服务端确实发了三个），而模型请求的工具表里只剩 `mcp__v1_devkit__v1_` 一个，
且它的形状是 `v1_replace` 的 ⇒ 门禁与符号两个工具等于不存在。旧仓那套 MCP 的工具名本来就
是 ASCII（`capability_call` / `code_map_search` / `capability_search`）⇒ 它没这个问题。
中文名放进 `description`，语义不丢。同「腿名必须 ASCII」一类：**外部机制写死 ASCII 的地方就用 ASCII**。

**★改成 ASCII 之后必须重启客户端才生效（2026-09-27 实测）**：改完文件当场验服务端是 `v1_gate` / `v1_symbol` /
`v1_replace`（`printf '…tools/list…' | python3 -B -u 开发工具/MCP服务.py` 直读帧，见 §六），
但**模型侧的工具表还是旧的** `mcp__v1_devkit__v1_` —— 客户端把上一次 `tools/list` 的结果缓存住了。
**重启 ZCode 之后三个工具全部出现**（实测 `v1_gate` 跑闸 0 退出码 0 · `v1_symbol` 查索引命中 22 个定义 ·
`v1_replace` dry-run 报 3 处落 2 件）。⇒ 改 MCP 工具名/形状后，**「重启客户端」是步骤的一部分**，
不是可选项；只改文件不重启会得出「改了没用」的错判。

安装形式：**ZCode 插件（仓外）**挂 `.mcp.json` 指向本仓的 `开发工具/MCP服务.py` —— 服务实现随仓走（受版本控制、随入口一起改），插件只做声明。协议层**标准库手写**（不引 MCP SDK ⇒ 守住零第三方依赖）。

**落点与装法**（插件在仓外，故不写进仓的目录树，在这里指认）：

```
/Users/hekunhua/Documents/Agent/PHP/系统工程平台V1.插件/     ← 市场根（加市场时粘这一条）
  marketplace.json                    市场 `dev-v1-devkit`
  v1-devkit/
    .zcode-plugin/plugin.json         插件 `v1-devkit`
    .mcp.json                         mcpServers.v1-devkit → `${CLAUDE_PLUGIN_ROOT}/启动.sh`
    启动.sh                           薄转发：exec python3 <仓>/开发工具/MCP服务.py
```

装法：**插件市场 → 添加 → 添加插件市场**，粘上面的市场根；然后 **个人 → dev-v1-devkit → v1-devkit → 安装**。管理入口 = **设置 → 插件**。
`启动.sh` 的仓根由自身位置推出（插件根 = `<仓父>/系统工程平台V1.插件/v1-devkit`）—— 仓挪了要改它；找不到仓内服务时**退出码 2 并出声**，不静默连上一个空服务。

**★实际装法（2026-09-27 实测）：走用户级 `mcp.servers`，不走插件。** 插件那条路要人在图形界面点
「添加市场 → 安装」（ZCode 无 `zcode` CLI，装态存在 1.8 GB 的 `~/.zcode/cli/db/db.sqlite` 里，
agent 改不动），而 `~/.zcode/cli/config.json` 的 `mcp.servers` 是同一机制的**用户级**配置源，
agent 可直接写。实测落地形状（`v1_devkit` 一条，`enabled: true`）：

```json
"v1_devkit": {
  "type": "stdio",
  "command": "/opt/homebrew/bin/python3.14",
  "args": ["-B", "-u", "<仓>/开发工具/MCP服务.py"],
  "cwd": "<仓>",
  "env": { "PYTHONDONTWRITEBYTECODE": "1" },
  "timeoutMs": 130000, "enabled": true
}
```

三处讲究：① **解释器写绝对路径** —— 非交互 shell 里 `python3` 会解析到 `/usr/bin/python3`（3.9），
写死 homebrew 的 3.14 才与手跑一致；② `-B` 免得在仓里落 `__pycache__`；③ **配置文件的 MCP
项不展开 `${...}` 模板**（那是插件专有）⇒ 这里只能写绝对路径。
**插件与配置别两边都装**：会变成两套工具（`v1_devkit` 与 `v1-devkit`）。

## 三 三条边界（不许越）

1. **它是适配层，不是能力**（老仓 `支持库/后端/代码解析支持库/代码地图/说明/设计说明.md` §2：「MCP 只是适配层（渲染文本、给 Agent 用），它消费本能力，不拥有能力」）：三个工具只**转发**仓内已有入口，**零业务逻辑、零第二套实现**（老仓 1.3「结果唯一即收口」）。
2. **判据面不依赖它**：`构建装配/一键验证/` 里 **0 处**调 MCP。它是**环境依赖**（同 rust-analyzer，11.1 四条）——退法 = 删插件，底座与判据面照跑。
3. **写操作必须过认领机制**：`v1_replace` 的 `应用` 模式先读 `开发工具/认领机制/账本.json` —— 有活跃租约时**必须指名 `腿`**，且目标路径必须全在该腿的认领集里，否则**拒**（fail-closed）；账本读不出 ⇒ 报「判不了」，**不许当成「没有租约」**。这条是「符号级替换」与「自由批量替换」的分界：**改动作不是风险，绕过所有权才是**。

## 五 协议层

stdio 上的 **JSON-RPC 2.0**（一行一个 JSON）。实现 MCP 服务端要的四件事 —— `initialize` · `tools/list` · `tools/call` · `ping`；其余方法一律回「方法不存在」（**不许静默成功**）。`开发工具/MCP服务.py --自检` 自造三帧（含一个不存在的方法）当协议层的身份证。

本入口**永不返回**（协议主循环）⇒ 属「结构边界：永不返回」，登记在 `构建装配/一键验证/入口白名单.json`（判据 ㉔）。

## 六 超时

三个工具的子进程上限 = **5 秒**（与全项目同一条上限）。实测：`v1_gate`（闸 0）4.2 s · `v1_symbol` 0.6 s · `v1_replace` dry-run 0.6 s · `--自检` 44 ms。
