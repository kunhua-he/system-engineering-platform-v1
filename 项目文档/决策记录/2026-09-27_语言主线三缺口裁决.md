# 语言主线三缺口裁决（1103 形状归属 · 1102 两处铺法 · 1106 三个障碍）

> 2026-09-27｜判据：华哥五条（稳固 · 简单 · 不漂移 · 可读 · 不两条腿）
> 起因：语言主线把三条**自身动不了**的缺口如实报上来，只登记不顺手改 —— 理由正当。
> 本件把三条**一次裁完**，不留「同一件事两个说法」。

---

## 〇 先定一条分类规则（后面三条都靠它）

`契约声明/冻结登记.json` 里的 `冻结项` 与 `旁路`，**冻的不是「住在哪个目录」，是「有没有第二个消费方」**：

| 冻的 | 为什么它进登记 | 例 |
|---|---|---|
| **盘面格式** | 外面有**逐字节的对照物**（真 `.e` 语料） | 容器主结构（段头 44 字节 + 段类型号 + 名称区密钥）· 调用形状 · 数据槽形状 |
| **跨缝形状** | 缝的另一侧（别的扩展 / 宿主 / 前端）要按它读 | `平台信息` 字段 · 接口面返回体 · 通知号段 |
| **不进登记** | **中间表示**：唯一消费方在同一扩展内，且形状**还在长** | 记号流 · 语法树 · 记录流 · 1103 的带号结构 |

第三条的判据是**「它有没有第二个消费方」**，不是「它稳不稳」：中间表示即使今天很稳，
**它随取证推进而变**（`语义/形状.rs` 自身写明「取证没到的部分不判、本形状不假装表达」）——
把一份**证据还没到的中间表示**冻进登记，等于给还没有据的地方上锁，后续取证反而要绕开它。

⇒ **规则**：`冻结登记.json` 只收**盘面格式**与**跨缝形状**。中间表示写进各自形状件的文档注释即可。

## 一 · 1103 的「带号结构」**不是契约冻结件**，是扩展内的中间表示 ⇒ **更正 A2 的措辞**

### 实测（先量再判）

| 件 | 落点 | 在不在 `契约声明/` | 在不在 `冻结登记.json` |
|---|---|---|---|
| 1101 的**记号流** | `扩展根目录/原子支持库/编译器支持库/src/语言面/记号定义.rs` | 否 | 否 |
| 1102 的**语法树** | `扩展根目录/原子支持库/编译器支持库/src/语言面/语法树定义.rs` | 否 | 否 |
| 1103 的**带号结构** | `扩展根目录/原子支持库/编译器支持库/src/语义/形状.rs` | 否 | 否 |
| **容器主结构** | `扩展根目录/原子支持库/编译器支持库/src/容器/形状.rs` | 否 | **是**（旁路 · 盘面格式） |

⇒ 三者**在同一层**，处置**一致**；而容器主结构虽然也不住在 `契约声明/`，却是登记在案的冻结项
（因为外面有 1444 个真 `.e` 文件当逐字节对照物）。

### 裁

**1103 的带号结构不进 `冻结登记.json`。** 三条理由：

1. **无跨缝消费方**：它唯一的消费者是同一扩展里的 1106（编译）；前端不读它
   （实测：`前端呈现/网页应用/` 只调网关，**不解析任何能力返回字节**）。
2. **不是盘面格式**：它不对外逐字节复刻任何东西（`.e` 的声明记录区怎么排，它一个字节都不替着编）。
3. **还在长**：形状件自身把「取证没到的部分」单列出来（五类分区边界 · 令牌字段语义 · 字节码操作码表）。

⇒ **A2 裁决记录里「独立『带号结构』冻结件」的「冻结件」三个字是措辞错**，改读为
**「一条独立的结构（扩展内的中间表示），不寄生在 `记录流` 里」**。A2 的**实质**（独立 · 不寄生 ·
形状先取证后立）**已落实**：取证地基写在 `语义/形状.rs` 的文档注释里，把「实测已证 / 裁定已定 /
取证没到的部分」三段分开写。**故 是措辞缺口，不是施工缺口。**

### 防回潮判据

**判据（可跑）**：`契约声明/冻结登记.json` 的每条 `冻结项`/`旁路`，其 `落点` 必须能回答
「它冻的是盘面格式还是跨缝形状」——**答不出的一律不许进**。落点若指向**扩展目录**，
必须同时是盘面格式（有真语料对照物）；`记号流`/`语法树`/`带号结构` 这类中间表示**出现即红**。
（判据的三元读数：登记里**有**中间表示 = 红；登记里**全是**盘面格式或跨缝形状 = 绿；登记为空 = 未判。）

**退回一步**：若日后真出现第二个消费方（例：前端要自身解析带号结构来画变量表），
那它就**升级成跨缝形状**，届时走 `冻结登记.json` 的新增旁路 —— 规则不变，只是分类变了。

## 二 · 1102 两处铺法：①**铺** ②**保持兄弟但补口径**

### ① 单行声明头字段：**铺成子节点**（与「头带体」统一）

**实测现状**（`语法/语句.rs::建单行` 的 `match` 分支）：

| 声明形态 | 谁建 | 头字段铺不铺成子节点 |
|---|---|---|
| `.子程序` / `.程序集` / `.数据类型`（头带体） | `语法/建树.rs::建头带体` → `声明字段` | **铺**（子 0 = 名字，子 ≥1 = 类型候选） |
| `.局部变量` / `.参数` / `.成员` / `.常量` / `.支持库` / `.程序集变量` / `.全局变量` / `.DLL命令`（单行） | `语法/语句.rs::建单行` | **不铺**（只挂尾叶：空白 / 注释 / 换行） |

实测读数（`语法/测试/真形状其余.rs::真形状3_带局部变量的子程序` 的期望树）：
`8 局部变量声明 [36,76) 子(9,10)` —— 子区间里**只有** `9 换行`，`.局部变量 监听服务器, Fiddler`
那两个字段**一个节点都没有**。

⇒ **同一件事（声明头）在同一个扩展里两套处理**。1103 因此有两条取值路径：
头带体走**子节点**，单行走**节点区间内的记号扫描**（`语义/建表.rs::单行声明` + `记号区间`）。

**裁：铺。** `建单行` 的八个单行声明分支一律改走 `声明字段`（`建头带体` 已经在用的那个），
于是全扩展只剩**一条**规则：**声明头字段一律是子节点**。1103 的记号扫描那条路**整条删掉**
（不保留旧腿），`建表.rs` 的 `单行声明` 改成读子节点。

**为什么不裁「不铺」**：那样要保留「同一件事两套取值」，且「哪个记号是声明的名字」这条
**语法事实**会同时活在 1102（知道这是哪一类声明）与 1103（自身从区间里挑第一枚标识符）两处。
判据 `判据的可信性.md` §三 的假绿来源之一正是「同一件事两套实现」——
**两处今天结论相同，不代表明天还相同**。

### ② `.程序集` 与 `.子程序` 是**兄弟不是父子**：**保持兄弟**，把「归属靠行序」写成显式口径

**实测现状**：`语法/建树.rs::建体` 里 `行类::程序集` 走 `建头带体(… 段末判据::程序集变量)`，
而 `段末判据::程序集变量` 在**第一条非 `.程序集变量`/非空行**处收尾 ⇒ `.程序集` 的体里
**只有它自身的变量声明**，紧随其后的 `.子程序` 是**它的兄弟**。

**裁：不改。** 理由：**易语言的文本事实就是平级** —— `.程序集` 行与 `.子程序` 行**缩进相同**、
各占一行，文本里**不存在**一层包含关系。把兄弟改父子是**发明一层文本里没有的结构**，
而「哪个子程序属于哪个程序集」由**行序唯一确定**（它之前最近的那条 `.程序集` 行）。

**跨 `源单元` 的关联看不到 —— 这不是缺陷**：`源单元` 由 `.版本` 行切分；程序集头与它的子程序
被 `.版本` 行切到两个单元里，在语言上就不成段（`程序文本格式.md` §二）。

⇒ **补一条口径**（写进 `说明/语言面形状.md`，不是新冻一个形状）：
**子程序归属程序集，靠「它之前最近的那条 `.程序集` 兄弟节点」判，不靠父子包含。**
这条口径必须**同时**写进 1103 的取值处（`语义/建表.rs` 的程序集归属那一段），
免得后人把它「修」成父子。

### 防回潮判据

- ① 的判据：`语法/测试/真形状*.rs` 的期望树里，**每个单行声明节点都必须有头字段子节点**
  （子区间不只剩尾叶）—— 反向样本：把 `建单行` 的 `声明字段` 调用去掉 ⇒ 期望树当场对不上。
- ② 的判据：**形状测试里不许出现「程序集包住子程序」的树**（即 `.程序集` 节点的 `原文区间`
  不许把任何 `.子程序` 节点的区间包在里面）—— 反向样本：把 `段末判据::程序集变量` 放宽到
  吞下子程序 ⇒ 该断言当场红。

## 三 ③ · 段类型号只能是 **u8** ⇒ 更正 `256–258` 为 **`16–18`**（**不改容器宽度**）

### 实测（先量再判）

盘面段头的布局（`说明/使用说明.md` §一 的字段表 + 已冻结的 `段头长度 = 44`）：

```
u32 校验和(4) · u8 段类型(1) · 27 字节名称区 · u32 段名长(4) · u64 数据长(8)  = 4+1+27+4+8 = 44 ✓
```

⇒ **段类型是 1 字节**。这不是「没登记」，是**字段宽度就只有 255** —— `256` 在盘面上**不存在**。
`冻结登记.json` 的旁路条目却写着「新增段类型号 `256–258`」，理由「参照实现的段类型号是 `1–255`，
`256+` 留给我们自身」——**这条理由是错的**：`1–255` 不是「参照实现的号段」，是**字段本身的取值范围**；
参照实现只用了 `1–15` 与 `255`。

⇒ 两者是**契约层的自相矛盾**（登记里写了盘面上表示不了的号）。这正是 1106 的第三个障碍。

### 裁

**改登记的号，不改容器宽度。**

- **不改宽度**：段头 44 字节与「逐字节等于真 `.e`」是同一件事；把段类型加宽 1 字节 ⇒
  段头 45 字节 ⇒ 1444 个真文件上「反解 ∘ 生成 = 恒等」这条**唯一**的盘面证据**当场失效**。
- **改登记**：我们自身的段类型号 = **u8 里没人用的那些**。现有占用 `1–15` 与 `255`
  ⇒ 可用 **`16–254`**。能力包件三段取前三个：

| 段 | 旧（写错） | **新** |
|---|---|---|
| 接口说明段 | `256` | **`16`** |
| 能力码段 | `257` | **`17`** |
| 指纹段 | `258` | **`18`** |

`项目文档/设计文档/能力包件.md` 的 §一 表 · §一 尾段 · §五 末行 · §六 待办 3 四处同步更正
（`256+` 的说法一并改掉：不是「我们的号段从 256 起」，是「**我们的号取 u8 里的空洞**」）。

### 防回潮判据（**可跑**，已进 `一键验证.py` 第 9 项）

`冻结登记.json` 新增**机器可读**键 `段类型号登记`（对象：段名 → 号）。判据三问：

1. 每个号是 `0–255` 的整数（**`256` 当场红** —— 这正是本条要防的回潮）；
2. 每个号**不与已占用的 `1–15` / `255` 相撞**；
3. 每个号在容器形状里**真能表示**（`容器/形状.rs::段类型::自号(号)` 返回 `Some`）。

反向样本（自测里跑）：把某个号改成 `256` ⇒ 判据红；改成 `3`（撞已占用）⇒ 判据红。

## 四 ① · 接口说明段的字段形状 = **接口面返回体的六个字段**（一份数据，两个出口）

`项目文档/设计文档/能力包件.md` §六 待办 1 的原话是「需与 `接口面形状.md` 的返回体对齐后再冻
（两者是同一份数据的两个出口，不许各定一套）」。**实测：两者已经逐字对齐** ——

| 出口 | 字段（逐字） |
|---|---|
| `GET /接口/能力/<编号>` 返回体（`接口面形状.md` §三，已冻结） | `编号` · `名称` · `参数表`（行序）· `返回类型` · `可抛错误码` · 一句用法 |
| 接口说明段（`能力包件.md` §一 · §三） | `编号` · `名称` · `参数表`（行序）· `返回类型` · `可抛错误码` · 一句用法 |

⇒ **裁：接口说明段就是那个返回体的盘上装法**，字段**逐条同名同序**，不许增删。
两处**不许各定一套**，也**不许互相复述字段表**（复述就是第二个来源）：
`能力包件.md` §一 只写「字段 = `接口面形状.md` 的返回体，逐条同名同序」，字段表**只在 `接口面形状.md` 一处**。

⇒ 待办 1 的**形状部分当场闭**；剩下的只是**编码**（这些字段在段里怎么排字节），
那属 1106 的施工面，不属契约待裁。

## 五 ② · WASM 载体**成立**；工具链是**施工前置**，不是契约待裁

`能力包件.md` §二 已按 `代码形态分工.md` §四 的规矩回答了「为什么必须」：**各系统都载得动**
（浏览器 / Node / Deno / wasmtime / wasmtime-py / Wasmtime.NET / wazero 都有现成载入器）·
**沙箱默认拒**（与资源网关口同一条哲学）· **确定性**（浮点与内存语义被规范钉死 = 本项目「0 漂移」的直接诉求）·
**不新增形态**（`代码形态分工.md` 里本就有「编译到 WebAssembly 的那份」）。
备选（原生共享库）**不跨系统**；自造字节码要自身写 N 个载入器 = N 条腿。

⇒ **裁：载体保持 WASM，不改。** 它的**理由已经答完**，缺的**不是裁决，是一次工具链供给动作**：

| 缺什么 | 性质 | 归谁 |
|---|---|---|
| 装 `wasm32` target（实测 `rustup target list --installed` 只有 `aarch64-apple-darwin`） | **工具链供给**（一次性，不是构建期联网） | 台账施工前置 |
| `.cargo/config.toml` 的 `net.offline = true` | **构建期不联网**，与装 target **不冲突**（前者管 cargo 取依赖，后者是 rustup 的 target 安装） | 同上 |
| `代码形态分工.md` §四 的正式回答 | 实质内容 §二 已给，**搬过去即可** | 同上 |

⇒ **② 从「契约待裁」降级为「施工前置」**，并**明确它不挡 1106 的另外两件事**：
形状（① 已闭）与段类型号（③ 已闭）现在都通了，1106 只剩「码段里装什么」这一步等 target。
