# 开工铁律与「项目记忆」的形态 —— 用 `AGENTS.md`，不另立 `项目记忆.md`

日期：2026-09-27 ｜ 起因：华哥问「能不能像 V3 那样子，做一个项目记忆的类型？轻量化的记忆，
至少换另一个 agent 可以继承上所有信息，不至于信息丢失」

---

## 一 裁决

**本仓的「项目记忆」= 仓根 `AGENTS.md`，一个自动注入的薄壳。不另立 `项目文档/项目记忆.md`。**

它是**唯一自动注入**的东西：ZCode 每个会话读 `<仓根>/AGENTS.md` 并放进上下文。
装成两件事：**开工顺序**（按什么顺序读）· **不许做什么**（硬边界与实测撞过的坑）。
**事实一律指路，不复述。**

## 二 为什么不照 V3 的形状抄

V3 是 `AGENTS.md`（32 KB，行为铁律）＋ `开发文档/项目记忆.md`（业务事实与裁决速查，153 行）两件。
那个形状在 V3 成立，**在本仓会违反本仓自身的宪法**：

- 本仓 `README.md` §十一 已经是一张**唯一落点表**（「要什么 → 唯一落点」），
  并明写「**本件不复述它们 —— 复述就是第二个落点，必然漂**」；§十二 同口径。
- 所以再造一份 `项目记忆.md` = **第二个路由器**。本仓宪法级硬约束里就有「同一职责只留一套」
  （`README.md` §三 第 1 条「一个唯一入口」的精神）。
- V3 没有这张表，才需要那份速查；本仓有，就不需要。

**判断依据**：要新增一份「汇总件」之前，先问「这张汇总表是不是已经存在」。存在 ⇒ 加的是漂移源，不是记忆。

## 三 `AGENTS.md` 的内容边界（写它的人照这个守）

**许放**：
1. **开工顺序** —— 先拿基线读数（`v1_gate` / `闸0.py`）· 读唯一台账 · 查在飞的工作树与认领账本 · 才动手；
2. **硬边界** —— 宪法九条与「本树不含什么」**只指路**（`README.md` §三 · §十），另列 **agent 侧**最容易犯的几条；
3. **本仓自身的工具**（MCP 三件 · 并行工作树 · 认领机制 · 代码地图）—— 这些是「命令住在 `开发工具/` 里、
   agent 不记得就不会跑」的那一类，放进自动注入的件才有用；
4. **权威源地图** —— 指 `README.md` §十一 与 `开发规范.md`，**不重复列**；
5. **只此一处的坑** —— 实测撞过、且别处没记的。

**不许放**：
- 会漂的数（行数 · 件数 · 测试个数 · 台账条数）；
- 任何权威源的内容副本（复述即第二个落点）；
- 业务事实（那是 `契约声明/` 与 `设计文档/` 的事）。

## 四 为什么必须是「自动注入」这一条

「工具在不在**工具表**里，决定它会不会被用」—— 同 `2026-09-27_MCP适配层.md` §二的实证。
一份放在 `项目文档/` 里、要人主动去读的「项目记忆」，等价于
`并行工作树.sh` 与 `认领机制` 当年的状态：**已在药柜、从未吃过**。
自动注入是它唯一的区别，也是它存在的全部理由。

## 五 这一轮实测撞出来的两条，已写进 `AGENTS.md`

1. **`git grep` 看不见未跟踪件** ⇒ 「全仓 0 处」这个结论必须由**逐字节全树（含未跟踪件）**背书。
   现场样本：一份讲「清零」的审计文件**漏了自身**（它自身就是未跟踪件）。
2. **写「已清」这个动作本身会留下新残留** ⇒ 清完必须把「刚写的件」再扫一遍。
   现场样本：本件写完后扫一遍，`AGENTS.md` 里就带了 5 处待清字；补记同理。
