# 构建段归环境步

**背景**：`2026-09-27_所有运行五秒硬顶.md` §一 的范围是「**任何命令**」，§四 只留了一个豁口：
「唯一不算命令的只有工具链**一次性冷构建**；命令触发的增量构建**算在内**」。两条实测读数把这个豁口
顶到了台面上：`上线切换/构建制品.py` 首跑 **5570 ms**（release 缓存冷时编底座网关 + 扩展可装载库）；
`cargo test --workspace` 冷 **14.80 s** / 热 1.83–1.95 s。

## 一 豁口的**落地形态**是「一条能单独指名的环境步命令」，不是「命令自己顺手编一下」

**理由**：§四 的豁免若只读作「允许某条命令在冷缓存时超顶」，它**不可执行** —— 谁来判断
「这一次是冷构建，还是这条命令真慢」？豁免必须**可指名 · 可复跑 · 可观测**。三条推论：

1. 一条命令要编东西，那个「编」必须能被**单独跑**（环境步）；**命令本体不许编** ——
   产物缺失或与源不符即 **fail-closed 报错指路**（同 `构建装配/演示/起演示.py` 对网关的处理）。
2. 「产物与源相符」不许靠手感（「我刚编过」不是保证），要靠**源指纹比对**：
   `构建装配/上线切换/构建制品/指纹.py::预构建指纹` 覆盖底座根文件 + 底座目录 + 扩展 + 装配器整包；
   戳记落在**构建缓存里**，不落源码树（判据 ⑳ 的口径）。
3. 环境步的墙钟**照实报、不判顶**，而且豁免的**口径与理由只写在一处** ——
   `构建装配/门禁/壳.py::报告环境步`。不许让各入口自己写 `if 参数 == "--预构建": 跳过门禁`：
   那样豁免就散进了各入口，下一个人读那条入口时看到的是「这里漏了门禁」，而真相是「这里按 §四 豁免」。

## 二 #233 的落法（**已落**）

`构建制品.py` 分两档：

| 档 | 做什么 | 判顶 |
|---|---|---|
| `--预构建` | 环境步：编底座网关 + 编每个扩展的可装载库 + 写戳 `构建环境/构建缓存/预构建.json` | **不判**（§四 豁免，照实报） |
| 装配档（默认） | 命令本体：**不编任何东西**，只比对戳；不符即「拒绝装配」+ 指路，退出 1 | 判（`自门禁`） |
| `--检查` | 只读一份已产出制品的不可变判据 | 判（`自门禁`） |

**实测（2026-09-27）**：冷 5570 ms ⇒ 装配档 **227 ms**（首跑，产出新制品）· 148 ms（制品已存在时拒绝）；
`--预构建` 172 ms（缓存热；冷时它本来就要编 —— 那正是 §四 豁免的那一段）。
**三态反向样本**：戳缺失 ⇒ 拒（退出 1）· 戳不符（`0000…`）⇒ 拒（退出 1）· 戳相符 ⇒ 装配成功（退出 0）。
样本制品用完按新纪律**显式指名**删掉（`rm -rf 构建装配/制品产物/861e968c2a5b-eac3ea7a9c926f4d`，
不用通配 —— 见 `开发规范.md` §八.8）。
**门禁反向样本**：`V1_CMD_SLOW_MS=5200 … --检查 <标识>` ⇒ 5230 ms > 4800 ms ⇒ 红、退出 1。

## 三 #226② `cargo test --workspace` **不算 bug**

冷 14.80 s = **测试 profile 的一次性冷构建** = §四 豁口项；命令本体（测试运行）热跑 **1.83–1.95 s**，
在顶内。它的环境步能被指名：`cargo test --no-run`。
**判据**：先跑 `cargo test --no-run`（环境步），再量 `cargo test --workspace` 的墙钟 ≤ 5000 ms。

**★ 补测（2026-09-27 复量）：上面那条判据**不够** —— 只跑 `--no-run` 再量，首跑仍会超顶。**
实测：`touch` 一个叶子 crate 的源 ⇒ `--no-run` 编 5 个 crate（退出码 0）⇒ 紧接
`cargo test --workspace` **5716 ms**，而它的日志里 `Compiling` **0 行** ⇒ 那约 3.9 秒的差值
**不是编译**，是**把刚写出的测试二进制从盘上读进页缓存**（同一次复量里更早一次读到 10151 ms，
差值更大是因为刚重建的件更多）。紧接第二跑 **1820 ms**。
⇒ **环境步的正确形态 = `cargo test --no-run` + 一次首跑**（把页缓存也热上）；量的是**第二跑**。
这也解释了「先 `--no-run` 再量」在本仓为什么时快时慢 —— 差的是**读盘**，不是测试。

**但如实登记一条边界**：**工具链命令没有我们的壳**。§六.1 的「每条命令的壳自量自门禁」只对
**我们自己写的入口**成立；`cargo …` 这类命令的墙钟只能靠**跑法**（先环境步）保证，不靠壳。
这不是「不判」，是「判据的落点不在壳上」—— 别为它造一条永远报「未判」的中央判据（§六.1 的两条实测理由）。

## 四 薄壳 `.sh` 的覆盖面（附带裁）

`构建装配/上线切换/{切换,回退,装载}.sh` 是三行 `exec python3 …上线切换.py` 的**薄壳**：
被它 exec 的 Python 入口**已带壳**，量到的就是同一条命令的墙钟（薄壳自己只多一次进程启动，
实测 < 10 ms，落在 200 ms 尾巴余量里）。
⇒ **薄壳不另加壳**：另加等于为每个包装脚本再起一个 `python3`，把墙钟做长而没有多出任何信息。
**配套判据（这条裁的守卫）**：薄壳必须「**只 exec、零逻辑**」；一旦它自己长出逻辑，就得自带壳。
纯 shell 且**有逻辑**的必须自带壳 —— `测试验证/案例/装门禁.sh` 已落：用 `trap … EXIT` 覆盖它那几条
`exit 1` 路径，阈值从 `构建装配/门禁/` 取（**不抄第二份**），反向样本 `V1_CMD_SLOW_MS=5200` ⇒ 红（5264 ms）。

## 五 附带发现（已单独立条 #235）

量 `上线切换` 时发现 **`切换` 的最坏路径 6544 ms 超顶**（两个活实例、其中一个不响应 SIGTERM
要走强杀）；实测里正常路径（`回退`，一个实例、干净 SIGTERM）= **910 ms** ⇒
**超顶的是最坏路径，不是正常路径**。根因一条：`上线切换/常量.py` 的 `停等秒 = 5.0` 一个数就顶破五秒
（那时最坏路径的账是 2×5 + 2×15 = 40 秒）。

**已修**：`停等秒 = 0.5` · `健康超时秒 = 1.8` ⇒ 最坏路径 2×0.5 + 2×1.8 = **4.6 s ≤ 4.8**（壳自门禁阈值）。
两个值的依据都是实测，不是拍的：SIGTERM 是**立即**走的（退出码 -15，正常路径 10 毫秒级）；
「起实例 + 等它打出 `监听 127.0.0.1:<端口>` + 健康检查 200」实测合计约 **600 ms**（1.8 秒 = 3 倍余量）。
**改后实测**：装载 663 / 935 ms · 切换 260 ms（两个实例）· 回退 201 ms · 现状 85 ms —— 全部在顶内，
`上线切换.py` 的壳自门禁同时落地（反向样本 `V1_CMD_SLOW_MS=5200` 必红）。

## 六 覆盖面与边界

**结论**：全仓入口逐条量过 —— **能跑完的入口要么带壳自门禁，要么落在下面三类边界里**；
边界由结构决定，不是「懒得加」。**清单与读数不在这里复述**（会漂）：判据是
「问一条入口『它跑完吗』」，答不出才归边界。

| 类 | 为什么硬顶不适用 | 实例（举例，不是全集） |
|---|---|---|
| **永不返回** | 没有「一条命令完整运行」这个可量的对象 | `前端呈现/桌面应用/启动.sh`（`exec swift` 起 GUI，窗口关才退出）· `构建环境/进入.sh`（**source 脚本**：只设环境、绝不 exec —— 它自己的注 2 明写「本入口只设环境，不做闸门」，理由是闸门放在入口会在别人半成品时把所有人卡住） |
| **环境步** | §四 豁免项（构建） | `构建制品.py --预构建`（走 `报告环境步`）· `构建环境/自检.sh`（内含 `cargo check --workspace`，自带墙钟报告与 3 秒提示） |
| **工具链本体** | §三 末段：`cargo …` 没有我们的壳，只能靠跑法（先环境步）保证 | `cargo test` / `cargo build` / `cargo check` |

**其余入口的覆盖形态**：
- 自带壳（`自门禁`）：各 `*.py` 入口 —— 阈值与注入**只从 `构建装配/门禁/` 取**（不抄第二份）。
- **薄 `.sh` 不另加壳**（§四）：`命令行界面.sh` · `上线切换/{切换,回退,装载}.sh` 一律
  **只 `exec` 已带壳的 Python 入口、零逻辑**。
- 闸 1 自己**不用壳**：`一键验证.py` 的墙钟由**判据 ⑱** 自量（`进程起始时刻` → 判据跑完）——
  它是「壳的判据化」，不是漏了。
- 有逻辑的纯 shell **必须自带壳**：`测试验证/案例/装门禁.sh`（§四）·
  `开发工具/并行工作树.sh`（2026-09-27 补：`trap … EXIT`；实测四档 列出 1384 / 自检 85 /
  新建 215 / 移除 91 ms 全在顶内；反向样本 `V1_CMD_SLOW_MS=5200` ⇒ 退出码 1）。
  补壳时撞到的 `set -e` 坑已写进 `开发规范.md` §八.9（教训归那里，不归本记录）。

**仍未做（唯一一条）**：一条**判据**断言「每个能跑完的入口，要么带壳、要么在边界白名单里」。
现在这件事**靠人逐条量维持**（本节就是那次量的记录），**不是判据** ⇒ 它会随仓长大而失效。
立它要给 `一键验证.py` 加行 ⇒ **暂时受阻**（判据⑲：超限件存量只许减）。
