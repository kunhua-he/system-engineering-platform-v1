## 一 裁决：四工具 · 四道闸 · 一开工一工作树一索引 · 只留一本账

| 工具 | 干什么 |
|---|---|
| `v1_task` 开工 | 功能 0=查询 · 1=登记 · 2=补充 · 3=释放 · 4=单纯释放 |
| `v1_symbol` 符号查询 | `关键词` / `限定名` / `限定名`+`关系`（调用者 / 被调用 / 影响面） |
| `v1_edit` 代码修改器 | 四道闸 + 按内容定位 + 原子写盘；每条改动带 `功能`（0=新建 · 1=修改 · 2=删除） |
| `v1_gate` 门禁 | **验证器**：留空 `判据` = 全量（放行凭据）；给判据名的一段 = 只跑那几条（快速复验） |

**四道闸**（`修改.py`）：① 开工号存在且「进行中」② 路径在那条开工的认领集里
③ 账本指纹 == 盘上指纹 ④ 旧内容能**唯一**定位。
**① ② ③ 全批先验**（任一不过 ⇒ **一个字节都不写**）；**④ 只能逐条**（前面写盘会改变文件）。
逐条走完「定位 → 写盘 → 刷索引 → 更新账本指纹」再走下一条 —— 定位靠内容不靠行号 ⇒ **顺序无关**。

**一开工 = 一条支线 + 一个工作树 + 一棵独立的索引。** 两条开工改同一个文件是**各改各的副本**
⇒ 根本不会互相覆盖，冲突推迟到合并（谁先推谁赢）。工作树的建/清走现成的 `并行工作树.sh`
（它还负责那棵树的构建缓存与 venv —— 没有它那棵树跑不了门禁）。

**只留一本账**：`开工账本.py`（sqlite 三张表，落 `<运行数据根>/数据库/`）。
**并掉** `开发工具/认领机制/`（整目录）＋ 撤掉 `.git/hooks/pre-commit` 里那个提交闸 ——
所有权与指纹的闸搬到了**写盘前**，比在提交时拦更早也更准。
**并掉** `v1_replace`（它就是「批量 `v1_edit`」的特例）。

**★ 不存 diff**：diff 本来就在 git 里（支线名就是开工号）⇒ 存第二份是第二套实现，
还会让 DB 随每次写盘疯长。代价：搜历史搜不到「上次把超时从 30 改成 5 是哪条开工」。

## 二 为什么 `v1_edit` 必须有「旧内容」（实测，不是口味）

`v1_symbol` 的行号来自**索引库**（快照），而它返回的指纹是**现读盘**算的
⇒ **同一条记录里两个数不同源**。实测（在 `开发工具/代码地图/落点.py` 顶上插一行、不刷索引）：

    改前    行=25  末行=26  指纹 e50086ffba0e3f7b
    改后    行=25  末行=26  指纹 ca83b2fbb622cc20      ← 行号没动，指纹变了
    盘上真位置：`def 库路径` 比这个读数**晚一行**（行号漂了）

而指纹闸比的是「账本 vs 盘」，**比不出「索引 vs 盘」** ⇒ 会出现「指纹绿灯 + 行号错一格」
= **静默改到隔壁那一行**。`旧内容` 把这一整类换成「当场拒」。

`旧内容` 一次干三件事：① **定位**（不靠行号）② **验证**（对不上就拒）③ **报错带解法**
（「在第 N 行」「出现 3 次 ⇒ 多给几行上下文」「找不到 ⇒ 文件已变」）。

## 三 为什么 `v1_gate` 按「判据」切，不按「件」切（实测）

判据的 `扫描面` 是按**顶层目录**声明的 ⇒ 拿一个件去筛，37 条里还命中 10–17 条，
而重型那几条几乎每条件的面里都有：

| 跑法 | 判据数 | 墙钟 |
|---|---|---|
| 全量 | 37 | 1164 ms |
| 只跑「扫描面覆盖 `开发工具/MCP服务/工具.py`」的 | 10 | 1124 ms |
| 只跑「扫描面覆盖 `运行内核/装载入口/src/判定.rs`」的 | 16 | 1135 ms |

**省 3% —— 白搭**。按**判据**切才是真杠杆：

| 跑法 | 墙钟 |
|---|---|
| 空集（纯读仓的地板） | 247 ms |
| 只跑 ㊲ 超时设置 | 1097 ms |
| 只跑 ㉒ 命名防回潮 | 689 ms |
| 只跑 ⑱ 命令墙钟 | 245 ms |

**㊲ 一条就吃掉全量的 73%**（它和 ㉒/㉕/⑪/⑫/⑩ 各自把全仓过一遍 `剥字面量` —— 台账 #224）。

**哲学**：局部绿 ≠ 全仓绿（判据之间有耦合）⇒ **局部只作反馈，放行只认全量**。
局部存在的理由是「反馈要快」，不是「少验一点」—— 没有这一档，agent 会因为全量慢而干脆不验。
五秒硬顶**不进工具描述**（它是本仓的内部纪律，不是模型要背的规则），但它是这个形状的来源之一。

## 四 实测撞到并修掉的三处

1. **`codegraph index` 对全新目录直接失败**（`✗ CodeGraph not initialized`）⇒ `建` 要先 `init` 打底。
   撞在两处：刚建出的工作树、以及**新克隆的仓**。这一条是上一轮交的 bug。
2. **`库读数` / `建` 的返回用错了变量**（`库路径` 只在查询函数上是参数，`建` 的参数叫 `仓根`）
   ⇒ NameError；顺带修 `库读数` 漏把 `库路径` 传给 `连库`（会静默数到默认那个库）。
3. **判据 ㉕ 抓到两处「第二来源」**（都是本仓的规矩，实测当场红）：
   · `Path("/tmp") / …` 拼临时件（形④「临时根拼路径」）⇒ 改成 `git commit -F -` **走 stdin**，连临时件都不落；
   · 在 Python 里又写了一份 `"系统工程平台V1.工作树"` 目录名（形②）—— 那个名字的唯一定义处是
     `并行工作树.sh` ⇒ 改成**问 git**（`git worktree list --porcelain` 按支线找路径）。

## 五 钩子闸（唯一强制点）

`装钩子.py` 把 PreToolUse 钩子写进 `~/.zcode/cli/config.json`（**用户级，版本库外** ⇒
「怎么装」必须版本化，同 `装门禁.sh` 的理由）。**零逻辑 · 一张名单**：

- matcher = `Edit|Write|MultiEdit|NotebookEdit`（大小写敏感的正则，匹配工具名）；钩子体只打印
  「该走哪个工具」然后 `exit 2`（MCP 协议：2 = 拦）。
- **`Bash` 放行**：钩子分不出 Bash 的读与写，硬拦会让 agent 连 `闸0.py` 和 `git status` 都跑不了。
  绕过 MCP 的 Bash 写由**指纹对账**兜 —— 一处实现（`修改.py::对账`），两处用：
  `v1_edit` 的第 ③ 道闸（变过 ⇒ 拒写）与 `v1_gate` 的绕过检测（变过 ⇒ 报出来）。
- 配置文件的钩子**默认不跑** ⇒ 必须 `hooks.enabled: true`（本件写它）。
- 实测：装完 `PreToolUse` 只有自家 1 条（幂等，别人的一条没动）；真跑一次退出码 **2**。

## 八 交付后审计（探针实测，不是读代码猜的）

四件工具交付、重启实测通过之后，又按「还会在哪儿炸」逐条探了一遍。**三处缺陷 + 两处收口**，
都改在这条记录之后的一次提交里。

### 八.一 功能 = 0 新建是**死代码**

认领那一刻**读不到盘**（`读盘指纹` 只收读得到的件）⇒ 新建的件进不了认领集 ⇒ 第 ② 道闸
「不在认领集里」把它挡死。实测：`功能 = 0` 新建 ⇒ 码 3「拒（第 ② 道闸 · 认领）」。

改两处，缺一不可：

1. 第 ② 道闸对「不在认领集里**且盘上确实不存在**」的件放行 —— 存在却不认领的仍然拒（那才是真越界）。
2. `开工账本.写回指纹` 由 `update` 改 **upsert** —— 新建出来的件写完之后账本里没有它那一行，
   下一次改动会被第 ③ 道闸判成「变过」⇒ **这个件再也改不动**。这一处是修完第 1 处才暴露出来的
   （第一处修完，新建通了、第二次改它又拒了）。

### 八.二 释放重试**卡死**

「提交成功、推送失败」之后重跑释放：工作树已干净 ⇒ `git commit` 以 `nothing to commit` 失败
⇒ 被当成错误返回，而且**报成「门禁钩子可能拒了」—— 归因是错的**，状态还留在「进行中」⇒ 永远释放不了。

改：提交前先 `git status --porcelain -- <改动表路径>` 问一句有没有东西可提交，没有就跳过、直接推。

### 八.三 释放**不查绕过**

有人用 `Bash` 直接写盘的件**不在改动表里** ⇒ 不会被提交；而门禁是在**工作树上**跑的、读的正是盘上的
新内容 ⇒ 一次「门禁绿、提交里却没有那份改动」的释放。改：提交之前跑两道 ——
`修改.对账`（与 `v1_edit` 第 ③ 道闸**共用一份实现**）+ `git status` 查改动表之外的路径，有就拒。

### 八.四 `callers` / `callees` 有**系统性假阴性**

实测：`读认领` · `连账本` 明明被多处调用，`codegraph callers` 说 `No callers found`；
而 `文件指纹`（13）· `出现位置`（4）· `找命令`（6）能正常列出。差别在**调用写法**：
`模块.函数(...)` 这种带限定名的调用它解析不出来，**裸名字**调用才认得。`impact` 不受影响（可用）。

⇒ 工具不能把空集直接摆出来（会被读成「真没有」，agent 照着删东西）。`符号.py` 现在在这种输出后
补一句：**这是索引器的说法、不等于真没有**，并给出复核办法（用 `限定名` 查**出现位**）。
口径与 §一 那条「空集是未判，不是没有」一致。

### 八.五 两处收口

- git 的 `commit` / `push` 带上 `GIT_TERMINAL_PROMPT=0`：远端要认证时 git 会**停下来等人敲密码**，
  而这两个子进程**不设超时** ⇒ 那不是超时，是**永挂**。
- `符号.py` 里的关系命令改走 `索引库.找命令()`（命令名只此一份；找不到给安装指引，不是 traceback）。
- 顺带修一处**说谎的注释**：`修改.py` 写着「每条写完都刷索引」，代码一直是**循环外刷一次**
  （代码是对的：定位靠**内容**不靠行号，一次 `sync` 389 ms，N 条改动不必付 N 次）。注释已改回实话。

### 八.六 探针的验收与清理

- 探针一（登记 → 新建 → 再改同一件）：通，盘上内容是第二版，账本认领栏补上了新指纹。
- 探针二（手工提交 → 重跑释放）：通，码 0，输出写明「这一步没有新改动要提交 —— 上一趟已经提交过了」，
  真推到了 `origin/腿/v1-100001`。
- 清理：远端那条支线**已删**、工作树已移除、本地支线已删、账本三张表清空。全量门禁 37/0/0 绿。
