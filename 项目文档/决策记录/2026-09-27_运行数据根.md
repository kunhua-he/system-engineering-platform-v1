## 一 为什么它必须是一个唯一物（入核五问）

| 问 | 答 |
|---|---|
| 是不是**唯一**的？ | 是。「运行数据放哪」全平台只有一个答案，第二个答案就是位置漂 |
| 换掉它要动调用方吗？ | **不要**。调用方拿「根路径」这个值，不认它是怎么定出来的 |
| 它是**机制**还是**策略**？ | 机制（唯一解析器 + 四类封闭枚举）。**具体位置是部署事实**，由环境变量注入 ⇒ 策略不进核心 |
| 它认识任何扩展吗？ | 不认识。零依赖，不碰契约、不碰任何别的内核节点 |
| 删了它，底座还跑吗？ | 跑。要落运行数据的节点会拿到 `无位置` 这个结构化失败，**不是崩溃** |

⇒ 入核。它是第 13 个唯一物（前 12 个见 `2026-09-27_核心只放唯一物.md` §四）。

## 二 落点与命名（本条闭掉 README §十一 那条未定项）

| 项 | 定死 |
|---|---|
| **落点** | `运行内核/运行数据根/`，crate `v1-dataroot` |
| **名字** | **运行数据根**（源码、文档、常量名一律用这一个；不许叫「数据目录」「工作目录」「临时根」——那三个词在仓内已有别的意思） |
| **默认目录名** | `系统工程平台V1`（`解析.rs::默认目录名`，**唯一来源**） |
| **覆盖** | 环境变量 `V1_RUN_DATA_ROOT` —— **变量名 ASCII**（`macOS` 的 `/bin/sh` 是 bash 3.2，不认中文变量名；`.git/hooks/pre-commit` 顶部同一条理由），**值可以是任何路径** |

**默认位置 = 平台数据目录 + `系统工程平台V1`**（三条规则互不重叠）：

| 平台 | 基 | 依据 |
|---|---|---|
| macOS | `$HOME/Library/Application Support` | Apple 的应用数据约定（`~/Library/Application Support/<应用>`） |
| Linux | `$XDG_DATA_HOME`，未设则 `$HOME/.local/share` | XDG Base Directory 规范（未设时的退回值是规范自身写的） |
| Windows | `%APPDATA%` | Windows 的应用数据目录（**不是**家目录 —— 两者别混） |

**四类子目录**（`README.md` §十 的四类，做成**封闭枚举**）：`数据库` · `缓存` · `日志` · `临时件`。
做成枚举而不是四个字符串：加第五类**编译期**就要动一处，而不是散在调用方各写各的目录名。

**为什么覆盖非空时不再拼 `系统工程平台V1`**：覆盖是**完整根**，部署方说了算。
再拼一层，部署方说的位置与平台实际用的位置就不是同一个了（「一份数据两处读法」）。

## 三 两条自证判据（配反向样本）

| # | 判据 | 怎么判 | 反向样本 |
|---|---|---|---|
| 1 | **唯一解析器** | 解析口只有 `解析.rs::解析` 一处；其余口都拿「已解析的根」当入参（`解析当前` 是读 env 的薄壳，零判断） | 把某条平台规则改成 `PathBuf::from(".")` ⇒ 判据 2 当场红 |
| 2 | **默认位置永不在源码树内** | 三条规则各来一次，断言结果**既绝对、也不以当前目录为前缀** | 同左（`测试.rs::默认位置不在源码树内_三条规则都推不出当前目录`） |

另配三条：覆盖优先（且不再拼目录名）· 全缺时**结构化失败不编路径** · 四类子目录名两两不同且次序与判别值一致。

## 四 明确不做

| 不做 | 为什么 |
|---|---|
| 不在解析时建目录 | 「只是想算个路径」不该有副作用；建目录是 `确保子目录` 单独一口 |
| 不把默认目录名放进 `契约声明/常量表.json` | 常量表**只认整数**（`格式说明.md`），放文本要改生成器；而这个名字只被本 crate 一处引用 ⇒ 不满足「两处以上引用就必须进常量表」 |
| 不读全局环境做解析 | 解析器只吃注入的 [`环境`]；读真实环境是 `解析当前` 那一层 —— 否则六条分支互相污染（本项目已有「两测试共用进程级 `static`」的教训） |
| 不自行造 `~` 展开 / 路径规范化 | 那是文件系统的事，不是「运行数据放哪」的事；多一层变换就多一处会漂的地方 |
