# 安全边界（裁定：防到哪一层为止）

日期：2026-09-28 ｜ 裁决人：华哥（原话：「本质上是安全边界的设置的多，这个是需要去做的。但是也不可能无限深度，需要定义一个边界」）
上级：`README.md` §三 设计前提 ｜ 落点：`项目文档/决策记录/2026-09-28_安全边界.md`
相关：`项目文档/设计文档/资源网关口.md`（默认拒绝）· `项目文档/决策记录/2026-09-27_外部支持库准入判据.md`（16 条）· `项目文档/设计文档/进程隔离方案.md` · `项目文档/开发规范/开发规范.md` §四

**一句话**：**只防「经边界的不可信输入造成内存不安全 / 静默误判 / 进程死」；不防「要有权限才能发动的攻击」，也不做鉴权。** 前者是本平台宪法（错误必须立刻可见 + 定长槽可判）的延伸；后者要么已有别的机制兜住，要么代价大于收益。

---

## 一 信任模型（谁可信 · 谁不可信）

| 主体 | 可信度 | 依据 |
|---|---|---|
| 底座自身（契约声明 · 运行内核 · 跨语言适配 · 对外接口面） | **可信** | 我方代码，同一批判据面管着 |
| **经边界的输入**（HTTP 请求体 · 声明文件 · 容器字节 · 程序文本 · JSON · 扩展声明） | **不可信** | 平台「首先是给 agent 用的」⇒ 调用方会乱发、发错、发畸形 |
| **扩展本体**（外部支持库 / 模块） | **当前完全可信（同进程 · 无隔离）** | `进程隔离方案.md` §一：`dlopen` 同地址空间、裸函数指针直跳。⇒ 这是**已知的边界外**，用**准入纪律**兜：`外部支持库准入判据.md` 全绿前不装外部扩展 |
| 浏览器 / 跨站页面 | **边界外** | 网关只监听回环、无会话、无凭据、无 cookie |
| 本机已拿到文件系统写权限的进程 | **边界外** | 它已越过了本平台的边界 |

---

## 二 边界内（必做）—— 四条

这四条不是「安全加固」，是**本平台宪法的落点**（宪法「失败可编程处理」「错误必须立刻可见」+ 定长槽「类型不符当场可判」）：

1. **边界输入一律 fail-closed**：来自 §一「不可信」那一行的输入，解析失败必须给结构化错误码，**不许 panic / 越界 / 无限循环 / 无界分配**。
2. **一切长度 · 个数 · 偏移有上界**：`参数个数` · 表项数 · 段长度 · 指纹条数 · JSON 深度 —— 有界才有「当场可判」；无界既是不安全，也是静默误判的来源。
3. **副作用默认拒绝**：资源网关口（`资源网关口.md` §五 四处拒绝）· 声明里没写的不存在。
4. **不许挂死**：子进程 · HTTP · 健康等待 · 浏览器 goto 一律 ≤ 5 秒（`AGENTS.md` §二 · 判据 ㊲）；长活不许走同步请求路。

## 三 边界外（明确不防 —— 逐条写清为什么不防）

| 不防 | 为什么不防 |
|---|---|
| 鉴权 / 认证 / 多用户 / 多租户隔离 | 平台是**本机单用户**、给 agent 用；加鉴权会把「一个入口、一次调用」变成「先拿令牌再调」，直接违使用角色的极简判据。要隔离就用**进程 / 机器**边界（部署层的事），不在平台内做 |
| CSRF / `Origin` / `Referer` 校验 | 网关无会话、无 cookie、无凭据可窃；写盘端点只认 `.程序文本` 后缀、只在回环可达。**收益 ≈ 0，代价是每个请求都要过一条检查** |
| 进程隔离 / 沙箱 | 属 `外部支持库准入判据.md` ① 的**施工项**（候选 A 子进程，见 `进程隔离方案.md` §二），不是运行期防御；且**准入全绿前不装外部扩展** ⇒ 今天没有这个攻击者 |
| 侧信道 / 时序攻击 | 本平台不处理秘密（无密钥 · 无口令 · 无隐私数据）⇒ 无可窃之物 |
| DoS / 速率限制之外 | 已有单项超时 + 配额账本（`契约声明/常量表.json::配额上限`）⇒ 单调用有界；多调用打满本机是**本机自身的事** |
| fuzz 全覆盖 / 形式化验证 | 边界内只要求「定向反向样本」（每条解析器配畸形输入样本）；**不做全自动 fuzz 基建** |
| 静态托管的符号链接 | 需要在仓内建符号链接 = **已拿到文件系统写权限**（§一 最后一行）⇒ 已在边界外 |
| 32 位 / Windows 平台特有路径 | **不防，但要测**：`Path::join` 遇 `C:/x` 会替换根 ⇒ 归边界内第 1/2 条（路径包含性校验），标为**待实测**，不许当已判 |

## 四 已知威胁逐条归类（把审计发现落进边界）

| 威胁 | 归类 | 处置 |
|---|---|---|
| 扩展声明的 `参数个数` 缺上限 ⇒ 越界 UB | **边界内**（第 2 条） | 必做：给上限 + 反向样本（台账 260） |
| `工具链::跑命令` 无超时且挂请求路 | **边界内**（第 4 条） | 必做（台账 261） |
| 引用槽出参 `长度` 无上界 ⇒ `from_raw_parts` 越界 | **边界内**（第 2 条） | 必做：给长度设上限 |
| `POST /接口/程序文本` 任意 `*.程序文本` 读写 | **边界外**（已裁设计：调用方自带路径，`2026-09-28_华哥的尺子与七条裁决.md` §二 206）+ 登记「仅回环 · 开发期端点」 | 只补登记，不改行为 |
| 网关不校验 `Origin` | **边界外**（见 §三） | 登记理由，不改 |
| 扩展崩了带走网关 | **边界外**（准入纪律兜） | 准入判据 ① 的施工项（台账 239） |
| 静态托管跟随符号链接 | **边界外**（见 §三） | 不改 |
| 静态托管 `C:/x` 替换根（Windows） | **边界内**（第 1/2 条） | 待实测后修（路径包含性校验） |

## 五 新威胁怎么归入（可数规则，不必每次重裁）

来一个安全问题，按顺序问三句：

1. **攻击者是谁、他在哪？** 若在 §一「边界外」那几行里 ⇒ **边界外**（登记一行理由，完事）。
2. **他能经边界送入什么？** 若送进来的东西能让底座 **UB / panic / 无限循环 / 无界分配 / 静默误判** ⇒ **边界内**（必做，配反向样本）。
3. **两问都答不出** ⇒ **判不了**：不许当成「边界外」默认放过，也不许当成「边界内」无限加固 ⇒ 报收口方裁。

**判据（可数）**：§四 那张表里每一条 ∈ {边界内, 边界外}，且「边界内」每一条在 `项目文档/未完成事项.md` 有对应条目（或已绿）。

## 六 明确不做

| 不做 | 为什么 |
|---|---|
| 不因「安全」给平台加第二套入口 / 令牌 / 会话 | 违宪法 1（一个唯一入口）与使用角色极简判据 |
| 不把「边界外」当成「永远不看」 | 边界外要**登记理由**；理由过期（如网关将来监听非回环）⇒ 边界要重裁 |
| 不用「深度」代替「边界」 | 华哥原话「不可能无限深度」；**每加一层防御都要答「攻击者在哪」，答不出就不加** |
| 不为边界内条目放宽已有判据 | `开发规范.md` §四：唯一禁止的动作是改判据让它变绿 |
