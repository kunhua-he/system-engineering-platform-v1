# DAG 与资源调度升级方案单

状态：方案待实施；本轮仅修改本文件，不改代码、契约、数据库或服务。
裁决：复用现有单能力执行、进程池、许可、取消和回收；补齐图调度及接线，不重建一套底座。

## 一、固定主链与分工

```text
HTML / C ABI / 资源操作
  └─ 适配器公开调用面（同实例共用调度器）
       ├─ 单能力请求 → 归一为单节点图
       ├─ DAG 请求 → 校验依赖与输入引用
       └─ 查询 / 取消 / 释放 → 访问同一任务记录
                    ↓
          图调度：依赖计数 → 就绪 → 等资源
                    ↓
          资源取得：CPU / 内存 + 具名资源租约
                    ↓
          适配器内部叶子执行（不再次提交任务）
             ├─ 进程内 → 原调度核心
             └─ 跨进程 → 原池与原协议
                    ↓
          异步任务跟踪 → 真实终止 → 资源收尾
                    ↓
          状态落库 → 唤醒等待者与后继 → 回执
```

HTTP 执行地址保持 `POST http://127.0.0.1:43110/接口/调用`。图调度不放在 HTTP 专属层，避免 C ABI、资源操作和模块内部调用漏管。控制请求不排在业务执行队列后面。

## 二、已有件怎么用

以下均为已有路径；不整体搬目录、不改既有公开名称。

- **单能力执行**：`运行内核/调用调度/src/调度核心.rs::调度调用`保留校验、配额、执行和记账；不塞 DAG、不直接承担跨进程执行。
- **适配器**：`跨语言适配/适配器实现/src/核心实现/适配器定义.rs::调用能力带追踪`是统一接线点；原函数体收成私有叶子执行，新公开调用先过图调度。`调用能力`、C ABI、资源装配共用它，不各加调度器。
- **连接线程**：`对外接口面/调用接口面/src/网关.rs::服务`继续接收 HTTP；连接线程与节点执行线程分开，等待资源不得占满连接线程。
- **取消原语**：`运行内核/调用调度/src/协作取消.rs::协作取消表`继续记录取消交涉阶段；节点表只关联其凭据，不复制一套取消阶段。
- **预算与回收**：`跨语言适配/适配器实现/src/原池执行/进程池/`中的`动态预算.rs`、`进程额度.rs`、`回收.rs`、`资源读数.rs`保留。通过回调向图调度交付读数、额度与退出确认，不把上层进程实现搬入内核。
- **提供者任务**：网络、模型、进程的任务表继续归各支持库；图记录仅关联“提供者身份、实例代次、原子任务句柄”，不复制执行体。
- **存储**：已有 SQLite 能力 `5101 执行事务 / 5102 只读查询`用于任务持久化；已有运行数据根负责定位。不得把开发工具的`信息核心.db`用作业务任务库。

## 三、缺失件的唯一落点与名称

以下为拟新增件；名称为施工冻结名，登记时按该名检查，不另起同义名。

### 1. 内核：算法、类型与回调接口

置于既有`运行内核/调用调度/src/`，该层不依赖适配器、HTTP、具体扩展或 SQLite 实现：

- `调用任务图.rs`：冻结图、剩余依赖数、后继索引、输入引用；提交后图不可变。
- `调用节点状态.rs`：节点/任务状态及转换守卫；不含执行体。
- `调用资源车道.rs`：中央等待队列、资源需求、具名车道、组合资源准入。
- `调用任务调度器.rs`：就绪调度、结果事件、失败传播、取消传播、统一收尾编排。
- `调用任务接口.rs`：执行、存储、资源、异步跟踪四类回调合同；供适配器实现。

修改原`lib.rs`再导出以上公开面；保持入口零实现。叶子执行器、配额账本、协作取消不迁移。

### 2. 适配器：持有实例、接现实资源

拟新增`跨语言适配/适配器实现/src/调用任务装配/`：

- `调度实例.rs`：实例级调度器、持久工作线程、唤醒信号、停止与汇合。
- `叶子执行.rs`：承接原`调用能力带追踪`执行体；唯一可调用原池/调度核心的业务叶子入口，防止递归提交。
- `资源接线.rs`：预算采样、资源画像读取、提供者租约、句柄归属；不另维护提供者占用表。
- `任务跟踪.rs`：异步任务的查询/取消/释放接线；返回“生成中”不等于节点成功。
- `任务存储.rs`：建表、事务、幂等提交、状态回读与重启对账。

`适配器定义.rs`持有共享调度实例；候选装载克隆路由快照，不重建任务账。调度实例不强持其宿主，工作项持所需执行快照，避免 Arc 循环。

### 3. 协议、画像与生成

- 拟新增`契约声明/调用任务协议.json`：任务字段、状态、错误类别及回执的唯一声明源。
- 修改`构建装配/形态装配/生成声明/生成编排/生成流程.py`：由该声明生成内核/接口面共用类型与契约样本；不手抄枚举。
- 各支持库既有`包声明.json`增加`调度画像`，按能力号关联执行类别、参数名到资源键、异步查询/取消/释放能力及副作用类别；不复制参数类型和默认值。
- 修改制品构建与装载，将画像随制品封包并校验与能力声明对应；`资源接线.rs`只读取已装载版本。无画像的能力不得默认为轻量/可重试。
- 画像为宿主侧调度元数据；不改`命令信息`的 C 布局，不让扩展反向依赖调度器。

## 四、请求与返回固定形状

1. 单能力仍用`编号 + 值/命名值`；内部转成单节点，不保留旁路执行。现有即时完成响应保持原结构；同步 C ABI 继续等待结果，不在原返回槽里塞入文本任务标识，不改槽 ABI。
2. DAG 体用`任务操作=提交、请求标识、节点表`；可选`同步等待毫秒、截止时刻`。缺省截止时刻表示不设整图截止；同步等待缺省立即交回任务标识。
3. 节点固定字段：`节点标识、编号、命名值、依赖节点、输入引用`。资源参数由宿主推导，调用方不得指定车道/额度。
4. `输入引用`为“目标参数名 → 来源节点标识 + 返回路径”；同一参数不得同时给字面值和引用。引用节点必须属于其传递前驱；提交时核返回类型，前驱完成后再核实际路径和值。
5. 控制体用`任务操作=查询/取消/释放、任务标识`；查询可带`节点标识`，默认只回任务摘要，避免每次复制整棵图。
6. 同步窗口结束未完成：保留平台信封，在`值`中返回`任务标识、任务状态`，`成功`只表示受理成功；任务是否成功看任务状态。
7. 图任务用不透明文本`任务标识`，绑定实例、调用身份和存储记录；不改标签 7 的扩展任务句柄语义，不把追踪号当任务标识。
8. 同一调用身份下相同`请求标识+规范化请求摘要`返回原任务；同标识不同内容明确冲突。查询/取消/释放校验同一身份，不能仅凭可猜编号操作其他任务。
9. 第一版静态冻结图；嵌套分支展开为同一图，不允许运行中增边或循环。重复依赖、未知节点、自依赖、环及非法引用一并拒绝。

协议落点：修改`对外接口面/调用接口面/src/协议报文/请求.rs`、`执行装配/分发.rs`、`响应.rs`；字段与返回验证读取同一声明源，不在三个文件维护三张词表。

## 五、调度、状态与时间固定规则

- 节点主状态：`等待依赖、就绪、等资源、执行中、收尾中、成功、失败、跳过、已取消`。补偿阶段复用协作取消原语；没有补偿能力不能宣称已补偿。
- 所有前驱成功才释放节点；前驱失败/跳过/取消则后继跳过，独立分支继续。整个图终态须等待执行体与收尾完成。
- 节点完成事件带实例代次、节点标识和执行批号；重复/迟到回执不得重复减依赖数或启动后继。
- 同资源键按入队序；不同车道按任务轮转，避免大图独占。第一版不做未经标定的“关键路径预测优先”。
- 工作线程复用持久池，CPU与阻塞任务分池；同池内部调用复用任务上下文，不提交后同步等同一池。中间值按消费者计数释放；需交付的最终输出保留至任务结果到期或显式释放。
- 资源等待、同步响应窗口、叶子执行预算、整图截止分别记录。同步窗口结束和客户端断线不取消任务；排队不消耗叶子执行预算。
- 截止/取消先记录请求，再停止未运行节点并请求执行侧终止；未确认退出仍为收尾中，继续计资源占用，不能提前放租约。
- 业务失败、无效句柄、权限/路径错误不可重试；只有结构化“暂忙且确认尚未执行”可重新准入。执行结果未知不自动重放，防止文件/数据库副作用重复。

## 六、资源组合与必须修的接缝

### 1. 共性收口

- CPU、内存和具名资源采用一次试取；任何一项暂不可得，撤销本次预留再入队，不持一部分资源睡等另一部分。提供者试取必须短时、无业务副作用。
- 预算采样接既有`动态预算.rs`；资源释放事件立即唤醒，外部压力变化沿用现有采样节流。高利用率本身不判故障，不以 CPU 时间不涨直接判 GPU 推理卡死。
- 进程额度只计真实进程，模型常驻内存只计一次；节点计算额度不重复扣进程驻留成本。模型不同服务可并行，同服务按许可容量。
- 资源键包含实例/提供者/代次及真实句柄；输出路径按同一归一化规则生成键。租约只有一个所有者，回执/队列/快照均为该账的视图。
- 任务终态不等于释放调用方原有连接/会话/模型。借用资源只还执行许可；任务创建且未交出的资源由统一收尾释放。
- 准入按真实成本和压力；不把未复核的“单浏览器632MiB”当标定依据。重新按进程树归属测成本，区分共享内存、常驻量与增量。
- 正常任务持久化后排队，不无限堆在内存。存储不可写、请求不合法或单项明确无法容纳时才拒绝受理；危急态回结构化原因，不能假装已接收。

### 2. 定向修改已有实现

- **模型**：`大语言模型支持库/src/推理许可.rs`保留按服务持有表，移除第二套公平队列；`2516–2518`接同一许可账。`一次对话.rs`与`生成任务.rs`把许可所有权移交真实生成任务，终止确认后归还；禁止固定5秒一到就把仍在跑的许可转授。已持许可的节点内部调用不得重复申请。
- **浏览器**：`浏览器支持库/src/浏览器会话.rs`把表锁缩到取会话引用；CDP收发锁放到会话内，不同会话不共用长锁。创建失败和关闭都确认退出并清目录；`静态声明.rs`接生命周期通知。
- **PostgreSQL**：`PostgreSQL支持库/src/连接与句柄.rs`同样拆成短表锁+连接锁；移除锁忙即失败。同连接/事务串行，不同连接并行。
- **文件**：`文件支持库/src/受控写入面.rs`保留原子替换；路径互斥由资源车道负责，原子落盘不冒充排队顺序。
- **进程任务**：`进程执行支持库/src/进程任务管理.rs`取消改成按归属终止进程组、确认退出、收管道并回收；接生命周期通知。状态取消不能只写成普通失败。
- **原池**：`原池执行/进程调用.rs`与`进程池/帧收发.rs`先核执行域串行边界。无状态能力可分配多个受控域；有句柄能力固定所属域/代次。同域共享通道若需并发，按请求标识分发响应并联动`工作进程.rs`，不盲目多开进程导致句柄失效。只改浏览器表锁不能宣称跨进程多会话已并行。

以上路径前缀分别为`扩展根目录/原子支持库/`与`跨语言适配/适配器实现/src/`。

## 七、持久化、退出与升级边界

- `任务存储.rs`通过装配注入存储回调，复用现有5101/5102叶子调用；这是状态机内部存储，不再次生成任务、申请业务资源或排业务队列，避免递归。启动时固定绑定该存储提供者，缺失则不受理图任务；内核不直接依赖扩展。
- 路径由既有运行数据根解析为`数据库/调用任务.db`；表固定为`调用任务、调用节点、调用依赖、调用资源租约、调用状态变更`。摘要、幂等键、任务/节点状态和完成事件以事务提交；内存队列只作可重建索引。
- 任务受理先落库再回凭据；节点执行前记执行批号，完成先提交终态再唤醒后继。收尾失败保留收尾中及错误，不删除证据、不报已清理。
- 重启后先核对资源指纹/进程代次；未开始节点可恢复，执行过但结果未知的节点记失败并注明结果未知，不自动重放副作用。原子句柄不跨重启复用。
- 任务固定执行快照和画像摘要；排队期间不偷偷切换版本。停机先停受理、取消等待、排空或终止在途，再释放快照和提供者；更新不得卸载仍被任务持有的执行体。
- 任务凭据在显式释放前可查；到期清理先确认无在途、无借出输出、无未归还租约。结果保留期限、同步等待上限和执行预算统一由`契约声明/常量表.json`给出；不再保留“全仓5秒硬顶”散文。

- `网页界面支持库/src/组件树.rs`及`交互脚本/组件引导.rs`：宿主脚本以4929真实契约构造`/接口/调用`，按平台信封取组件片段；不只换URL。客户端组件事件顺序可保留，业务依赖/资源调度归服务端。

## 九、施工依赖与验收落点

1. **冻结声明**：协议、状态、画像、回调、存储表结构与错误类别齐备；生成类型和请求样本，不改现有槽 ABI。
2. **组合现成件**：先接适配器公开面/私有叶子面及存储回调，消除递归；保留原池与执行快照。

5. **迁移消费者**：组件脚本、编译页面、C ABI、资源操作一起核调用路径，不漏旧入口。
6. **统一验收**：拟新增`测试验证/DAG调度验收.html`，由现有网关静态托管；拟新增`测试验证/DAG调度断言.js`读取同源声明样本，串联真实页面和任务回读。纯算法测试只定位缺陷，不替代此验收。

必须覆盖：菱形汇合、嵌套展开、跨图并行、环/坏引用拒绝、同键FIFO、独立资源并行、资源不足排队后唤醒、重复提交、重复/迟到完成事件、异步生成许可保留、独立分支失败隔离、取消执行/等待节点、断线续查、重启结果未知不重放、升级快照、终态资源回落。

并行证明同时看节点执行区间、真实资源持有和返回值；不以连接并发或HTTP 200替代。结果绑定同一源码/契约/制品摘要，候选真验通过后才切正式口复验。
