# 案例回执不进版本库 —— 它是运行数据，不是源码

日期：2026-09-27 ｜ 裁决人：华哥（原话：「这个就需要解决一下了」）

---

## 二 裁决：不进版本库

`.gitignore` 加一行（`测试验证/案例/运行回执.jsonl`）＋ 钩子第 ⑤ 步从「`git add` 回执」改成
**「不暂存回执」**。文件本身留在盘上、路径不变、写入方不变。

**为什么选这条而不是「按支线分片」**：

| | 不进版本库 | 按支线分片 |
|---|---|---|
| 改动面 | `.gitignore` ＋ 钩子第 ⑤ 步 ＋ 四处文档 | 写入方（Rust）＋ 读取方（Rust）＋ 常量 ＋ 形状.md ＋ 读取工具要会跨分片取最新 |
| 判据面 | **0 处依赖**（实测：`构建装配/一键验证/` 里 0 处引用它） | 同上 |
| 冲突 | **归零** | 归零 |
| 代价 | 克隆下来没有历史读数 | 分片永久累积，且「最新一份」要跨件聚合 |

**判据面 0 处依赖**是决定性的一条 —— 换路径要动 Rust 的写入方与读取方（`跑案例/src/回执.rs` ·
`对外接口面/调用接口面/src/工具响应_案例.rs` · `常量.rs`），而这条修法**一行 Rust 都不用改**。

## 三 保证没变（这条要写清，否则像是放松了门禁）

- 钩子**每次提交都跑全部案例**，任一失败即拒提交 ⇒「**提交存在 ⇒ 案例当时过了**」仍然成立。
- 回执只是**读数**（死在哪一层、耗时多少）。要查最近一次读数就读本机那个件。
- `跑案例` 那一侧的「工作区是否干净」判定（`跑案例/src/回执.rs::工作区干净`）用
  `git status --porcelain -- :(exclude)<回执>` —— 回执被忽略后 `git status` 本来就不列它，
  那行 exclude **成了不必要的兜底**，留着（万一有人再把它加回版本库，排除逻辑仍然对）。
  同理 `构建装配/上线切换/构建制品/命令.py::提交哈希` 里那行排除。
