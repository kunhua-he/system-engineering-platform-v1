# 代码地图 —— 本仓的符号索引（独立一套）

日期：2026-09-27 ｜ 裁决人：华哥（原话：「能不能单独给这个项目，装一个代码地图？不是 mcp 的那套，而是独立装一套。方便快速索引代码」）

---

## 一 裁决

V1 的代码地图 = **预建符号索引 ＋ 只读查询**，产出者是 **`rust-analyzer`**（Rust 官方组件）。
落地两件：

- `开发工具/代码地图.py` —— 入口（`建` / `查 <关键词>` / `引用 <限定名>` / `状态`）；
- `开发工具/代码地图/` —— `索引.py`（读 LSIF 建符号表）· `建索引.py`（调 rust-analyzer）。

索引落点 = **`<运行数据根>/缓存/代码地图/索引.lsif`**（判据 ⑳：运行数据不落源码树）。

**它买的是什么**：`rg` 管「哪几行有这个字」，代码地图管「**谁是定义、谁在引用它**」。

## 二 为什么是这个形状

| 问 | 答 | 读数 |
|---|---|---|
| 为什么不每次现查 | rust-analyzer 的查询子命令（`symbols` / `search` / `unresolved-references`）**每次都要加载整个 Cargo 工程** | 冷跑 ≈ 11.6 s ⇒ 超五秒硬顶 |
| 为什么读 LSIF 不读 SCIP | SCIP 是 protobuf（标准库解不了 ⇒ 破零第三方依赖）；LSIF 是**一行一个 JSON** | 全量 **238198 行** · 347 文档 · 9101 符号 · 解析 **379 ms** |
| `rg` 不够吗 | 不够在**语义**上：它分不清定义与引用、认不出两个同名符号 | `rg 校输入形状` = 6 行 · **31 ms** —— 快，但答不出「谁是定义」 |

老仓的同一课（只作口径来源，不改不引其代码）：老仓 `支持库/后端/代码解析支持库/代码地图/说明/设计说明.md` §1 记「外部 CLI 每查一次起一个子进程」正是它被换掉的原因，换成**底座直读预建 SQLite**（`<项目根>/.codegraph/codegraph.db`：nodes 10896 · edges 22788 · files 564）。V1 照此：**建一次 · 查只读**。

## 三 环境依赖的准入（照 11.1 四条）

- **缺能力先证不可替代**：语义查询没有第二条路 —— `rg` 是文本匹配；自己写 Rust 解析器 = 重造 rust-analyzer。
- **判定必须用数字**：冷构建 11.6 s（6.3 MB SCIP / 24.7 MB LSIF）· 解析 379 ms · 查 0.4 s 级。
- **装了要能退**：`rustup component remove rust-analyzer` ＋ 删缓存目录。**底座不调它、判据面不依赖它** ⇒ 退掉其余一切照跑。
- **环境依赖 ≠ 底座能力**：它是**开发工具**（给人读代码用）—— 不进 `契约声明/`、不出现在任何运行期路径、不写进任何判据。

装法（下载走 4780 代理）：`HTTPS_PROXY=http://127.0.0.1:4780 rustup component add rust-analyzer`。

## 四 与 MCP 那套的关系（明确不做）

MCP 的代码地图提供者**属老仓**，且实测已坏：`重建项目地图索引` 对 V1 根崩（退出码 1，`全量` 与 `同步` 两种重建方式都崩）· `查询项目地图状态` 对**老仓自己的根**也崩 ⇒ 坏的是提供者，不是 V1 特有的；其底层 `仓库地图.建符号图` 的**语言集只认 python / typescript / vue** ⇒ 永远索引不了 V1 的 Rust 核。**本仓不接它、不修它。**

## 五 判据面的边界

代码地图**不是判据**：判据必须随源码可复算，不许随环境飘（装了 rust-analyzer 才有读数 ⇒ 它就是环境依赖）。故 `构建装配/一键验证/` 里 **0 处**调它。

## 六 五秒硬顶的归属

`建` 要加载整个工程 ⇒ **属环境步**（`2026-09-27_构建段归环境步.md` §四）：用 `报告环境步` **照实报、不判顶**。`查` / `引用` / `状态` 只读预建文件 ⇒ **是判顶对象**：用 `自门禁` 判顶（实测 0.4 s 级）。
