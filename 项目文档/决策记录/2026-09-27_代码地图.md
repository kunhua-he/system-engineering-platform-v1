# 代码地图 —— 本仓的符号索引（独立一套）

日期：2026-09-27 ｜ 裁决人：华哥（原话：「能不能单独给这个项目，装一个代码地图？不是 mcp 的那套，而是独立装一套。方便快速索引代码」）

---

## 一 裁决

V1 的代码地图 = **预建符号索引 ＋ 只读查询**，产出者是 **SCIP 那套开源索引器**
（Sourcegraph 开源，业界标准 —— GitHub / Sourcegraph 的代码导航就是它）。
落地两件：

- `开发工具/代码地图.py` —— 入口（`建` / `查 <关键词>` / `引用 <限定名>` / `状态`）；
- `开发工具/代码地图/` —— `SCIP前端.py`（调索引器 + 读回 + 转统一形状）· `建索引.py`（编排，环境步）· `查询.py`（流式扫）· `落点.py`（放哪）。

索引落点 = **`<运行数据根>/缓存/代码地图/`**（判据 ⑳：运行数据不落源码树）：
`rs.scip` / `py.scip` / `js.scip`（三条腿的原始产出）＋ `定义.jsonl` / `出现.jsonl`（统一形状）。

**它买的是什么**：`rg` 管「哪几行有这个字」，代码地图管「**谁是定义、谁在引用它**」。

## 二 为什么是这个形状

| 问 | 答 | 读数 |
|---|---|---|
| 为什么不每次现查 | 三条索引器都要**加载整棵工程**（Rust 要 cargo check、Python 要建项目模型） | 冷跑 **12.3 s** ⇒ 超五秒硬顶 |
| 为什么不自己写解析器 | 自研只做得到**名字级**（同一模块内精确、跨模块靠猜），且三种语言各一套、口径不一 | 旧自研版：Rust 精确 · Python `ast` 同文件 · JS 词法 —— **三条腿三种精度** |
| 为什么 SCIP | 每个符号有一根**全局唯一符号串**（`scheme manager package version descriptor`）⇒ 定义/引用是**符号级**的，三种语言**同一套口径** | 定义 **10385** · 出现 **111017** · 定义表 4.2 MB · 出现表 20.8 MB |
| 为什么不读 LSIF | LSIF 与 SCIP 同源（rust-analyzer 都出），但 LSIF **只有 Rust 有**；SCIP 三条腿都有，且是 protobuf 标准格式 | `rust-analyzer lsif` 无 Python/JS 对应物 |
| `rg` 不够吗 | 不够在**语义**上：它分不清定义与引用、认不出两个同名符号 | `rg 校输入形状` = 6 行 · **31 ms** —— 快，但答不出「谁是定义」 |

老仓的同一课（只作口径来源，不改不引其代码）：老仓 `支持库/后端/代码解析支持库/代码地图/说明/设计说明.md` §1 记「外部 CLI 每查一次起一个子进程」正是它被换掉的原因，换成**底座直读预建 SQLite**（`<项目根>/.codegraph/codegraph.db`：nodes 10896 · edges 22788 · files 564）。V1 照此：**建一次 · 查只读**。

## 三 环境依赖的准入（照 11.1 四条）

四条工具（**都不是底座能力**）：

| 腿 | 工具 | 装法 |
|---|---|---|
| `.rs` | `rust-analyzer` | `rustup component add rust-analyzer` |
| `.py` | `scip-python` | `npm i -g @sourcegraph/scip-python` |
| `.js` | `scip-typescript` | `npm i -g @sourcegraph/scip-typescript` |
| 读回 | `scip` | 从 `github.com/scip-code/scip/releases` 下 `scip-darwin-arm64.tar.gz`，解出的 `scip` 放进 PATH（或 `~/.local/bin`） |

（下载走 4780 代理：`HTTPS_PROXY=http://127.0.0.1:4780`。）

- **缺能力先证不可替代**：语义查询没有第二条路 —— `rg` 是文本匹配；自己写三种语言的解析器 = 重造三个索引器（旧自研版就是这么做的，实测精度不如 SCIP）。
- **判定必须用数字**：冷构建 **12.3 s**（三条腿**并发**：rs 4.6 s · py 12.9 s · js 1.4 s）· 查 **109 ms** · 引用 **270 ms** · 状态 **76 ms**。
- **装了要能退**：卸工具 ＋ 删缓存目录。**底座不调它、判据面不依赖它** ⇒ 退掉其余一切照跑。
- **环境依赖 ≠ 底座能力**：它是**开发工具**（给人读代码用）—— 不进 `契约声明/`、不出现在任何运行期路径、不写进任何判据。

## 四 与 MCP 那套的关系（明确不做）

MCP 的代码地图提供者**属老仓**，且实测已坏：`重建项目地图索引` 对 V1 根崩（退出码 1，`全量` 与 `同步` 两种重建方式都崩）· `查询项目地图状态` 对**老仓自己的根**也崩 ⇒ 坏的是提供者，不是 V1 特有的；其底层 `仓库地图.建符号图` 的**语言集只认 python / typescript / vue** ⇒ 永远索引不了 V1 的 Rust 核。**本仓不接它、不修它。**

本仓自己的 MCP 适配层（`开发工具/MCP服务/`）**只转发**这套代码地图（`v1_符号` / `v1_替换`），零第二套实现。

## 五 判据面的边界

代码地图**不是判据**：判据必须随源码可复算，不许随环境飘（装了 SCIP 那套才有读数 ⇒ 它是环境依赖）。故 `构建装配/一键验证/` 里 **0 处**调它的**索引**。

**但「规则」共用一份**（2026-09-27 追加）：命名规范的口径（`天干字` · `词内天干` · `含天干作标识符` · `无义单字` · `是单西文字母` · `命名后缀` · `是命名件`）收口在 `开发工具/代码地图/查名.py`，判据 ㉒ 也 import 它（照判据 ⑲ 引 `开发工具/查文件行数/核心.py` 的先例：工具从「判据自己所在的仓」取）。**规则一份 · 面各取所需**：代码地图用**索引**（全语义，`代码地图.py 检名`），判据 ㉒ 用**自己的零依赖剥器**（它要能在合成仓上跑，索引是整仓产出的 ⇒ 夹具仓没有索引）。判据那条面的假阴性（`self.d` · f-string）已进台账 #225。

依据：`项目文档/决策记录/2026-09-27_第二条腿审计.md`（这次审计的方法与结论）。

## 六 五秒硬顶的归属

`建` 要加载整棵工程 ⇒ **属环境步**（`2026-09-27_构建段归环境步.md` §四）：用 `报告环境步` **照实报、不判顶**。
`查` / `引用` / `状态` 只读预建的 JSONL ⇒ **是判顶对象**：用 `自门禁` 判顶（实测 0.1–0.3 s 级）。

## 七 改判留痕：自研三前端 → SCIP（2026-09-27 同日）

华哥原话：「github 没有开源的代码地图？直接复用就行了啊，你还要自己搞啊？」·「我是说，你直接 github 找那个开源的代码地图，成熟的方式不好用吗？ 非要自己自研呀。 底座用的那个，他那个好像也是 github 下载下来的吧」

**改判前**（本会话前半段落地、同日作废）：自研三前端 —— `.py` 用标准库 `ast`、`.js` 复用判据面词法器、`.rs` 读 rust-analyzer 的 LSIF。
**作废理由**（三条，都是实测）：
1. **精度三条腿不一样** —— Rust 有作用域（moniker），Python 只有同文件名字级，JS 只有词法级。同一条 `引用` 命令，三种可信度 ⇒ 是陷阱。
2. **JS 那条腿会撞名** —— 自研版按「名字」聚合，`呈现.js::建` 这类同名符号分不开。
3. **华哥要的是成熟开源**，不是自研；本仓已有先例（`rust-analyzer` 当**环境依赖**，「环境依赖 ≠ 底座能力」）。
**改判后**：三条腿全走 SCIP，**同一套口径**（符号串唯一决定限定名）。
**退回一步的承重证明**：改判前 `查 sys` 会答「`sys` 定义在某个只是 import 了它的文件里」——那是**假定义**（SCIP 里该处 `symbol_roles` = 8 = 只读，**没有 Definition 位**）。改判后定义表只收带 Definition 位的符号，`sys` 只进出现表。同一处还修掉两件：JS 形参被折叠进方法名（`建` 撞 3 行）、JS 匿名局部变量（`local 1` 全仓每文件都从 1 起 ⇒ 跨文件撞名）。

**顺带一条纪律**：三条索引器的调用**不设超时**（仓里 `cargo` / `nm` / 闸 0 起子进程同样不设）—— 索引器一趟就是它自己的时长（最慢那条 12.9 s），这是**环境步**、由 `报告环境步` 照实报墙钟；给它配一个 >5 s 的容忍度，正是判据 ㊲ 禁的「把硬顶让给被调方」的假数字。
