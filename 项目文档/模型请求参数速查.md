# 模型请求参数速查

> 能力走正式口 `http://127.0.0.1:43110`，模型直连各自端口。本文件是调用方唯一的传参依据，与底座声明表不一致时以这里为准并立刻修声明。

## 一、两个硬规矩

**参数一个都不能少**，漏传报「缺参数「X」：本能力这一行没有声明默认值」。

例外只有 `2512` 的两个整数型超时能带真默认值 —— 枚举型塞不进底座 const 表。其余参数一律必传。

**复合参数必须显式写标签**，标量给裸值：

| 标签  | 含义          | 怎么传             | 例子                        |
|-------|---------------|--------------------|-----------------------------|
| 1 / 2 | 整数 / 双精度 | 裸值               | `41981`                     |
| 3     | 逻辑型        | 裸值               | `true`                      |
| 4     | 文本          | 裸值               | `"LLM文本模型"`             |
| 5     | 字节集        | 裸值               | —                           |
| 6     | 句柄          | 裸整数             | `3`                         |
| 7     | 任务句柄      | 显式带标签         | `{"类型标签":7,"值":N}`     |
| 100   | 列表          | 显式，元素各带标签 | `{"类型标签":100,"值":[…]}` |
| 101   | 对象          | 显式，字段各带标签 | `{"类型标签":101,"值":{…}}` |

复合参数不能靠裸值自动装箱。静态请求头传 `{}` 会报 `25 输入形状不符`，要写 `{"类型标签":101,"值":{}}`。

## 三、拉起模型服务 2512

```json
{"编号": 2512, "命名值": {
  "模型引用": "/Users/hekunhua/Documents/AI模型/文本模型/Qwen3-8B-Q4_K_M.gguf",
  "可执行文件": "/opt/homebrew/bin/llama-server",
  "启动参数": "-m {模型文件} --host 127.0.0.1 --port {端口} -c 4096 --no-webui",
  "监听端口": 0,
  "就绪路径": "",
  "模型类型": "LLM文本模型",
  "闲置超时秒": 900,
  "载入超时秒": 120
}}
```

回执：服务句柄 `900001`。**立刻返回，不等载入** —— 端口和状态都要用 `2514` 查。

- **模型引用**：模型文件**绝对路径**（推荐）或纯 model 名。传路径时校验文件存在，不存在当场报 `2513`；传纯名不校验，要等推理才炸
- **可执行文件**：推理引擎，如 `/opt/homebrew/bin/llama-server`
- **启动参数**：支持 `{端口}` 与 `{模型文件}` 两个占位符，路径只写一遍
- **监听端口**：传 `0` 自动分配（40000-49999 里第一个没在听、没被登记、没被预占的）；固定端口被占就报错，不偷换
- **就绪路径**：传空按类型取默认，`ASR语音识别模型` 取 `/`，其余 `/health`
- **模型类型**：五个词之一，见第七节
- **闲置超时秒**：默认 `900`，闲置多久自动退出内存，见第四节
- **载入超时秒**：默认 `120`，超了转 `载入失败` 并收掉进程，`0` = 不限

**拉起前算内存预算**：需求 = 文件字节 × 1.15 + 512MB，可用 = `vm_stat` 的 free + inactive × 页大小 × 0.8。不够报 `2506 资源受限`。路径或内存读不到时跳过放行。

**传路径而不是传名字**的理由：纯名字底座无从校验，模型在不在本机没人知道，要等推理才炸；传路径当场炸，错得早。模型类型**不从文件名推断** —— 猜测值顶替调用方表态等于留后门。

## 四、载入状态与闲置退出

`2514` 的 `状态` 只有四种：

| 状态       | 含义                       | 该做什么               |
|------------|----------------------------|------------------------|
| `载入中`   | 进程起来了，还没真就绪     | 轮询，别发请求         |
| `已载入`   | 真就绪过一次               | 可以发请求             |
| `载入失败` | 过了 `载入超时秒` 仍未就绪 | 巡检会收掉；重拉查日志 |
| `已退出`   | 进程没了                   | 要用手就重新拉起       |

**闲置退出是滑动的**：

```
载入完成 ──► 每次真正使用把计时清零 ──► 连续闲置满 闲置超时秒 ──► 自动退出内存 ──► 下次要用再载入
```

**只有调 `2516 申请推理许可` 才算真正使用**。查 `2514` 不刷新 —— 否则监控一直轮询，模型永远退不掉。所以用模型前必须走 `2516`；绕过许可直连模型端口发请求，底座不知道，模型可能正被用却被判闲置退出。

**`载入超时秒` 怎么填：实测完再按双倍留余量。**

本机七个模型用底座实际拉起、记到状态转 `已载入` 的耗时（llama-server 报 `model loaded` 0.557 秒，对得上）：

- `Qwen3VL-32B`（18.8G）→ **3.2 秒**
- `Qwen3-14B`（8.5G）→ **1.0 秒**
- `Qwen3-Embedding-8B`（7.7G）→ **1.0 秒**
- `Qwen3-8B`（4.8G）→ **1.0 秒**
- `Qwen3VL-8B`（4.8G）→ **1.0 秒**
- `Qwen3-Reranker-4B`（4.1G）→ **1.1 秒**
- `bge-reranker-v2-m3`（1.1G）→ **1.1 秒**

热载入都在 3 秒附近（llama-server 用 mmap，文件在 page cache 里）。默认给 **30 秒**，是最大实测值的九倍，留足冷启动和内存压力下的余量，又不至于载入卡死要等两分钟才发现。

**换更大的模型要先实测再填**：拉起来记到 `已载入` 的真实秒数，乘二向上取整，别照抄 30。

**不建议传 `闲置超时秒` = 0**（永不自动退）。`0` 等于回到「拉起就一直占内存」，正是这套机制要解决的问题。要常驻就**给长值**（如 `3600`）：有人用就续、真没人用仍会退，保留兜底；给 `0` 只能靠人记得手动释放，一定会忘。`0` 只留给确实不能退的场景。

`2514` 回执 16 个字段，全部只读：

- `状态` / `存活` / `端口就绪`：四态 / 进程在不在 / 就绪路径通没通
- `进程号` / `运行秒` / `监听端口`：PID / 活了多久 / 实际端口
- `模型短名` / `模型路径` / `模型类型`：翻出的 model 名 / 校验过的完整路径（传纯名时为空）/ 五个词之一
- `就绪路径`：这个服务用的判定路径
- `CPU毫秒`：累计 CPU 时间，连查两次增量为 0 = 进程在干烧
- `闲置秒` / `距自动退出秒`：距上次真正使用多久 / 还剩多少秒退（`闲置超时秒`=0 时是 **`null`**）
- `闲置超时秒` / `载入超时秒`：这个服务当初设的两个阈值

**推荐流程**：

```
2512 拉起        → 句柄，状态「载入中」
循环 2514        → 直到「已载入」，间隔 1~2 秒
2516 申请许可    → 拿到许可（同时刷新闲置计时）
直连端口发请求   → 用完 2517 归还
```

巡检每 5 秒一轮，退出最多晚 5 秒生效。

## 五、释放模型服务 2513

```json
{"编号": 2513, "命名值": {"服务句柄": {"类型标签": 6, "值": 900001}, "强制": false}}
```

**幂等**：句柄本来就不在也回真；并发释放同一个句柄全都回真，不会有人收到「服务无效」。

`强制` = **假**：常规释放，进程不退就保留条目待重试。= **真**：不管退没退一律摘除条目、解封句柄与端口，是卡死时的逃生口，代价是可能留孤儿进程。

## 六、多模型并存与推理许可

端口一模型一个，服务表允许多条同时存在。

- **端口怎么分**：传 0 自动分配，**分配与预占在同一把锁内**，8 线程同时拉起实测端口全不同
- **谁能同时推理**：**按服务分槽** —— 同模型内排队（共享 GPU 上下文与 KV 缓存，挤进去互相拖慢），不同模型并行（各独立进程，由驱动调度）
- **待命占不占许可**：不占

- **2516 申请推理许可**：`服务句柄` + `等待毫秒` + `租约毫秒`。等待上限 3 秒（传 5000 会先撞内核 5 秒预算判 `4 超时`），租约 5 秒
- **2517 归还推理许可**：`许可句柄`（2516 的回执）
- **2518 取推理排队快照**：无参数，看每个服务几个持有、几个排队

就绪判定口径：端口在听 + 就绪路径 200 + `/health` 非 503。只看端口或只看 `/v1/models` 都不够。

| 模型类型          | 用什么口                          | 协议               |
|-------------------|-----------------------------------|--------------------|
| `LLM文本模型`     | 2501 连接模型 + 2502 提交生成任务 | `chat_completions` |
| `VLM看图模型`     | 2501 连接模型（内容用图文数组）   | `chat_completions` |
| `EM向量模型`      | 2508 连接向量模型 + 2509 生成嵌入 | `embeddings`       |
| `Rerank重排模型`  | 2510 连接重排模型 + 2511 执行重排 | `rerank`           |
| `ASR语音识别模型` | 暂无连接口，只由 2512 拉起        | —                  |

必须从这五个里选一个。留空、漏传、写别名、写别的词一律拒 —— 不认 `LLM`、不认 `文本`、不认 `大模型`/`视觉`/`嵌入`。别名一开口下游就各写各的，最后没人确定该传哪个。

**三个连接口各只接本类型**，用错口当场拒：2501 只接文本/看图，2508 只接向量，2510 只接重排。用错口在建连阶段毫无感觉，要等真提交任务才炸成上游 400。

要加类型改底座 `模型类型表`，别在调用方发明新词。

## 八、常见报错

- 漏传参数 → `400 缺参数「X」：本能力这一行没有声明默认值`
- 静态请求头传 `{}` → `25 输入形状不符`
- 消息列表传普通数组 → `400 每一项必须是 {"类型标签":N,"值":V}`
- 元素字段用裸值 → 同上（元素本身也要 101 对象）
- `模型类型` 写别名或留空 → `参数不合法`
- 协议传错 → `协议不支持`

## 九、缓存：模型层有，底座层没有

同一段 652 token 前缀连发三次：第一次 0.67 秒、命中 0；第二三次 0.44 秒、命中 646（99%）。

- 模型层：llama-server 的 prompt cache **默认就开**，不用配
- 底座层：**不缓存**，每次真请求

**三铁律**：

1. 长期不变的内容（身份、产品资料、规则）放最前面，越长越划算
2. 历史只追加不改写 —— 中间插一句前缀就断，后面全部重算
3. 会变的东西（时间戳、请求 ID、本次参数）只放当前问题那一条里

反例：把「今天是 X 月 X 日」拼进系统提示词，每次前缀都不同，命中率归零。
