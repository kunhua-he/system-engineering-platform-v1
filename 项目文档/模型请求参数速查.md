# 模型调用

## 直接抄这三行

```python
import sys; sys.path.insert(0, "/Users/hekunhua/Documents/Agent/PHP/系统工程平台V1/模型调用")

实测 4.1 秒出结果：

```
我是阿里云开发的超大规模语言模型，能够高效处理多种任务…
```

**不用管模型有没有起、要多少内存、端口是多少、许可怎么拿** —— 全在 `模型.py` 里办完。

命令行也能直接跑：

```

## 就这三个函数

| 函数                                                               | 干什么                                                                    |
|--------------------------------------------------------------------|---------------------------------------------------------------------------|
| `对话(消息, 系统提示词="", 温度=0.7, 最大令牌数=2048, 超时秒=180)` | 文本对话。`消息` 可传字符串，也可传多轮 `[{"role":"user","content":"…"}]` |
| `看图(图片路径, 问题="描述这张图", 超时秒=180)`                    | 视觉模型看本地图片，传绝对路径                                            |
| `状态()`                                                           | 现在跑着哪些模型、还剩多久自动退                                          |

出错抛 `模型错误`，消息里是真正的错误名（不是"调用失败"四个字）：

```python
from 模型 import 对话, 模型错误
try:
    对话("你好")
except 模型错误 as 错:
    print("失败了：", 错)        # 例：资源受限（码 2506）
```

## 网页里只要一个请求

底座自己就托管静态页（`--静态根 前端呈现/网页应用`，和接口**同源**），所以网页里不用管 CORS、不用另开端口，一个 `fetch` 就到答案：

```javascript
const 回 = await fetch('/接口/调用', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    编号: 2519,
    命名值: {
      消息列表: { 类型标签: 100, 值: [{ 类型标签: 101, 值: {
        role: { 类型标签: 4, 值: 'user' },
        content: { 类型标签: 4, 值: '用一句话介绍你自己' } } }] },
      系统提示词: '', 温度: 0.7, 最大令牌数: 2048,
      模型类型: 'LLM文本模型', 模型引用: '', 等待毫秒: 90000
    }
  })
});
```

现成示范页 `前端呈现/网页应用/对话示例.html` → 打开 `http://127.0.0.1:43110/对话示例.html`。

`2519` 把原来二十次请求（拉起/等就绪/许可/连接/提交/取结果/清理）串成一个：模型没起会自动拉起，起了就复用，跑完直接把内容返回来。

**「一个请求」的前提是那个数改了**：`契约声明/常量表.json` 的 `单项超时毫秒` 从 1000 提到 120000。1000 是按纯计算能力定的，一次对话要真跑模型（载入 1–3 秒 + 生成几十秒），1 秒会把它每次都判成失控、并把已经算完的结果丢掉。平台注释早写明这种情形「要重定的是本表那一个数，不许退化成每个能力各设一套」。超时只记账报码、不强杀执行方。

## 它替你做了什么

```
你调 对话("你好")
   ├─ 有同模型的已载入服务 → 直接复用
   ├─ 没有 → 拉起（自动挑端口、先查内存够不够）
   ├─ 等真就绪（不是「能连上」，是接口真能应答）
   ├─ 申请推理许可（同模型排队，不同模型并行）
   ├─ 连接 → 提交 → 读结果
   └─ 归还许可
服务不释放：闲置 15 分钟自动退出内存，下次要用自动回来。
```

## 要不要自己拼 HTTP

**一般不用**。只有这几种情况才往下看：用非 Python 语言调、要用向量或重排模型（`模型.py` 只封了对话和看图）、要自己控制模型进程生死。

### 底座入口

`POST http://127.0.0.1:43110/接口/调用`，体是 `{"编号": 2512, "命名值": {…}}`。

### 十八个能力

| 号   | 能力         | 号   | 能力           |
|------|--------------|------|----------------|
| 2501 | 连接模型     | 2510 | 连接重排模型   |
| 2502 | 提交生成任务 | 2511 | 执行重排       |
| 2503 | 读取生成任务 | 2512 | 拉起模型服务   |
| 2504 | 断开连接     | 2513 | 释放模型服务   |
| 2507 | 资源快照     | 2514 | 取模型服务状态 |
| 2508 | 连接向量模型 | 2515 | 等待模型就绪   |
| 2509 | 生成嵌入     | 2516 | 申请推理许可   |
|      |              | 2517 | 归还推理许可   |
|      |              | 2518 | 取推理排队快照 |

### 传参两个规矩

**一、复合参数必须显式写标签**，标量给裸值：

| 标签  | 含义          | 怎么传             | 例子                        |
|-------|---------------|--------------------|-----------------------------|
| 1 / 2 | 整数 / 双精度 | 裸值               | `41981`                     |
| 3     | 逻辑型        | 裸值               | `true`                      |
| 4     | 文本          | 裸值               | `"LLM文本模型"`             |
| 5     | 字节集        | 裸值               | —                           |
| 6     | 句柄          | 裸整数             | `3`                         |
| 7     | 任务句柄      | 显式带标签         | `{"类型标签":7,"值":N}`     |
| 100   | 列表          | 显式，元素各带标签 | `{"类型标签":100,"值":[…]}` |
| 101   | 对象          | 显式，字段各带标签 | `{"类型标签":101,"值":{…}}` |

静态请求头传 `{}` 会报 `25 输入形状不符`，要写 `{"类型标签":101,"值":{}}`。

**二、绝大多数参数没有默认值**，漏传报 `缺参数「X」：本能力这一行没有声明默认值`。只有 `2512` 两个整数型超时带真默认值：`闲置超时秒` 900、`载入超时秒` 30。

### 2512 拉起模型服务（八参数）

```json
{"编号": 2512, "命名值": {
  "模型引用": "/Users/hekunhua/Documents/AI模型/文本模型/Qwen3-8B-Q4_K_M.gguf",
  "可执行文件": "/opt/homebrew/bin/llama-server",
  "启动参数": "-m {模型文件} --host 127.0.0.1 --port {端口} -c 4096 --no-webui",
  "监听端口": 0,
  "就绪路径": "",
  "模型类型": "LLM文本模型",
  "闲置超时秒": 900,
  "载入超时秒": 30
}}
```

- **模型引用**：模型文件绝对路径（推荐，校验存在，不存在当场报 `2513`）或纯 model 名（不校验，等推理才炸）
- **可执行文件**：推理引擎
- **启动参数**：支持 `{端口}` 与 `{模型文件}` 两个占位符，路径只写一遍
- **监听端口**：传 `0` 自动分配（40000-49999）；固定端口被占就报错，不偷换
- **就绪路径**：传空按类型取默认，`ASR语音识别模型` 取 `/`，其余 `/health`
- **模型类型**：五个词之一，见后
- **闲置超时秒**：默认 900。闲置多久自动退出内存。**不建议传 0**（永不退）—— 那等于回到一直占内存；要常驻给长值如 3600，有人用就续、真没人用仍会退
- **载入超时秒**：默认 30。实测本机七个模型热载入都在 3.2 秒内（最大 32B/18.8G），30 秒是九倍余量；换更大模型先实测再按双倍填

**拉起立刻返回句柄，不等载入。** 端口和状态用 `2514` 查。拉起前会算内存预算（需求 = 文件字节 × 1.15 + 512MB，可用 = 空闲+非活跃页 × 0.8），不够报 `2506 资源受限`。

### 2514 状态四种

| 状态       | 含义                       | 该做什么               |
|------------|----------------------------|------------------------|
| `载入中`   | 进程起来了，还不能应答     | 轮询，别发请求         |
| `已载入`   | 真能应答了                 | 发请求                 |
| `载入失败` | 过了 `载入超时秒` 仍未就绪 | 巡检会收掉，重拉查日志 |
| `已退出`   | 进程没了                   | 重新拉起               |

**判定必须走真就绪探测**（就绪路径 200 + `/health` 非 503），不能只看 TCP 能不能连 —— llama-server 载入期间就已经在 listen 了，但接口回 503 `Loading model`。

回执十六个只读字段：`状态`、`存活`、`端口就绪`、`进程号`、`运行秒`、`监听端口`、`模型短名`、`模型路径`、`模型类型`、`就绪路径`、`CPU毫秒`、`闲置秒`、`距自动退出秒`、`闲置超时秒`、`载入超时秒`。注意 `闲置超时秒` 为 0 时 **`距自动退出秒` 这个字段不出现**（不是 null）。

**只有调 `2516 申请推理许可` 才算真正使用**，查 `2514` 不刷新计时 —— 否则监控一轮询，模型永远退不掉。

### 2513 释放（幂等）

```json
{"编号": 2513, "命名值": {"服务句柄": {"类型标签": 6, "值": 900001}, "强制": false}}
```

句柄本来就不在也回真；并发释放同一句柄全都回真。`强制`=假：进程不退就保留条目待重试；=真：不论退没退一律摘除条目、解封句柄与端口，是卡死时的逃生口，代价是可能留孤儿进程。

### 推理许可（2516-2518）

- **2516 申请**：`服务句柄` + `等待毫秒` + `租约毫秒`，租约 5 秒
- **2517 归还**：`许可句柄`（2516 回执），用完必须还
- **2518 快照**：无参数，看每个服务几个持有、几个排队

**按服务分槽**：同模型内排队（共享 GPU 上下文与 KV 缓存），不同模型并行（各独立进程）。

### 五个模型类型

| 模型类型          | 用什么口                   | 协议               |
|-------------------|----------------------------|--------------------|
| `LLM文本模型`     | 2501 + 2502                | `chat_completions` |
| `VLM看图模型`     | 2501（内容用图文数组）     | `chat_completions` |
| `EM向量模型`      | 2508 + 2509                | `embeddings`       |
| `Rerank重排模型`  | 2510 + 2511                | `rerank`           |
| `ASR语音识别模型` | 暂无连接口，只由 2512 拉起 | —                  |

必须从这五个里选一个，留空、写别名（`LLM`/`文本`/`大模型`）一律拒。三个连接口各只接本类型，用错口当场拒 —— 不然要等真提交才炸成上游 400。

### 常见报错

- 漏传参数 → `400 缺参数「X」：本能力这一行没有声明默认值`
- 静态请求头传 `{}` → `25 输入形状不符`
- 消息列表传普通数组 → `400 每一项必须是 {"类型标签":N,"值":V}`
- 模型类型写别名或留空 → `参数不合法`
- 协议传错 → `协议不支持`
- 查不存在或已释放的句柄（2514）→ `2508 服务无效`；但释放不存在的句柄（2513）**回真**
- 内存不够 → `2506 资源受限`

### 一个约束要知道

全平台单项超时是 `契约声明/常量表.json` 的 **1000 毫秒**（调度只记账报码，不强杀执行方）。所以**任何同步等结果的能力都不能等超过约 1 秒** —— `2515` 单次封顶就设在 800 毫秒，要长等就循环调。生成任务走 2502/2503 异步，不受这个限制。

## 缓存：模型层有，底座层没有

同一段 652 token 前缀连发三次：第一次 0.67 秒、命中 0；第二三次 0.44 秒、命中 646（99%）。llama-server 的 prompt cache 默认就开，底座层不缓存。

**三条**：长期不变的内容（身份、产品资料、规则）放最前面；历史只追加不改写，中间插一句前缀就断；会变的东西（时间戳、请求 ID）只放当前问题那一条里。反例：把「今天是 X 月 X 日」拼进系统提示词，每次前缀都不同，命中率归零。
