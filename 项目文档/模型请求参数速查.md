# 模型请求参数速查

> 2026-11-04 实测：能力走正式口 `http://127.0.0.1:43110`，模型直连各自端口。每条都是真跑出来的读数。

## 一句话

**标量给裸值；列表 / 对象必须显式写 `{"类型标签":N,"值":…}`；参数一个都不能少。**

## 三步调用（真实跑通）

**① 连接模型 2501** —— 5 个参数全给

```json
{"编号": 2501, "命名值": {
  "模型": "/Users/hekunhua/Documents/AI模型/文本模型/Qwen3-8B-Q4_K_M.gguf",
  "服务器地址": "http://127.0.0.1:40002",
  "接口密钥": "",
  "协议": "chat_completions",
  "静态请求头": {"类型标签": 101, "值": {}}
}}
```
回执：连接句柄 `3`

> `模型` 传**绝对路径**：底座会验文件在不在，再把文件名翻译成请求体里的 model 名（这里就是 `Qwen3-8B-Q4_K_M`）。
> `服务器地址` 里的端口来自 `2514 取模型服务状态` 的 `监听端口` —— 如果模型是 2512 拉起的，用那个端口；连外部模型就填对方的地址。

## 拉起模型服务（2512）—— 六个参数

```json
{"编号": 2512, "命名值": {
  "模型标识": "/Users/hekunhua/Documents/AI模型/文本模型/Qwen3-8B-Q4_K_M.gguf",
  "可执行文件": "/opt/homebrew/bin/llama-server",
  "启动参数": "-m {模型文件} --host 127.0.0.1 --port {端口} -c 4096 --no-webui",
  "监听端口": 0,
  "就绪路径": "",
  "模型类型": ""
}}
```
回执：服务句柄 `900001`（端口用 `2514` 查：40002）

> `模型标识` 传**绝对路径**，不是名字。`启动参数` 里用 `{模型文件}` —— 路径只写一遍，两边不会打架。

| 参数     | 说明                                                                                        |
|----------|---------------------------------------------------------------------------------------------|
| 监听端口 | **传 0 = 底座自动分配**（40000-49999 里第一个既没在听、也没被服务表占用的）；固定端口就照传 |
| 启动参数 | 支持 `{端口}`（实际端口）和 `{模型文件}`（`模型标识` 那条路径）两个占位符，路径只写一遍 |
| 就绪路径 | 传空 = 按模型类型取默认                                                                     |
| 模型类型 | 不传 = 文本（有默认值，老调用不必改）                                                       |

**模型类型是受控枚举**，乱写直接拒（`2501 参数不合法`），别名自动归一：`LLM→文本`、`VLM/视觉→看图`、`EM/embedding→向量`、`ASR/识别→语音`。

| 模型类型 | 默认就绪路径 | 后续该用哪对能力                  |
|----------|--------------|-----------------------------------|
| 文本     | /health      | 2501 连接模型 + 2502 提交生成任务 |
| 看图     | /health      | 2501 + 2502（内容用图文数组）     |
| 向量     | /health      | 2508 连接向量模型 + 2509 生成嵌入 |
| 重排     | /health      | 2510 连接重排模型 + 2511 执行重排 |
| 语音     | /            | （暂无对应连接能力，只拉起）      |

> 注意：`2501 连接模型` 里的 `模型` 参数是**请求体里的 model 名**（llama-server 基本不看它），
> **不是 GGUF 文件路径**。文件路径只出现在 `2512` 的 `启动参数` 里（`-m /path/xxx.gguf`）。

## 模型引用转化器（传路径，别传名字）

`2501` 的 `模型` 和 `2512` 的 `模型标识` **都收模型文件绝对路径**，底座负责翻译：

| 你传什么                             | 底座怎么翻译                                                         | 效果                                     |
|--------------------------------------|----------------------------------------------------------------------|------------------------------------------|
| `/…/Qwen3-8B-Q4_K_M.gguf`            | 先校验文件在不在 → 取名去扩展名 `Qwen3-8B-Q4_K_M` → 从文件名推断类型 | 不存在当场报 `2513`，不等推理才炸        |
| `/…/Qwen3VL-8B-Instruct-Q4_K_M.gguf` | 识别出 `VL` → 类型自动判「看图」→ 就绪路径自动 `/health`             | 不用再手填模型类型                       |
| `qwen3`（纯名字）                    | 原样当 model 名                                                      | 兼容老写法；但机器上没有这个模型不会报错 |

**为什么坚持传路径**：传纯名字时底座无从校验——模型在不在本机没人知道，要等推理那一步才炸；
传路径则当场炸，错得早、错得准。这是「早失败」不是「多此一举」。

翻译结果能在 `2514 取模型服务状态` 的 `模型标识` 字段里看到，确认它被认成了什么名字。

## 类型标签怎么传

| 标签  | 含义          | 怎么传              | 例子                        |
|-------|---------------|---------------------|-----------------------------|
| 0     | 空            | 不传                | —                           |
| 1 / 2 | 整数 / 双精度 | 裸值                | 41981                       |
| 3     | 逻辑型        | 裸值                | true                        |
| 4     | 文本          | 裸值                | "qwen3"                     |
| 5     | 字节集        | 裸值                | —                           |
| 6     | 句柄          | 裸整数              | 3                           |
| 7     | 任务句柄      | 显式带标签          | {"类型标签":7,"值":N}       |
| 100   | 列表          | 显式 + 元素各带标签 | {"类型标签":100,"值":[ … ]} |
| 101   | 对象          | 显式 + 字段各带标签 | {"类型标签":101,"值":{ … }} |

## 四个坑（都是真撞出来的）

| 错误写法           | 真实报错                                             |
|--------------------|------------------------------------------------------|
| 少传「静态请求头」 | 400 缺参数「静态请求头」：本能力这一行没有声明默认值 |
| 静态请求头传 {}    | 25 输入形状不符                                      |
| 消息列表传普通数组 | 400 每一项必须是 {"类型标签":N,"值":V}               |
| 元素字段用裸值     | 同上（元素本身也要 101 对象）                        |

**结论：复合参数不能靠"裸值自动装箱"，必须显式写出来。**

## 缓存：模型层有，底座层没有

同一段 652 token 前缀连发三次：

| 第几次 | 耗时    | prompt token | 命中缓存   |
|--------|---------|--------------|------------|
| 1      | 0.67 秒 | 652          | 0          |
| 2      | 0.44 秒 | 652          | 646（99%） |
| 3      | 0.44 秒 | 652          | 646        |

- 模型层：llama-server 的 prompt cache **默认就开**，不用配
- 底座层：**不缓存**，每次真请求（避免"看着快、其实旧数据"）

**三铁律**：

1. 长期不变的内容（身份、产品资料、规则）放最前面，越长越划算
2. 历史只追加、不改写 —— 中间插一句前缀就断，后面全部重算
3. 会变的东西（时间戳、请求 ID、本次参数）只放当前问题那一条里

反例：把「今天是 X 月 X 日」拼进系统提示词 ⇒ 每次前缀都不同 ⇒ 命中率归零。

## 模型服务的三个必查口径

| 项       | 正确口径                                   | 错误口径                             |
|----------|--------------------------------------------|--------------------------------------|
| 就绪判定 | 端口在听 + 就绪路径 200 + `/health` 非 503 | 只看端口 / 只看 `/v1/models`         |
| 等待上限 | 单次 ≤ 3 秒，慢就循环调                    | 传 5000（撞内核预算，报成 `4 超时`） |
| 空闲判定 | 连查两次 CPU毫秒，增量为 0                 | 看 GPU 利用率                        |
