# 模型请求参数速查

> 2026-11-04 实测于正式口 `http://127.0.0.1:43110`，每条都是真跑出来的读数。

## 一句话

**标量给裸值；列表 / 对象必须显式写 `{"类型标签":N,"值":…}`；参数一个都不能少。**

## 三步调用（真实跑通）

**① 连接模型 2501** —— 5 个参数全给

```json
{"编号": 2501, "命名值": {
  "模型": "qwen3",
  "服务器地址": "http://127.0.0.1:41981",
  "接口密钥": "",
  "协议": "chat_completions",
  "静态请求头": {"类型标签": 101, "值": {}}
}}
```
回执：连接句柄 `3`

**② 提交生成任务 2502** —— 8 个参数全给，列表里每个元素也要带标签

```json
{"编号": 2502, "命名值": {
  "句柄": {"类型标签": 6, "值": 3},
  "消息列表": {"类型标签": 100, "值": [
      {"类型标签": 101, "值": {
          "role":    {"类型标签": 4, "值": "user"},
          "content": {"类型标签": 4, "值": "用一句话说明你是谁"}
      }}
  ]},
  "系统提示词": "你是一个简洁的中文助手。",
  "温度": 0.2,
  "最大令牌数": 300,
  "工具":      {"类型标签": 100, "值": []},
  "响应格式":  {"类型标签": 101, "值": {}},
  "附加请求头": {"类型标签": 101, "值": {}}
```

回执：任务句柄 `12460130520380741933`

**③ 读取生成任务 2503**

```json
{"编号": 2503, "命名值": {"任务句柄": {"类型标签": 7, "值": 12460130520380741933}}}
```

真实返回（也是带标签的结构）：

```

思考     → "好的，用户让我用一句话说明我是谁…"
已完成   → 1

```

## 类型标签怎么传

| 标签  | 含义          | 怎么传              | 例子                       |
|-------|---------------|---------------------|----------------------------|
| 0     | 空            | 不传                | —                          |
| 1 / 2 | 整数 / 双精度 | 裸值                | 41981                      |
| 3     | 逻辑型        | 裸值                | true                       |
| 4     | 文本          | 裸值                | "qwen3"                    |
| 5     | 字节集        | 裸值                | —                          |
| 6     | 句柄          | 裸整数              | 3                          |
| 7     | 任务句柄      | 显式带标签          | {"类型标签":7,"值":N}      |
| 100   | 列表          | 显式 + 元素各带标签 | {"类型标签":100,"值":[…] } |
| 101   | 对象          | 显式 + 字段各带标签 | {"类型标签":101,"值":{…} } |

## 四个坑（都是真撞出来的）

| 错误写法           | 真实报错                                             |
|--------------------|------------------------------------------------------|
| 少传「静态请求头」 | 400 缺参数「静态请求头」：本能力这一行没有声明默认值 |
| 静态请求头传 {}    | 25 输入形状不符                                      |
| 消息列表传普通数组 | 400 每一项必须是 {"类型标签":N,"值":V}               |
| 元素字段用裸值     | 同上（元素本身也要 101 对象）                        |

**结论：复合参数不能靠"裸值自动装箱"，必须显式写出来。**

## 缓存：模型层有，底座层没有

同一段 652 token 前缀连发三次：

| 第几次 | 耗时    | prompt token | 命中缓存   |
|--------|---------|--------------|------------|
| 1      | 0.67 秒 | 652          | 0          |
| 2      | 0.44 秒 | 652          | 646（99%） |
| 3      | 0.44 秒 | 652          | 646        |

- 模型层：llama-server 的 prompt cache **默认就开**，不用配
- 底座层：**不缓存**，每次真请求（避免"看着快、其实旧数据"）

**三铁律**：

1. 长期不变的内容（身份、产品资料、规则）放最前面，越长越划算
2. 历史只追加、不改写 —— 中间插一句前缀就断，后面全部重算
3. 会变的东西（时间戳、请求 ID、本次参数）只放当前问题那一条里

反例：把「今天是 X 月 X 日」拼进系统提示词 ⇒ 每次前缀都不同 ⇒ 命中率归零。

## 模型服务的三个必查口径

| 项       | 正确口径                                   | 错误口径                             |
|----------|--------------------------------------------|--------------------------------------|
| 就绪判定 | 端口在听 + 就绪路径 200 + `/health` 非 503 | 只看端口 / 只看 `/v1/models`         |
| 等待上限 | 单次 ≤ 3 秒，慢就循环调                    | 传 5000（撞内核预算，报成 `4 超时`） |
| 空闲判定 | 连查两次 CPU毫秒，增量为 0                 | 看 GPU 利用率                        |
