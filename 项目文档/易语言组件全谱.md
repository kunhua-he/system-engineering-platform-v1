# 易语言组件全谱（2026-11-02）

> 回答一个问题：易语言的组件到底有多少、都是什么，我们照着它做该覆盖哪些。
> 结论先说：**核心库已全，扩展库还没全**。下文把「已确证」「已读到但缺名」「还没读到」三段分开写，不混。

## 一、结论

- **核心支持库 krnln：完整**。类型表 51 槽全部有名字（2026-10-06 用 Wine 实跑读出，
  证据在 `节点/支持库/03_命令表与类型表.md` 第 2.15 节）。
- **扩展库：只到「数量」和「首槽名」**。静态解析 77 个库共 **563 个类型槽**，
  但易语言只在加载时用代码填名字，磁盘文件里**每个库只填了首个槽的名字**。
- **20 个库静态解不开**（GetNewInf 返回值形式不固定，工具 fail-closed 直接拒）。
- 要把扩展库补全，必须在 Windows/Wine 里逐个库 `LoadLibrary + GetNewInf` 读运行期类型表。
  本机当前没装 Wine，这一步没做。

## 二、证据与方法

- 数据源：本机 易语言 5.95 完整安装 `缓存/原包_e/lib/` 下 97 个库文件。
- 工具：`工具/逆向底座.py`（pefile + capstone），按官方 SDK `lib2.h` 的 LIB_INFO 布局解析。
- 判「是不是界面组件」用官方标志位：`LDT_WIN_UNIT = 1 << 6`（SDK 原文：窗口组件标志）。
  实测 `树型框` 状态位 64、`超级按钮` 64，与标志位吻合。
- 静态解析拿到 77 库、563 个类型槽；能取到名字的只有各库首槽（见第一节）。
- 补充证据：`参考资料/help文本/txt_help/` 下 72 个库的帮助文本，
  方法条目里的「所属对象：X」说明 X 是可操作对象（含组件，也含数据库对象这类非界面对象）。

三路证据分别记作：【位】=状态位判定为窗口组件；【文】=帮助文本里以它为所属对象；【槽】=krnln 运行期 51 槽。

## 六、静态解不开的 20 个库

ESpeechEngine、ExuiKrnln、HP-Socket、JY、Javalib、WNet、detour、e2ee、eCompress、eTools、
edroptarget、exkz、exui、exuiextensionone、iext6、jedi、spec、vclbase、wke、易绘美化。

失败原因是 `GetNewInf` 的返回值形式不固定（有的是 `mov eax`、有的是 `push` 后再取），
工具按「判不出就不返回」的纪律直接拒。这些库里 **exui / exuiextensionone / jedi / vclbase / iext6 / wke**
是界面库，补全时必须优先解决。

## 七、补全方案（要真·全量就走这条）

1. 装 Wine（或用已存在的 Windows 虚拟机）。
2. 写一个探针 DLL/EXE：对每个库 `LoadLibrary` → `GetNewInf()` → 读 `m_pDataType` 全槽，
   逐槽取 `m_szName` / `m_dwState`（判 `LDT_WIN_UNIT`）/ `m_nCmdCount`。
3. 输出一张全库全槽清单，替换本文件第三节的人工归类。
4. 探针要能跑在 20 个「解不开」的库上——它们的返回值形式不固定，只有运行期调用才稳。

在补全之前，第三节那 54 个已确证组件足够作为设计基线：它已经覆盖了
文件夹树（树型框 / 目录框）、浏览器（超文本浏览框 / 互联网浏览器）、
大表格（超级列表框 / 高级表格）、选项卡（选择夹 / 高级选择夹）这些我们最缺的形态。
