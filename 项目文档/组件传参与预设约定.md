# 组件传参与预设约定（V1 出能力，V4 只传差异）

这份文件是**唯一口径**：V1 给什么、V4 传什么、传几个字段、哪些字段不用传。
凡是与本文冲突的写法，一律以本文为准。

---

## 一、核心原则：能内置的不传

三层分工不变：

- **底座（V1）**：算。排版、排序、翻页、展开收起、选中、尺寸换算、单位翻译、句柄登记，全在这里。
- **业务（V4）**：说。只说「是什么、放在哪、什么内容」，不写算法、不拼样式、不连数据库。
- **浏览器**：搬。一份公共引导脚本，把点击转成一次能力调用，回来把片段贴上去。

判断一句话：**算在底座，说什么在 V4，浏览器只搬运。**

在这个基础上再压一层：**V4 只传差异**。同一串字段反复出现的，内置成预设；
字段不写就继承上一次或继承缺省，不需要传空值。

## 二、关于「配置文件」这个想法：分两半看

华哥提的 `Cargo.toml` / `*.ini` 那一类，我给的判断是**分成两件事**：

### 可以做：配置文件当「内置值的来源」

底座自身有几张表需要固定——组件预设、视觉基准缺省、阈值上限。
这些适合写成配置文件，编译期随源码进制品，调用方改不到也传不进。

判断依据：**同一份制品在任何机器上必须渲染出同样结果**。所以配置是「内置」，
不是「运行时外部文件」——外部文件会让两台机器的制品表现不一致，制品就不再可复现。

### 不能做：配置文件当「能力的传参通道」

不让调用方「给一个配置文件路径，内容随你写」。理由三条：

- 契约会失效：参数藏在文件里，契约校验看不见，出问题时无法判断是谁传错。
- **会多出第二套解析器**：配置文件解析是一套，能力入参解析是一套，两套并存就回到「同类两套」。
- 审计不了：改一个字就能改行为，却没有契约变更记录。

所以结论：**配置 = 内置缺省值的仓库；传参 = 能力的显式入参。两者不混。**

## 三、预设：把反复写的那串字段内置掉

### 用法

```json
{"类型": "按钮", "预设": "主按钮", "文字": "登录"}
```

就这三个字段，底座出：

```html
<button class="hs-button hs-button-primary" style="height:36px;padding:0 18px;font-weight:600">登录</button>
```

对比不用预设的写法，同一个按钮要写：

```json
{"类型":"按钮","样式":"样式1","高":36,"内边距":"0 18px","字重":600,"文字":"登录"}
```

### 样式只给槽位，语义交给预设

按钮的 `样式` 值域是 **`基础` / `样式1` / `样式2` / `样式3` / `样式4`**，不写等于 `基础`。

不写成「主要 / 成功 / 警告 / 危险」的原因：那几个词是业务语义，写死在底座里，
以后想加一种语义（比如「次要」「信息」）就得改底座、改编译、改回归——
而语义本来该由业务方和预设决定，底座只提供槽位。

对应关系（`预设表.json` 里定，改语义不改代码）：

- 主按钮 → `样式1`
- 次按钮 → `基础`
- 危险按钮 → `样式4`
- 文字按钮 → `基础` + 透明背景

写旧值（`主要` 等）会直接报 `4922 内容不合法`，不做兼容别名——保留两套值域等于又开一条第二实现。

字段数从 6 个压到 3 个，其中 2 个（`类型`、`文字`）是真正要变的东西。

### 合并顺序

1. 预设表里的字段先铺底；
2. 节点自身写的字段压在上面（同名字段以节点为准）；
3. `预设` 本身不参与渲染，只决定取哪一套底。

### 内置了哪些（`预设表.json`，随源码进制品）

- `按钮`：主按钮（样式1）/ 次按钮（基础）/ 危险按钮（样式4）/ 文字按钮（基础+透明底）
- `输入`：普通输入 / 搜索框
- `窗口`：应用窗口（可移动、可最小化、可最大化、可关闭、720×480、左上 40）
- `表格`：数据表（可排序、每页 20 行、表头固定）
- `树型框`：目录树（缩进 16、条目行高 28、显示连线）
- `条目列表`：选项列表（条目行高 32）

预设名写错**直接报 `4921 参数不合法`**，不静默降级成空预设——写错了要当场知道，
不能让他偷偷用一套默认值把界面画出来。

### 加预设的规矩

- 只加「同一串字段在三个以上地方重复出现」的；只出现一两次的不加，加了反而多一层要找。
- 预设里只放**外观与行为缺省**，不放内容（文字、数据、条目）——内容是业务说的，不是预设说的。
- 预设名用中文、说人话（`主按钮` 不是 `primary`）。

## 四、V4 到底传什么（四条能力的入参）

### 4928 渲染组件树 ── V4 出声明

```json
{
  "页面标识": "文件管理",
  "根": {"类型": "列", "子": [ {"类型":"按钮","预设":"主按钮","文字":"刷新"} ]}
}
```

- `页面标识`：给一次即可，用来做句柄归属（同一页的句柄一批释放）。不写就由底座生成一个临时归属。
- `根`：那棵树。每个节点最少只要 `类型`；有预设就写 `预设`；要变的东西才写。

回：HTML 片段（每个节点首标签带 `data-hs-h` 句柄）。

### 4929 操作组件 ── V4 说「对哪个句柄做什么」

```json
{"组件句柄": 100003, "操作名": "排序", "参数原文": "{\"键\":\"名称\"}"}
```

- `组件句柄`：4928 回执里那个 `data-hs-h` 数字，或 4929 `嵌套`/`追加` 回的句柄组里的数字。
- `操作名`：`排序` / `翻页` / `移动` / `设置` / `嵌套` / `展开` / `收起` / `选中` / `上移` / `下移` / `追加` / `删除`。
- `参数原文`：一段 JSON **字符串**（不是对象），里面只放这条操作要变的值。

回：`{"片段": "<html>", "句柄组": [数字…]}`。片段直接贴回原位，句柄组只在新生成组件时非空。

### 4930 读组件状态 / 4931 释放句柄

- `4930`：给句柄，回该组件当前的声明与状态（V4 要存布局、要判断状态时用）。
- `4931`：给句柄，幂等。释放后再操作同一个句柄报 `4924 组件句柄无效`。
  一次性弹层、临时弹窗用完就释放，别攒着。

## 五、参数越写越少的三个通行规则

这三条对所有能力通用，V4 不用记字段名也能少写一半：

1. **不写 = 继承**。容器里已经有宽高，子组件不写宽就不重设；不写位置就按排版走。
2. **数值给数字 = 绝对设置；给 `"+20"` / `"-20"` = 在当前值上增减**。
   `容器.移动 {"上":"+100"}` 是「往下挪 100」，不是「到 100」。
3. **文本给空串 = 清空；不写 = 不动**。逻辑值只认真 / 假，`"是"` 之类会被拒。

- **句柄四能力通了**：渲染即签句柄、十二个操作按类型分派、读状态、释放幂等。
- **预设与命名收敛完成**：反复写的字段内置成预设；状态类与窗口属性全部中文，无英文残留。

所以接下来的顺序就是华哥说的那个顺序：

1. **这一份传参约定先冻住**（本文）。
2. **V1 侧按约定补齐**：只补真缺口，不再加组件类型。
3. **V4 开始接入**：页面声明写 JSON，交互只调 4928 / 4929，前端不写算法。

V4 接入时只有一个心智负担：**手里有句柄就够**。要改什么，拿句柄说一句；
不再「整页重渲染」，也不在页面上算。
