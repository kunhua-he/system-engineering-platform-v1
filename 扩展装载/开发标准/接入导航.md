# 接入导航（一页）

> 档：落点与规范（正文跟着仓走，不入库 `条款`）。
> 这份是**给扩展作者 / 接入方的一页指路**：从哪里开始 · 三步接入 · 每步的权威件在哪。
> 机器可读的必备件清单 = `扩展装载/开发标准/必备件.json`；本件只管「怎么走」，不重复它的字段表。

## 一 从哪里开始

三句话定位：

1. 你要做的是**三类扩展之一**：支持库（原子能力 · 1000–6999）· 组合模块（封装 / 组装 · 7000–7999）· 技能（用法包 · 8000–8999）。三类形态不同 —— 支持库有本机码段，模块是程序文本编出的 WebAssembly，技能没有码段（本体是 md）。
2. 你**不动底座**：声明放**你的扩展目录**里（`必备件.json` §声明归自身），底座载入时读它 —— 加一个扩展不需要重发底座。
3. 你交付的是**制品**（`.支持库制品` / `.模块制品` / `.技能制品`），不是源码目录。

## 二 三步接入

### 第一步 落声明与实现（照模板抄形状）

- 模板：`扩展装载/开发标准/模板/支持库/` · `模板/组合模块/` · `模板/技能/`（三套骨架，内容全是占位）
- 必备件逐件对齐：`扩展装载/开发标准/必备件.json` §必备件（包声明 / 能力声明 / 错误码表 / 类型声明 / 说明 / 指纹）
- 能力声明形状 = `契约声明/格式说明.md` 第三节；包声明形状 = 同件 §二·五
- 两条纪律：编号落自身层号段且**永不回收**；参数表行序公布后**冻结**

### 第二步 本地自检（秒级）

```bash
python3 测试验证/契约一致性/扫实现.py
```

判据：通过 12 · 失败 0 · 未判 0（默认范围）。这是与底座全量验证**同一个验证器**的不同范围，不是第二套工具。

### 第三步 出制品 · 装进扩展根 · 底座零改动载入

- 出制品：支持库由**装配侧现场编**（`构建装配/上线切换/构建制品.py::扩展产物`，`cargo rustc -- --crate-type cdylib`）；模块 / 技能不编本机码
- 装进扩展根：位置 = `扩展装载/扩展根声明.json` 指定的目录
- 底座载入：`POST /接口/生命周期 动作=装载`；装载回执里 `剔除[].原因` 是拒因的**唯一出口**（缺件 / 版本不满足 / 声明不自洽）
- 载入后能不能调：`GET /接口/生命周期` → `数据.逐份就绪`（号段内有号可寻址）· `数据.接入回执`（十二类逐类交代）；真调一次看 `GET /接口/留痕`

## 三 最小范例在哪

- 支持库：`扩展根目录/原子支持库/编译器支持库` · `扩展根目录/原子支持库/数值计算支持库`
- 组合模块：`扩展根目录/组合模块库/求和模块`
- 技能：`扩展根目录/技能封装库/取文技能`
- 出制品的最小范例：`契约声明/examples/出技能制品.rs`

## 四 走不通时看哪

| 症状 | 看哪 |
|---|---|
| 载入失败 | `POST /接口/生命周期 动作=装载` → `数据.剔除[].原因` |
| 调不到（未命中返回空） | 该编号的能力声明是否在扩展目录里（没声明 ⇒ 底座侧不存在，不是报错） |
| 错误码抛不出 | `错误码表/<码>.json` 是否登记（未登记不许抛，载入即拒） |
| 声明形状不符 | `契约声明/格式说明.md` |
| 自检红 | `python3 测试验证/契约一致性/扫实现.py` 的逐条明细 |
