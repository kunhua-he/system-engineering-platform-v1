# 支持库与组合模块：开发与调用标准

> 档：落点与规范，正文跟仓走，不入库 `条款`。本件是操作导航；字段定义查 `扩展装载/开发标准/必备件.json` 与 `契约声明/格式说明.md`，不另起副本。

## 一 唯一流程

```text
查已有能力 → 定契约与编号 → 开工认领 → 实现
  → 生成制品 → 自检 → 部署装载 → 真实HTTP正反验证
  → 正常释放 → 合主干 → 合后复验 → 关闭反馈、销账、清树
```

- 支持库：原子能力，目录 `扩展根目录/原子支持库/`，能力号1000–6999。
- 组合模块：复用和组装，目录 `扩展根目录/组合模块库/`，能力号7000–7999；不复制支持库算法。
- 技能：用法正文，目录 `扩展根目录/技能封装库/`，能力号8000–8999；没有业务实现码段。
- 扩展声明归扩展；普通新增扩展不改底座按号分支，不改公开协议。

## 二 开工先定六件事

1. 目标及可复用的已有能力。
2. 扩展身份、能力编号、版本；查号段，不照抄样例身份，不复用已作废编号。
3. 参数名称、类型、顺序、必填性；公布后不重排。
4. 返回类型、字段、所有权；明确空值与零值。
5. 错误码、失败条件；声明、实现、错误码表一致。
6. 依赖身份与版本、修改文件、正常例与失败例。

先读 `AGENTS.md`，发现MCP操作目录。`v1_task` 登记独立工作树并认领文件；`v1_name` 批量登记新名；源码用 `v1_edit`，生成物用 `生成物记账`。正式规则库命令改动后用 `源件记账`，不手写数据库或账本。

## 三 支持库怎么开发

完整最小范例：`扩展根目录/原子支持库/文件支持库/`，数值类参考 `数值计算支持库/`。

- `包声明.json`：身份、版本、能力号段、依赖、导出目标。
- `能力声明/<编号>.json`：一个能力一份，编号使用登记值。
- `错误码表/`、`类型声明/`：错码语义、类型和返回字段。
- `Cargo.toml`、`Cargo.lock`、`src/`：独立扩展工作区，依赖公开契约，不接底座私有实现；`[lib]` 不写 `crate-type`。
- `src/lib.rs` 只路由；声明面、执行面、业务实现分文件，运行期表与JSON逐项一致。
- `说明/使用说明.md`：参数、返回、错误、真实调用例。
- `指纹.json`：按现有指纹机制更新；文件存在不等于制品新鲜。

当前文件支持库用 `静态声明.rs` 同步JSON并导出 `GetPlatformInfo`；不要假设 `生成声明.py --声明根` 已覆盖所有扩展类型。先核该库实际生成链，再复用。

第三方crate只进独立扩展并锁版本，不加到底座Cargo。首次先用独立探针验证引擎并准备仓内Cargo缓存；已有正式锁可显式联网执行 `CARGO_NET_OFFLINE=false cargo fetch --locked --manifest-path <支持库/Cargo.toml>`。环境准备与正式构建分开，生成器及构建保持离线并使用仓内编译环境，不误用系统Cargo家。`Cargo.lock` 经 `准备扩展依赖.py` 生成物记账，传目标支持库目录；生成器补文本产物头标，禁止手改锁或头标。

在目标工作树执行；腿树没有虚拟环境时，解释器使用主仓 `构建环境/python/bin/python3` 绝对路径：

```bash
unset PYTHONPATH PYTHONHOME
. 构建环境/进入.sh
"$V1_PY" 测试验证/契约一致性/扫实现.py
cargo test --locked --offline --manifest-path 扩展根目录/原子支持库/文件支持库/Cargo.toml
"$V1_PY" 构建装配/上线切换/构建制品.py --预构建
```

测试清单以文件支持库示范；新库替换其路径。自检看真实退出码、失败与未判，不抄历史数量。支持库机器码由装配侧现场编译并包成 `.支持库制品`，不另立动态库构建腿。

## 四 组合模块怎么开发

完整范例：`扩展根目录/组合模块库/求和列表模块/`；直算范例为 `求和模块/`。

- 包声明、能力声明、错误码、依赖身份与版本齐全。
- 当前一个制品承载一个能力，多入口分别建包；不能借入口丢弃能力号假分派。
- 本体为同目录同名 `.程序文本`，不建模块的 `src/` 或 `Cargo.toml`。
- 调公开能力名，不导入支持库内部源码；错误及结果结构原样透传。

实际本体：

```text
.版本 2
.子程序 求和列表, 结果结构
    .参数 待求和列表, 列表
    返回 数值计算支持库_求和(待求和列表)
```

先认领目标 `.模块制品`，再用 `v1_task` 操作 `生成物记账`，参数对象：

```json
{"生成器":"构建装配/形态装配/生成模块制品.py"}
```

外层带真实 `开工ID`。默认扫全部模块，未变化件不新增记账；零认领、越界链接、生成器自改声明均应拒记。不能先手工改二进制再补记零件数。

当前生成器转调编译器支持库 `examples/出模块制品.rs`，段20承载本机执行体并校验平台身份。仅有接口说明或WASM字节不等于当前生产口可执行；运行依据为 `跨语言适配/适配器实现/src/模块执行体装载.rs`。

## 五 怎么部署

1. 支持库及依赖先预构建，模块通过正式生成物记账口出制品。
2. 模块隔离执行的工作进程：`cargo build --locked --offline -p v1-adapter --example 工作进程`。
3. 网关启动传 `--声明根`、`--后缀表`、`--缓存根`、`--工具根`；模块另需 `--跨进程配置`。部署表给标识串、版本、制品路径、启动程序；模块启动程序给已构建工作进程绝对路径，依赖支持库也列入部署表。
4. 配置形状查 `对外接口面/调用接口面/src/跨进程装配.rs`。`POST /接口/生命周期` 装载后核剔除原因与逐份就绪；目录存在不等于能调用。缺依赖或版本不符不得回落直调。
5. 临时验收端口由系统分配并读监听日志；不改常驻配置，不新增第二业务入口。

## 六 如何调用

`V1_URL` 指已就绪网关；本机常驻入口示例为43110，临时实例换实际监听地址。模块须先完成第五节部署。

```bash
export V1_URL=http://127.0.0.1:43110
curl -fsS -H 'Content-Type: application/json' "$V1_URL/接口/生命周期" -d '{"动作":"装载"}'
curl -fsS "$V1_URL/接口/生命周期"
curl -fsS -H 'Content-Type: application/json' "$V1_URL/接口/调用" -d '{"编号":7950,"值":[{"类型标签":1,"值":2},{"类型标签":1,"值":3}]}'
curl -fsS -H 'Content-Type: application/json' "$V1_URL/接口/调用" -d '{"编号":7951,"值":[{"类型标签":100,"值":[{"类型标签":2,"值":1.5},{"类型标签":2,"值":2.5},{"类型标签":2,"值":3.5}]}]}'
curl -fsS -H 'Content-Type: application/json' "$V1_URL/接口/调用" -d '{"编号":3101,"值":[{"类型标签":4,"值":"/Users/hekunhua/Documents/Agent/PHP/系统工程平台V1/README.md"}]}'
curl -fsS "$V1_URL/接口/留痕"
```

- 7950期望整数5；7951期望结果结构里的 `结果=7.5`；3101返回真实字节数、行数、摘要。
- 模块参数查包内 `能力声明/`；当前 `GET /接口/能力/7951` 不能作为模块已就绪的判据，装载后用生命周期与真实调用核实。
- `值` 按参数表顺序排列，每项带类型标签：1整数、2双精度、4文本、100列表、103结果结构；列表元素也带标签。
- HTTP200不等于业务成功：还需检查正文 `成功`、返回槽和错误对象。`curl -f` 不会替你判200正文中的失败。
- 7951空列表回1001；3101相对路径回3004；错型、少参必须拒绝。零值可以成功，不擅改成失败哨兵。
- 应用、HTML、脚本用同一公开HTTP入口；模块内部经实例适配器和宿主回调调用支持库，不另建调度腿，不删既有成功/错误结构。

## 七 完成标准与提速

- 每项至少正常例、失败例；涉及空值、零值、列表或资源，加对应边界。外部引擎结果按锁定版本的真实定义作独立对照，不凭名称猜字段语义；失败回执给实测值与期望值。
- 库内外部请求预算必须短于平台外层绝对截止，留出错误编码与传回时间；相同截止会争抢成外层超时，不能靠放宽平台预算修复。
- 自动改名只改语法绑定与引用，不对源码原文做全局词替换；HTML标签、CSS选择器和协议键等字面量须原样保留。
- 组合必须由一次模块调用取得内层能力留痕，不靠另调支持库凑同值。
- 涉及状态时，双实例不同输入验结果、错误、留痕不串；卸载后验证所属进程回收。
- 当前源码重新构建后验真实HTTP；单测作补充。依赖缺失、版本不符也要反例。
- 永久案例放齐 `案例.json` 与 `期望.json`；真空目录跳过，非空破损报错。
- 定向验证后走正常释放与合并门禁，不额外重复全量；缓存复用写明，不伪报冷跑。
- 合后复验再关闭反馈、销账、清树；已销台账的反馈关联转到真实维修开工，避免悬空。
- 工具先发现再复用，独立查询批量发，不重复全仓探索，不为单个能力扩成底座重构。
- 交付只报能力号、怎么调、真实返回、失败条件、提交和未覆盖；失败报具体节点与错误。

## 八 原理与复杂度边界

```text
调用方/HTML
  → 同一HTTP入口按能力号与参数行序传值
  → 适配器：检查契约、路由、错误、所有权与留痕
  ├─ 支持库：原子操作 → 外部引擎/服务或自身算法 → 必要值
  └─ 组合模块：构建侧编译的程序文本
       → 本实例宿主回调 → 已声明支持库 → 原样结果/错误
```

- 支持库负责一种技术领域的原子操作，可有多条能力；复杂算法、数据库、媒体或模型引擎属于该库内部，不因内部复杂就把算法加进核心。
- 模块负责组合已有能力，不复制引擎；核心只处理共同边界，不知道具体库名。技能负责用法，不伪装成执行实现。
- 一类事实一个源：本件管操作流程，必备件管交付清单，格式说明管字段形状，各扩展声明管自身参数、返回、错误与依赖；不是把全项目塞进一个文件，也不代表全仓从此没有漂移。
- 运行适配器能承载某类型，不等于模块生成器能表达它。当前本机生成子集只支持一个子程序、参数与一个返回表达式；类型为整数、文本、列表、结果结构。双精度等可在复合结果内透传，不等于允许作为独立模块参数。
- SQL事务等多步流程可以封装为一个原子能力；这不等于模块语言已有局部变量、分支、循环、字段取用、异常补偿或完整流程编排。
- 常规同步复杂库先按现有接缝接入；跨调用长期句柄、长任务、流式结果、取消、外部运行环境分发须分别实证，不能从求和或SQLite推定全部成熟。未实证不是已确认缺陷，不能擅改冻结公开面。

### 代表性实证与复跑

SQLite支持库5101/5102、数据库查询模块7952、数据库事务模块7953的合同与部署依赖只住各包声明及使用说明，不在这里复制字段表。与老项目SQLite一样，每次调用独立连接并回收，不冒充长期连接池；老项目源码不参与V1构建。

真实验收入口：`扩展根目录/原子支持库/SQLite支持库/验收/HTTP验收.py::执行HTTP验收`。传入仓根与仓外全新缓存目录，启动两个临时网关，在真实SQLite上验证提交/回滚、只读拒写、类型保真、锁与结果上界、并发不串、内外留痕和资源释放；所有请求原文落缓存目录。单测不替代此链。

```bash
"$V1_PY" -c 'import runpy,sys; runpy.run_path("扩展根目录/原子支持库/SQLite支持库/验收/HTTP验收.py")["执行HTTP验收"](sys.argv[1],sys.argv[2])' "$PWD" "$HOME/.hermes/cache/scratch/SQLite独立验收"
```

SQLite是外部系统引擎，须具备可链接libsqlite3。零第三方Cargo包不等于零外部运行环境；不会把外部引擎塞进底座，也不宣称任意机器无环境即可运行。

### 扩大覆盖的开发与验收

- 压缩支持库3201/3202封装系统libz；URI编码支持库4101/4102按RFC3986处理UTF-8组件；合同与限制只住各包说明及声明。
- 文本压缩／解压、URI编码／解码模块7954–7957验证原子调用；编码压缩7958、解压解码7959验证两支持库的嵌套调用；列表回传7960验证空列表与嵌套值，不把复合结果套壳来绕开返回类型。
- 文本及列表沿既有整槽IPC返回。返回引用输入时，必须先编码后释放；同一分配只释放一次。宿主回调产出的中间值由单次模块上下文持有，调用结束归还，最终返回交外层归还；不落全局状态。
- 空文本、空字节集按标签返回空字符串，不能退成指针地址。错型、少参、无效编码、压缩损坏、尾随垃圾和膨胀越界必须具名失败。
- 多模块部署显式填写跨进程配置的 `子进程数上限`；默认配额不是无限容量，不因压测偷偷放大默认值。实际配额按部署的模块执行域数确定。
- 公共实证入口为 `测试验证/扩展量级/HTTP验收.py::执行量级验收`，传仓根及全新仓外缓存根。两个临时网关、多包同实例、12线程、三轮装卸、模块物理回收均走真实HTTP；技能包不属于本次执行域覆盖。
- 主闸35与独立准入⑭共用原通用指纹检查节点，编译器专用检查保留；合并后的真实制品必须与快照一致。跨旧基线合并不能只信施工树通过，也不得回退正确制品来迁就旧快照。
- 指纹先按归属刷新再零写检查：编译器和数值库保留原专用生成器，其余扩展统一用 `构建装配/形态装配/扩展指纹.py`。快照含声明、源码、Cargo锁文件和模块制品；改源码或重新出制品后必须同步生成物记账，禁止手改摘要。
- 批量装载的HTTP外层预算引用 `构建装配/门禁/常量.py::效率目标毫秒`，不随包数无限累加；单次能力请求取该上限与5秒的较小值。工作进程握手仍用原预算，不放宽生产执行限额。超时回执必须记录路径、动作、预算与实际耗时；取证临时放宽预算的运行不得冒充正式验收。
- JSON数据支持库5201–5204与正则表达式支持库4401–4403各自封装成熟引擎；编号、参数、限制及差异只归包内声明与说明。第三方引擎依赖不进入底座，运行不读老项目源码。
- 模块7961–7966覆盖规范化、取值、提取、替换、分割和摘要；7967串联JSON取文本与正则提取，7968串联规范化与压缩，不复制算法。
- 数据文本扩展入口为 `测试验证/数据文本扩展/HTTP验收.py::执行数据文本验收`，仍复用原量级驱动的网关、部署、请求、装卸和回收；增加大整数、同名私有键、固定结构、列表空项、资源反例和12线程组合对照。
- 规模只按当前声明目录和真实验收报告计算；更多同步库通过不等于长期句柄、异步长任务、流式、取消和完整编排语言已经实证。需要这类库时按原契约接缝验证，不以此次同步压测代替。

### 分层批量与成品调用

- 先冻结整批契约、编号和资源边界，整层写齐支持库，再整层写齐组合模块，最后统一构建、严格检查和真实HTTP正反并发验收；不要每写一个能力就重跑整套。
- 模块契约一次写齐依赖原错误码、真实复合返回类型和说明。第三方crate及枚举成员用中文导入别名，不为外来名字放宽命名闸。
- 同步生成物口有5秒执行上限；模块源齐备后用 `生成器参数` 按适当大小切片编译，四模块一片为已用做法，不是逐能力重做验收。失败未记账的产物不算成品；最终真实产物必须由正常成功生成口记账。
- 每条能力明确输入上界、适合CPU或GPU的资源性质及估计成本；估计标明未实测，不能把耗时模型或媒体任务当作普通小文本计算。开发耗时按依赖准备、业务编写、生成、构建和验收分段记，修公共接缝不反复摊到每个库。
- 发布准备与使用分开：开发侧编译、封装、验收并准备不可变执行映像；制品更新重新做这些。调用不重新扫源码、编译或跑功能验收，保留请求类型、权限、资源、结果所有权和错误校验。
- 成品准备公开入口为 `构建装配/上线切换/准备执行映像.py`：传 `--仓根`、`--代码缓存根`、`--日志路径`。它只经生产启动入口准备宿主支持库映像并退出，不执行业务能力；模块进程仍按需启动。部署网关的 `--缓存根` 复用该代码缓存根；不能准备到一条路径、使用时又换到全新路径并宣称已经准备。
- 模块登记只记目标与部署，不启动未使用的业务进程、不占活进程配额；首次调用合并同域启动，复用原进程池和IPC。每次调用到达重置30秒保活，在途及排队持租约；空闲回收保留登记，不算崩溃，之后可重新启动。配额按真实活进程计算，默认上限不因压测改动。
- 多实例可共享按内容定名的不可变代码文件，部署、回调、数据库和业务进程归属仍独立。批量验收先单列同一生产入口的映像环境准备，再起两份新业务进程；报告明确准备开销与代码缓存复用，不冒称无准备冷跑。业务实例原启动线、单调用与握手预算不随包数增加。
- 热调度、完整HTTP、首次调用含进程创建与装载、业务执行分别计量。微秒热调用不等于新建进程或模型首次回复也达到微秒；不能用模型装载耗时掩盖简单计算的人为等待。
- 通用数据层统一入口为 `测试验证/通用基础扩展/HTTP验收.py::执行通用基础验收`，复用量级驱动并覆盖原数据文本层，加入编码、日期、路径、网址、CSV、XML和二至四库组合；合同仍只查各包声明，不另抄字段。
- 回收排序先对活动期限取一次快照再排序，不能在比较函数里反复读变化的锁状态；执行回收前仍重检租约。格式化类引擎可能对可解析但不可输出的格式返回错误，应显式接收格式化结果，不用会因错误而panic的文本转换。

### 输入输出扩展层

- 文件库3101保持原契约，新增3102–3110：有界文本及字节读写、拒覆盖新建与复制、单层目录与非递归删除；二进制沿原字节槽，不转自定义编码文本。绝对路径不是沙盒承诺，平台进程权限仍适用。
- 网络请求2401–2404封装HTTP客户端，HTTP/HTTPS、TLS验证、无重定向、全程预算取公开契约常量 `单项超时毫秒` 的一半（短同步联网，不争抢调度截止）、响应65536字节；允许内网但不继承环境代理；下载拒覆盖。不是通用命令执行壳。
- 网页解析4801–4804封装HTML5解析器与CSS选择，不执行脚本；模板4901–4902只做JSON对象上下文的简单变量插值与变量提取，禁止控制语句、过滤器及算术，输出有界写入，不声称完整模板编程语言。
- 字符编码4001–4002用真实文本与字节类型做明确编码名转换，拒静默替换；UTF-16大小端显式处理；ZIP3401–3403做有界归档字节读取及单成员生成，不写解压目录，拒上跳成员路径。限制、引擎与参数形状只住各包，不在此重抄。
- 模块7982–7999组合网络、网页、文件、模板、JSON、CSV、摘要、正则与URI能力；新建文件类有实际副作用，调用方必须显式给绝对目标路径。不可把纯查询的重试策略直接套到写入流程。
- 唯一真实HTTP验收入口：`测试验证/输入输出扩展/HTTP验收.py::执行输入输出验收`，传仓根及全新仓外缓存根；自有本地HTTP靶场只作被请求的外部源，实际能力返回必须来自正式V1网关。两实例、原生字节、独立标准库解包与文件读回、错误与资源边界以及并发回收统一覆盖。

### 构建缓存与生命周期边界

- Cargo 依赖缓存统一归Git主仓的 `构建环境/构建缓存/cargo`，普通工作树和隔离集成树共用这一份；`进入.sh` 是唯一环境解析源，编译输出默认仍在各树自身的构建缓存，保留上游源码、锁校验与原包说明；不得删第三方说明来消除文档误判，也不得将项目编写的散文塞进缓存。
- 滑动保活的30秒是资源生命周期，不是命令允许执行30秒。唯一保活常量按冻结值校验；复制常量、延长周期或直接拿它作传输超时仍应拒绝。业务执行预算不变。
- 一整层源码和验收件齐备后统一执行正式 `落库` 更新命名快照，再建库、记账、放行；绑定名登记不能替代字段名全量快照。
- 新克隆先按锁准备依赖原包；已准备主仓的新工作树和集成树不得另起空依赖家。共享缓存由Cargo自身锁协调，不复制为多份长期源，不因此共享业务数据。

## 九 失败定位

- 装载失败：查生命周期剔除原因、身份、版本、依赖。
- 调不到：查能力声明与逐份就绪，再核部署表和工作进程路径。
- 错误缺失：查错误码表与声明引用，不将内层失败抹成成功零值。
- 自检失败：读默认范围的逐条明细，不放宽白名单过关；零写断言失败须报变动件。预检及回执元数据查询共用 `开工账本.py::只读连账本`，不调用建表连接。
- 模块构建：契约产物只取本次Cargo构建图回执，按契约清单绝对路径匹配；例子与本机生成验证共用 `编译器支持库/examples/出模块制品/契约产物.rs`。缓存里多份rlib是正常状态，不按时间猜、不靠清缓存消歧。
- 原生可装载库的路径只取本次Cargo构建回执，按清单绝对路径和库名匹配，绑定库字节摘要；只找档只读该回执，不再运行Cargo。多份同名缓存可以共存，缺回执、回执多产物、文件缺失或摘要漂移均明确拒绝并指向正式预构建，不按前缀、时间或第一份猜测。
- 原生库打包：由Cargo直接接收 `--crate-type cdylib` 并决定全部依赖链接，不把参数塞到分隔符后，不扫缓存或人工指定第一份rlib。接线及失败中止样本已挂原机制自测；真实可用性仍以当前制品的HTTP结果判定。
