# 解释器唯一化与「假绿 / 假红」定位

「手工用 3.14 跑全绿、走门禁却红」这一类问题的完整定位与修法。SKILL.md 的「解释器唯一化」小节是结论，
本件是取证过程、全部落点与处置姿势。

## 一、两条真源，各管一面

| 面 | 唯一真源 | 落点 |
|---|---|---|
| Python 侧（具名作业、子进程） | `sys.prefix/bin/python` | `开发工具/MCP服务/作业.py::解释器路径()` |
| shell 侧（`.sh`、钩子、入口） | git 解析出的主仓 + `构建环境/python/bin/python` | 各 `.sh` |

**不许写候选链**（华哥口径：「不要说做兜底，本质上要咬合紧，没有兜底，没有第二条腿」）。

### 为什么 Python 侧不能拼调用方目录

`解释器路径(仓根)` 写成 `Path(仓根) / "构建环境/python/bin/python"` 是错的，两个反例：

- `开发工具/MCP服务/验证样本/作业执行/作业样本.py::异步短样本` —— 传的是**腿树**当 `仓根`（跑自检时 cwd 在腿里），
  腿树按新规矩**不建 venv** ⇒ 取不到。
- `开发工具/MCP服务/验证样本/作业执行/裸仓回执样本.py` —— 夹具是 `tempfile.mkdtemp()` 下的 bare 仓与普通目录，
  根本没有 `构建环境/`。

「不在即抛错」会把这 5 条拒绝样本一起打死：`v1_shell bare 仓根` · `v1_shell 非 bare 目标` ·
`真实start返回任务ID` · `真实status短作业` · `真实log短作业`。
**解释器不属于调用方的目录，它是服务进程的属性。**

正确写法（无参、无候选、无回落）：

```python
解释器 = Path(sys.prefix) / "bin" / "python"
if not 解释器.is_file():
    raise FileNotFoundError("跑本服务的 venv 里没有解释器：%s" % 解释器)
return str(解释器)
```

实测 `sys.prefix` = `/Users/hekunhua/Documents/Agent/PHP/系统工程平台V1/构建环境/python`（仓内 venv）。

### 为什么 shell 侧由 git 解析主仓

shell 里拿不到 `sys.prefix`。腿（linked worktree）的 `.git` 是**文件**
（`gitdir: <主仓>/.git/worktrees/<腿名>`），而 `git rev-parse --path-format=absolute --git-common-dir`
在腿里就返回 `<主仓>/.git` ⇒ `dirname` 即主仓。一行、无手工拼 gitdir、无 sed：

```sh
ROOT=$(cd "$(dirname "$0")/../.." && pwd)
ROOT="$(dirname "$(git -C "$ROOT" rev-parse --path-format=absolute --git-common-dir 2>/dev/null || echo "$ROOT/.git")")"
PY="$ROOT/构建环境/python/bin/python"
```

落点清单（凡出现 `构建环境/python` 的 `.sh` 都要过一遍）：
`构建环境/进入.sh` · `构建环境/自检.sh` · `测试验证/测试案例/装门禁.sh` · `开发工具/并行工作树.sh` ·
`构建装配/上线切换/{回退,装载,切换}.sh` · `前端呈现/命令行界面/命令行界面.sh`。

**根因面**：`开发工具/并行工作树.sh` 原用裸 `python3 -m venv` 建腿 ⇒ **每条新腿都带一个 3.9.6 venv**
（按 venv 目录 mtime 能看出它建于该腿登记时刻）。改成**腿里不建 venv**（解释器只住主仓），
并清掉腿里历史误建的那份（`rm -rf <腿>/构建环境/python`，该目录是 gitignore 的、不进版本库）。

## 二、`v1_shell` 是通用 shell 面

它同时跑 git / ls，目标树可能根本不是仓（夹具、临时目录）。取不到仓内 venv 时
**不前置 PATH、也不另找 PATH 上的 `python3` 顶替** —— 没有替代解释器被指定，只是不注入。
判据：`v1_shell` 在非仓目录跑 `echo x` 必须**退出码 0**（`裸仓回执样本.py` 卡这条）。

## 三、服务跑的是主干那份代码

常驻服务 `开发工具/MCP服务_http.py --服务 --端口 43140` 由**主干**路径拉起 ⇒
`v1_gate` / `v1_job` 走的模块是**主干那份**。腿里改 `作业.py` / `shell.py`，**工具面看不见**
（只有 cwd 落在腿里的子进程用腿的代码：`v1_shell` 起的命令、判据起的子进程）。

推论：

- 「闸 0 红是不是我改坏的」先分这一层 —— 腿里改动未生效时，红必然是主干既有的。
- 修「工具面自身」的问题，**得先合主干再重启服务**，在腿里怎么改都看不见。

## 四、假红的完整链条（判据 ㊽）

1. `v1_gate 全量` → `门禁.py` 同步窗口只有 4–10 秒，闸 0 跑不完 ⇒ **转后台具名作业 `闸0`**。
2. 具名作业命令串取自**具名作业表**，走 `shell=True` ⇒ 裸 `python3` **按服务进程的 PATH 解析**。
3. 服务 PATH 里 `/usr/bin` 在 `/opt/homebrew/bin` 之前 ⇒ 解析到系统 **3.9.6**。
4. `闸0.py` 与其子进程都继承这个解释器 ⇒ `MCP服务.py --自检` 里 `read_text(newline=)`（3.13+ 才有）
   报 `TypeError: unexpected keyword argument 'newline'` ⇒ 判据 ㊽ 红。
5. 而**手工用仓内 3.14 直跑** `构建装配/一键验证/闸0.py` 全绿（52 项 + 12 项）⇒ 这就是分裂点。

两条一起做才算修完：

- 具名作业表命令写 `"$V1_PY"`（由 `接管作业` 注入绝对路径）；
- 起服务时把仓内 venv 的 `bin` **前置进 PATH** —— 环境变量在进程启动时固定，
  **自愈 execv 重放不会改它**（重放继承的是旧进程的环境）。

## 五、重启常驻服务的姿势（状态件 PID 漂移）

`服务管理.py::停止服务` 只信**状态件里的 PID**，且核「该 PID 命令行含本服务入口件名」才发 SIGTERM，
**不杀陌生进程**。实测状态件里记的 PID 早已不在、真实进程是另一个 ⇒ `--重启` 回
「端口 43140 已被占用（可能是别的进程）⇒ 拒绝启动」。

处置：**先核身份再手动停**，然后 `--启动`：

```sh
ps -p <真实PID> -o command=                      # 核命令行含 MCP服务_http.py
kill <真实PID>; sleep 1
PATH="<主仓>/构建环境/python/bin:$PATH" ./构建环境/python/bin/python 开发工具/MCP服务_http.py --启动
ps -eo pid,ppid,command | grep 'MCP服务_http.py --服务' | grep -v grep   # 核新 PID
```

`启动服务` 用 `sys.executable` 起新进程 ⇒ **起服务那个解释器决定新服务的版本**，必须用仓内 3.14 起。
状态件与日志落**运行数据根**（`临时件/MCP服务_http.状态.json` · `日志/MCP服务_http.日志.txt`）。
起完立刻用 `v1_shell` 跑 `command -v python3` + `python3 -V` 验落点。

## 六、定位方法：主干 vs 腿对照

同一条自检在两棵树各跑一次，**主干绿、腿红 ⇒ 就是本次改坏的**，别归因成环境或偶发：

```sh
PY=<主仓>/构建环境/python/bin/python
cd <主仓> && $PY 开发工具/MCP服务.py --自检 | grep -E '✗|拒绝样本没过' ; echo "主干退出码=${PIPESTATUS[0]}"
cd <腿>   && $PY 开发工具/MCP服务.py --自检 | grep -E '✗|拒绝样本没过' ; echo "腿退出码=${PIPESTATUS[0]}"
```

`--自检` 只跑短自检（几秒）；判据自测是 `构建装配/一键验证/一键验证.py --自测`（约 35 秒），
**以退出码为准**，`grep ✗` 会误命中说明文本。

## 七、两个小坑

- **命名闸的十干字面禁项会拦表示「本人」的那个词（U+5DF1）** —— 注释里写「服务本人的解释器」当场**整批零写**
  （回执点名第几条、第几行）。改成「服务进程的解释器」「由 git 解析」。同类：`docstring` 里
  「这个库件自身坏没坏」也要改口。
- **`/bin/sh`（macOS 上是 bash 3.2）不认中文变量名** —— 写验证脚本用 ASCII 变量名
  （`腿=x` 报 `No such file or directory`；`"$VAR（"` 要写 `"${VAR}（"`）。
- **`构建环境/自检.sh` 曾「先用后定义」**：`$PY` 在**定义之前**就被引用 ⇒ `set -e` 下跑空当场退出。
  解释器解析段要放在**任何**用它的语句之前。
