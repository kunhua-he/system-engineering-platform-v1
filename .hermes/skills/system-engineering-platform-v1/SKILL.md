### 调用姿势

- 每个工具**同形三字段**：`开工ID`（可选）· `操作`（操作名或号；**留空 = 只读发现**，回操作目录）· `参数`。
  操作参数放顶层会被客户端校验直接拒。**操作名一律先发现、不要猜**（`操作:""` 回操作目录，每个带真名 + 号）。
- **改代码只能走 `v1_edit`**；读文件用内置 Read 或 `v1_tree`。
- 小操作一律用 `dict(...)` + `pop(..., None)` 之类现成面孔，**别引入新标识符**（命名闸会拦未登记的新名，单汉字名是禁止形状）；
  改名要 `v1_name` 的 `批量登记`（参数 `名单: [[名]]`，幂等）。**新建件顺序：先登记名、再新建**。
- **引用一律按符号、不许按行号**（判据 ⑮，连注释也管）：写 `路径::符号名`。
- **起作业返回 `退出码 -3` = 在途，不是失败**；取终态用 `v1_job` 的 `status`/`log`（参数 `任务ID`）。
- **改台账/建库后要 `源件记账`**（参数 `源件` 是**字符串、一次一件**），再释放。它**只收 `v1_edit` 读不动的件**
  （二进制 / 非 utf-8，如 `信息核心.db`）；文本件改完直接释放即可。
- **★ 改库/改台账的命令必须在「腿」目录里跑，不能在主干跑** —— 命令改的是 **cwd 下的那本库**：
  跑在主干 ⇒ 腿里库没变、主干库变脏，于是两处同时拒（`源件记账` 报「盘上没变过」，合主线报「推进前同步保护拒绝」）。
- **删台账条目**：`未完成.json` 是建库源件 ⇒ 走 `v1_edit` 的「空 `新内容` = 删段」，**要连条目的 `[` 与 `],` 一起删**；
  改前先 `补充` 把 `开发工具/信息核心/未完成.json` 加进 `文件认领`（不加会整批拒、一个字节不写），改完 `建库` → `源件记账`。
- **台账行里禁止写腿号**（判据 ㊳「引用即悬空」会反锁清树）；源码树里连注释也不许出现「台账 + 空白 + 号」。
- **`v1_name` 登记名会写 `信息核心.db`** ⇒ 该件不在本腿认领里时释放会被闸拦，先 `补充` 加进去。
- **一批改动带新标识符时，整批先验会一次列全所有要登记的名** ⇒ 照它一次登记完再重提。
- **开工状态机**：改码需「进行中」；**合并只接受「已提交待合并 / 已释放」**；已释放就改不动。
  要接着干必须新登记 + **`基线: 腿/v1-100XXX`** 把未合腿并进来（新腿从主干建，前一条腿的改动不在里面）。
- **解释器只有一个：仓内 venv（3.14）**，建库/跑闸/钩子一律走它。

### 失败回执口径（华哥裁定，适用一切对外接口）

**一句话、非 JSON、按「你传了什么」给下一步**：`<原因，带上调用方传的那个值> ⇒ <下一步具体怎么传>`。

- 例：`快照超时秒、还原超时秒 没登记 ⇒ 跑 v1_name 批量登记 名单=["快照超时秒","还原超时秒"]`。
- **判据编号、口径出处、语录、多种备选载荷一律移进文档，不塞回执**。
- 正向口径：接口「返回就是那个值本身，没有成功/失败包装」，失败 = 0（哨兵），失败原因作可选第二值，
  纯查询返回结果本身，**参数全空 = 返回「怎么调」**。
- 改回执要分清**对模型那面**与**内部/探针协议面**：承重字段（如 `退出码`）不能一刀切删。
- **★ 「已过预检」≠「已落盘」**：整批原子的写口在整批零写时，回执必须说「整批未写，**全部**条目都要重发」；
  写「这次不必重发」会把没写盘的条目静默丢掉。

### `v1_edit` 的操作语义

- **顶层 `操作` 只有 改 / 只检查 / 恢复 / 恢复已记账写后**（没有「新建」）。
- **建新件** = 顶层 `操作="改"` + 条目 `{"操作": "新建", "路径": …, "新内容": …}`；
  改既有件 = 条目 `{"操作": "修改", …}`；**删内容片段** = `修改` + 空 `新内容`（只给要删的那段，
  禁止「旧内容=前后段+要删段、新内容=保留前后段」那种两条腿写法）。
- **一次发多条时每一条都要带 `操作`**，只在顶层给会整批被拒、一个字节不写。
- **操作 `删除` = 删整个文件**，不是删片段。
- **`旧内容` 必须从腿里读原文再拼**（缩进差一格就找不到）；**替换大段会吃掉紧邻的 `import`/常量** ⇒ 改完立刻回读。
- **删片段别把控制流删空**（`if` 的块体删光会触发语法闸）。

### 回执信封：字段有「承重 / 壳」之分，删前必须 grep

- **承重**（删了立刻红）：`退出码`（`反馈帧样本.py::取码` 靠它读业务码，缺了退化成 -99 ⇒ 探针齐红）、

- **纯壳**（实测 0 处引用）：`树`、`服务`（版本 + 指纹）。
- **改前先 grep 全部读者**：`成功`/`退出码` 的读者散布在六处（命令行界面 `命令.py`/`显示.py`、
  声明编写面 `编排.py`、准入判据 `八条必证.py`/`夹具.py`、演示 `网关与调用.py`）⇒
  「把回执改成易语言式」是跨六件的大改，先加「承重/可裁」标记与判据兜底再动删减。
- **Hermes 侧会去重**：`tools/mcp_tool_handlers.py::_render_call_tool_result` 按「文本块与 `structuredContent`
  逐字相同即丢后者」⇒ 同形两份时模型只收一份，别当成上下文浪费。
- `说明` 对结构化工具只是「结构化结果见 结果（N 字节）」一句 —— 想让模型看到内容得让 `content` 携带正文。

### ★ 同类错误出现 2 次 ⇒ 抽节点 + 全仓同步（华哥硬口径）

三步，缺一步不算做完：① **全项目排查**（还有哪些地方会出现）；② **全部同步**（所有落点都引用该节点，不留第二套）；
③ **加闸防回潮**（写成判据进闸 0）。

**排查手法**：先用粗糙正则定位候选，再**逐个读原文定性** —— 正则阶段几乎必然误报，
写成判据时也要选**不会误报的判法**（判据 62 选 AST 而非正则就是这个理由）。已抽出的节点：判据 61（解释器唯一化）· 判据 62（顶层模块名必有导入）。

| 全案例 cargo | 约 0.5 s |

**双层全闸**：释放跑一遍、合并再跑一遍。已按「自测只跑一次」改：钩子只在 ①合并提交（`MERGE_HEAD` 在）
②本次暂存进了判据面（`构建装配/一键验证/` 或 `测试验证/案例/`）③显式 `V1_FULL_GATE=1` 时跑自测，
其余腿提交跳过并**明写回执**。

**分段读数已内建**：钩子打一行 `门禁分段：闸0 X ms · 自测 Y ms · 案例 Z ms · 合计 W ms`；
合主线报告打 `分段耗时：① 校验 … ② 集成合腿与源库重放… ③ 集成验证… ④ 推进主干… ⑤ 同步主目录…`。
**★ 改 `合主干编排.py` 的那一次合并看不到新读数**（正在执行的是它自身、用旧代码）；改钩子后第一次提交同理。

### 钩子只有一个版本源：发射器（`装门禁.sh`）

`.git/hooks/*` **不进版本库**，唯一版本源是 `测试验证/案例/装门禁.sh` 的 `<<'HOOK_BODY'` 段 ⇒
**直改盘上钩子必然被下一次装门禁覆盖**。改钩子一律改发射器，再装：

```bash
GATE_INSTALL_SHARED=yes sh 测试验证/案例/装门禁.sh   # 不加这个变量会被「钩子目录不在本仓内」拒掉
```

heredoc **必须带引号** `<<'HOOK_BODY'`（不带引号时安装过程会把仓内 `$`/反引号当场展开、静默变义）。
**bash 3.2 不认中文变量名/函数名** ⇒ 钩子与 `装门禁.sh` 里 shell 变量、函数名一律 ASCII，且 `$VAR` 后紧跟中文要写 `${VAR}`。

### 解释器唯一化：仓内 venv（3.14），不留第二个版本

**唯一真源是环境变量 `V1_PY`**，三层分工：

| 层 | 职责 | 落点 |
|---|---|---|
| **入口层** | 保证本身是仓内 3.14，并注入 `V1_PY` | `装门禁.sh` · `服务管理.py` · `构建环境/进入.sh` · `并行工作树.sh` · `一键验证.py` · `MCP服务.py`/`MCP服务_http.py`/`合并主干.py` 的 `__main__` |
| **传播层** | 把 `sys.executable` 注入 `V1_PY`，随子进程继承 | `作业.py::确保注入()` |
| **使用层** | 一律读 `V1_PY`，**缺失即拒**（不回落 PATH、不猜路径） | `作业.py::解释器路径()` · `shell.py::_执行环境` |

**★ 无兜底、无第二条腿**（华哥硬口径）⇒ 解释器解析**不许写候选链**（`||` 接力），链子一长总会有一条静默生效。
**★ 入口的 `__main__` 里不许 `from 开发工具.MCP服务.作业 import 确保注入`** —— 脚本直跑时 `sys.path[0]` 是脚本目录，
样本夹具仓里更没那个模块 ⇒ `ModuleNotFoundError`。那一层写一行：`os.environ.setdefault("V1_PY", sys.executable)`。
**★ 夹具仓里没有仓内 venv ⇒ `V1_PY` 仍要注入**（唯一来源是**本进程**的解释器，不是调用方的目录）。
**★ 解释器解析段要放在任何用它的语句之前**（`set -e` 下先用后定义会当场退出）。

**判据 61「解释器唯一化」已进闸 0**：全仓 `.py` 执行面 0 处裸 `python3`/`python`（扫**保串**的生产区文本）。
写注入样本件时**内容要避开自身的扫描面**（裸名用 `%s` 拼）。`.sh` 面另用
`grep -rn 'exec python3\|\$(python3 \|`python3 ' --include='*.sh' .` 核，应为空。

## 三、收口链与合并/清理

**★ 收口链已封成脚本**：`~/Documents/Hermes工作区/工具/收口链.py <开工ID> [--不推] [--从 <步号>]`
—— 固定九步（建库 → 自检 → 源件记账 → 闸0 → 提交放行 → 释放 → 合主干推送 → 单纯释放 → 安全清收口），
自带「起作业 → 轮询终态 → 判退出码」；每步打「步号 + 步名 + 耗时」，失败即停并打该步回执。**能用脚本就不要手工逐条调**。

**★ 脚本级坑（2026-10-10 实证，前两条各真卡过 6 分钟）**：

1. **`v1_job status` 回的是纯文本**（`状态：…` / `退出码：…` 写在 `说明` 里，顶层没有 `状态`/`退出码` 键）
   ⇒ 读 `果["状态"]` 恒为 `None`，轮询永不终止。必须从 `说明` 正则解析；
   且解析出来是**字符串**，要 `int()` 归一，否则 `"0" != 0` 会把成功误判成失败。
2. **主仓 index 残留 ⇒ 合主干「同步保护」拒绝**（回执 `④ 推进前同步保护拒绝：index 与旧提交不同`）
   —— 合主干前先 `git reset -q` 清空主仓暂存区（工作区未跟踪文件不受影响）。
3. **合主干失败会留集成现场**（`/private/var/folders/…/v1集成-*`）⇒ 直接重跑会被「已有集成现场」挡住；
   此时 `--清理现场` **会被拒**（现场基点正是当前主干 = 集成提交没进主干）⇒ 正确顺序是 **`--恢复现场` 再重跑**。

4. **`登记` 认领的件必须「盘上已存在」** ⇒ 主干里还没有的**新件**（如 `.hermes/skills/**` 首次纳版）不能一步认领：
   登记腿（认领留空）→ **在工作树里建件**（`cp` 或 `v1_edit` 新建）→ `补充` 认领 → 再收口。
   直接认领会回「盘上不存在」并把刚建的工作树回滚。
5. **腿只提交「认领过的件」** ⇒ 改文件前先确认它在认领集里；漏认领 ⇒ 改动**不进主干**（`v1-100769` 就因此只进了文档账本、技能件漏掉，只能另开一条腿补）。
6. `登记` 的真参数名是 **`工作内容`**（不是 `任务`/`说明`/`任务描述`）。
9. **★ 提速先量节点，别估**：`--自测` 33 s 里 `自检_长样本` 独占 38 s（串行单跑）；
   而**正向样本只要 0.47 s**（曾误猜 6 s）、`--长样本全套` 本体只要 12 s（注释里 55 s 是旧读数）。
   真正的空间在「**这个节点有没有做与它声明无关的活**」，不在提并发 ——

   而那个 5 秒**不许调大**（判据 ㊲ 卡「超时设置 ≤ 硬顶」，调大 = 降判据强度）。
10. **★ 效率改动有生效时序**：`提交放行` 与判据自测都跑**仓根代码**（腿提交时作业跑仓根）⇒
   腿里的改动要**合主干后、下一条腿**才受益。实测佐证：`v1-100772` 自身跑时 `提交放行` 仍 45.8 s，
   合主干后实测 `v1_gate` 操作 `提交放行` = **9.3 s**。所以「改完没变快」先看这条，别当改动没生效。
11. **`自检_长样本` 的反样本只需证「入口把反馈专项的退出码聚合进总退出码」** ⇒
   其余六个套件与这条声明无关，**必须一并 mock**（`耗时反馈样本`/`验证超阈样本`/`释放作业样本`/
   `空改主干样本.旧路复现样本`/`空改主干样本`）；原先它们真跑且跑两遍 ⇒ 本单元 38.19 s，
   mock 后 **12.90 s**，声明面一条不减。
7. **★ 工作树里的件只能走 `v1_edit` 建/改**：`cp`、脚本直写、`sed` 一律会在**释放**口被拦 ——
   回执有两种，都难一眼看懂：「账本记的指纹与现在盘上的对不上」（绕过 v1_edit）·
   「盘上这些件动了，但**不在改动表**里」。正解不是撤销重认领，而是**删掉盘上文件 →
   `v1_edit` 顶层 `操作="改"` + 条目 `{"操作": "新建", "路径": …, "新内容": …}` 重建**
   （新建的字段是 `新内容`，不是 `候选全文`；后者只给 `修改` 用）。
8. **主仓的未跟踪件会挡住合主干**：合主干最后一步「同步主工作区」若撞上同名未跟踪文件，
   会报 `error: Untracked working tree file '…' would be overwritten by merge`。
   **但主干其实已经推进了**（先看 `git log -1 主干` 再判断）—— 处理办法是把主仓那份未跟踪件
   移走（Python `shutil.rmtree`，`rm -rf .hermes` 会被 Hermes 硬拦），再 `git checkout -- <路径>`
   从主干同步回来。**别重跑合主干**，否则白等 47 秒。

12. **★ 断线会杀掉后台进程** ⇒ 收口链跑到一半就断（本轮实测：第 1–6 步跑完、第 7 步没跑）。
   续跑用 `--从 <步号>`；**但续跑前先查结果** —— 本轮两次都出现「第一次其实已跑完，
   续跑才报错」（一次报「合并忙，快速拒绝」、一次报「工作树不在」）。
   查法：`git log -1 主干` + 工作树在不在 + 支线在不在。**别拿续跑的报错当失败**。
13. **★ 已回退的腿，释放前必须先让树对齐现主干**：这类腿的树 HEAD 停在**回退当时的旧主干**
   ⇒ 直接释放会把旧版文件提交回主干、**把后来的新提交回退掉**（本轮 `v1-100775` 实测：
   树 HEAD 是 `c57d98e8`，现主干已是 `04e1d247`，差 5 件）。
   正解：先丢弃树里过时的源件改动（`git -C <树> checkout -- <源件>`），再
   `git -C <树> merge --ff-only 主干` 快进对齐，然后才 `释放` → `单纯释放`。
14. **★ 华哥硬口径：做完的东西必须删除**（2026-10-11）：过程产物（审计登记、临时报告、
   一次性清单）**做完即删**，不留归档、不留划线原文；长期产物（技能、台账、权威文档）才留。
   清理临时文档要**一份一份看 + 一份一份验证 + 结论先落进权威文档**，禁止脚本批量删。
15. **★ 发号口径（2026-10-11 根治）**：`开工账本.新开工号(连接, 仓根)` ——
   ① **只在非 9 开头号段内递增**（9 开头是样本/测试号段，共用序列会让号序列被永久带偏）；
   ② **按数字排序**取最大（`cast(substr(开工号,4) as integer)`），不是字符串序；
   ③ **跳过台账正文点名过的号**（`台账点名号集(仓根)` 读 `未完成.json` 正文里的 `v1-XXXXXX`）。
   实测事故：一个 9 开头的测试号进库 ⇒ 号序列跳到 9 万段 ⇒ 新腿撞台账里的历史编号 ⇒
   保全判据按号点名连坐 ⇒ 现场清不掉。

**★ 长任务一律后台 + 不阻塞等待**（华哥口径）：`background=true` 只是第一步，
**不要再用 `process wait` 阻塞等它**；放后台就去干别的（查数据 / 写反馈 / 沉淀技能），完成通知会回来。
脚本每步打进度是硬要求 —— 否则调用方会以为卡死（「成功静默」是**最终回执**口径，不是长任务过程口径）。

- `v1_gate` 操作 `提交放行`（异步转作业）一次跑「闸 0 + `--自测` + 案例」；取终态用 `v1_job`。
- **★ 释放前先预演「集成树场景」**（几秒，省掉「释放 → 合主线失败 → 开新腿」一整轮）：
  ```bash
  cd <腿目录> && git worktree add --detach /tmp/预演集成树 HEAD
  cd /tmp/预演集成树 && <主仓>/构建环境/python/bin/python 构建装配/一键验证/闸0.py
  cd <腿目录> && git worktree remove --force /tmp/预演集成树
  ```
  合主线会在「新建 worktree」里再跑一遍闸 0，而**有些判据只在 worktree 里红**（worktree 只 checkout 跟踪件）⇒ 只跑腿里的闸 0 就释放，问题到合主线才暴露。
- `合并主干.py <开工ID> --推送` **只能从终端后台跑**（`v1_shell` 超时上限 5 秒且不授权远端推送）。
- 收尾：`单纯释放`（清树与支线）+ `安全清收口`（参数 `确认: true`，**真删**本开工的检查点与工具流水；默认拒绝）。
- 验收三读数：`git log --oneline -1`（主干已推进）· `git status -sb`（无 ahead/behind）· 工作树列表为空。

**★ 合并失败后先看「集成现场」**（报「已有集成现场」时）：用 `合并主干.py <开工ID> --查看现场 / --恢复现场 / --清理现场`。
**先 `--查看现场`** 再分路：

| 现场基点 | 处置 |
|---|---|
| **就是当前主干** | 走 `--恢复现场`（重放源库、跑提交门禁、推进主干、同步主工作区） |
| **是旧主干** | `--恢复现场` 会拿旧基点重放、`--清理现场` 又以「未提交成果」拒 ⇒ **死锁** ⇒ 破局：`git worktree remove --force <现场路径>` → `git worktree prune` → `git branch -D 集成/<开工>` |

**★ 推远端是显式动作**：合主线与释放都不会替你推 ⇒ 最后自身跑 `git push origin 主干`，
再用 `git rev-list --left-right --count 主干...origin/主干` 验成 `0\t0`。**只报「合主线成功」不算交付**。

**★ 判「这条腿真合进主干了没」**：`is-ancestor` 不够（未提交的腿 HEAD 本来就在主干历史里）⇒
两条同时成立：① `git log --oneline 主干..腿/<号>` 为空；② 该腿工作树净。**状态字段会漂，只作线索不作凭据**。

- **释放失败后开工状态仍是「已释放」** ⇒ 不能再 `源件记账`；改动仍在腿分支 HEAD 上，照 `--恢复现场` 补推即可，不必重登记。
- **合并前先确认主干那本库是干净的**（腿里改了 `信息核心.db` 却在主干也跑过改库命令 ⇒ 主干 db 脏，同步保护会拒）。
- **合主线前置 = 该开工已 `释放` 成功**。
- **释放失败定位真因**：在腿目录跑 `构建装配/一键验证/一键验证.py --自测`，**以退出码为准**（`grep ✗` 会误命中样本说明文本）；
  再手动跑那条真入口看真实输出（真因往往只在真入口返回里）。
- **对照主干判「是不是我改坏的」**：同一条样本主干绿、腿红 ⇒ 就是本次改坏的。同类迁移要扫干净（每个起子进程或走旧帧的样本件都要一起搬）。
- **清树**：`单纯释放` 逐条真核（已合主干 · 净树 · 无在途作业 · 无未释放继承者 · 台账未点名 · 无未蒸馏反馈），一条不成立就拒并保留树。
  **保留项不是缺陷**（台账点名 / 有未蒸馏反馈 / 树有未提交改动），不许清。

## 六、判据扫描面与其它硬口径

**★ 字段名/字面量类判据必须 `保串=True`**：`并行取生产区文本(件表, 测试文件集, 保串=?)` 是扫描面唯一入口
（不能直接取上层读数的键 ⇒ 没有 `去串` 键，直接取会 0 件 ⇒ 判据报「未判」）。
裁字段点与字段名**都住在字符串里**，`保串=False` 会一起抹掉 ⇒ 反向样本根本抓不住（闸 0 全绿、自测三红）。
⇒ **闸 0 全绿不等于判据有效**：新判据立完必须跑 `--自测`。判据抓到自身的 docstring/注释是正常代价，按「宁可多报」取、不设豁免表。

**★ 判据 ㊵ 扫天干十字面量，口径是「新增即红」**：存量豁免、**新写进去的**才判红 ⇒ 撞的必然是新落的文档、
新写的件头注释、新写的样本说明串。最常撞的是 **U+5DF1**（日常词组「自+该字」里那个字，本项目已撞两次，都在临时文档）。
⇒ **落盘后先自查再交**：按码位逐字扫这十个 —— U+7532 U+4E59 U+4E19 U+4E01 U+620A U+5DF1 U+5E9A U+8F9B U+58EC U+7678，
或直接读判据回执报出的码位。**技能正文与临时文档同样在扫描面内** —— 本条自身也不许写出字面。

**★ `MCP服务.py` 的 stdio 传输已移除**：该入口只提供 `--自检` / `--长样本` / `--长样本全套`，喂帧会回「stdio 传输已移除」。
改 MCP 服务面的行为验证**改跑 `--自检`**（约 5 s，跑真 HTTP 环回）。
**★ 入口件的路径别记错**：入口是 `开发工具/MCP服务.py`（单件），同名目录 `开发工具/MCP服务/` 装的是它的子模块。

**★ 「直接收口」四步**（不卡在反馈上）：① `查反馈` 看清未蒸馏 → ② `批量判定`（墙钟类一律「非问题」）
→ ③ `登记报告审完`（提取/判词条数必须与库中实际相符）→ ④ `清理已解决任务`（`确认: true`，**连工作树与分支一起清**）。

**腿清零与空登记位**（「反馈已蒸馏完但腿清不掉」的两大真身：**待核须保留** / **空登记位**）见 `references/腿清零与反馈阻断.md`。

**★ 删掉一条传输/一个特性：分两批 + 收尾 grep**：第一批代码面（删件/删主循环/摘导出/改入口分支）；
第二批注释与文档串面（引用**已删函数名**的注释是真漂移）。收尾判据 = 全仓 grep 特性名，剩下每处命中都要能读成「已移除 / 为什么只留 Y」。
**迁移一件的省力法：换掉函数内部、保住返回结构** —— 下游几十条断言按那个形状解包，返回结构一字不改 ⇒ 断言零改动。
**判「服务有没有真重载」别看 PID**（`execv` 替换映像，PID 与启动时间都不变）⇒ 看回执里有没有「当前加载码已过期」提示行。
**同一批里客户端配置一起改**：Hermes `~/.hermes/config.yaml` · ZCode `~/.zcode/cli/config.json` · Codex `~/.codex/config.toml` · 仓根 `.mcp.json`，改前先全枚举并留带时间戳备份。

**★ 别把设计当脏数据**：库 `条款` 表里 `文档路径` 在盘上找不到的行**不是孤儿**（`条款` 属分片源件表，已删 md 的正文按设计留在库里）。
判断某张表该不该清，先读 `建库/编排.py::装表`。
**核对「库行对应的文件在不在盘上」别用 `os.path.exists(仓根 + 库里的路径)`**：macOS 上中文路径 NFD/NFC 不一致 ⇒ 大面积假阴性，
用 `find` 或目录列举交叉验证，或先 `unicodedata.normalize` 归一。

**★ 建库必须字节确定**（否则「恢复现场」必造第二个同内容提交）：`建库/编排.py::装表` 与 `建库/源件.py::装分片源件`
都是「先 `delete from` 再 `insert or replace`」⇒ `创建时间 TEXT DEFAULT (datetime('now','localtime'))` 会取**当前时刻**。
已落地修法：`开发工具/信息核心/建库/保留时间.py` —— 重抽**前**记 `{主键: 创建时间}`、重抽**后**按主键回填旧值
（口径：创建时间是「第一次登记的时刻」，不是「这次重抽的时刻」）。
**自检法**：连跑两次 `信息核心.py 建库` ⇒ 库 sha **必须相同**；主仓跑建库后 `git status` 必须仍净。

## 七、行数硬数（判据 ⑲）

**硬数 = 单源文件 ≤800 行 · 入口 ≤120 行 · 入口零实现**。
