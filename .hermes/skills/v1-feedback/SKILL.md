# 向 V1 反馈口提交发现（反馈技能）

## When to Use

华哥说「提交一下 mcp 的反馈」「就是卡点」「反馈给主会话」「每做完一个任务留个汇报」时。
也适用于：同一条腿反复试错后要沉淀教训、工具回执噪声大、某个动作只能靠终端绕。

**坐标**：反馈库 = `<运行数据根>/数据库/开工账本.db`（macOS：`~/Library/Application Support/系统工程平台V1/数据库/`），
表 `反馈来源` / `反馈条目` / `反馈判词` / `反馈证据` / `反馈关闭`。

## 一、唯一入口：`v1_task` 操作 `提交反馈`

顶层 `开工ID` = 当前腿（**已释放的腿仍可提交** —— 实测释放后提交退 0）。

| 参数 | 形状 | 要点 |
|---|---|---|
| `幂等键` | 字符串 | 同键同文 = 重放零新行；**同键异文 = 拒且整批零写** |
| `来源标识` | 字符串 | 写 `agent反馈/<一句话>-<日期>` |
| `报告指纹` | 十六进制 sha | **必须是真 sha**（8–128 位十六进制）；自造串会被整批零写拒 |
| `条目` | 数组 | **必须显式给**（省或非数组即拒；空数组 = 提取 0 条，不是缺参） |

报告指纹算法（先构造好条目、再算、再提交）：

```python
import hashlib, json
指纹 = hashlib.sha256(json.dumps(条目, ensure_ascii=False, sort_keys=True).encode()).hexdigest()
```

**整批事务**：任一条不合规 ⇒ 一条 SQL 都不落，逐条列错。

## 二、条目形状（省略要付代价）

每条**必需** `现象`；`落点` / `触发` / `预期` / `实际` 可省但**须给明确 `未测` 理由**；
`证据` 与 `未测` **至少一个**；性能问题可填 `耗时毫秒` / `调用次数`。

**推荐全填**（写得越具体，主会话越好修）：

- `现象` —— 一句话说清「谁 + 什么操作 + 报什么」；
- `落点` —— 写 `件::符号`（**不写行号** —— 判据 ⑮ 连注释也管）；
- `触发` —— 调用方做了什么才撞上；
- `预期` / `实际` —— 两者对照；
- `证据` —— **原文回执 / 日志行 / 作业ID + 时间戳**（不写「实测过」这种空话）。

## 三、强制句（华哥要求，必带）

**效率类**条目里必须写：

> 用户强制要求，如效率问题是优先级最高的，主会话需立刻处理这个事项。

**同时把反馈记录进任务文件**（如 `开发文档/临时文档/…工作台.md` 的「MCP 反馈台账」一节），
表头建议：`条号 | 内容 | 类型`，另附**历次反馈来源**与**本轮效率实测**。

## 四、问题类型分类（华哥给的清单，照它归类）

1. **返回噪声过多**（不够简单干练）
2. **传参太多** —— 哪些能后台自动补，给具体建议
3. **同类请求报错 > 2 次** ⇒ 改提示词或流程
4. **太绕、不如一条终端命令** ⇒ 本质流程问题
5. **用得最多的命令类型** —— 汇报时要写，并判断要不要加/新增工具
6. **修复空间优先内置** —— 一条命令后台跑完内置流程，减少 agent 手动请求次数

**架构面**还要先答一个前置问题：这是**架构不稳定**（有过期事项 / 内容没对齐 ⇒ 挖掘架构不足，
**加初始化或注入对齐提示**）还是**纯 MCP 功能不足**（⇒ 维修）？**别盲目加功能。**

## 五、判词与关闭不在本口

本口只落「发现」。后续走：

| 动作 | 操作 | 要点 |
|---|---|---|
| 给判词 | `批量判定`（号 17） | 三档 `债务` / `非问题` / `待核`；债务必须给 `关联种类`（`未完成条目` / `开工`）+ `关联目标`（**不许悬空**） |
| 来源审完 | `登记报告审完`（号 19） | `提取条数` / `判词条数` 必须与库中实际相符 |
| 债务关闭 | `验证关闭`（号 20） | 要 `验证证据` / `验证命令` / `退出码` / `承接提交`（仓里真存在的提交） |

**顺序**：先 `验证关闭` 撤关联，**再**删台账条目（反过来会让关联悬空）。

## 六、汇报格式（给华哥）

1. **来源号 + 条目号区间 + 条数**（例：来源 942 · 条目 4703–4709 · 7 条）；
2. 一张表：条号 / 一句话内容 / 类型（效率 · 精度 · 一致性 · 架构）；
3. 本次**用得最多的命令类型** + 要不要新增工具的建议；
4. 已同步记录进哪个文件。

## 七、常见坑

- **提交前先 `v1_job 操作=status` 确认上一步作业已终态** —— 反馈里引用的作业ID 要真存在。
- **`报告指纹` 改了条目就要重算**（条目变了、指纹没变 ⇒ 幂等校验会判成「同键异文」）。
- **别把「自报」当验收**：本口只落发现，判词/关闭在别件；汇报时别说成「已修复」。
- **自动性能记录不阻断释放**（来源标识以自动前缀起头）⇒ 看到「另有 N 条自动性能记录（不阻断释放）」不用处理。
